# FLAME-MoE: A Transparent End-to-End Research Platform for MoE Language Models（arXiv 2505.20225，2025-05；Kang, Yu, Xiong，CMU；venue 未核对）`[证据级别：HTML §6.3 + GitHub/HF 页]`

1. 论文形态：开放平台 / 资产 + 初步分析（专精、共激活、路由饱和）。
2. 背景与压力：MoE 训练动力学研究只能用 OLMoE / OpenMoE 的少量 ckpt；缺跨尺度、全透明的轨迹。
3. 改变的前提：把多尺度 MoE 连同中间 ckpt、数据管线、日志全部公开，使训练轴分析可做尺度比较。
4. idea 来源（DOCUMENTED）：沿 OLMoE §5.1 的饱和公式，在自己的 7 个尺度上复算。
5. 与最近邻的距离：相对 OLMoE（单尺度 7B、每 5000 步 ckpt），它给 7 个尺度（38M–1.7B 激活，64 专家 top-8 + 2 共享）；相对 OpenMoE-8B（5 个 ckpt），点更多；饱和定义与 OLMoE 相同，结论同向。
6. 方法 / 数据：§6.3 Eq.10 饱和 = 逐 token t 与终点 top-k 交集 / k（k=1,2,4,8）；"rises sharply within the first few thousand steps"，中点多数层 >70%，深层先饱和；附录 D：大模型浅层饱和更慢（1.7B 的第 2 层 top-1 起点更低）。HF API 逐仓库核：**只有 1.7B（18 层，23.1B token，每 1100 iter ≈ 2.3B）、721M（12 层，18.4B，每 880 ≈ 1.85B）、290M（9 层，11.4B，每 540 ≈ 1.13B）有 10 个 `iter_*` 点**；419M 3 点；38M / 98M / 115M 只有终点。每 iter = 1024 × 2048 token。格式 Megatron torch_dist `.distcp`，仓库无 HF 转换脚本，HF 上无第三方转换版；仓库有自带 Megatron capture / router_saturation 脚本。
7. 证据强度与短板：预印本；饱和只对自身终点、无随机 / 固定路由器、无隐状态稳定性对照；附录图注 "top-6" 与正文 k 集合不一致；ckpt 为 Megatron 格式（能否直接转 HF 未核对）。
8. 可迁移的研究动作：把一个只在单模型上报的训练动力学读数放到同族多尺度上，得到"尺度"这条命名轴。
9. 对我们：推翻叙事"第二条训练轨迹没有公开的"，但不是零改动：需 Megatron → HF 转换；可用规模轴只有 290M / 721M / 1.7B 三点，且总训练量 ≤ 23B token（≈ OLMoE 第一个公开点），覆盖的是 OLMoE 左删失之前的早期段；也是"饱和被读成路由早定"的又一个持有者（BR B3）。
