# E185 三个残差的"平凡原因"核查（2026-11-09）

- **对象：** [E185 卡](../../../workbench/mechanism-population-dynamics/division/experiments/E185-routing-variance-atlas.md)"(ii) 没有简单解释的残差"里的三条：Qwen3 的 12 层周期、OLMoE 第 0 层按前一 token 路由、OLMoE 末层标点按语言分路。
- **做法：** 先查配置 / 代码 / 技术报告 / 权重，再看路由器一侧的统计，最后才谈解释。**GPU 0**（fvcrc20 CPU，`CUDA_VISIBLE_DEVICES=` 空）；缓存只读（`~/mechpop_cache/e179`、`e180`、`e184`、HF 权重）；中间文件放在 `~/mechpop_cache/atlas_e185/resid/`。
- **脚本**（`workbench/mechanism-population-dynamics/division/scripts/`）：`e185x_toksub_ids.py`（按 E179 的种子重放 toksub 抽样，恢复每行的 token id / 位置，与 `toksub_meta` 逐行一致）、`e185x_weights.py`（逐层权重统计 + 跨层相似度）、`e185x_layerstats.py`（路由器输入范数 / 各向异性 / 门控对齐 / T 与 Haar 旋转门控的熵）、`e185x_qwen_period.py`、`e185x_copy_agree.py`、`e185x_layer0.py`（在 CPU 上从权重精确重算第 0 层路由器输入，并按注意力来源拆分）、`e185x_gate_ov.py`、`e185x_punct.py`。
- **结果文件：** `division/results/e185/residual_*.json`、`residual_qwen3_period.png`。
- **一句话：** (1) 12 层周期**已解释**：Qwen3-30B-A3B 的第 6–17 层被整块复制成 18–29 层和 30–41 层（权重与路由都能看出来），周期是同一层出现了三次。(2) OLMoE 第 0 层**机制已定位、成因未解释**：第 0 层有一个前一 token 头（head 1），训练路由器读它输出子空间的强度是随机方向的 8.5 倍。(3) 末层标点**大部分由"后面接什么"解释**：不是语言专属的标点 id，也不是句末位置；以真实下一 token 的文字为条件后，T 的语言信息少了 77%；另外"OLMoE 远超几何"只对 N_B 成立，按 bit 算 Haar 零模型更多。

## 1. Qwen3-30B-A3B 的 12 层周期

**配置与报告（无周期结构）。** `config.json`：48 层，`decoder_sparse_step` 1，`mlp_only_layers` 为空，`use_sliding_window` false，`max_window_layers` 48，`rope_scaling` null，rope_theta 1e6，128 专家 / top-8，`norm_topk_prob` true，不 tie 词嵌入。transformers 4.57 `Qwen3MoeDecoderLayer` 每层同构（pre-norm RMSNorm，逐头 QK-norm，GQA 32/4）。技术报告（[arXiv 2505.09388](https://arxiv.org/html/2505.09388) §2）写的是：与稠密 Qwen3 同构、细粒度专家、"excludes shared experts"、global-batch 负载均衡、QK-Norm；**没有提到升级（upcycling）、层复制、逐层差异或流水线并行**。配置和代码里没有任何以 12 为周期的东西。

**权重：存在 lag-12 的整块复制（主要发现）。**
- 逐层把 q / o / v 投影矩阵展平后算余弦：**lag 12 的平均值 .26 / .37 / .48，lag 24 为 .11 / .20 / .30，其余所有 lag 都是 .000（|cos| < .001）**。逐对看，第 l 层与 l+12 层在 l = 6–29 时余弦 .26–.54（q），l = 6–17 与 l+24 层为 .15–.31；第 0–5 层和 42–47 层找不到任何伙伴。所以第 6–17、18–29、30–41 层是**同一个 12 层块的三份拷贝**，复制之后又继续训练（相似度没有回到 1）。
- 路由器行（置换不变的配对 |cos|）：拷贝层之间 .84–.91，相邻层 .73–.78，lag 11 / 13 只有 .64 / .63。
- 后注意力 RMSNorm 增益的均值在块边界跳变：第 17→18 层 .84→.99，第 29→30 层 1.09→1.23。
- 对照：OLMoE 的同一读数在所有 lag 上都是 .000（没有复制）。
- 旁证：有人在 Qwen3-32B 上用同样的权重余弦发现了间隔 24 层的复制（推测是第 8–31 层被复制成 32–55 层），并说 Qwen3-30B-A3B 也有人间接注意到（[LessWrong shortform，2026-10-20](https://www.lesswrong.com/posts/SaH4kx32vzTP9NHpC/andrew-epstein-s-shortform)；文中引用的 X 帖 https://x.com/kilian_maciej/status/1982612297874026731 **未读**）。Qwen 官方没有说明。

**复制也体现在逐 token 路由上**（`e185x_copy_agree.py`，E184 英语存储约 85k token，T）：用匈牙利算法按路由器行配对两层的专家后，拷贝层 (l, l+12) 的 top-1 一致率在块内平均 **.43**（逐对 .35–.51，偶然水平 .02–.05），top-8 重合 .68；相邻层只有 .13 / .41，lag 11 / 13 为 .11 / .37，lag 24 为 .33 / .60。也就是说，拷贝层把同样的 token 送到"同一个"专家。

**周期与块内位置对齐**（`e185x_qwen_period.py`；第 6–41 层，先去掉线性深度趋势，然后算"块内位置 0–11"的 R²，置换层序 2 万次求 p）：
| 剖面 | R²(块内位置) | p | 三份拷贝之间的相关 |
|---|---|---|---|
| E185 序列份额 T / N_B | .88 / .92 | < 1e-4 | .90–.99 |
| G_freq(序列∣输入) T / N_B | .87 / .91 | < 1e-4 | .92–.98 |
| G_freq(位置∣输入) T | .72 | .002 | .84–.94 |
| D180 专家熵 H(e) T | .82 | < 1e-4 | .72–.96 |
| T 的 top-8 负载熵（E179 全部 token） | .86 | < 1e-4 | .82–.92 |
| 权重：o_proj 范数 / 路由器范数 | .92 / .80 | < 1e-4 | .84–.98 |
| G_freq(序列∣输入) 的 **T / N_B 比值** | .47 | .08 | −.09–.69 |
| 路由器输入范数、PC1 份额、参与比 | .35 / .38 / .47 | .08–.34 | 不一致 |

对应关系："内容层"6–7 / 18–19 / 30–31 = 块内位置 0–1；"熵塌缩层"11–13 / 23–25 / 35–37 = 块内位置 5–7；T 的位置尖峰 20、22、25、32、37 = 块内位置 2、4、7（第一份拷贝里较弱：第 8 层 .11、第 13 层 .09 bit）。同一个块内位置在 N_B 上就是 D184 负载匹配失效的层（N_B 的 H(e)：第 20、22、25、32、34、37 层为 4.3 / 4.4 / 3.6 / 4.5 / 4.2 / 2.8 bit，T 为 5.3–5.6 bit）。

**路由器一侧的其他统计（周期不在这里）：** 第 0 个 token（没有 BOS）的路由器输入范数在第 4–39 层是其他位置的 2.1–3.0 倍（第 2 层 10 倍），在第 4–39 层解释 9–15% 的方差，基本就是 PC1；在 toksub 的 363 个句首 token 上，T 在第 1–46 层把 99–100% 的句首 token 送到同一个专家；门控避开这个方向（第 5–44 层 PC1 对齐 .23–.79，随机为 1）。熵塌缩层**并不**对应低范数或高各向异性（范数、PC1 份额、参与比都不随块内位置变化，见上表）。

**判断：周期由层复制解释（平凡原因）。** 在 Qwen3 上，第 6–41 层是 12 种层功能各出现 3 次，**三份拷贝不是三次独立复现**——E185 里"在 3 个周期层上都出现"的读数只算一个观察。仍未解释：(a) 为什么块内位置 0–1 的那一层携带文档信息，以及 T 在那里约是 N_B 的 2 倍（这个比值本身不跟着块走）；(b) 块内位置 2 / 4 / 7 的位置尖峰与 N_B 负载匹配失效同层，T − N_B 在这些层不可靠，尖峰可能部分来自零模型。检验：(a) 在 Qwen3-30B-A3B-Base 上重复复制检验，看拷贝层之间的路由一致率在后训练前后是否不同（0 GPU，Base 权重已缓存）；(b) 下次 GPU 采集时在测量语料上重新拟合 N_B 偏置，看位置尖峰是否还在。

## 2. OLMoE-1B-7B-0125-Instruct 第 0 层按前一 token 路由

**配置 / 代码 / 论文（第 0 层没有特殊处理）。** transformers 4.57 `OlmoeDecoderLayer`：input RMSNorm → 注意力（QK-norm 作用在整个 2048 维投影上，`clip_qkv` null）→ 残差 → post-attention RMSNorm → MoE（64 专家 top-8，`norm_topk_prob` false）。没有共享专家，第 0 层也没有稠密层。OLMoE 论文（[arXiv 2409.02060v2](https://arxiv.org/html/2409.02060v2)）§5.1 说"Layer 0 is an outlier saturating significantly more slowly"，§5.4 只比较输入 token 与预测输出 token，没有提到前一 token。检索没有找到 MoE 第 0 层按前一 token 路由的报告（最接近的是层间循环路由器 [arXiv 2408.06793](https://arxiv.org/html/2408.06793v2)，与此无关）。

**在 CPU 上精确重算**（`e185x_layer0.py`，FLORES dev 20 语 × 150 句，31.3 万 token）：从权重重算的路由器输入与 E179 存储的余弦 ≥ .99997，top-1 一致率 .993（400 个 token）。份额方向复现 E185：T 的前一 id .68 > 当前 id .32；3 个 Haar 旋转门控反过来，当前 id .66 > 前一 id .28。
- **注意力：** 16 个头里只有 head 1 是前一 token 头（平均注意力 .73），head 14 / 15 看自己（.84 / .93），其余接近均匀。范数：词嵌入 .36，注意力输出 .18，其中来自前一位置的部分 .075——**按范数算词嵌入占优**，所以几何零模型按当前 token 路由。
- **门控读哪里：** 路由器（乘以 post-norm 增益后）落在各头输出子空间里的能量，与随机子空间相比：**head 1 为 8.5 倍（16 个头里最高）**，head 14 / 15 为 6.4 / 5.8，其余 0.8–4.6。第 1 层最高 7.3，第 8 层 ≤ 2.3。Qwen3 第 0 层也有前一 token 头（head 20 / 22：.78 / .66），但门控对各头的读取比较平均（1.1–5.0），没有集中在某一个头上。
- **把某个成分换成它的均值之后 top-1 改变的比例：** T 的"来自前一位置的注意力输出"**79%**、词嵌入 52%；Haar 旋转门控分别是 36%、93%。logit 方差里"前一位置"那一项：T .72，Haar .12（6 倍）。

**判断：机制定位到了权重层面，成因未解释。** OLMoE 第 0 层"按前一 token 路由"，是因为训练路由器选择性地读取了 head 1（前一 token 头）写入的子空间。这不是架构或范数造成的伪影（第 0 层没有特殊结构，几何上也是当前 token 占优），但"为什么训练会把第 0 层路由器对齐到这个头"、"为什么只有 OLMoE 这样"仍未解释。检验：OLMoE 在 HF 上以 revision 形式公开了预训练中间检查点（0924 版；0125 版是否也有**未核对**），只需第 0 层权重就能在 CPU 上追踪 head-1 对齐倍数随训练的变化（与论文 §5.1"第 0 层饱和最慢"对照）；再加上 OLMoE-1B-7B-0125 Base 与 Instruct 的对比。

## 3. OLMoE 末层：标点按语言分路（T .246 vs N_B0 .088）

（`e185x_punct.py`，D180 无字母 token 8.4 万个，E185 同一估计器，份额 = Î / H(e)；复现 E185：OLMoE .246 / .088，Qwen3 .209 / .176，GPT-OSS .148 / .194。）
- **不是语言专属的标点 id：** 条件量 Î(语言∣输入 id) 按定义只来自"同一个 id 在不同语言里"。逐 id 分解后，T 的 .354 bit 中 `.`（18 种语言都有）占 40%（.141 bit；N_B0 只有 .027），`,` 占 30%，空格占 12%，前 5 个 id 合计 86%。印地语 `।` 在 OLMoE 的分词器里是字节碎片，不属于 NON 类，不参与这一项。
- **不是句末位置：** `.` 有 81% 在句末，但以"是否句末"为条件后，T 的份额只从 .246 变成 .242。
- **大部分是"后面接什么"：** 以预测下一 token 的文字（按数据为每个 id 定文字）为条件后，T 从 .246 降到 .125（−49%），N_B0 从 .088 降到 .043（−51%）；以预测下一 id 本身为条件则分别降到 .098 / .032。在非句末 token 上，以**真实**下一 token 的文字为条件后，T 从 .193 降到 .045（−77%），T − N_B0 的差从 .110 缩到 .016。Î(预测下一文字∣输入) 是 T .157 vs N_B0 .059；给定语言之后只剩 .028 / .010。
- **"远超几何"要看零模型和单位：** OLMoE 末层 T 在 NON token 上的专家熵只有 1.45 bit（N_B0 1.47，Haar N_A0 5.29）。按 bit 算，语言信息 T .35、N_B0 .13、**N_A0 .64**——T 只比负载匹配的 N_B0 多，比 Haar 旋转少。Qwen3 / GPT-OSS 末层同样由 `,` `.` 空格承担，T 与 N_B0 相近。

**判断：大部分已解释。** 标点上的语言信息不是 token 身份，也不是位置，主要是"下一个 token 是什么文字"——这与 E185 观察 3（末层 T 在给定输入后多携带下一 token 信息）是同一件事。仍未解释：句末 `.`（没有真实下一 token）上 T 的大额语言信息，以预测下一文字为条件后只去掉一部分。检验：在 23:00 后的采集中存 lm_head 的 top-k 预测分布，用预测分布的文字熵替代硬 argmax 作条件。

## 对 E185 读法的影响（建议，未改 CLAIMS / DIRECTION）
- Qwen3 的任何逐层或层段统计都应按块内位置报告，或者把第 6–41 层当成 12 种层而不是 36 层；"内容层 / 查表层"是同一层的三份拷贝。
- OLMoE 第 0 层是一个可以直接操作的对象：路由器 × 前一 token 头的对齐，有权重层面的读数（8.5×），可以用中间检查点追踪。
- 末层"标点按语言分路"并入观察 3（下一 token 信息），不单列为语言效应。
