## 1. 一句话

把自进化 agent 留下的持久产物（playbook / memory / skill）当作资产来记账：训练流停止后冻结产物，在**不相交的 held-out 任务**上测它的净价值，同时记录每次 LLM 调用的成本。结论：在 AgentStream 套件里实测的所有产物（ACE playbook 为主），**没有一个被确认为资产**。GPT-5.5 自己写的 playbook 有害；GPT-5.4 的在 reasoning=medium 下“无法判定”，在 reasoning=none 下有害。

## 2. 四个账户（Table 1 的定义）

| 账户 | 符号 | 定义 |
|---|---|---|
| 冻结 held-out 价值 | v = r_src | 在构建该产物的 backbone 上，held-out 任务的成功率「注入产物」减「不注入」，配对差，任务级 bootstrap 置信区间 |
| 构建成本 | B | evolve + curate 阶段所有 LLM 调用的 token / 美元 |
| 每任务携带成本 | c | 执行阶段「有产物」减「无产物」的每任务成本（含产物文本每次调用都被重发，以及产物诱发的额外调用） |
| backbone 寿命 | H | min(厂商下线时间, 部署方主动换更好模型的时间)；开源权重可固定版本，故强制项为无穷 |

派生量：
- 折旧 δ = 1 − r_tgt / r_src（r_tgt：把同一冻结快照移植到另一个 backbone 后的价值）。**只对已确认的资产定义**。
- 升级价格 p：换成后继模型多解出一个任务的成本；盈亏平衡价值 v* = c/p；回本任务数 N* = B/(v·p − c)。
- 另有 churn：在线改写产物会让 prompt cache 的前缀失效，每次改写约多一次未命中。

## 3. 如何冻结与评测

- 所有调用经统一 wrapper，必须带 phase 标签（execute / evolve / curate / benchmark / overhead）；绕过 wrapper 的调用写入 phase=unknown 毒记录，含毒记录的 run 作废。每条记录含服务端报告的用量、cache 命中、前缀哈希、按公开价目表算的美元成本。账本与账单对账：$176.04 vs 提供商面板约 $180。
- **构建集** = AgentStream 自带的 50 任务（seed 42）；**held-out** = 同一选择内其余任务（Tau2-telecom 为 64 个；前 50 先跑，后 14 个是看到结果后追加的）。
- 构建结束后对所有存储做 SHA-256 内容寻址快照；评测时 evolve 被硬禁用（冻结标志下任何 evolve 调用直接抛错）。
- **识别闸门（recognition gate）**：r_src 的 95% 置信下界 ≤ 0 即 REFUSED，不计算 δ。结局三类：recognised（区间在 0 之上）/ harmful（在 0 之下）/ inconclusive（跨 0）。闸门用未校正的双侧 95%，在闭源实验之前写进 runner（但开源轮次已看过，也未公开预注册）。Holm 校正另报，不决定闸门。
- 不改动 AgentStream 的方法、基准、任务选择、提示词；仅换底座模型。无资产对照用“空 playbook 的 ACE 脚手架”，另有 vanilla 工具调用 agent 作交叉对照。
- 统计功效（附录 D）：配对差 SD 约 0.40–0.48；n=50 时区间半宽约 12–14 点，n=64 且 2 个重复约 8 点；真实 +13 点的功效只有 0.55（n=64 时 0.62）；真实 +0.02 需要 n≈2000。

## 4. 被审计的系统、模型、基准、种子

- 套件：AgentStream（6 个基准、5 种自进化方法、3 种流场景）。本文**实际跑**的：方法只有 ACE（主）和 ReasoningBank（R4 一轮，及闭源上一次失败的尝试）；A-Mem、AutoSkill、Harness 仅插桩未运行。基准 3 列：GSM8K（套件之外的 sanity）、BFCL、Tau2-telecom。
- 模型：开源 Qwen3-4B、Qwen3-8B、Qwen3-8B-AWQ、Qwen3-32B-AWQ、gpt-oss-120b、granite-3.3-8B（移植目标）；闭源 gpt-5.4-2026-03-05、gpt-5.5-2026-04-23。
- 规模（投稿时）：54 个 run（30 开源 + 24 闭源）、2212 个 agent session、51K 次 LLM 调用、4.82 亿 agent 侧 token；闭源侧花费 $176。讨论期又加了独立重建 C1b / C2b / C2c、C1n 以及附录 H 的对照。
- 重复：C1 每臂 2 个重复（n=64）；其余多为单次，n=50。每个闭源模型有独立重建（从空 playbook、同任务顺序重来），但共享同一任务顺序，所以重建间的差异是下界。reasoning=none 的那一轮只有一次构建。
- 选 Tau2-telecom 是看了开源轮结果后才定的（作者承认）；这是 AgentStream 报告中增益最大的一列（GPT-5.4：50.0 → 63.3）。

### 5.2 GPT-5.4 / Tau2-telecom 细节（Table 3）

- held-out 成功率 有 / 无 资产：0.84 / 0.82；两个重复各自的差为 −0.02 和 +0.06；前 50 个任务 +0.05 [−0.04, +0.14]。
- 在线增益（构建任务上，ACE 在线 vs 无资产）：0.78 / 0.74 = +0.04 [−0.08, +0.16]。**冻结价值与在线增益都与 AgentStream 报告的 +13 点对不上。**
- 噪声地板：同一条件两个相同的 run 只在 47–48 / 64 个任务上结果一致，约 25–27% 的任务仅因采样而翻转。
- **reasoning 设置不一致**：AgentStream 论文写 GPT-5.4-medium，但其发布代码未设该参数，实际等于 none（账本里推理 token 为 0；medium 约 2,400/任务）。无资产基线：论文 0.50；其发布代码实跑 0.44 [0.30, 0.58]；medium 的 vanilla agent 0.82，ACE 空 playbook 脚手架 0.74。在 none 下重跑：ACE 在线 0.34 vs vanilla 0.44（−0.10 [−0.30, +0.10]），冻结后 0.25 vs 0.42（−0.17），逐任务 playbook 更好 10 个、更差 26 个、持平 28 个。即“+13 点”在作者构建里没复现，且无法判定其来源。
- 附录说明 AgentStream 发布脚本在其环境里还有别的差异（session 无结果就丢弃而作者记 0、开 client cache 等，见 Table 11）。

### 5.3 成本账户

- 携带成本：7.6K token 的 playbook，使每任务执行成本 +48%（$0.172 vs $0.116；c = $0.056），每次调用 prompt token ×1.96，即使 96% 的 prompt token 命中缓存。其中约 30% 来自诱发的额外调用（20.2 vs 16.7 次/任务），其余是产物文本每次重发。
- 构建成本 B：GPT-5.4 $3.77（$0.075/构建任务），GPT-5.5 $8.58。回本任务数 B/c ≈ 67（携带成本累计在 67 个任务后超过一次性构建成本）。
- churn：在线重写使每任务首次调用基本不命中缓存（2%），冻结后首次调用 97% 命中；每任务约 $0.0086（GPT-5.4）/ $0.0096（GPT-5.5），约占 carry 的 15%、执行账单的 5%。
- 事前的 token 计数预估（Table 7）把 carry 估成 $0.21–$0.93/任务，比实测高 4–16 倍，因为没考虑缓存。
- 开源 R5：5.7K token 的 playbook 每任务多 318K prompt token（46% 为文本重发，51% 为多出的 15 次调用）；15 个任务撞到 40K 上下文上限（无资产时 2 个），所以 R5 的负价值部分可能是截断而非内容。

### 5.4 升级替代与寿命（Finding 5/6、Table 6、Figure 3）

- 把 GPT-5.4 的冻结 playbook 移植到 GPT-5.5：0.92 vs 0.90，r_tgt = +0.02 [−0.06, +0.12]，携带成本 $0.103/任务（$0.291 vs $0.188）；GPT-5.5 无资产已有 0.90，天花板最多 +0.10。
- 升级价格 p = $0.62 / 多解一个任务（95% [$0.36, $1.96]，GPT-5.4→5.5，无资产，49 个共同任务：成功 0.796→0.918，成本 $0.112→$0.188）；v* = c/p ≈ 0.09。GPT-5.4 产物 v=0.023，边际 −$0.041/任务；即便取区间上界 v=0.10，边际仅 +$0.007，N*=526，约需每天 1.4 个任务以上才能在 12 个月内回本。
- 快照寿命数据集（46 个 id）：Anthropic 2025 年发布的实际寿命 12–13 个月，OpenAI 14.2–20.7 个月，通知期 60–180 天，发布后 12 个月是公开下限。
- 对此产物，边际符号决定结论，H 只在边际薄且吞吐低时才起作用。

### 5.5 对照与探索（标明为探索，非预设）

- **语法破坏的 placebo**：把 GPT-5.4 playbook 每条内的词打乱（长度、词表、段头保留）。64 任务 0.875 vs 无资产 0.820；真 − 安慰剂 = −0.03 [−0.11, +0.05]；carry 复现了 $0.056 中的 $0.047（84%）；调用数 17.9（placebo）vs 19.4（真）vs 15.8（无）。即**在 medium 下无法区分“内容”与“同长度同词表的文字”**。（placebo 是 1 个重复对两个种子的均值；关键词效应不能排除；移植侧没测 placebo。）
- **“自己写自己用”的特异性**：GPT-5.5 的 playbook 对 GPT-5.5 自己有害，而 GPT-5.4 写的两个 playbook（C1、C1b）在 GPT-5.5 上比它自己写的三个高 0.26 [0.16, 0.36]，且 GPT-5.4 的更长（约两倍），所以不是长度所致。作者不给机制。
- **失败集中**：C2 里 13 个由成功变失败的任务全是 MMS troubleshooting（基线占 50%，二项检验 p≈1e-4）；三次构建里 42 个丢失任务 38 个是 MMS；对话变长、客户离开（长度在 C2、C2c 复现，C2b 反而变短）。
- **条目质量**：C1 playbook 106 条，76 条从未被 ACE 自己的 curator 标记为 helpful（占 token 74%），33 条标过 harmful，但全部每次调用注入。C1n 112 条里 69 条同样。ACE 在线成功率随 playbook 增长而下降（在 C1n 的位置分段：前 10 个解 6，中 15 个解 5，后 25 个解 6）。
- **剪枝（探索，事后选的）**：只留 helpful>0 的条目。Pruned C1（106→30 条）r_src = +0.09 [+0.03, +0.16]，是**唯一被闸门确认的产物**，carry 降 36%；但 Holm 后 p=0.11，且与其自身 placebo 不可分（+0.04 [−0.02, +0.12]）；被删的 76 条本身为 −0.16 [−0.27, −0.06]。Pruned C1b −0.01（不确定），Pruned C2 −0.28（有害，carry 仅降 6%）。移植到 GPT-5.5：C1 +0.02、C1b +0.04、Pruned C1 +0.06，均不确定；对唯一的“资产”，δ 的区间覆盖从保留到有毒全部分档，故不给点估计。
- **headroom 分析**：无法判断效应是否依赖难度（在已解 / 未解任务上效应区间都很宽）。
- **ReasoningBank 在 GPT-5.4 上**：构建完成（$9.0），但 agent 在线 50 题只解 1 题，48 个 session 完全不调工具（模型把 “Memory Item…” 前言当作对客户的回复就停了）；AgentStream 报 46.7%。因为不改提示词，冻结 run 被取消，账本作为失败记录存档。

## 6. 它回答了“累积的记忆/技能保持价值吗”

作者的回答：在被测的 ACE playbook 上，冻结后价值在多数情况下检测不到，在若干情形下为负；没有证据显示累积产物在冻结后的 held-out 上保持了流式评测里的增益。同时它是持续开销（携带成本 +48%，67 个任务后超过构建成本）。证据强度不等：有害结论最强（GPT-5.5 三次重建），“无价值”在 medium 下只是“n 太小，不能排除 ≤ +0.09–0.10”。

## 7. 局限（作者自己列的 + 我读到的）

作者自陈：
- 统计：n=50–64 只能检测约 8–14 点以上的效应，inconclusive 不是无效；C1 两个重复符号相反；所有重建共享同一任务顺序；reasoning=none 只有单次构建；46 个对比 Holm 校正后只有一个闭源有害产物仍显著；C1 的 14 任务扩展与讨论期所有 run 都是看到 50 任务结果后决定的。
- 构造：placebo 保留词表，不排除关键词效应；“label-free” 只由 ACE 和一轮 ReasoningBank 实例化。
- 混杂：R5 与上下文截断重合；三个大 backbone 在基准和 reasoning 设置上都不同，不读趋势；AgentStream 论文与代码的 reasoning 不一致；作者与其发布代码的另几处差别（日期快照、无结果 session 记 0、关 client cache）。
- 外部：一种方法（ACE）、三列基准、一个闭源厂商（只有 OpenAI），narrow generality。
- 闸门在开源轮之后才定，未在公共平台预注册；选 Tau2-telecom 是事后的。
- 无资产参考存在漂移：C1b 对 9 月的无资产 run 是 +0.09 [+0.01, +0.16]（会被确认），对 11 月的是 +0.04；作者用同月参考。两个月的无资产水平 0.82 vs 0.87，漂移不可排除。
- 我补充（读后判断，不属作者陈述）：核心 backbone 比较里 GPT-5.5 的 reasoning 是“提供商默认”，而 GPT-5.4 是显式 medium；GPT-5.4 的 playbook 是在没有推理的 reflector 写的，GPT-5.5 的有推理；这些差别被作者写在附录 H.2，但没有被用来解释结果。

## 8. 对 data-centric RSI 的含义

### 8.1 事实（来自本文、可直接引用）

1. **“留存增益”必须在冻结+held-out 上测。** 本文把“在线累积增益”和“冻结后在不相交任务上的价值”分开，并给出了完整协议（内容寻址快照、evolve 硬禁用、配对 bootstrap、同月无资产对照）。在 GPT-5.4 / Tau2-telecom 这一列，在线增益 +0.04、冻结价值 +0.02，都跨 0；在套件里报告的 +13 点没复现。
2. **持久状态可以有负的留存价值。** GPT-5.5 自己的 playbook 三次独立构建均有害，合并 −0.23 [−0.34, −0.12]。所以“状态累积 ≠ 有益”，至少对 label-free 的 ACE 如此。
3. **成本不可忽略且可测。** 携带成本 +48%/任务，67 个任务后超过构建成本；预估（只数 token）比实测高 4–16 倍，因为缓存。成本账必须读服务端 cached token。
4. **产物并不随模型升级自动继承价值。** GPT-5.4 的 playbook 在 GPT-5.5 上价值 +0.02（天花板 +0.10），携带成本加倍。
5. **“谁写的”比“写了多少”重要。** 在 GPT-5.5 上，GPT-5.4 写的 playbook 比 GPT-5.5 自己写的高 0.26，而前者更长。
6. **条目级筛选有迹象但弱。** 剪成 helpful>0 的条目后一例变为正（+0.09），但仅一例、事后选取、Holm 后不显著、与 placebo 不可分；另一例 −0.01，另一例仍有害。
7. **评估设计提示。** 文中的 placebo（词打乱）在 medium 下复现了 84% 的携带成本和大部分行为足迹（调用数变化），说明 playbook 的效应可能很大程度是“文本存在”本身；同一条件两次运行有 25–27% 任务翻转，噪声地板很高。
8. 本文**没有**测：improver（反思/整理产物的过程）是否变得更好；多轮迭代中状态如何演化到停止后；权重更新类的 data-centric RSI。只测了一次构建（50 任务）后的冻结产物。

### 8.2 推测（标注为推测，未被本文证明）

- 【推测】本文提供了我们“留存增益”读数的现成模板：冻结 → 不相交 held-out → 配对差，附“同长度/词表打乱”的 placebo 和“作者 backbone vs 他者 backbone”的移植对照。若我们做 data-centric RSI，自己的实验卡应当至少含这三个对照；它们与我们的 R8（提示词行为探针需恢复对照）精神一致。
- 【推测】“improver 是否变好”在本文里近似对应“在线增益 vs 冻结价值”的差：如果流内增益存在而冻结价值为零，说明增益来自在流中的反思动作而非留存状态。本文数据（在线 +0.04 / 冻结 +0.02）两者都不显著，不能据此区分，需要更大 n。
- 【推测】负价值伴随“对话变长”和“集中在某类任务（MMS）”，暗示留存状态的伤害可能是行为/节奏偏移而非事实错误；若如此，权重级或事实级数据状态（而非提示词级状态）可能表现不同。本文没有测权重更新，这条无证据。
