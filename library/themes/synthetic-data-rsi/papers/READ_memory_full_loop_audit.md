## 1. 一句话

作者审计"自演化记忆系统"的整条循环（评估→诊断→编辑→接受→保留）。他们逐题（question-level）记录每个版本的对错，用"不改动重评"当噪声参照，把每一步的变化拆成 repairs（错变对）、regressions（对变错）和 no-edit flips（无编辑翻转）。结论是：循环三个隐含假设都不成立，早期增益大部分来自一次大的检索升级，后期改动的"修复"量衰减到与无编辑翻转同量级，而"回归"不降。

## 2. 三个被审计的假设及其测量

| 假设 | 失败模式 | 怎么测 |
|---|---|---|
| I 评估能识别失败 | 评估给出不稳定反馈 | (a) 同一版本重评 3 次，算翻转率（flip rate）和分数差的 2σ；(b) 整个循环从同一 root 重跑 4 次；(c) 把每个失败题做 replay（同版本 temperature 0 重放）和 gold-evidence（只给标注证据作答），分成 replay-correct / gold-unresolved / 可归因（S1 抽取、S2 检索、S3 生成） |
| II 编辑能修复失败 | 编辑会破坏未瞄准的题 | 每个编辑与它实际修改的父版本配对，数 F={父错子对}、B={父对子错}；用"瓶颈阶段"s*（可归因失败最多的阶段）判断编辑是否 aligned；用"检索上下文是否变化"解释回归落点 |
| III 被接受的修复会保留 | 修复不累积 | 把每个版本的修订分成早半（E）和后半（L），比较 repair/regression 体量与无编辑翻转；沿接受谱系看"新修复的题"在下一步是否又错；减去无编辑翻转率 ε+、ε− 得到"超出噪声的"修复与回归 |

关键公式：accuracy 变化 = (|F|−|B|)/N（精确）；近似分解 ΔAcc ≈ (1−p)·φ·r − p·h + (ε+ − ε−)。p 为父版本准确率，φ 为瓶颈阶段占失败的份额，r 为该份额内的修复率，h 为对题的回归率。判断是：对齐只提高 φr，而 h 来自共享组件，不被对齐降低。作者强调这是近似，且假设修复集中在被瞄准的池子里。

## 3. 系统、模型、基准、种子

**系统（4 个方法）**
- EvolveMem：调一个固定检索式记忆管线的配置，≤7 轮，用 mixed F1 选择，在一个对话的全部题上演化（in-sample）。
- ARC（AutoResearchClaw）：8 种配置，action 空间 closed（只改配置）/ open（还可改抽取和答题 prompt），诊断器读 root（r0）或当前 incumbent（inc），≤10 轮。作者在 EvolveMem 的弱初始管线上跑 ARC，另在已发布的 Omni-SimpleMem 上跑（附录 E.2）。
- MemPro：agent 重写自己的记忆程序（代码+prompt），judge accuracy 选择，在随机 10% 题上演化，其余 90% 作 held-out，10–15 轮。
- GEPA：优化 MemPro 管线的 5 个 prompt，不写诊断，所以只测反馈和保留，不能比诊断与编辑。

**基准**：LoCoMo（10 个长对话，类别 1–4 共 1,540 题）、Mem-Gallery（caption-only，20 场景，1,711 题；另有一组用真实 query 图重复）、LongMemEval_S（500 题，每题自己的历史，100 dev / 400 held-out，可检验"对话格式"依赖）。

**模型**：主实验各角色用 Qwen3-max；MemPro 的演化 agent 是 kimi-k3，任务模型 Qwen3-30B-A3B，选择 judge 为 Qwen3-max。附录 E.3 把诊断器/答题模型/ARC agent 换成 GPT-4o 或 GPT-4o-mini 重做。

**种子/重复**：整个循环每方法重跑 4 次（GEPA 在 LongMemEval 只一次）；LoCoMo 的 dev 拆分种子 2026–2029（MemPro 探针和谱系用 2027–2029），LongMemEval 种子 2028；每个版本"不改动重评"另做 3 次。干预实验每臂 3–5 次独立运行（见 §7）。

## 4. 关键数字：增益在哪个阶段丢失

### 4.1 评估不稳定（Table 1、10、22、20、21）
- **翻转率**（同一版本重评，题的对错变化的比例）：F1 选择的循环约 2.4–3.2%（LongMemEval 2.5–5.7%）；judge 选择的 MemPro 8.7%、GEPA 10.8%。MemPro 的 root 重评在 462 对题上让 39/117 个失败变对、22/345 个正确变错，净变 +3.7 pp，翻转率 13.2%（Table 的 B.5 段）。
- **噪声来源**（MemPro root，Table 22）：对固定答案重新判分只翻 0.43%（dev）/0.31%（held-out）；固定记忆重新生成答案翻 7.47%；重建记忆再答翻 7.79%。所以翻转主要来自**答案生成**，不是 judge。EvolveMem 上同代码重建记忆翻 17%，是同一记忆答两次（约 3.5%）的约 5 倍。
- **temperature 0 也不可复现**（Table 12）：两次评估翻 15.4%，与 0.3 下最离散的一对相当；同一 prompt 在服务端 5 次调用给出 5 个不同输出。因此作者用"不改动重评"当噪声参照。
- **接受的步骤落在 2σ 内的比例**：EvolveMem 50%、ARC 56–68%、MemPro 96%（22/23）、GEPA 88%；LongMemEval 44–83%。
- **整循环重跑 4 次**（Table 1b）：方向可复现，大小不可复现。F1 选择的循环每次都有正增益，但谱系终点的 SD 是 root 的数倍（1.3–3.3 pts 对 0.4–0.5 pts）。MemPro dev 增益稳定（+16.2±0.5）但 held-out +3.8±2.0；GEPA held-out +0.2±1.0（符号会变）；ARC open 两个变体有几次最终停在 root 上；LongMemEval 上 MemPro held-out 从 +4.0 到 +12.8。
- **可归因失败只是少数**（MemPro 实际收到的 root 失败）：LoCoMo 34%（40/117）、Mem-Gallery 26%（35/136）、LongMemEval 40%（10/25）。LoCoMo 另有 31% 靠 replay 就变对，34% 给了 gold 证据也错；Mem-Gallery 21% replay 变对、38% gold 仍错、15% 是无证据的对抗题。
- **judge 敏感性**：对同一批 held-out 答案换第二个 judge（GPT-4o-mini），选中版本增益从 +2.74 变成 −0.15 pp（Table 21，seed 2029 符号翻转）。**选择指标敏感性**：F1 选择的 MemPro run 在 held-out 上 F1 +5.70 但 judge accuracy 仅 +0.29 pp；judge 选择的同拆分版本 +3.17 F1、+5.56 pp。
- **dev 集分辨率**（E.6）：154 题时重评 root 的 2σ=5.76 pp，一题=0.65 pp，而第 6–10 轮被接受的步只改 1–2 题（0.65–1.3 pp）。要在 MemPro 翻转率 8.7–13.2% 下分辨这些步，约需 2,000–12,500 题 dev，而 LoCoMo 总共 1,540 题。dev 加倍到 308 题、每版评 3 次，root 的 2σ 降到 2.54 pp，但 15 次修订里只有 2 次超过它（+2.71、+2.60 pp，都加了日期锚定，修的是 temporal 题）。

### 4.2 编辑破坏未瞄准的题（Table 2、Fig 3、Table 24–26、E.4）
- **提案常瞄不准瓶颈**：EvolveMem 67 个提案中 56 个没有指向瓶颈阶段，34 个可评分诊断里 18 个"解释是检索、提案却改答题"。ARC closed/r0 按设计读 root，却在 57 轮中 47 轮编辑已演化的 incumbent，其中 28 轮的诊断就此首次出错（诊断漏斗 Fig 4：closed/r0 55 个可评轮次 → L2 参考失效剔除 28 → 执行/覆盖 −10 → 噪声内 −4 → 10 轮有增益；closed/inc 48 → L1 阶段判断错 −24 → …→ 11 轮有增益）。读 incumbent 只是把失败从 L2 移到 L1，有增益的轮数几乎不变。
- **对齐的编辑修得多**：aligned 修复父版本 34–41% 的失败，misaligned 只有 8–20%；EvolveMem 和 ARC closed/r0 里 28 个 aligned 编辑中 17 个提分，42 个 misaligned 只有 1 个（三个循环合计 24/38 对 1/46）；所有 26 个"修复和净变都超过自己 2σ 带"的编辑都是 aligned。
- **但回归不降**：aligned 与 misaligned 都破坏约 4–6% 原本正确的题（Table 2：如 EvolveMem 5.7% 对 4.7%；ARC closed/r0 3.6% 对 5.0%）。46 个 misaligned 里 14 个"修复超噪声但被回归抵消"（Offset）。
- **回归的机制是共享组件**：编辑改的是检索旋钮、抽取模板、答题 prompt 或代码，所有题共用。499 个回归里 427 个落在检索上下文被改变的题上；上下文被改变的题回归率是未变题的数倍，未变题接近"不改动重评"的水平。ARC open/inc 的两次答题 prompt 编辑保持所有上下文不变，却丢了 12.5% 的正确题。案例（附录 G，Table 38）：A、B 是 gold 记忆被挤出上下文；C 是新近重复记忆进入上下文导致答案漂移；D 是答题 prompt 改写使 gold 在上下文中却改成拒答。
- **按类别限制编辑也不隔离修复**：离线"组合控制"（类别内用子答案、类别外用父答案）保留 31%/26%/27% 的修复，与同样大小的随机类别门（34%/25%/27%）相当，净增益下降。
- **阶段信息的作用只是更早到达检索升级**（Table 26）：固定 EvolveMem 的 root、guard、接受规则和 12 个 recipe 的菜单，对比上游 LLM 提案器 A0（7 轮后 +7.9）、三种随机菜单顺序 A2（+8.3，三次分别 +11.6/+4.4/+9.0）、按 incumbent 瓶颈阶段取下一个菜单项的 A3（+12.3，第 1 轮就 +10.5）。优势来自更早找到检索升级，而不是延长后续增益；所有 17 个提分的 aligned 编辑都发生在父版本启用语义检索之前。作者自己注明：只是该提案策略+菜单的实例，in-sample，三个随机顺序不支持一般性等价结论。
- **模型替换**（E.3，Table 17）：stage 对齐率不排序增益。LoCoMo EvolveMem：Qwen3-max 0.16/+7.9，GPT-4o 0.30/+11.9，GPT-4o-mini 0.69/+2.9（对齐率最高、增益最低）。决定增益的是循环多早提出语义检索：GPT-4o 在 10/10 对话的第 0 轮提出，GPT-4o-mini 只有 3 个对话在第 4–7 轮到达。ARC 换 GPT-4o 增益翻倍（+11.0 对 +5.5），因为它的编辑留在检索设置内（67 个 claim 全部被执行），而 Qwen agent 的 43 个诊断中 26 个被 guard 拦下。
- **根部瓶颈**：10 个对话的 root 里 S2（检索）都占可归因失败的约四分之三（root φ=0.76）；最终版本里 S2 失败减少一半以上（EvolveMem、ARC closed/r0）或三分之一（ARC open/inc），S1/S3 几乎不变。

### 4.3 修复不累积（Table 3、27–32、Table 11）
- **18 个设置**（6 方法 × 3 数据集）里修复体量从早到晚**全部下降**；回归体量下降更少或不降，除一个设置外；**16/18** 个设置里后期修订破坏的题不少于修复的题。例：LoCoMo EvolveMem 修复 5.0→2.9、回归 2.4→3.3（pp）；ARC closed/r0 修复 8.7→1.2、回归 1.8→2.3；ARC closed/inc 10.9→2.8 对 2.7→5.5。MemPro 与 GEPA 的后期修复降到无编辑翻转（5.2/5.7 pp、3.5/4.7 pp）附近。
- **减去无编辑翻转**（Table 30）：噪声占后期翻转的 1/3 到 2/3（EvolveMem 33%、ARC closed/r0 67%、ARC open/inc 61%）。ARC closed/r0 后期：观测修复 1.25 pp、观测回归 2.34 pp，减去 1.11/1.29 后只剩修复 0.13、回归 1.05 pp；后期调整后净增益的 bootstrap 95% 区间为 EvolveMem [−1.82,+1.17]、ARC closed/r0 [−1.26,−0.54]、ARC open/inc [−0.73,+0.95]。
- **单次翻转不是修复的可靠证据**：无编辑下，刚变对的题在第三次评估中约一半又变错（MemPro 12/25=48%、GEPA 14/31=45%、ARC open/inc 8/14=57%，对照组 4.8%/4.4%/1.1%）。MemPro 在 308 题 dev 的 16 版本 run 里，后 8 次修订共 232 个单次翻转，只有 4 个修复和 7 个回归在父 3 次评估全错/全对、子 3 次全对/全错上稳定（即 221 个不稳定）。无编辑的两组各 3 次评估相比，每个方向仅 0.15 pp。
- **谱系上新修复更易再丢**（Table 28）：MemPro 更新后新修复的题下一步错 28.9%（对照 4.6%）；GEPA 36.9%（对 5.5%）；Mem-Gallery MemPro 33.4%（对 2.5%）。EvolveMem 8.3% 对 2.0%。作者注明两组选择方式不同，无编辑时也有同向差异（如 5.4% 对 0.9%），所以不能当作"后续编辑针对新修复"的证据。
- **周转远大于净增益**（Table 32）：MemPro LoCoMo 谱系上单步改变 108–236 题，沿谱系 W→C 约 470–810、C→W 约 395–770（仅差 +42 到 +77），约 29–41% 的 held-out 题至少改变一次状态，而 root 重评本身就有 150–162 题不同；终点比 root 高 3–6 pp。
- **Mem-Gallery 查询图 vs caption**（Table 11）：有图的 487 题 F1 +6.25 pts，无图的 1,224 题 −0.07；两个臂的演化增益相差 0.53 pts，所有发现不变（步内 2σ 比例 49%/51%，修复 4.5→1.9 / 5.0→2.2，回归 2.0→2.9 / 2.9→2.9）。
- **Omni-SimpleMem（E.2）**：从已发布配置出发，增益仅 +1.4 到 +2.0 pts（LoCoMo）、+1.0 到 +1.7（Mem-Gallery），与测量噪声同量级（重评 root 翻 3.6%；Qwen agent 四个配置的 59 个被接受步中 43 个在 2σ 内，closed/r0 22 个里 19 个）。Mem-Gallery split-half 回放只保留 +0.2 到 +1.0。从"弱起点"（关闭系统自己报告的发现）出发增益 +32.7 到 +36.9 pts，其中 +29.5 到 +35.6 在第 2 轮前到位；closed/r0 的 10 个对话中 9 个的第一次接受编辑就换回已发布的规则式答题 prompt，6 个还打开混合检索。这一步是泛化的：在一个对话上选出的配置用到其他 9 个对话，混合分从 24.1 升到 58.5，全部 9 个都为正（+28.6 到 +36.8）。弱起点下 134 个被接受步里仍有 51 个在 2σ 内。

## 5. 干预实验（Section 6，MemPro）

**三个机制，对应三个失败模式**（Algorithm 1，附录 C.4）：
1. *verified feedback*（I）：harness 对每个新版本评两次，并对第一次的错题做 temperature 0 replay；题分类为 fragile（两次不一致）/ stable-correct / replay-correct / stable-wrong，把这份"ledger"给 agent。
2. *repair round*（II）：对同时有 ≥1 个稳定修复和 ≥1 个稳定回归的修订，开一个独立会话，只给它看修了哪些题、破坏了哪些题，让它缩窄改动（保留修复、去除回归；禁止按题号/题面/金标答案特判，harness 扫 diff）。
3. *paired acceptance*（III）：只有稳定修复数−稳定回归数 ≥1 且 z=(f−b)/√(f+b) ≥ 1 才通过（z≥1 是设计选择，不是显著性检验），通过的里选 f−b 最大者。

**臂**：E0 = 原 MemPro（4 次）；E1 = +ledger（3 次）；E2 = +ledger+失败阶段（1 次探索性）；E1+repair（3 次）；E2+repair（1 次）。154 题 dev，1,386 题 held-out，10 轮。**另有 5 次匹配对照**（本地 Qwen3-30B-A3B + Qwen3.7-max judge，因原 judge 端点下线）：E0、E0-2x（评两次取均值，无 ledger/repair）、E1+repair 各 5 次。

**结果（Table 4、33–37）**：
- 针对性：agent 的目标中稳定失败占比 E0 69%、E1 86–97%、E2 96%。但"子版本新答对的题"中，52–71%（E0–E2）在父版本里是 fragile 或 replay-correct，即假修复。
- 稳定回归（每次修订）：E1+repair 由 2.5 降到 1.4（每个有标注的 run 都降），E2+repair 3.0→2.7。
- dev 准确率（round-10 incumbent，root 75.97）：E0 86.69，E1 85.50，E2 89.29，E1+repair **92.31**（SD 0.49），E2+repair 89.29。
- held-out 增益：E0 +3.79（SD 2.00，4 次跨度 4.4 pp），E1 +2.60，E2 +2.61，E1+repair +3.50（SD 0.29），E2+repair +3.05。与 E0 的差异**不显著**，95% 区间在 +3 pp 以下。
- 匹配对照：E0 +3.24±1.40，E0-2x +2.59±2.12（评两次本身不提升也不降方差），E1+repair +4.76±0.84，对 E0 的差 +1.52 pp（Welch p=0.08，95% CI [−0.23,+3.27]），对 E0-2x +2.17（p=0.08，CI [−0.42,+4.75]）；两侧区间都含 0。
- dev 增益只部分转到 held-out：E0–E2 的选中版本在二次评估中比第一次低 3–6 pp（选择偏差，Cawley & Talbot），但仍比 root 均值高 4.5–11.7 pp，而 held-out 只有 1.2–3.8 pp。作者给两个解释：（i）去掉噪声翻转后，root 的 20 个稳定失败中只有 5 个在 gold 证据下变对，其余可能需要"适合这些具体题"的改动；（ii）后期步只改一两道稳定题，在 dev 集分辨率以内。
- repair 的效果不一致（Table 35）：E1+repair 共 7 个 repair 孩子，5 个被接受；其 8 个轮内比较中 3 个显著正（+2.98、+6.25、+2.10）、1 个显著负（−1.95）、其余在带内；E2+repair 9 个 repair 孩子**一个都没被接受**，稳定修复/回归 3.0/2.7 对原修订 3.1/3.0。作者写明"同一设计在不同臂和 run 上结果不同"。
- 成本（Table 37）：E0/E1/E2 的 agent 时间和 kimi-k3 token 约 22–27 小时、120–132M；repair 臂再多 ~26 小时 agent 时间、总 265–375M token，生成 17–19 个版本。**臂只在轮数上匹配，不在成本上匹配**。

## 6. 异常与作者自己的保留

1. 单次评估之间的差异在 temperature 0 也存在，服务端不确定，无法靠解码设置消除。
2. MemPro 复现与原文有偏差：evolving agent 用 kimi-k3、judge 换成 Qwen3-max、任务模型温度 0.3 而非 0.7；发布的 root 已含演化组件，held-out 78.50% 高于论文初始框架 72.35%。held-out 增益 +3.8 近似论文 +4.7。
3. 其 E0–E2 的选择只用第一次评估，所以选中版本的 dev 分带选择偏差。repair 臂两次评估都进入接受，所以无法用第二次评估无偏复测 incumbent。
4. MemPro/GEPA 的 held-out 与 dev **共享对话历史**（LoCoMo、Mem-Gallery），所以 held-out 增益不证明对未见对话的迁移；只有 LongMemEval 拆分整体隔离。
5. 干预臂中 agent 读 154 个 dev 题和金标答案，接受也基于同一批题，dev 增益可能是题特异性的；作者明说检测不到小于约 3 pp 的 held-out 差异，证据只支持"每个机制的局部效应"和"更低的跨 run 方差"，不支持显著的 held-out 均值优势。
6. 二元对错的定义对 EvolveMem/ARC 是"类别 1–4 F1>0"（宽松）。stage 参照对失败只覆盖约三分之一，且三阶段是粗分。2σ 假设翻转在题间独立。
7. 阶段对齐分析在 LongMemEval 上做不了（每版本约 8 个可归因失败，30 个被评分的 ARC 编辑中只有 1 个 aligned）。
8. 作者看到 EvolveMem 的发布代码是 elitist 循环，与论文 Algorithm 1 不同；已在 Table 27 补充非 elitist 版本。

## 7. 是否区分了 improver/editor 质量与任务增益？

**部分区分，但不是论文的主轴，也没有一个独立的"改进器质量"指标。**
- 引用而未复现：Lin et al. 2026 "evolver capability barely changes gains"；Wang et al. 2026 "evolved harnesses do not consistently beat test-time scaling"（只在引言和相关工作提及）。
- 本文自己做了三件相关的事：（a）E.3 换诊断器/agent（GPT-4o、GPT-4o-mini vs Qwen3-max），结果是 stage 对齐率**与**增益无序（0.69 对齐率→+2.9；0.30→+11.9），但"多早提出检索升级"和"编辑是否被 guard 拦下"与增益对得上；（b）Table 26 的"阶段引导提案器"是把编辑器换成一个只看瓶颈阶段的菜单策略，随机菜单顺序的三次结果跨度 +4.4 到 +11.6，说明**提案策略的差异在这一菜单上基本等于"先到检索升级"的差异**；（c）诊断漏斗和 Table 24 给出诊断—提案—执行三层对瓶颈的对齐率（EvolveMem 提案 0.16、陈述 0.76；ARC 0.50/0.22）。
- 没有的东西：没有测"编辑器的改进能力随演化轮数变化"，没有在同一固定任务上比较不同质量编辑器产生的编辑的 repair/regression 分布，也没有把"编辑器的提案质量"与"被接受的编辑质量（受选择噪声影响）"分开归因。其 aligned/misaligned 是以测量到的瓶颈阶段为标准，是对单个编辑的描述性标签（作者明说），不是编辑器质量的度量。

## 对 data-centric RSI 的含义

> 先列事实（来自论文，标明出处），再列推测（标 **[推测]**，是我的，不是论文的）。论文研究的对象是"改记忆系统的 agent 循环"，改的是配置/prompt/代码，不是训练数据。迁移到 data-centric RSI（用模型产出的数据改模型本身）是类比，需要先问对象是否同构。

### A. rise–plateau–decline

**事实**
- 论文里观察到的是 rise–plateau，没有 decline：best-so-far 曲线按定义不降（Fig 1a）。"decline"只出现在：repair 体量逐轮下降、regression 体量不降（Table 3，18/18 与 16/18），后期调整后净增益区间含零或为负（ARC closed/r0 后期 [−1.26,−0.54] pp）。
- 论文给出的 plateau 解释有两条，彼此叠加：①**池子被耗尽**——早期大步是一个检索升级（S2 占 root 失败的 ~3/4，最终减少一半以上），之后对应的失败池变小，repair 项 (1−p)φr 随之缩小；②**噪声+共享组件**——regression 项 p·h 由共享组件产生并不随池子缩小，且评估噪声使单次翻转当作修复。E.2 弱起点实验也说明：+29.5 到 +35.6 pts 在第 2 轮前就到位，之后的 51/134 步在 2σ 内。
- "plateau 的时点"随提案策略前移：A3 第 1 轮就到 +10.5，而 A0 到第 7 轮才 +7.9（Table 26）。所以曲线形状取决于"先走哪一步"。
- 论文没有做"更长轮次后是否真的下降"的实验；所有循环都停在 ≤10–15 轮或"两轮无改进即停"。

**推测**
- **[推测]** 若把 data-centric RSI 的一轮看成"生成数据→训练→评估→按 dev 分数接受"，则同样会有 (1−p)φr 与 p·h 的结构：自生成数据能修的"池子"随轮数变小，而训练更新是共享参数，必然会改变未瞄准的能力。这是从论文公式做的结构类比，论文并未验证到训练场景。
- **[推测]** 真实的"decline"可能需要保留项不仅是噪声：如果 selection 用 best-of 而非 incumbent，则 best-so-far 不降而真实 held-out 可能降；论文的 Table 33 里选中版本二次评估比首次低 3–6 pp 正是这种"赢家诅咒"的量级。对我们而言，应当画 held-out（而非 best-so-far in-sample）曲线来区分 plateau 与 decline。

### B. selection ≠ learning（选择不等于学习）

**事实**
- 循环里的"接受"在 dev 上选 argmax 版本，但：噪声使 50–96% 的接受步在 2σ 内（Table 1a）；每个选中版本在二次评估中平均低 3–6 pp（Table 33，选择偏差）；dev 增益 4.5–11.7 pp 而 held-out 只有 1.2–3.8 pp。
- 加倍评估次数本身不改善 held-out（E0-2x +2.59±2.12 对 E0 +3.24±1.40）：只是"多测一次再选"并没有把选择变成学习。
- 一个被"记录为修复"的翻转可能只是无编辑翻转：Table 28/F.2 里刚翻对的题约一半在第三次评估又错。周转（W→C+C→W 近千）远大于净增益（+42 到 +77 题）。
- 选择指标/judge 决定"增益"是否存在：F1 选择的 run held-out judge 只 +0.29 pp；换 judge 使 +2.74 变 −0.15。
- 在 dev 集分辨率以下的步（0.65–1.3 pp）无法被选择可靠分辨（E.6）；308 题 dev 下 15 次修订只有 2 次可分辨。

**推测**
- **[推测]** 这支持把"循环产生的 checkpoint 序列"拆成两个量报告：被选择的 dev 增益（含选择偏差）与 held-out 的配对增益；二者的差就是"选择而非学习"的上限估计。论文的 +4.5–11.7 对 +1.2–3.8 给了一组数量级。
- **[推测]** 对我们的任务，应在评估协议里同时做"同 checkpoint 重评"和"检验 held-out 是否与 dev 共享来源"（论文自己也承认 LoCoMo/Mem-Gallery 的 held-out 与 dev 共享对话历史，LongMemEval 才完全隔离）。这属于 R5（不筛幸存种子）一类的纪律。

### C. gate vs reward（门控 vs 奖励）

**事实**
- 论文里的"gate"是接受规则：原循环用 dev 净分提升作门；paired acceptance 是更严格的门：只数稳定修复/稳定回归，且要求 f−b≥1、z≥1。它不是训练奖励，而是版本选择规则。
- 门有真实的局部效果：稳定回归每次修订 2.5→1.4；新答对题中假修复比例是 52–71% 的问题，被"排除 fragile、需两次评估均通过"的规则消掉；E1+repair 的跨 run SD 由 2.00 降到 0.29（held-out）和 dev 的 0.49。
- 但门的 held-out 均值收益**未显著**（95% CI 含 0；p=0.08），且 E2+repair 的 9 个 repair 孩子零接受，所以门的效果依赖具体设置。z≥1 阈值是设计选择。
- 门会改变"agent 怎么搜"，而不只是"选哪个"：ledger 使目标中稳定失败占比从 69% 升到 90–96%，这是反馈（agent 看到的信号）而非单纯的接受门。论文把两者分开测了（E1 无 repair/门 vs E1+repair），E1 单独并没有提高 held-out（+2.60）。
- 评估预算是混杂：验证需 2× 评估，repair 再加近 2× agent 开销（Table 37），E0 只与它们在轮数上匹配。E0-2x 控制了"评估次数"但没有控制 repair 的 agent 时间。

**推测**
- **[推测]** "门只限制回归而不提供学习信号"：repair round 把 regression 当作显式负信号交给 agent，这更接近一种对回归的"奖励/惩罚"而非纯门控。论文没有拆分 repair round 与 paired acceptance 各自的贡献（只有 E1+repair 合起来对比 E1），所以哪一部分在起作用未知。
- **[推测]** 若 RSI 的"门"来自模型自己的 verifier，则门的噪声（flip rate 8–13%）可能比任务增益大一个数量级；应当先测"门对未改动 checkpoint 的重复判定一致率"，再谈门是否有用。这是论文第一部分（不改动重评）可直接移植的协议。

### D. improver gain（改进器本身是否变好）

**事实**
- 论文不直接测"改进器是否随轮次变好"。它测的是：改进器提案的**对齐率**（EvolveMem 提案 0.16；ARC claim 0.22–0.50；GEPA 无诊断不可测）、其执行（guard 拦下 26/43 个 Qwen agent 诊断）、以及被执行编辑的修复率（aligned 34–41% 对 misaligned 8–20%）。
- 换更强的诊断器/agent 的效果是不一致的：GPT-4o 在 ARC 上增益翻倍，在 EvolveMem 上 +11.9 对 +7.9，但 GPT-4o-mini 对齐率最高增益最低；且论文把解释落在"多早提出检索升级"和"guard 拦截"，并指出两者可由菜单策略（Table 26 的 A3）复现，所以提案质量的差异在该动作空间里被"到达一次大改进的时间"所主导。
- 编辑器不仅有提案质量问题，还有"读错版本"的结构问题：ARC 读 root 编辑 incumbent，47/57 轮，28 轮首错于此。
- 引用的外部结论（未复现）：Lin et al. 2026 说 evolver 能力几乎不改变增益。本文数据与"更强改进器≠更大增益"方向一致，但并不等于证明。
- 没有测量：改进器在轮次间是否积累经验（每轮 agent 会话是独立的，作者在 Table 4 之外也没比较"有无历史"）；没有同一任务下改进器质量的受控梯度。

**推测**
- **[推测]** 这篇论文给我们的最有用的东西是一个**区分改进器与任务增益的最小协议**：对每个被执行编辑，记录 (i) 它的 aligned/misaligned（用独立于改进器的阶段参考），(ii) 它的 repair/regression，(iii) 同条件下的无编辑翻转。改进器的"质量"可定义为 aligned 比例×repair 率，减去 regression 与无编辑噪声；这仍然只是描述性指标，而且论文自己说 alignment 不预测回归。
- **[推测]** 对 data-centric RSI，等价问题是："第 k 轮的数据生成器是否比第 0 轮更会生成有用数据"。需要固定一个下游训练配方和评估集，用第 0 轮与第 k 轮生成器各产一批数据，比较训练后的配对增益，并用无编辑（重复训练/重复评估）的方差作噪声下限。论文没有做这种测试，但 Table 26 的"固定菜单、换提案策略"是同类设计的雏形。

### E. retention（保留）

**事实**
- 论文对 retention 的操作化是**相邻步**的保留：新修复的题在下一步更新后再错的比例（Table 28：EvolveMem 8.3%、ARC closed/r0 9.8%、MemPro 28.9%、GEPA 36.9%；对照 0.5–5.5%）；以及沿谱系的周转量（Table 32）。作者自己说只测了相邻步，不是任意长视距（Limitations）。
- 保留失败的两类来源：（a）假修复——一个修复本来就是翻转；（b）真实回归——共享组件改动使旧能力丢失（427/499 的回归落在上下文改变的题上；案例 A–D）。
- 修复与回归的不对称：修复来自一个有限池（可归因失败，仅占观测失败的 26–40%），回归来自整个"已正确集合"（p·h，h 约 4–6%）。池子越小越吃亏。
- 干预：stable-regression 计数、repair round 能降低每次修订的稳定回归（2.5→1.4）；但没有验证长视距保留，也没有沿 10 轮保留率的曲线。
- 论文的"retention"限于 memory 系统版本间；没有遗忘、容量、参数更新意义上的 retention。

**推测**
- **[推测]** 对 RSI，retention 应当是显式的评估轴：每轮报告"上一轮 checkpoint 正确、本轮错误的题的比例"（即 h），并与"同一 checkpoint 重评"的翻转下限相比。论文这套量（F、B、ε+、ε−）可以直接搬，成本只是保留逐题记录和重复评估。
- **[推测]** 论文里最容易被误读的点：低 net gain 不等于没学到东西，Table 32 显示净 +42~77 题背后是近千次互相抵消的翻转；而且 W→C 里有大量是噪声。所以"学到的"需要用稳定转移（三次评估一致）来定义，论文的 stable repair/regression 就是一个可用的定义，但它的分辨率代价很大（308 题 dev 下 232 个单次翻转中只有 11 个稳定）。

### F. 迁移时要小心的地方（事实性限制）

- 论文改的是"共享组件"（配置/prompt/代码）而不是参数；编辑的粒度是整个管线，所以 regression 的"共享"机制在参数训练里对应什么需要另测。
- 所有结论依赖对每题二元对错的重复评估，且噪声主要来自**答案生成**（temperature 0 亦不稳）。我们的评估如果是 pass@k 或 exact-match 型指标，噪声结构会不同。
- 干预实验的 held-out 证据弱：区间含 0，5 次对照，dev 与 held-out 共享对话历史。不要把"paired acceptance 有效"当作已确立的结论；能确立的是"稳定回归减少、跨 run 方差降低"。
- 论文没有复现 decline，也没有改进器质量的受控梯度，相关结论请只引用上面标"事实"的部分。
