# READ: BenchEvolver: Frontier Task Synthesis via Solution-Centric Evolution

arXiv 2606.01286（cs.SE，v1，2026-05-31）；OpenReview 标 NeurIPS 2026 poster。Berkeley + 清华姚班，作者含 Stoica、Dawn Song。

## 1. 设置

- **演化的对象**：整道可执行题 I=(S,C,T,E)：题面 S、参考解 C、隐藏测试 T、执行 harness E。E 固定不变，S、C、T 会变。
- **“solution-centric”的具体含义**：先改参考解 C→C'，再围绕 C' 写题面 S' 和测试 T'（示例和期望输出都靠运行 C' 得到）。对照是“problem-centric”：先生成新题面，再去验证是否有解。Proposer 被要求做一个“dominant algorithmic lift”，让父题的解法不再够用。例：把加法差分改成 XOR 差分，区间求交失效，要用数位 DP。
- **跨轮累积的东西**（3.4、附录 B、E）：
  - 每个 seed 一份局部记忆：本谱系的已接受变异、失败尝试、验证问题、目标模型通过率、错误模式。
  - 一份全局记忆 G：本次运行里已接受/已尝试的变异“家族”。LCB 最多给 mutator 看 50 条，SciCode 20 条，字符上限 6000。
  - 谱系 L_i：下一轮的父题是“最近一个被接受的孩子”，不是随机采样的父题。
  - 全局记忆还进入接受规则：某个变异家族已在别处成功，新候选必须有更大的难度增益才被接受。
- **生成模型**：LCB 受控实验用 GPT-5.4-mini、Gemini-3-Flash、Claude-Sonnet-4.6 作 evolver（轻量档），另用 Gemini-3.1-Pro 作 evolver 对前沿档（每个难度 10 道饱和题）。RL 实验里 gpt-oss-20b 同时是 evolver 和 target。
- **验证**：
  - LCB：参考解、仅凭题面写出的暴力解、仅凭题面的“公共输出 oracle”三方投票，不一致就修复；共享修复预算 3 次。通过后暴力解在可行处跑生成的隐藏测试。
  - SciCode：无暴力解，用“题面忠实度”检查：评估模型仅凭题面写解，best-of-N（N=3）在候选测试上通过率须 ≥0.5，否则视为题面欠定。
  - 之后再有 LLM judge 过滤歧义、不自然边界、近重复换皮。事后有效率由 Claude Code Opus 4.7 判定。
- **领域与 seed**：LCB-v6 随机 65 个 seed（Easy 22 / Medium 23 / Hard 20）；SciCode 验证集 30 个自足子题（15 个主题，27 个被轻量档饱和、28 个被前沿档饱和）；LCB-Plus 用 v6 的 medium/hard 饱和题。RL 实验的 seed 是 880 道 LCB v1–v5（2025-01 之前）。
- **每个 seed 的预算**：最多 10 次迭代，LCB/SciCode 默认每 seed 最多接受 3 题，连续 4 次不被接受即停，target 每模型 k=4 次，温度 0.8。

## 2. 怎么证明题“前沿”（更难）

- **难度的定义**：行为式。目标模型面板每题多次尝试，全部隐藏测试通过才算成功，面板平均通过率越低越难。接受条件：难度等级须高于 seed，可选再高于父题（附录 B：ℓ′ ≥ ℓ(父) 且 ℓ′ ≥ ℓ(seed)+Δ）。**难度是选择条件，不是事后发现**：被接受的题按构造就是“目标面板做不好”的题。
- **LCB-Plus 上 8 个模型的 pass@1（表 3，k=4）**：
  - Hard 子集（43 个 seed / 55 道演化题）：seed 均值 87.0% → 演化 45.7%，降 41.3 点。Medium（23 / 35）：96.5% → 69.6%，降 26.8 点。
  - 单模型：GPT-5.4 Hard 94.8 → 49.7；GPT-5.5 97.1 → 62.3；DeepSeek-V4-Pro 83.7 → 23.2；Qwen-3.7-Max 74.4 → 58.6（降幅最小，−15.8）。
  - 91 题的 LCB-Plus 上 pass@1 范围 27.5%（DeepSeek-V4-Pro）到 62.6%（GPT-5.5）。
- **evolver 自己也变差**：正文说每个 evolver 在自己的演化题上都有明显掉分（图 2，我只读到图注）。
- **人工评测**：6 位竞赛专家（Codeforces grandmaster / IOI / ICPC 级）盲评 100 条谱系、72 个 seed、207 道演化题。难度 1.83→3.21，新颖 2.21→3.10，清晰 4.45→4.83，估计 Codeforces 评分中位数 1125→2100。65% 的题有两位评审。
- **LCB-Plus 的筛选**：质量/新颖 ≥3 分（1–5）且 8 模型合并 pass@1 在 0.05–0.75 之间；留下 64 道演化题（44 Hard + 20 Medium），加 27 道原题（同样 ≤0.75），共 91 题。
- **污染检查**：全文没有。“contamination”只出现在 LiveCodeBench 的论文标题里。没有查 seed 是否进了目标模型的训练集，也没有查演化题是否与公开题重合。
- **被排除的模型**：目标池里故意不放 Claude，理由是 Claude 在两个基准上略弱，放进去会让演化去针对 Claude 的特有失败。这说明难度是相对于选定面板的。

## 3. 与“同预算直接采样”的对比；覆盖/多样性；收窄

**没有做同预算对照。** 全文没有任何一个对照是：初始生成器用同样的 LLM 调用数/token 数，直接多采样（best-of-N、拒绝采样）去得到同样难度的题。已有的对照只有两个：
- Problem-centric（题面先行）基线，GPT-5.4-mini 作 evolver：有演化题的 seed 占比 Easy 54.5% / Medium 47.8% / Hard 30.0%，有效率 79.3%。
- Memory-Free（去掉记忆、独立一步变异）：59.1% / 65.2% / 45.0%，有效率 86.2%。
- 完整方法：77.3% / 69.6% / 60.0%，有效率 97.7%。
- 文中没写这三者的算力是否对齐（迭代预算同为每 seed 最多 10 次，但每次迭代的调用数、总 token 没报）。

**多样性度量**（只有人工评测一套）：
- 算法类别数 19（seed）→ 30（演化）；95.6% 的谱系至少引入一个 seed 里没有的类别，平均 2.54 个新类别/谱系。seed 中 Search/simulation 占标签提及的 32.7%。
- 这是**演化题相对于它自己的 seed**的比较，不是“谱系随迭代轮次”的变化，也不是“演化题 vs 初始生成器直接采样”的比较。
- 没有按迭代轮次画覆盖、熵、重复率。没有跟踪全局记忆里的变异家族是否越来越集中。
- 附录 H 的轨迹图只展示了 Gemini-3-Flash 在 Easy 上若干 seed 的通过率单调下降（这是被接受的谱系，按规则必然单调）。

**收窄/坍缩**：没有任何实验。唯一涉及的是未来工作里的一句：选择过窄会过拟合反复出现的失败模式，过激会产生“难但无信息”的题；要靠控制难度、保持算法多样性来平衡。这是作者自己提出的担忧，文中没有测。

## 4. 生成器是训练的还是冻结的；累积部分有没有消融

- **evolver 权重全程冻结**。演化阶段是 API 模型或 gpt-oss-20b 的推理（附录 B 里 q_θ、w_θ、g_θ 都是同一类模型的提示调用）。只有记忆/谱系/全局表在演化。
- RL 阶段训练的是 gpt-oss-20b（GRPO，LoRA rank 32），**只做一轮**：先用冻结的 gpt-oss-20b 演化出数据，再训练。训练后的模型没有再拿去当 evolver。作者把多轮闭环列为“未来工作”。
- **消融**：只有 Memory-Free 一个（见第 3 节）。它把“局部记忆 + 全局记忆 + 谱系继承”整体拿掉，对应的是“独立一步变异”。没有把局部记忆、全局记忆、谱系继承、“已有家族需更大增益”的接受规则分别拆开。所以**累积的效果与上述其他部件不能分开读**。
- Memory-Free 与完整版的比较指标是“有演化题的 seed 占比”和有效率（产出率），**不是**能否得到完整版得不到的题或更难的题。

## 5. 是否用来训练（数据中心用法）

**是，但只有一组。**
- **数据**：880 道 LCB v1–v5 原题作 seed 集；仅对 gpt-oss-20b 五次尝试全对的 seed 做演化，每 seed 最多 10 轮、最多接受 2 题，接受题须使模型经验准确率下降但非零。得到 586 道演化题，来自 404 个 seed（880 里约 46%）。三种训练集：seed 880、evolved 586、两者并集 1,466。
- **设置**：GRPO，每 batch 64 题×16 rollout，训练最长 24K token，评测 30K；每个数据条件 2 个随机种子（42、43）；每次 RL 约 40 小时、约 $800（Tinker 额度）。
- **留出评测**（峰值 checkpoint，两种子均值；pass@1 取 16 个样本平均）：
  - LCB v6 Hard（80 题）：基座 40.0 → seed-only 45.1，evolved-only 47.6，seed+evolved 48.7。
  - LCB-Pro Easy（96 题）：64.6 → 70.8 / 71.8 / 72.9。
  - LCB-Evolved Medium（35 题，由 Gemini-3-Flash 独立演化，未参与训练）：30.45 → seed-only 33.66，evolved-only 38.22，seed+evolved 37.32。
  - 摘要里的“+70.7% / +34.8%”是 (48.7−40.0)/(45.1−40.0) 与 (72.9−64.6)/(70.8−64.6) 的相对增幅（我核算：8.7/5.1≈1.71，8.3/6.2≈1.34，与文中一致）。
- **训练动态**（图 7，附录 D.4）：seed-only 起始奖励高、很快饱和；evolved-only 起始最低但持续上升。
- **要注意**：这里“更多数据”与“更难数据”混在一起。seed+evolved（1,466 题）比 seed-only（880 题）多了 586 题，但没有“补一个同样大小的 seed 或随机重采样数据”的对照；evolved-only（586）比 seed-only（880）题少，是更干净的一格，但仍是单次实验、两个种子，报的是**训练轨迹上的峰值**（取评测集上最高点，带选择偏差），文中没有给置信区间，图 5 给了两种子的均值±标准差。
- 只有 LCB v6 Hard 和 LCB-Pro Easy 被认为“信息量足够”，其他划分因饱和或太难被舍弃。

## 6. 作者没有展示/局限

- 无同算力的直接采样/拒绝采样对照；无“初始生成器 vs 累积后”的可达性对照（没有测：不带记忆的大量采样能不能也得到同样难的题）。
- 无逐轮覆盖/多样性/重复度曲线；无收窄或坍缩检验；多样性证据只有一次人工盲评，而且是相对 seed 的。
- 记忆只有整体消融（Memory-Free），各部件未拆；Memory-Free 与完整版的算力是否匹配未说明。
- 难度由目标面板选出：受面板选择影响（作者自己排除了 Claude），“更难”是相对这一面板、这一难度尺度 φ 的。无污染检查。
- 有效率由 Claude Code Opus 4.7 事后判定，存在 LLM 判官依赖；人工评测覆盖的是 207 道演化题，而不是全部。SciCode 的忠实度检查只能发现题面欠定，不能保证科学正确性（作者自己写明）。
- SciCode 上 Claude-Sonnet-4.6 作 evolver 仅 8/27（29.6%）seed 有演化题，不同 evolver 差别很大；文中未解释。
- RL 只有一轮、一个模型（gpt-oss-20b）、一个领域（竞赛编程）、每条件 2 个种子；报峰值而非终点；没有 seed+evolved 与等量数据的控制。多轮闭环、稳定性、课程、多样性都留作未来工作。
- 作者承认 LCB seed 较小（65 个）是出于成本；SciCode 只有 30 个子题。

## 7. 与我们问题的距离（以下为我们的推断）

问题：生产者（任务/数据生成器 + 它累积的档案/缓冲）能否到达初始生成器在同算力下到不了的任务（reach expansion），还是只是更便宜地找到（amortization），以及累积是否收窄探索（lock-in）。

- **有重叠的部分**：它有一个真正会累积的产物（局部谱系记忆 + 全局变异家族表 + 以最近接受题为父题），而且接受规则里写进了“已有家族要更大增益”，这是一个显式的反 lock-in 机制。生成器权重冻结，所以“累积”和“权重更新”不会混在一起，这对我们的拆分是干净的。难度按目标面板失败率选，所以“初始生成器做不到”可以用面板通过率来定义。
- **没有覆盖的部分**：它完全没有回答我们的核心问题。缺同算力直接采样/拒绝采样对照，所以看不出“演化后的题是初始 proposer 多采样也能得到”还是“多采样得不到”。Memory-Free 对比的是产出率和有效率，更像是**摊销**证据（同样预算下更多 seed 有产出），不是**可达性**证据。多样性证据只是演化题相对 seed 的比较，不是相对初始生成器直接采样的比较，也不是随轮次的变化，所以对 lock-in 一点证据也没有，作者自己把它写成未来风险。RL 实验没有“更多数据 vs 更难数据”的控制，也没有把累积部分单独拿掉。
- 一句话：这是一个“有累积的生产者”的好例子，且给出了可借鉴的接受规则与指标（面板失败率、算法类别数），但它的证据停在“产出更难、更有效的题”，没有碰“同算力下是否多到达了什么”。如果我们要用它，最合适的位置是被审计对象，而不是现成的答案。
