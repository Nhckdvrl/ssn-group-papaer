# READ: Evolving Together, Failing Apart: The Skill–Policy Co-evolution Trap in Self-Improving Agents

arXiv 2610.20845v1（cs.AI，2026-10-14），Alibaba Token Hub 等；文中有 ICLR 伦理声明，应为 ICLR 投稿稿。

**阅读范围**：arXiv HTML 全文（https://arxiv.org/html/2610.20845）：摘要、引言、§2 理论、§3 经验、§4 CODA、§5 相关工作、§6 结论、局限（附录 A）、附录 B–H（含证明 D.1–D.5、协议 E、扰动示例 F、配置 G、全部结果 H.1–H.7）。附录里的逐 anchor 大表（表 8–13）只读了表头、SkillRL-ALFWorld 前几行和正文对表的说明，没有逐格核对。下面数字均取自文中；我自己的推断只放在第 8 节。

## 1. 设置

- **agent**：LLM 策略 π_θ(·|x,S)，skill 库 S 以**文本**形式进入上下文。任务是 ALFWorld、WebShop、ScienceWorld、Mind2Web、AMC23 数学题。
- **skill 是什么**：自然语言条目，有字段（如 principle、when_to_apply、action）。例子见附录 F：“看见需要的物体就先拿起来，不要留下目标”“结账前……”。不是可调用代码，也不是模板程序。ARISE 在数学上的 skill 是推理策略文字。部分字段属于“检索侧”（决定取哪些 skill），部分是“内容”。
- **谁写、谁更新**：由各方法自己的流程从轨迹里蒸馏、改写、增删，再经各自的接收门（success-gated、Thompson sampling、边际效用>0、奖励阈值等）决定是否保留。SkillRL 从人写的种子 skill 开始累积（ALFWorld 55→91，WebShop 66→84）；ReSkill 从空库开始、库容上限 8（ScienceWorld 终 7，ALFWorld 终 8）。
- **策略训练**：**权重更新**（RL）。策略步和库步交替或联合进行。部署时策略冻结，库被外部改写。
- **被审计的四个方法**：SkillRL（Qwen2.5-7B-Instruct）、ReSkill（Qwen3-4B-Instruct-2507）、Evolving-RL（Qwen2.5-7B-Instruct）、ARISE（Qwen3-4B-Instruct-2507）。六个“方法×环境”设置：SkillRL×ALFWorld/WebShop，ReSkill×ScienceWorld/ALFWorld，Evolving-RL×Mind2Web，ARISE×AMC23。
- **种子**：**每个设置只有一次 co-evolution 训练**。重复是评测重复（SkillRL、ReSkill 3 次，ReSkill-ScienceWorld 5 次，其余记在释放的配置里），只共享同一个 checkpoint，只改 rollout 采样种子。文中明说误差带只反映评测噪声，不反映训练种子间的差异。
- 评测集：ALFWorld 140 任务，WebShop 500，ScienceWorld 155 个验证点。

## 2. “陷阱”是什么

- **失败模式**：策略和库被训练成互相特化的一对。在“交付库”上成绩高，一旦库被改写（措辞改变、步骤缺失、策略写错），成绩明显下降。作者称之为 co-evolution trap。
- **机制论证**：假设 1（理想化合作式接收）：保留的库在候选集里使当前策略回报最大。假设 2：候选集覆盖交付库的内容级邻域。命题 1：此时交付库是峰值，任何被覆盖的内容级改写都不会提升回报。命题 2：只在单个库上优化，等于不为“对邻域平均退化”付代价。附录 D.5：把接收规则反号（对抗式）则 Φ=0，所以决定性的是接收规则，不是 co-evolution 本身。作者承认两个假设是理想化的，理论只对“被覆盖的改写族”成立。
- **度量**：五个扰动轴。T1 同义改写，T2 删步骤/插无关内容，T3 换成错误策略，T4 增删混版本，T5 整库去掉。T1–T3 计分，T4/T5 只作诊断。指标：峰值 SR、最坏轴 SR_min、一致率 CR（T1 前后任务结果不变的比例，噪声基线 CR0）、抵抗率 RR（T2/T3 下仍解对且无 skill 也解对的比例）、门槛 Δnet=SR(S*)−SR(∅)>0。
- **何时出现**：fragility 曲线沿同一条训练轨迹取 checkpoint，固定最终库及其扰动版本，只换策略 checkpoint。六个设置里，未扰动成功率都上升（SkillRL-ALFWorld 5.2→88.8%，Evolving-RL-Mind2Web 16.4→25.2%，ARISE-AMC23 15.5→87.4%）；18 个“轴×设置”里 12 个的 Drop 斜率显著为正（T1/T2/T3 各 4 个），六个设置里五个至少有一个显著，SkillRL-WebShop 是唯一例外。
- **早期反向**：SkillRL-ALFWorld 在 s0、s5 时 RP_T3=2.33、3.38（误导库反而更好），到 s90 降到 0.86。早期去掉整库反而更好，后期变成依赖。
- **依赖中介**（H.4）：只用 SkillRL 的两个设置，32 个 checkpoint，依赖（去库掉分）与脆弱度（五档腐蚀平均掉分）Spearman ρ=+0.82（95% CI [0.68, 0.89]）。
- **终点数字**（表 2）：最坏成绩比峰值低 4.9–12.6 点（摘要说 5–13），吃掉库带来增益的 52–93%。例：ReSkill-ALFWorld 峰值 76.9，T1 为 64.3；ReSkill-ScienceWorld 峰值 50.3，T1 改写掉 10.9。CR 77.5–87.0，噪声基线 CR0 91.9–94.4，即 13–23% 的任务在同义改写下翻转，纯采样噪声下是 6–8%。SR_min 在六个设置里都高于无 skill 成绩，所以是“丢失库带来的收益”，不是“库有害”。
- **额外代价**（H.7）：SkillRL-ALFWorld 上，共演化策略去掉库得 57.6%，带库 84.1%；从未用 skill 的纯 RL 策略最后五个 checkpoint 平均 70.6%，峰值 87.5%。作者标明这是辅助观察：两次评测样本数和 ALFWorld 后端不同，纯 RL 自己也不稳（125 步 87.5%，150 步 53.1%）。

## 3. 是否显示“库把探索变窄 / 把策略锁进已有结构”

- **没有直接显示。** 全文没有任务多样性、行为覆盖、探索熵（H.7 只在纯 RL 对照里提到熵和 KL 上升）或库内容多样性随时间的度量。
- 最接近的证据是**依赖和脆弱**：策略被训练成对库的措辞敏感（κ=0.78 于 SkillRL-ALFWorld、2.14 于 ReSkill-ScienceWorld，后者表示同义改写比错误策略伤害更大；另两个设置 T3 没有把成绩压到峰值以下，κ 无定义），以及去库后的“独立能力”下降（H.7）。这是**策略对库的锁定**，不是**数据/任务分布的收窄**。
- 库的规模只在表 14 给出初始/终态条数；没有库随训练的内容演化，也没有去重或覆盖统计。
- 他们的机制论证是“接收规则偏向当前策略效用”，这在含义上接近“累积产物只服务现有策略”，但没有用探索或数据覆盖来检验。

## 4. 对照与基线

- **无库**：SR(∅) 作为锚点和门槛，每个设置都报告（表 2）。
- **库扰动**：T1–T5 五种，配对同一批任务、同一策略、同一批选中的 skill（检索只在原库跑一次，只替换内容）。
- **早期 checkpoint × 固定最终库**：fragility 曲线就是这个设计（策略变、库固定）。这是半个 swap：只换策略，不换库。
- **没有**：冻结库 vs 持续演化库的并行训练臂、重置库、静态库训练、算力匹配的无库训练基线。没有“早期库 + 晚期策略”的交换。
- **唯一的无库训练对照**：H.7 里 SkillRL-ALFWorld 的纯 RL（arm A），单次，且与评测的样本数和后端不完全一致。
- 评测使用作者自己在统一协议下的重评估，不用原论文数字。

## 5. 与初始系统在匹配算力 / 匹配样本下的比较

- **没有。** 文中不比较“共演化 vs 初始系统（无库或种子库）在同等算力、同等训练样本下的最终成绩”。表 2 的比较是同一交付策略在不同库（交付库、扰动库、空库）下的成绩。

## 6. 提出的修复及证据

- **没有提出方法。** 局限 L2 明说“diagnose but do not fix”。自然方向是公式 (6) 的分布式目标：对一批库扰动做训练，而不是只对单个库做训练；怎样选分布 P 又不损失峰值回报，文中说是开放问题。
- 他们提供的是**审计协议 CODA**：门槛 + 三个指标 + 绝对的“同方法内”通过/失败判定。判定规则：Δnet>0、CR 不低于 CR0−2σ0、每个有害轴满足 SR(S_a)≥SR(∅)（McNemar）。四个方法在六个设置上，门槛和有害轴检验都通过，**一致率检验在所有设置里都不通过**，所以整体判定不通过。
- CODA 的证据：T1 改写质量审计（H.6）——190 条 T1 改写全审，两个评审（qwen3-max、gpt-4o）都判 100% 保持含义（95% Wilson CI [0.0%, 1.9%] 为“改变含义”的比例），Cohen’s κ=1.0；20 条恒等对全判等价，40 条负对照全判不等价；人工复核了 95 条，无语义变化。改写模型是 gpt-4o-2024-08-06，温度 0.7。

## 7. 作者没有展示 / 局限

- 作者自列三条：改写不是比特可复现（若库由同家族模型写，则测得的脆弱度可能偏低）；诊断不修复；规模没有研究（更多数据是降低敏感度，还是只抬高峰值再掉下来，未知）。
- **每个设置单次训练**，没有训练种子方差；Evolving-RL、ARISE 的重复次数只记在释放的配置里。
- 四个方法用两个不同的底座，绝对数不可跨方法比。
- 只测**内容级改写**对固定策略的影响；这个“库被他人改写”的部署场景是作者设定的，不是库自己演化产生的分布。T4（组成变化）只作诊断，没计分。
- 理论依赖两个理想化假设（精确 argmax 接收、候选覆盖），文中只检验其预测（18/18 无改写显著提升），没有检验前提本身。
- 分析只用“最高未扰动成功率之前的上升段”checkpoint，之后的不用，作者解释为后期不是“更多共演化剂量”。这会截掉崩溃或平台段。
- T3 在四个设置里只用一种强度报告（ALFWorld 用弱，WebShop/ScienceWorld 用强），两种强度都跑了，另一种放在附录。
- 没有探索/多样性、没有算力或样本匹配、没有冻结库 / 静态库 / 重置库对照、没有早晚库互换。
- 我没有逐格核对表 8–13。

## 8. 与我们问题的距离（我们的推断，非论文结论）

**重合**：它研究的是“生产者一侧累积的产物（skill 库）与策略互相适配”这一结构，并给出一个显式机制：接收规则只偏向对当前策略有用的更新，于是库和策略被拉成一对，策略对库形成依赖，去掉库时独立能力反而比从未用库的纯 RL 更差（H.7，单设置、单次）。这与我们的“锁定”假设在**策略一侧**同向：累积产物绑定了下游。H.4 的“依赖随训练增长”也提供了一个可复用的度量。

**不重合**：它不碰“可达性扩展 vs 摊销”：没有与初始生产者在匹配算力下的比较，没有看生产者能否产出初始生产者到不了的训练数据，没有任务/行为覆盖或多样性的度量，也没有“库收窄探索”的直接证据。它的“锁定”是策略对措辞的脆弱，不是数据分布的收窄。它的实验是“交付后改库”，不是“用早期库 vs 晚期库产数据再训练”。库的作用只被测成“带库比无库高多少”，没有区分“库让原本能解的任务变便宜”还是“库让原本解不了的任务可解”。所以它对 reach/amortization/lock-in 三分里的任何一支都没有直接裁决，只能作为“累积产物与策略互相特化”的旁证，并提示：要证明锁定，还需要覆盖/多样性度量和早晚库互换对照。
