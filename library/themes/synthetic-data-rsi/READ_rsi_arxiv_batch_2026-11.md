## 1. 2610.08902 Agent Plasticity: Measuring Self-Improvement Through Experience（Meta／Berkeley，2026-10）

**读了哪些节**：摘要、§1–§5 全文；附录 A（相关工作）、B（实验设置，Table 2）、C（NetHack 曲线与 Table 3）、D（NetHack 例子）、F（学习成本曲线）、G（失败／复用分析器，Table 4）、H（各游戏诊断图的说明文字）。附录 E（国际象棋例子）和 I（提示词）只翻了开头，未逐字读；图中的曲线数值只能读到正文给出的。

**问题**：权重冻结时，agent 靠自己写的持久 artifact（工具、skill、策略、记忆）改进，怎么衡量“学得多有效率”。提出 plasticity P = 保留集得分增益 ÷ 学习成本（美元）。

**设置**：每个 checkpoint，actor 在全新上下文里玩，反思阶段用训练局轨迹改 artifact；改动要过结构与可执行检查。同一个模型既当 actor 又当反思者（“Actor and reflection calls use the same model within a run”）。环境：国际象棋（Hard／Easy，对 Stockfish 16，20k 节点）、5×5 围棋（GNU Go）、6×6 Hex、NetHack（Codex／Claude Code 原生 harness，checkpoint 0–40，每次 10 局新种子，共 2,460 局）。象棋每 checkpoint：16 训练局、12 保留 ID 局、12 保留 OOD 局；共 20 个 checkpoint。模型：Claude Fable 5／Opus 5／Opus 4.8／Opus 4.6／Sonnet 5／Opus 5.5、GPT-5.5／5.6 Sol／5.6 Luna、Gemini 3.1 Pro。成本只算 token 折美元，包含被拒的反思。每个模型每个环境似乎只有一条 lineage（NetHack 明说“one lineage”，其余未说有重复）；区间只有曲线拟合的参数 bootstrap。

**主要结果**：
- Hard 象棋保留 ID 分：Fable 5 从 37.5% 升到 73.3%（checkpoint 16–20 平均），Opus 5 从 25.0% 到 66.4%，Sol 从约 0% 到 36.9%；Opus 4.8 只在 Easy 里从 0% 到 19.0%；其余基本不动，少数下降。围棋 Fable 5 保留 ID 20%→80%、OOD 0%→50%；Hex 上 Sol 保留 ID 40%→77.5%。Opus 5 在围棋里先大涨，最后一个 checkpoint 因工具编写错误骤降。
- P_sat（拟合曲线到 90% 增幅的成本点之前，每 1000 美元的增益，三游戏合并）：Sol 298、Opus 5 233、Fable 5 57、Opus 4.8 14；Luna 增幅不足 10 个百分点，记为 0；GPT-5.5 还在缓升，算不出饱和点。Fable 5 的终点最高但 P_sat 远低于 Sol——终点能力与获取效率分开。
- NetHack：只有 Opus 5.5 有可靠上升（平均分约 2k→约 6k，P_sat = 61.75，p = 8.2e-7，checkpoint 11 到饱和，累计成本 1,072.73 美元）；其余五个模型无可靠上升，Sol 和 Luna 反而下降。注意附录 C 的告诫：Opus 5.5 在 checkpoint 0 就比别人高 2.6–25 倍，checkpoint 10 的均值 9,015 里 69% 来自三局，其他 lineage 用的是更早版本的 harness；checkpoint 10–40 均值在 3,518 到 16,689 间大幅波动。
- 失败分解（Gemini 3.1 Pro 离线判）：相关决策中不使用 artifact 的比例，Luna 约 98%、Gemini 3.1 Pro 87%、Opus 4.6 51%、GPT-5.5 28%，而 Fable 5／Opus 5／Opus 4.8／Sol 为 2–6%。19 个 模型×游戏格上，复用率与增益相关。但复用率高的四个模型，得分差距仍大；强改进者 83–99% 的剩余失败发生在 artifact 被使用时。GPT-5.5 在 Hard 象棋 checkpoint 2–8 复用 96–100%，第 9 个起降到 32–50%，而 artifact 没变。围棋 Opus 4.8 的成功复用份额从 59–65% 升到 93%，保留 ID 分却从 40% 降到 10–25%。

**没有展示的／局限**（作者自述加我判断）：作者明说不隔离“环境反馈的价值”与“额外的反思算力”（缺“预算匹配、无反馈的反思”对照）；artifact 使用与失败的归因是观察性的，不是因果；plasticity 依赖得分空间、学习时程、拟合假设和供应商定价，作者不让它当通用排名；各 lineage 单独训练，不检验 artifact 或改进策略能否跨任务迁移。（我判断）单 lineage、每个 checkpoint 12 局的保留集，二项标准误在 50% 附近约 14 个百分点（我算），checkpoint 级别的差异不能细读；失败分类依赖单一 LLM 判官，没有人工校准率。

**与关注点的关系**：
- (1) 相关但不是 improver gain。P 度量“同一个模型+固定反思协议”把经验换成保留集增益的效率，learner（actor）与 improver（反思者）是同一个模型、同时变化，没有“早期 vs 后期 improver 在同一起点”的对比，也没有 improver 自身的迭代。作者定位成“获取效率”，并把“post-training 去优化 plasticity”当作未来工作。它提供的是成本归一化的保留集增益曲线和“复用→成功”的诊断，可以当 improver 对比的读数模板。
- (2) 有零星的先升后降（Go 终点掉分、GPT-5.5 弃用 artifact、NetHack 平台期大幅波动），没有给原因；Fig. 7 显示复用率先升（checkpoint 3 达 93–99%）、分数峰值在 checkpoint 5 和 12。
- (3) 没有 pass@k 或 coverage 对照。
- (4) 验证：artifact 只过结构与可执行检查，作者建议“行为有效性”验证，但没做。
- (5) 保留：只有 ID／OOD 分开；OOD 增益一般更小或不稳。
- (6) 有保留 ID／OOD，但没有多 seed、没有 budget-matched baseline。

## 2. 2605.30290 Self-Trained Verification for Training- and Test-Time Self-Improvement（CMU，NeurIPS 2026）

**读了哪些节**：摘要、§1–§7 全文；附录 A（质性示例）。附录里没有训练超参、算力、seed 数；正文也没有写，只写了 p 值。

**问题**：验证-精炼（V-R）循环和自训练都卡在验证器上。能否训练验证器去抓“看似合理的错误解”。

**方法**：STV：同一个模型分“带参考解的教师验证器”和“不带参考解的学生验证器”，用 on-policy 蒸馏（α=0.5 的 JS 散度）让学生匹配教师的（判定+反馈）分布，再加一个判定正确性的 RL 项（λ 加权）。ViL：生成器在 V-R 循环里用冻结的 STV 验证器做 RL，奖励是最终答案正确性。

**设置**：Qwen3-8B 为主（也有 4B、1.7B 验证器；对照 Qwen3-32B、235B-A22B）；数学用 DAPO 题目，按 Qwen3-8B 32 次 rollout 的 pass@1 分 Hard（0<pass@1<0.2）和 Hardest（pass@1=0），训练在两档合并上，测试题与训练题 embedding 余弦>0.8 的被剔除，每档约 150 题；每题 32 个独立 V-R 循环、最多 20 轮；科学推理用 SciKnowEval。还有一个“RLVR 收敛”的生成器（Hard／Hardest 的 pass@1 为 37.2%／10.8%）。

**主要结果**：
- 基座生成器：STV 验证器最终轮 pass@1 为 Hardest 5.5%、Hard 27.4%；未训练验证器的流水线很快停滞；仅判定的 RL、SFT、用 GPT-5.2 代替元验证器的 RL 都几乎无效（p<0.01 是对未训练验证器流水线）。无验证的 4 倍大 Qwen3-32B：2.7%／17.8%，被 STV 8B 超过。
- 科学推理：Hardest 1.5%→21.0%，Hard 11.5%→42.4%；未训练的自验证 2.1%／11.4%；Qwen3-32B 8.9%／25.1%，Qwen3-235B-A22B 8.0%／23.6%。
- 弱到强：4B STV 验证 8B 生成器 26.4%，对 8B STV 的 27.4%；1.7B STV 21.7% ≈ 未训练 8B 验证器的 20.6%。
- 校准：未训练时验证器分数随轮数升而准确率停滞；STV 在同一覆盖率下精度高约 3–5 倍。给定真值判定、只换反馈：STV 反馈比未训练反馈在 Hard 终轮多 +3.2 个百分点（未训练反馈比无信息反馈 +5.2）。
- ViL：从 RLVR 收敛的生成器出发，第 0 轮 pass@1（无验证器）Hardest 10.7%→14.7%（+37%）、Hard 36.7%→47.7%（+30%）；同样额外步数继续标准 RLVR 无增益（“RLVR-only (longer)”）；终轮 Hardest 27.3% 对 16.1%。把“用参考解”换成“自验证、全程不见参考解”：第 0 轮 29.8 对 31.2、第 20 轮 39.4 对 43.3（STV）。前缀条件训练（用前一半参考解）第 0 轮 29.1、第 20 轮 38.5，低于 STV。
- 与 BoN 在同算力对比：精炼在基座与 STV 生成器上优于重采样；RLVR 收敛的生成器是例外（它只为第 0 轮准确率训练）。pass@k：在最强配置下前 10 轮 pass@k 一般上升，高 k 在某个非零轮数达峰后回落，越难的题峰越晚（Fig. 10，只有图，没有数值表）。

**局限**：作者列出：只有 Qwen3-8B 为主、没有更大模型、没有代码与开放式推理；验证器与生成器用同一批训练题；训练算力、验证 vs 生成 vs 测试时间的最优分配未研究；ViL 只做了一轮。（我判断）细节缺失：无 seed 数、无训练步数与算力、很多对比只给 p 值不给置信区间；测试集每档约 150 题；Hardest 档由“32 次 rollout 全错”定义，存在对估计噪声的回归均值风险——但同一定义下的对照臂（无验证器、32B）也在同一档上，对比仍成立。

**与关注点的关系**：
- (1) 不涉及 improver gain，但“训练验证器”是一个被单独改进的组件，且用了“固定生成器，只换验证器”（Fig. 4）和“固定判定，只换反馈”（Fig. 9）的隔离设计，可借鉴。
- (2) 没有塌：ViL 是一轮、延长标准 RLVR 无增益（平台而非崩塌）；V-R 轮数有“最佳点”（高 k 的 pass@k 先升后降）。
- (3) 最相关：Hardest 定义为 base 32 次 rollout 的 pass@1=0，STV 在该档达 5.5%、ViL 第 0 轮达 14.7%，超出 base 的 32 样本 coverage（受 32 次估计的有限性限制，我判断）；并且精炼赢 BoN、赢 4 倍与 30 倍大的无验证模型。pass@k 仅有图。
- (4) 核心主张：验证器是瓶颈，参考解可作为教师的特权信息；但训练仍依赖参考解（数学是有标准答案的域）。
- (5)(6) 不涉及。

## 3. 2609.24972 RRSI: Regularized Recursive Self-Improvement of Agent Harnesses（Google Cloud AI Research，2026-10）

**读了哪些节**：摘要、§1–§6 全文，局限；附录 A（局限）、B（八个评测基准的定义与打分）、C（基线方法的简述，未逐字）、D（算法细节，只读了开头与记账规则）、E（超参、E.2 可靠性、Table 6／7）、F（案例，Table 8／9）。原 PDF 含 NUL 字节，文本转换后已处理，未丢失内容。

**问题**：harness（提示词、控制流、工具、记忆、上下文管理）的迭代自动演化在有限的 evolve 集上会过拟合；怎么在不限制可编辑空间的前提下让改动可迁移。

**方法**：对“提案”与“选择”做正则化：退火的单轮编辑预算 b_t（1 到 3–4）、基于演化历史的信用分配与对未探索组件的结构化探索；选择侧有泄漏筛查（critic 读 diff）、噪声调整的接受下限 S ≥ S* − δ、按成本的接受（ΔC ≤ β0+β1ΔS）、对长期无正贡献的组件做剪枝。δ 由未改动的 base harness 重复评测得到。

**设置**：冻结策略 Claude Opus 4.8（另一路 Gemini 3.5 Flash），提案者、分析者、critic 也是 Opus 4.8。三个域八个基准：编码（Terminal-Bench 2.1，89 任务；SWE-bench Verified 仅 OOD）、agentic 工作空间（Harvey LAB：120 任务 evolve＋40 任务 ID 保留；JobBench、GDPval、APEX-Agents 仅 OOD，APEX 全部 480 任务）、工程设计（EngDesign 61 任务；Frontier-Eng 仅 OOD，47 任务里 38 个有分）。对比四个现有 harness 演化方法（Meta-Harness、AHE、TTHE、HarnessX），同一 H0、同一冻结策略、同一 evolve 集、同一候选预算。

**主要结果**：
- 增益（Δ 对 H0）：Terminal-Bench（evolve）+6.0，SWE-bench（OOD）+1.8，Harvey ID 保留 +2.3，JobBench／GDPval／APEX +4.7／+3.5／+3.7，EngDesign（evolve）+4.9，Frontier-Eng（OOD）+4.3（Medal 分，相对 +24.3%）。任务级配对 bootstrap（10,000 次）95% 区间：Terminal-Bench [+4.3,+9.3]，SWE-bench [+1.1,+4.0]，JobBench [+2.9,+7.4]，GDPval [+1.8,+6.9]，APEX [+1.4,+7.5]，Frontier-Eng [+1.1,+12.1]。
- 对比先前方法（Table 1，agentic 域）：evolve 集上各方法都升（H0 89.4；Meta-Harness 93.0，RRSI 90.5——RRSI 是 evolve 集增益最小的）；OOD 平均 H0 39.7，Meta-Harness +0.9，HarnessX 约持平，AHE 与 TTHE 低于 H0（TTHE −1.7），RRSI 43.6。
- 消融（Table 2）：无正则化的演化 evolve 92.8（最高）、OOD 平均 40.3（比 H0 高 0.6）、每试验 3.80M token；去掉提案侧正则 OOD 41.9；去掉选择侧 OOD 41.0（token +50%）；RRSI 90.5／43.6／2.42M。H0 为 1.56M。
- 迁移：换成 Gemini 3.5 Flash 为搜索策略，Terminal-Bench 64.6→78.7，SWE-bench +2.2；该 harness 不改地给 Gemini 3.1 Flash Lite（没参与搜索）用，11.2→14.6。
- 搜索重复（附录 E.2 Table 7）：每个演化跑做了两次独立重复（只重抽提案者的随机性），任何 split 都未倒退，OOD 平均 43.6 对 43.7，两次差异最大 1.8 点（Terminal-Bench evolve 80.2 对 82.0），其余八个 split 差异 ≤0.6。
- 案例（Table 9）：Meta-Harness 的最终 harness 是约 730 词的“按评分细则组织”的强制工作方法，TTHE 约 8,500 词的协议块；它们被判为“拟合了 evolve 集的打分方式”。RRSI 在 32 个评估候选里接受 4 个。

**局限**：作者自述：只做冻结权重的 harness 层 RSI；依赖有限 evolve 集与若干正则化超参；需要更广的验证。（我判断）搜索重复只有 2 次；Table 1 的先前方法各自只有一次跑；agentic 域的评分主要靠 LLM 判官（Gemini-3.5-Flash 等），对 JobBench、GDPval 的评分与演化时的判官可能同族（作者用确定性打分的工程域补强）；Harvey LAB 里 evolve 增益只有 1.1，OOD 的 4–5 点增益的幅度与判官噪声同量级但有配对区间。无“预算相等的非递归基线”（如同样候选数的 best-of-N／固定 improver）。

**与关注点的关系**：
- (1) 相关：它是“同一起点 H0、同一预算下比较不同改进过程（演化方法）在 OOD 上给出的增益”，本质是 improver 对比，但比较的是不同方法而不是同一个 improver 的早期版本 vs 后期版本；改进过程本身没有被迭代改进。可当作“improver 质量=同起点同预算的 OOD 增益”这一读数的实例。
- (2) 关键证据：未正则化演化 evolve 分最高而 OOD 几乎不动，说明 evolve 集上的“升”大部分是过拟合；没有“先升后塌”的轮次曲线。
- (3) 不涉及 base 上限；但有“harness 演化比 token 成本”这一成本控制（H0 最便宜，演化部分靠测试时算力换增益，作者自承）。
- (4) 泄漏筛查 critic 与噪声下限是选择侧验证；判官打分的域有共享偏差风险。
- (6) 是有审计意识的一篇：配对 bootstrap、两次搜索重复、OOD 与确定性打分的域；被审计论文（#4）把它的 Table 2 当作“evolve 增益转移不过去”的案例。

## 4. 2610.27610 Auditing the Product, Not the Recursion: The Evaluation Evidence Behind RSI Claims（Stevens／UMass Boston，2026-10）

**读了哪些节**：摘要、§1–§9 全文；附录 A（证明）和 B（codebook）、C（检索日志）只看了小节标题与关键定义，D 的 Table 14（按域）与 Table 15（报告“开发增益未被审计确认”的研究清单）通读，Table 16–20（编码一致性、锚点工作）只读了标题与正文引用的数字。

**问题**：RSI 论文报告的证据，对它们所声称的“过程”（improver 变好、增益累积、可重复）到底支撑多少。

**方法**：arXiv 检索框架（12 个 title／abstract 查询，截至 2026-10-17，173 条，114 篇合格，90 篇自称自己的系统是 RSI），逐篇全文编码 30 项；独立人工对 30 篇随机样本盲编码，第三位读者裁决 177 处分歧；对声称“更好 improver”的论文另做盲编码；另用 Wu 等综述 Fig. 8a 选的 20 个“锚点工作”作为对照。首轮编码有 LLM 助手，裁决后一致率 81%（900 格），作者称 LLM 首轮错得明显多于人工。

**主要结果**（90 篇强标签研究）：
- 产品评估：宽口径“有超出开发任务的评估”90%，严格“评估任务从未用于选择”60%（Wilson 区间 50–70）；在人工裁决样本里这一项是 41–45%。

## 5. 2610.21646 The Self-Improvement Problem（DFKI／RPTU，2026-10）

**读了哪些节**：摘要、§1–§10 全文；附录 A（多 agent 扩展，A.1–A.5）、附录 B（交互评估）。无实验，纯理论（附 Lean 4 形式化，仓库链接在文中）。

**问题**：自动门（奖励模型、测试集、自动评审）能否既不放过真改进（完备）又不接受非改进（可靠）。

**结果**：
- 定理 1：对语义得分 J（停机且输出 1 的指示函数），不存在可靠且完备的全可计算认证器 V，构造用 Kleene 递归定理（“被拒绝则好、被接受则坏”的候选）。更一般：只要 J 外延且存在可比的 ψ_lo<ψ_hi，结论成立（Rice 定理的关系版）。
- 定理 2：给定提案枚举器代码的“尊重提案”搜索器同样不可能。命题 1：有界错误的随机门也不可能（König 引理＋去随机化）；隐藏门只防特定攻击者，不修复保证；有状态门对每个状态都有失败候选；人工门不是全可计算过程，不受约束。
- 定理 3：有界评估（T 步）＋有限提案预算 B，穷举得到对有界得分 J_T 可靠且“预算内弱完备”的搜索器。
- 命题 2：在有界体制内也可能每轮接受都使有界得分上升而真得分下降（构造：n=2^k 个输入，每步以“慢但正确”换“快但覆盖更少”，有界分 0→k，真分 2k→k），不需要自指或对手；“漂移对更大预算可见”，建议定期用更大预算复核。
- 作者明说：证明技术经典，贡献是形式化；最坏情况结果，不表示任何具体系统出错。

**局限**：最坏情况、全可计算门；对交互评估的正向结果需要有限动作观测、有理概率与奖励、每步计算上限（附录 B）；没有量化实际系统离边界多远；没有经验数据。

**与关注点的关系**：(1) 不涉及 improver gain，但命题 2 的“有界代理分上升、真分下降”给出 (4) 与 (2) 的一个构造性反例（无需自指）；(4) 理论支撑：门必须设界或引入外部接地；(3)(5)(6) 不涉及。与 #4 的 P1／P2 互补：#4 是统计层，这篇是可计算性层。

- 后续轮多数无变化（平局占 80–95% 的轮次间转移）；每任务“至今最佳”的平均每轮增益：Haiku 0.097→0.036→0.033，Sonnet 0.156→0.068→0.029；两个混杂：能继续改进的任务集在缩小且更难；一旦通过就停止调用模型（后续轮次没有真正运行）。

- Part C：70% 的多提交会话改动量逐提交下降，晚/早中位比 0.49；人类基线同形（衰减因子 0.86 对 AI 的约 0.77）；Opus 与 Sonnet 的“幸存比例”无差异（≈0.55 对 0.55，p=0.93）。

**局限**（作者自述）：减速不是 AI 特有的；每轮度量是条件性的（通过后停跑）；“轮次是否重启而非修改”未检查；Part C 的模型档位是观察性选择。（我判断）一个厂商两个档位、一个基准、一个 harness、T=4；核心主张（脚手架扩张能抬高天花板）本文自己不检验；M1 与 M2 均为假设。

**与关注点的关系**：(3) 理论上相关：用 pass@k coverage 作为“可达集”的实用替身，并设计了固定模型、逐级增加脚手架、对比 coverage 平台的决定性实验——但未运行；描述性实验中的同族 worker 共同失败（23/55）是 coverage 的反面证据。(1) 间接：把“改脚手架”与“改权重”与“更多搜索”区分，为 improver 分类提供了框架，但没有测 improver gain。(2) 不涉及先升后塌，只有“增益递减至零”。(4) “用评测器判断”靠真实测试；(5) 无；(6) 作者自己详细披露了评分器 bug、功效不足、混杂，是一份诚实的小样本描述。

## 9. 2610.38266 Recursive Self-Improvement in Physical AI: Mechanisms, Evidence, and Evaluation（中科院自动化所等，综述，2026-10）

**读了哪些节**：摘要、§I–§VIII 全文（含 Table 1–10、Fig. 1–12 的说明文字与数值表）；参考文献只翻了首尾。没有附录。

**问题**：综述物理 AI（机器人）里“经验→持久能力”与“经验→改变改进过程”两条线，并给出证据分级与受控对比协议。

**框架**：区分 learner 状态 x 与 improver φ：x_{t+1}=U_{φ_t}(x_t, D_t)，φ_{t+1}=R(φ_t, x_t, D_t)。三种经验性主张：能力增益、机制上的递归、improver 增益。L0–L3 证据阶梯：L0 任务内适应（重置即丢）、L1 持久能力增益、L2 继承的过程修订、L3 经验证的 improver 增益（须在共享 learner 起点、匹配资源、独立测试下，后者的后续增益更大）。提出“共同数据”（两个 improver 看同样的经验，隔离用法）与“交互式”（各自采集，隔离获取＋更新）两种对比；目标量 G(φ; x0, B, T)=J_T(U_φ^B(x0)) − J_T(x0)，ΔG=E[G(φ′)−G(φ)]；要求同时报告绝对增益和相对增益（“两个 learner 都退化时差值也可为正”）；预算是向量 (转移数、机器人时间、训练算力、验证算力、人工时间、能耗、重置次数)；用 RL 的 rliable／Procgen／D4RL 作方法学参考。

**数据**：不是自己做实验，而是汇总论文内的前后对比（Table 9）：EmbodiRSI（数据采集）+20.6 点（59.3→79.9）、FIND +16.9（55.0→71.9）、RoboCoach +61.7（13.3→75.0；统一采集控制为 30.0）、Motus2 +7.5（控制 67.5）、LWD +5.0（92.0→97.0，约 60 机器人小时）、RPG +27.5、SHAPER +8.7；RoboMemArena 全 26 任务表（RoboFoundry TSR 53.5／CSR 72.8，HarnessWAM 59.6／69.9）；RoboDojo 2026-09-28 排行榜快照（PhysicalRSI 1.0 平均分 36.27、SR 31.38）。作者明说这些跨论文数字的预算与协议不同，不排名。

**局限**（作者自述）：不同任务分布、人工协助与成本核算使跨研究不能直接比较；L0–L3 分级的标注者一致性未测（建议将来做）；无自己的实验数据；“正在处理”的 improver 对比在已有文献中几乎没有。

**与关注点的关系**：(1) 最相关的方法学：把 improver gain 形式化为“同一 learner 起点、匹配预算、独立测试下两个 improver 后续增益之差 ΔG”，并区分共同数据与交互两种条件，明确指出“对角线”（learner 与 improver 同时变）的比较不能识别；与 #4 的 swap test 一致。它自己说物理 RSI 里还没有满足 L3 的实例（我判断：Table 9 的对比都是 L1 的能力增益）。(5) 第 V.C 节讨论遗忘、不可访问和被物理条件废止的区别、回滚要成套恢复版本。(4) 反复强调“独立于更新循环的评估”、评判器与被评对象共享盲点（世界模型与奖励模型依赖同一视觉线索）。(2)(3)(6) 基本不涉及。

## 跨文献小结（只列事实）

**improver gain 到底有没有人量过**
- 被明确定义的只有两篇：#4（C4：早期 vs 后期 improver，同起点 artifact，同预算，审计后继；对角线不可识别命题；演化 vs 冻结只答另一个问题）和 #9（ΔG 与共同数据／交互两种条件）。两篇表述互相一致；#9 引用了“The Last AI Built by Humans”和 Wu 等综述的受控对比。
- 实测：#4 的普查数据里，26 篇声称 improver 变好的论文中只有 4 篇做了“同起点、匹配预算”的对比（MetaRSI：+4.9 对 +7.2；Sivia；MASS；STOP 为 mixed），另有 3 篇没有匹配预算的同起点、7 篇演化 vs 冻结；论文清单见 #4 的 Table 5（含正文引文 Tan et al. [8]、Yuan et al. [75]、Lee et al. [76]、Zelikman et al. [10]）。这四篇本批没有读原文。
- #1 的 plasticity、#3 的 RRSI 与 #6 的三层控制都在“固定协议下比较不同的改进过程或模型”，但都不是 improver 的早期 vs 后期对比：#1 的 learner 与 improver 是同一模型；#3 在同一起点同预算下比较不同方法的 OOD 增益；#6 的 CARE 比较的是控制规则。
- #4 和 #9 都明确提醒：看到后期增益变小或变大不能归到 improver，因为 solver 状态也在变（#4 的两状态例子：A、B 得分都为 0，improver 在 A 增益 0.1、在 B 增益 0.8，轨迹上看差 0.7，但每个状态下 improver 对比为 0）。

**先升后塌与原因**
- 同任务上最直接的数据来自 #6（Qwen-2.5 3B／7B，REINFORCE 与 GRPO，5 seed，单步“悬崖”，GRPO 不消除 17 点峰—终点差，KL／EWC 无效）。#4 的 Table 15 汇总了另外 8 篇左右的“在轮次上先升后降”的报告（DataFoundry、DA-RSIR、ECG-RSI、RSIBench-Data 等），本批没有读它们。#3 给出的是另一种机制：开发集上继续升而外部分布不动（过拟合式的“升而不迁移”）；#7 给出的是新任务适应导致旧任务降。#2 在 V-R 轮数上有 pass@k 的最佳点，ViL 本身没有塌。
- 原因：#6 推断为“同任务策略过度优化、覆盖先验被改写”，没有多样性／熵测量；#4 的 P1 给出了统计性的解释：从含噪的开发分里选最大值，期望的虚假增益随候选数增长；#5 给出可计算性层面的解释（有界代理分上升而真分下降，无需自指）。三者互不排斥，但本批没有任何一篇同时测量。

**增益是否超过 base 的可提取上限**
- 只有 #2 直接比较：在按 base 的 32 次 rollout 定义的“全错”档上，STV＋V-R 终轮 5.5%、ViL 第 0 轮 14.7%，高于该档的 base 估计（0%）与无验证 32B（2.7%）；仍受“32 次估计有限”和 pass@k 只有图的限制。
- #6 的 7B base 25.0% 高于所有训练后链终点（同一评测上 12.3–22%）；#8 只提出用 pass@k coverage 当“可达集”的替身并设计了实验，没运行；#8 的 30 个同族 worker 共同失败（23/55）；#1、#3、#7 没有 base 可提取性的对照。

**验证作为瓶颈**
- #2（训练验证器带来最大收益）、#5（门不可能既可靠又完备；有界下仍漂移）、#4（P2：评判器共享偏差；90 篇里 38% 的开发信号含自评或模型判官）、#3（泄漏筛查与噪声下限）、#9（评判与被评对象共享盲点）。#6 的奖励是二值 CodeGrader，验证本身不是瓶颈，瓶颈是优化动力学。

**保留／遗忘**
- #7（四通道，幅度 0.1–11 点，统计弱）；#6（跨语言迁移不随主指标升）；#1（GPT-5.5 弃用 artifact、OOD 增益小于 ID）；#9 的综述段；#4 的 Table 15 里 ECG-RSI 的外部基准倒退。RRSI 报告任何 held-out split 均未倒退。

**审计细节（seed／基线／保留集）**
- 有区间或重复的：#3（配对 bootstrap，两次搜索重复）、#6（3–5 seed，bootstrap，但 n 小且结论随 seed 数变）、#2（p 值，无 seed 数）。单次、无区间的：#1（每模型一条 lineage，保留集每 checkpoint 12 局）、#7（seed 42，表格无区间）、#8（5 次运行每任务，但功效只有 11–17%）。
- #4 的普查数字：产品评估独立于选择 60%、整环重跑 22%、预算匹配比较器 37%、零控制 19%、噪声感知接受 19%、improver 同起点比较 4/26。
