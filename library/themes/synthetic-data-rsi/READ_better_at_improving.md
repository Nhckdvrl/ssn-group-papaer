# Better at Improving? Separating Inheritance from Further Improvement in Coding Agents

- **状态**：ICLR 2027 投稿，审稿分 3/3/3，匿名。OpenReview ZMmJDeDTXk。PDF 在 `workbench/data-centric-rsi/papers_in/ZMmJDeDTXk_better_at_improving.pdf`。
- **阅读**：主笔亲自读完 27 页全部内容，包括正文 1–10 页、附录 A–D（档案审计、实验协议、四步 rollout、新改进 run、各模型 factorial、功效模拟）和附录 E 的全部证明。

## 问题

自我改进的编码系统（Darwin Gödel Machine、Hyperagents）里，改进器既改任务 agent，也能改自己。它们报告的逐代提升，有多少来自“保留了一个已经更好的改进器”（继承），有多少来自“改进器更会产出下一代改进器”？

## 概念与理论

**两个量。**
- **child quality** Q⁽⁰⁾(m)：改进器 m 写出的任务 agent 的平均分。
- **successor quality** Q⁽¹⁾(m)：m 当编辑者、去修改一个起始改进器后，得到的新改进器的 child quality。

**Theorem 1（谱系对比的分解）。** 两条谱系的差可以拆成两项：
- 继承项 Δ₀ = Q⁽⁰⁾(M₁) − Q⁽⁰⁾(M₀)；
- 编辑项：编辑概率 × 编辑带来的平均增益。

**Corollary 1。** 谱系对比偏离继承项的幅度，不超过两边编辑概率之和。所以只要改进器很少改自己，谱系差几乎就等于继承。

**Nested replay（Theorem 2，无偏）。** 两个编辑者拿到同一个起始改进器的副本，各自修改若干次，再在同一组任务状态上评测它们产出的改进器。统计单位是起始设置；检验用 sign-flip，在设置内随机化执行顺序。

**Theorem 3（低阶不识别高阶）。** 对任意阶 r，都存在两个改进器，所有低于 r 阶的质量都相同，只在 r 阶不同。在 horizon < r 之内，任何只依赖任务分数的选择或晋升规则都分不出它们。特别地，Δ₀ 不能识别 Δ₁。

**Proposition 1。** Δ₀ 和 Δ₁ 可以符号相反。

**Proposition 1A/1B。** 只看档案的分数轨迹，连 Δ₀ 都识别不了。分数轨迹的变化等于“改进器的变化”加上“呈现给改进器的任务状态分布的变化”，而轨迹只能观察到两者之和。

## 结果

### 1. 已发布历史的审计（71 个 Hyperagents run，15 种配置，1,550 份改进器转录，另有 DGM、ADAS）

- **档案曲线可以由选择产生。** 把每个 run 的分数打乱顺序后重算“迄今最好分”，141 个 checkpoint 里有 119 个落在置换的 90% 带内。用固定改进器做模拟，复用观察到的父代时，69 个 checkpoint 中有 64 个覆盖了观察到的最好分；连父代选择也一起模拟时，64 个中有 43 个覆盖。
- **论文评审任务的 label collapse。** 369 个完全评测的节点里有 163 个塌缩：至少 95% 的预测是同一个标签，或非标签输出超过 5%。进入塌缩状态的转变几乎都是退步，离开塌缩的转变几乎都是进步，分数曲线因此可以在改进器不变的情况下上升。
- **父代的产出力没有提高。** 控制父代自身分数后，看不出产生后代的改进器在 run 中变得更有产出力。改进器本身被编辑的代数只占 1–15%；在源 run 里，只有一个改进器编辑有后代，就是第一代的 briefing。
- **DGM。** SWE-bench 上 45–62% 的子代从未被评分；进步与退步大致各半，平均变化接近 0。
- **Meta^n。** 用验证集选出的 +0.309 增益，来自替换了两个无法解析的初始程序；只看可执行的起点，增益只有 0.014 [0, 0.047]。

### 2. Order 0：被选中的编辑 M₁ 确实写出更好的任务 agent（MiMo-V2.5）

| 任务集 | M₀ | M₁ | 差值与 95% 区间 |
|---|---|---|---|
| 12 个“未声明约定”程序 | 0.476 | 0.858 | +0.382 [0.221, 0.500] |
| SWE-bench Verified 10 个 issue | 0.500 | 0.800 | +0.300 |
| 状态跟踪任务 | 0.441 | 0.704 | +0.262 |

M₁ 的改动，是让改进器先读评估报告。

**新的改进 run（5 个种子 × 80 代）。** 共选出 6 个改进器版本：
- 只有一个（种子 3，同样是“读评估结果”）达到 0.858；
- 其余 0.476–0.575，区间覆盖 M₀；
- 5 个 run 中有 4 个在开发分上达到满分时仍在用 M₀，也就是说，开发分的上升来自固定改进器下的搜索。

### 3. Order 1：继承与后继质量

**MiMo-V2.5（6 个起始设置 × 6 次重复）。**
- 谱系差 0.293，与继承项相差不到 0.004（0.842 对 0.545）。
- M₁ 在 36 个自己的副本上一个都没改。
- 固定起始改进器为 M₀ 时，δ₀ = +0.031 [−0.044, 0.126]：M₁ 在 36 次中改了 M₀ 4 次，M₀ 自改 6 次。

**MiMo-V2.6-Flash（13 个起始设置，各 4 次重复）。**
- δ₀ = +0.148 [0.114, 0.182]。
- 让两个编辑者都被要求修改起始改进器后，差距降到 0.007 [−0.041, 0.056]。
- 原始差距正好等于编辑率之差乘以单次编辑增益：(43/52) × (0.849 − 0.670) = 0.148。

**Claude Sonnet 4.5（13 个起始设置）。** δ₀ = +0.271 [0.141, 0.448]；只要求 M₀ 修改，差距就降到 0.023。

**跨三个模型。** M₁ 在 101 次中只改过 1 次自己的副本；146 个被编辑出的后继里，有 145 个都指向“读评估结果”。

**正对照。** 一条构造的“分别诊断任务解法和改进流程”的指令，在 7 个设置上把后继质量提高 +0.171 [0.099, 0.240]，说明这个检验能检出真实的后继增益。

**其他改进流程。** 候选搜索、自写测试选择、失败记录这三种，只带来 +0.018 到 +0.053，不显著。

### 4. 机制：为什么“读评估报告”有效

- **报告越有信息量，帮助越大。** 任务描述越详细，读报告的效果越小：+0.372、+0.046、−0.067。
- **对平时不主动读报告的模型帮助大。** MiMo、Grok、GLM 平时很少主动打开报告，增益 0.19–0.34；DeepSeek、Gemini 平时就会读，增益为 0 或 −0.109。
- **真实仓库。** 不给 issue 描述时，读报告提高 0.253；给描述时只提高 0.013。

### 5. 功效与方差

- order-1 对比约等于“编辑率变化 × 单次编辑的平均增益（约 0.26）”，方差主要来自“是否发生编辑”这个指示变量，是评测噪声的约 3 倍。
- 用 12 个起始设置时，sign-flip 检验检出编辑率从 0.17 升到 0.50 的概率：每个方法 2 次重复时为 0.51，6 次重复时为 0.93。

## 局限（作者自述加阅读所见）

- 只测了一步递归（order 1），3 个模型，编码任务。
- 用的是重建的已发布指令，不是原始 run。
- Claude 的后继分数接近满分，存在天花板。
- 统计单位是起始设置，数量少（6–13 个）。
- 有一个修正记录（附录 B.1）：受影响的面板已在修正后的 harness 上完整重跑。

## 对 data-centric RSI 的含义

**事实。**
- “档案分数或学习者分数逐轮上升”不能说明改进器变好：选择、加上呈现状态的变化，就能在固定改进器下产生上升曲线（Prop 1A/1B，以及 119/141 的置换结果）。
- 衡量改进器，要在固定的共享状态上重放（order-0 replay）；衡量“更会改进”，要用 nested replay（order 1），而且每一阶都要单独比较（Theorem 3）。

**猜想（与我们方向 B 的关系）。**
- 方向 B 的设计（冻结各轮生成器、各训练一个全新学习者、在固定外部集上评测）就是这篇的 **order-0 replay** 在“权重被训练的数据生成器”上的版本：生成器的“child”是被它的数据训练出来的学习者。区别在于：
  - 它们的改进器改代码，我们的生成器靠 RL 更新权重；
  - 它们关心改进器改自己（order 1），而 R-Zero 类闭环里，生成器的更新规则（GRPO 加奖励）是固定的，所以我们的核心问题是“Q⁽⁰⁾(G_t) 是否随 t 上升”。这正是这篇在新改进 run 里发现“5 个种子里只有 1 个找到更好改进器”的那个量。
- 它们的分解“轨迹变化 = 改进器变化 + 状态分布变化”，对应 R-Zero 中“学习者变强 = 生成器变化 + 学习者状态变化”。全新学习者的设计固定了状态，正好分离出生成器的变化。
- 统计设计可以直接借鉴：统计单位、sign-flip 检验、事前功效模拟、正对照（构造一个确实更好的生成器，看检验能否检出）、避开天花板。我们的方差来自学习者训练的种子，所以每个生成器轮次要多个种子。
- 增量与压缩风险：这篇在 harness 端已经提出了 order-0/order-1 的概念和 nested replay；审稿人会把我们的工作看作把它搬到数据端。可辩护的增量是：权重耦合闭环中的共同适应问题（生成器为追随当前学习者而变）、全新学习者带来的训练噪声与统计设计，以及“有累积状态 / 无累积状态”的对比。
