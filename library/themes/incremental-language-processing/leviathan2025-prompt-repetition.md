# Prompt Repetition Improves Non-Reasoning LLMs（Google Research 预印本，2025-12）`[证据级别：全文（arXiv 2512.14982v1）]`

1. **论文形态：** 极简工程干预 + 广泛 benchmark。
2. **背景与压力：** 因果 LM 中过去的 token 看不到未来，所以输入顺序会影响结果（例如选项在前还是问题在前）。
3. **改变的前提：** 把 `<QUERY>` 改成 `<QUERY><QUERY>`，让第二遍里的每个 token 都能看到整段输入；只增加 prefill 开销。
4. **idea 来源（DOCUMENTED）：** 架构事实；观察到 RL 训练的推理模型会自己复述题目；相关做法有 Springer 2024（echo）、RE2（Xu 2024）。
5. **与最近邻的距离：** 相对 RE2，不需要生成更长的输出；用等长 padding 对照排除"只是变长了"。
6. **方法与数据：** 7 个 API 模型、7 个 benchmark（含两个自建），McNemar 检验；70 项测试中 47 胜 0 负；开启推理时基本中性。
7. **证据与短板：** 结论是一般性的；没有分析什么时候有用、为什么有用，作者把"表征在两遍之间怎样变化"列为未来方向。
8. **可迁移的研究动作：** 一个架构事实直接推出一个干预，再加一个能排除最简单解释的对照（padding）。
9. **对我们：** 这是 C1 "读两遍"最主要的压缩风险（"重复本来就有用"）。我们的增量必须是：选择性（真实 GP 条目与对照句之间的差距是否缩小）、截断重复对照（证明起作用的是能看到后文）、以及机制解释。如果"读两遍"恰恰**不能**修好 GP，反而更有意思。
