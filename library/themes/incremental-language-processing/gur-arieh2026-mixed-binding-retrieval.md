# Mixing Mechanisms: How Language Models Retrieve Bound Entities In-Context

**MAIN_TEXT_READ**：[作者arXiv v2](https://arxiv.org/abs/2510.06182v2)，2026-05-28，PDF标ICLR2026，arXiv作者接收记录；正式会议PDF未逐字比对。完整主文§1–6，App A.1/A.2文字、D.2、D.4文字和G的长度控制文字；其余附录未完整读。

1. **形态：** 将不够忠实的单机制解释扩成可预测的混合因果模型。
2. **背景与压力：** 短列表的绑定机制不能自动解释长列表/不同查询方向。旧位置机制在中间序号附近弥散，“没选对”本身没有说明模型到底如何检索。
3. **改变的前提：** 原始输入中多个策略指向同一个答案，正常准确率无法区分策略；反事实要让机制分别预测不同token，并另区分指针和已取回的答案。
4. **idea来源（RECONSTRUCTED）：** 扩大旧任务的实体数和目标方向，看到单位置解释失真；构造三种策略分歧的counterfactual，把残余mixed结果进一步拆成邻近位置误差。再用“目标不在原context”的新反事实与ℓ+1阳性控制，区分直接指针和答案复制，最后以分布预测检验组合模型。新意来自原解释的系统失败和可反驳替代，而不是“多加两个机制”这个名字。
5. **近邻距离：** Feng的表示因子分解、Prakash/Dai的lookback/位置查询提供部分；本文把它们的短上下文预测扩到不同组数、实体内顺序与自然噪声，并解释机制混合。它已经拥有位置/词汇/直接指针的检索竞争；我们的增量须具体到晚语法证据如何改变绑定、不同用途何时取回旧关系，不能只换GP数据复述三机制。
6. **方法/规模/基线：** 9模型/3族/2–72B：Gemma2、Qwen2.5、Llama3.1；全部九模型主要boxes/music，全部十任务只在Gemma2-2B/Qwen2.5-7B，不能写9×10全笛卡尔验证。十任务1个两实体/9个三实体，实体集合23–80；主列表n20、n3–20控制。组合模型每个(iP,iL,iR)150干预，8000组合共120万干预/设置，softmax后先平均；组合按70/15/15分割，不是跨任务/跨序号外推。位置onehot、Gaussian、oracle、机制消融与uniform均保留。
7. **证据与短板：** 0.95是1−JSD的JSS分布相似度，**不是95%准确率/独立token预测一致率**；只解释候选实体分布，非全词表。oracle约.96–.98，uniform约.44–.57。10k token是1000种“entity-less”填充交织，12句式变体也仍模板，不等于自然文档benchmark；等长控制区分实体数与token长。干预层是每模型最后检索前层、根据效果定位且跨任务一致，不能假设一固定分位就是语义层。指针不在原context时失效、ℓ+1可复制答案是重要阳性控制，仍须按干预粒度理解。
8. **迁移动作：** 让位置/词汇/角色关系解释在一次干预下给出不同可观察预测；保留未被机制解释的情况，再解释其结构。参考当问题方向改变时因果访问限制如何改变可用检索策略，不把注意力或一个正确答案当binding证据。
9. **对我们：** 词汇索引旧关系是I03/I05表里的竞争解释，尚没有我们自己的证据。E63固定任务未知源前缀检验共同用途，之后若有真信号，再设计能同时分开关系更新与检索选择的反事实；不提前认定narrative，也不因局部覆盖关闭方向。
