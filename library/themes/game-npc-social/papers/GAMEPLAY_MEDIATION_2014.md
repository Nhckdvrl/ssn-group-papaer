# Gameplay as On-Line Mediation Search（AIIDE Workshop 2014）

**证据级别：全文。** Justus Robertson、R. Michael Young；AIIDE 2014 Workshop on Experimental AI in Games，pp.42–48，DOI [10.1609/aiide.v10i3.12740](https://doi.org/10.1609/aiide.v10i3.12740)。实际读[AAAI 正式 7 页 PDF](https://cdn.aaai.org/ojs/12740/12740-52-16257-1-2-20201228.pdf)全部正文、伪代码、图注和案例；未逐图重建搜索树。部分网页存档时间为 2021 或以后，不改变研究年份。阅读日期：2026-10-19。

## 1. 论文形态与背景压力

可运行规划/游戏中间层。作者有故事计划，玩家行动可能构成计划、与计划相容但不推进它，或破坏后续前提；简单照脚本继续难以承接第三类行动。

## 2. 改变的前提

Game Mediation Engine 把每个世界状态作为节点，把所有合法玩家行动作为边，交替进行玩家行动和系统更新。传统只围绕计划及例外组织的调解树被扩为世界状态空间；它理论覆盖可达路径，不意味着实际穷举大世界。

## 3. Idea 来源

**DOCUMENTED：**叙事调解、PDDL 规划及游戏循环。**RECONSTRUCTED：**将“玩家偏离”按对后续计划的影响分类，避免所有非预定动作都被强制拉回原线。

## 4. 方法与任务

保留固定作者目标，分 constituent、consistent、exceptional 三类玩家行动；通常只有 exceptional 需要求新计划。系统更新可执行 NPC 计划动作和世界事件，通过可见性规则给客户端新状态。planner 可替换，示例使用 Fast Downward；预计算 frontier 和缓存降低玩家可感等待。

只有 **1 个 Evil Dead 改编领域**：12 种动作、最多 4 参数、13 对象、35 初始谓词和 3 目标谓词。玩家改去卧室时，Linda 可以承担开书动作，系统换后续行动但仍到作者结局。约 250 ms 规划节点、缓存使展示约 2 ms，是单案例旧 Core i7/8 GB RAM 的报告，非跨世界延迟分布。

## 5. 证据与独立单位

系统案例展示了实际合法状态更新和调解调用；没有新增玩家对照、作者工作量测量或体验改善。动作离散且等时长，剧情规则/目标已人工定义。玩家个性化、概率选择与限制玩家行动的 intervention 部分在本文属于未来工作；已实现的是 accommodation 型续演。

## 6. 限制

动态修复主要保持预设作者目标，不解决开放语言中人物意图、知识披露或作者主动改变艺术意图。不能因缺 LLM 就忽略它，也不能把形式域单例的“有解”当成玩家愿意接受该故事。未核得公开评审分数。

## 8. 可迁移的研究动作

把用户动作、合法性、前提破坏、剧情修复及呈现结果明确连接；用普通事件触发重规划作基线；分开固定目标内的重新找路与获授权修改故事目标。

## 9. 对矿区 C

“能承接没写在剧本里的玩家行动并重规划”至少已有这类经典系统。潜在新问题需要超出固定动作/结局内换路，解释玩家如何影响人物和作者愿意接受的故事范围，并将这种影响与体验相连。本轮只阅读，不运行 planner 或引擎。
