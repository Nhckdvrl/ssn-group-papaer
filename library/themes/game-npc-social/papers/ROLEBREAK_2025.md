# RoleBreak: Character Hallucination as a Jailbreak Attack in Role-Playing Systems

证据级别：全文正文；COLING 2025 主会，7386–7402，ACL 正式 PDF 17 页。[发表记录](https://aclanthology.org/2025.coling-main.494/) · [正文](https://aclanthology.org/2025.coling-main.494.pdf)。公开评审/分数未核验。

阅读范围（2026-10-19）：完整主文与 limitations，PDF pp.1–9；附录逐条提示未完整读。未运行论文攻击或模型。

## 1. 论文形态

失败模式、干扰数据集与提示式修复；核心是 role-query conflict 和 query sparsity 下的人物幻觉。

## 2. 背景与压力（DOCUMENTED）

人物角色可能被问题牵引到相似角色、错误知识或通用助手状态。简单拒绝虽能减少错扮，却会损害开放角色扮演；用户可能故意要求新情节或同人改写。

## 3. 改变的前提

Narrator Mode 先丰富整体人物，再补当前局部情节与处境，最后验证/重试，使回答同时贴合角色和当前提问。它容许补写背景来解释新输入；补写并非经游戏世界事实确认。

## 4. idea 来源

DOCUMENTED：从叙事中的全局人物信息和局部情节组织得到 Narrator Mode。RECONSTRUCTED：问题从“只保持角色”转成“角色与提问共同满足”，因而修复也可能变成过度合理化用户输入。

## 6. 方法、单位、基线与结果

从 WikiRoleEval 选 50 个英语角色，匿名化后构造 1,013 queries；包含领域稀疏、换语言、遗漏关键条件及以相邻人物替换等干扰，主要由 GPT-4 合成。角色数是 50，问题不是 1,013 个独立角色/游戏世界。

对照含 GPT-3.5-Turbo、Claude-3-Haiku、Llama-3-8B、Mistral-7B，以及 CharacterGLM、改造 Character-LLM、Protect、DITTO、RoleFact。它未测当下强旗舰模型配完整人物/场景与反馈的上限。

表 4：GPT-3.5 幻觉率 0.48→Narrator Mode 0.36，RoleFact 0.37；问题服从 0.83→0.89，而 RoleFact 0.78。Llama 上 RoleFact 幻觉率 0.40，Narrator Mode 0.41，所以后者不是每项都最好。叙事连贯分由量表评委给出，不代表长时剧情质量。

## 7. 证据强度与短板

没有真人玩家或作者研究，没有游戏引擎后果，也没有随机种子/置信区间。角色服从/问题服从主要靠 LLM 分类；主文对部分指标的 GPT-3.5/GPT-4 评委描述不完全一致，不能自行消除歧义。匿名化降低显式名字捷径但不消除原作知识影响。

作者承认局部创造性扩充可能再次导致 OOC。它支持在其合成干扰中兼顾两目标的可行性，不证明玩家更喜欢该系统，也不证明给玩家编造一段合理背景就是正确世界互动。

## 8. 可迁移的研究动作

将缺信息、信息冲突、合法即兴分别建模；同时保留角色成立与玩家请求得到有意义回应两个观察面；用核查/拒绝、局部背景、全局人物分别作普通系统参照。

## 9. 对我们

B 必须让作者决定哪些设定可扩展、哪些过去事实不可随口改写；“偏离原作”有时正是玩法。角色保持的提升不应通过一律拒绝或一律补写取得，也不宜把 Narrator Mode 重新命名为新贡献。
