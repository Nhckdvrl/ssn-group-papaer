# PHASE-Tree：Character-State Evolution in Long-Horizon Role-Playing Dialogue

证据级别：主文选读＋官方代码/数据。2026-10-22读取arXiv:2608.06975v1（2026-08-07）主文§1–5、方法公式/主表，核对官方prompt与状态演化关键入口；未声称全文/全部附录完成。来源：[论文](https://arxiv.org/abs/2608.06975) · [代码](https://github.com/MemTensor/PHASE-Tree) · [数据](https://huggingface.co/datasets/IAAR-Shanghai/LongEvoRoleBench)。本地代码固定`0be378fd23c49915255406d881f2389b46b608b8`。

1. **论文形态：** 动态人物状态表示、统一下一句回复benchmark、文本与参数适配两种条件化方式；目前核对为预印本身份，不冒充主会已接收。
2. **背景与压力：** 固定人物档案难以反映当前叙事状态。作者已将仍按过去人物状态说话命名为stale-state failure；“旧人物状态妨碍成长”不是我们的新发现。
3. **改变的前提：** 身份根节点固定，persona/session/moment三个时间尺度分别更新；不是单一persona树或简单近期加权。
4. **idea来源（DOCUMENTED）：** 作者关联人格特质与情境适应、状态/特质情绪区分；阈值来自固定叙事节奏先验，不是学出的更新策略。
5. **近邻距离：** 文本RAG/PAG/CFG与MT-LoRA/Steering/OPPU/P2P均有实测；profile-to-LoRA继承P2P路线。与ArcANE的区别是对话下一轮/剧集状态，不是同一小说Probe跨phase；不能直接混合分数。
6. **方法与资产：** 官方包含事件重要性、累计证据、逐字段候选、resistance/evidence/cooldown门控及替换/增量合并。核心字段需要跨≥16集、≥6高重要性证据；关系等低阻力字段可快更新。默认局部状态只看目标前缀，跨集persona用严格早于当前集的快照。公开八语料，四长程、四短程；长程OOD为后续时间，不等同新人物。
7. **结果与限制：** 论文长程文本PT的Sem均值3.697，普通NR为3.474；动态树DT单独为3.363，说明仅长期演化并不自动优于普通重写。Char的NR 2.989与PT 3.004很近；作者已做参考敏感性、跨judge和人评，不能预判“judge无效”。参数路线更省prompt，但树细节压缩是作者已讨论的瓶颈。
8. **可迁移研究动作：** 把持续身份、跨集状态和当下适应分开；使用普通重写这一实质强基线；区分直接状态供给与学会更新；在同一时间可知信息上核查作用，而非再造动态树。
9. **对矿区D：** 直接强近邻与第二任务体系。固定阈值/来源政策、长期与当下贡献是开放问题，须从真实输入和表现中确定残差。不能把B/I01证据转写为本任务发现。新方法需正面对比本工作已有实现。
