1. **论文形态**：方法学/审计（把"probe 显示 helix"拆成四个可分别判定的主张）。
2. **背景与压力**：helix/circle 常仅凭 probe + PCA 可视化宣布，并被当成"模型用它计算"的证据。
3. **改变的前提**：四个主张——decodability、shape、ownership（形状是否属于该概念而非相关概念）、causal use——可以得到不同答案，需要分别给判决。
4. **idea 来源（DOCUMENTED）**：probe 文献（Hewitt & Liang 控制任务、amnesic probing、Belinkov）+ 叠加导致概念共用方向。
5. **与最近邻的距离**：Kantamneni & Tegmark 2025（广义 helix + patching，同三模型）；Gurnee 2026；Wurgaft/Sarfati/Modell（沿流形 steering 证因果但不比较命名形状）。增量 = 贝叶斯模型比较选形状 + 去除相关概念判归属。
6. **方法 / 实验 / 数据**：
   - 模型：GPT-J 6B、Llama 3.1 8B、Pythia 6.9B（base；全 Transformer，"两种 block 布局"）；每模型 5 个相对深度层；只读最后 '=' token。
   - 任务：两位数加法（10,000 题）与乘法（3,023 个单 token 答案题），只用答对的题；108 个概念（41+47 单概念 + 各 10 个联合概念）；3 种预处理（off / 去掉答案 unembedding 方向 / 单位范数）；共 4,860 cells。
   - Stage 1：中心 SVD + 置换检验（99 分位）得 probe 子空间 B；superposition 判定（主角比随机低 10°、FDR 0.05）。
   - Stage 2（形状）：候选 = line、circle、open helix、torus、ribbon（半径随值线性变化的 helix）、concentric；线性-高斯模型 z = W^T φ_k(y) + ε，W 解析积分得边缘似然；基线 = 三次多项式；**选中阈值 g = log Z_k − log Z_0 ≥ 5 nats（≈Bayes factor 150；值 ≤6 个时为 10）**，alignment <0.5 拒判；Tier A 另需留出误差、9 种种子×先验稳定。
   - Stage 3（归属）：投影去掉预先列出的相关概念子空间后重拟合，Δ = g − g⊥ < 0 为 owned，否则 inherited。
   - Stage 4（因果）：在 B 与形状基 Q_geom（rank ≤5）上做均值消融与供体 patching，减去 5 个同秩随机子空间的效应（causal excess ≥0.5 logit 为活跃）。
6b. **关键数字**：89% cells 可解码；superposition 率 0.80（加法）/0.90（乘法）；1,457 个有形状拟合的 cell 中 ribbon 1,208、torus 230、其他 19（基线 13、circle 4、open helix 2）；338 个强支持比较全是 ribbon/torus；强支持比较的**中位证据差 10,866 nats**（作者自己说 5 nats 阈值是必要条件而非决定性条件）；归属 19% owned / 81% inherited（核心概念 16/337 = 5% owned；答案位与进位 0/217 owned）；Q_geom 消融保留 B 消融效应的 61%（0.32–0.70）；四项全过 46/1,330。
7. **证据强度与短板**：作者自认判决依赖预先列出的相关概念清单、单一 prompt、单一 token 位置；cells 不独立不做显著性。我的补充：样本量大时边缘似然几乎总偏向候选集里最灵活的形状（ribbon 内含 line、circle、helix），所以"选中什么"主要由候选集决定；line 从未胜出不说明没有线性成分。
8. **可迁移的研究动作**：形状判定用模型比较 + 预注册候选集与阈值；"owned vs inherited"检查（去掉相关变量后形状是否仍在）。
9. **对我们（候选 2）**：
   - 回答了"line/helix/cloud 能否不靠任意阈值判定"的一半：可以用贝叶斯证据比较，但候选集与阈值仍是研究者定的，而且大 N 下判决几乎总落在最灵活形状——三分法被"ribbon（线 + 周期分量）"吞掉。
   - ownership 问题对计数直接致命：字符计数与 token 位置、词数高度相关（Gurnee 的 L0 head 就是用 token 数 × 平均长度估计），在不同架构里看到的"计数流形"可能继承自位置表示——Transformer 的 RoPE/位置机制与 SSM 的递归状态不同，形状差异可能只是位置编码差异的继承。
