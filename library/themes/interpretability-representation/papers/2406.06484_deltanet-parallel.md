# Parallelizing Linear Transformers with the Delta Rule over Sequence Length（NeurIPS 2024，poster，分数未核对）`[证据级别：全文（正文 §1–6 与附录 A.2；算法推导附录 B 略读）]`

arXiv 2406.06484 v6（2025-01-15）；Songlin Yang, Bailin Wang, Yu Zhang, Yikang Shen, Yoon Kim（MIT 等）。2026-11-25 读 HTML 正文（本地 scratchpad lit/2406.06484.txt）。本卡只关心 delta rule 的“取回并更新当前 key 的值”动机与合成证据。

1. 论文形态：训练算法（WY 表示 + chunkwise 并行）+ 中等规模预训练验证。
2. 背景与压力：门控线性注意力 / Mamba 在 recall 密集任务上落后 Transformer；Schlag 2021 的 DeltaNet 合成任务好，但只有串行算法，无法扩展。
3. 改变的前提：把 DeltaNet 写成广义 Householder 转移的矩阵 RNN，S_t = S_{t−1}(I − β_t k_t k_tᵀ) + β_t v_t k_tᵀ；L2 归一化 key 后 β=1 时转移是投影，“erasing information in one subspace while preserving the other subspaces … enabling more targeted forgetting”。
4. idea 来源（DOCUMENTED）：Schlag et al. 2021（delta rule 解决线性注意力的容量与更新问题）；Widrow–Hoff；Hopfield 容量文献（Hebbian 容量低、delta 容量高）。
5. 与最近邻的距离：Schlag 2021（2102.11174，串行、小规模）→ 可并行、1.3B/100B；GLA / Mamba / RetNet（加性写 + 衰减）为基线；后续 GDN（2412.06464）加门控。
6. 方法 / 实验 / 数据：
   - 合成：MQAR（Zoology 设定，序列 512、64 对，DeltaNet 2 头、**不加卷积**）；MAD（compress / fuzzy recall / in-context recall / memorize / noisy recall / selective copy）；RegBench（PFA 语言的上下文学习，附录 A.2）。
   - 语言建模：340M/15B 与 1.3B/100B（SlimPajama 子集），Wiki ppl、常识、SWDE/SQuAD/FDA；hybrid（+SWA、+2 层全局注意力）。
7. 证据强度与短板：
   - 关键数字：MQAR 最难设定 DeltaNet 满分、在低维时胜过带卷积的 Mamba（Fig. 4，只有图）；MAD（Table）：DeltaNet fuzzy recall 35.7（Transformer 29.8、Mamba 6.7），in-context recall 100、noisy recall 100、selective copy 100，但 memorize 52.8（Transformer 85.2、Mamba 89.5）；1.3B：DeltaNet(w. conv) Wiki ppl 16.87 vs Transformer++ 16.85、Mamba 17.06；SWDE 49.5 vs Transformer++ 66.6、Mamba 41.4；+2 层全局注意力 SWDE 71.0。
   - **没有任何键重新赋值 / 覆写的合成任务**：MQAR、MAD、RegBench 中每个 key 只绑定一次（MAD 的 noisy/fuzzy recall 是噪声与多 token key，不是更新）。“更新当前 key 的值”是机制描述，没有行为验证。
   - 作者承认：训练仍慢于 GLA（头维受限 → 状态小 → recall 受限）；长度泛化差，推测因缺少显式衰减。
8. 可迁移的研究动作：用“同一合成套件 + 是否带短卷积”分开 recurrence 与卷积的贡献（后来 2609.16183 把这一点做成因子设计）。
9. 对我们：DeltaNet / GDN 原论文对“原位擦除”的证据是理论动机 + 无更新的 recall 任务；**真正的覆写行为证据只有 Schlag 2021 Setting 2（玩具、单层、从头训练）**。预训练 delta-rule 模型是否真的按 key 擦除，是没人测过的经验问题——这是探针 A/B 的真实空白，也是其风险（结果可能是“不擦除”，见 2609.16183 的 collision-key 结果）。
