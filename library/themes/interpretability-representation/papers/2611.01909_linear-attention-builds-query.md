# Who Asks, Who Answers: Linear Attention Builds the Query in Hybrid Language Models（arXiv 预印本 v1 2026-11-01，cs.AI，Preprint，未见评审，分数 —）`[证据级别：全文]`

- 作者：Wenqi Zeng, Chen Feng, YuAng Chen（HKUST / PolyU / CUHK）。arXiv:2611.01909v1，abs 页已核对。
- 阅读范围（2026-11-25）：正文 §1–8、附录 A（复现、任务生成）、B（单层 vs 块级干预）及附录中可见的其余模型结果。

1. **论文形态**：电路定位（截断、块移除、块移植）+ 跨架构移植。
2. **背景与压力**：hybrid 的上下文检索通常归于 softmax 注意力（Bick 2025 G&A），线性注意力被当作压缩；但"哪里发生检索"不解释"线性层对检索贡献了什么"。
3. **改变的前提**：以连续线性注意力层组成的"块"为单位做移除与 final-position 移植；在供体/宿主提示间只改被问的 key。
4. **idea 来源（DOCUMENTED）**：Bick 2025 渐进剪枝；activation patching。
5. **与最近邻的距离**：2609.04434 与 2609.33093 说"值由 KV 承载"→ 本文补上"查询（检索目标）由递归块的状态承载"；Bick 2025 G&A → 本文的 Address 块在 G&A 中没有对应物。
6. **方法 / 实验 / 数据**：
   - 模型：Qwen3.5-0.8B（24 层）/2B/4B/9B（32 层）/27B（64 层）/35B-A3B（GDN:attn 3:1）；Granite4.0-1B 与 Granite4.0-7B（Mamba-2，40 层中 4 层注意力；7B 为 MoE，约 1B 激活）。
   - 任务：8 对单 token 字典（键 22 词、值 20 个颜色/材料词）+ 问题，chat 模板，助手前缀预填使答案为下一 token；三种格式 chat8 / list8 / rev8（值在前），各 100 题；全词表 top-1 准确率，四模型 chat8 ≥0.99。
   - 干预：截断到层 L（归一化准确率，chance=1/8）；块移除（mixer 输出置零，保留 MLP）；final-position 块输出移植（100 对）；递归状态移植（前缀算到倒数第二 token）；读者头的 query/key 分别用"去掉 G4"重算；ridge 线性映射做跨模型移植与块替换。
7. **证据强度与短板**：
   - 关键数字（Qwen3.5-9B）：检索在保留 softmax 层 L19 时突然出现（归一化 0→0.67），保留 24/32 层即有 0.94 的检索、0.47 的知识。移除最早块 G0 → 准确率 0.01（只移除第一层 0.05）；G0 可用逐 token 线性投影替代（检索 1.00，但 PPL 10.6→44.7），输入嵌入 patch 即可恢复（1.00）→ Encode 只保留 token 身份。移除 G4 → 准确率仍 1.00 但 logit gap 23.8→11.6、读者注意力 0.83→0.06（后续读者 L23/L27 补偿；0.8B 中移除降到 0.13，Granite-1B 降到 0.00）。移植 G4 final-position 输出 → 0.99 回答供体问题（list8 0.97、rev8 0.98），其他块 0.00；移植 G4 递归状态 → 0.99；G0/G3 状态 0.00。读者 selectivity：去 G4 的 query 5.45→1.36（top-1 约一半），去 G4 的 key 4.80（top-1 1.00）→ Address 决定 query 不决定 key。跨架构：Qwen-0.8B→Granite-1B 输出移植 0.98，块替换 0.92（线性投影 0.24、零 mixer 0.28）；Qwen-9B→Granite-7B 两个 Address 块 0.99 / 替换 0.94；反向 0.83 / 0.46。缩放：27B 与 35B-A3B 无单块可重定向，联合移植 0.98 / 0.75。
   - 作者承认/可见局限：单一字典检索任务；无种子与 CI 报告；"Address 块"由块边界定义（块 = 连续线性层），单层移植无效。
   - 我的评价：8 对、单 token、模板化，难度低；只测"问哪个键"，不测键→值绑定如何形成；结论与 2609.33093 的"递归替换恢复 <4%"并不矛盾——后者换的是 pre-query 状态里的值信息，这里换的是含有被问键信息的状态。
8. **可迁移的研究动作**：(a) 区分"检索目标（query）"与"被检索内容（key/value）"的通道；(b) 读者头 query/key 分别重算以定位影响点；(c) 用线性对齐图做跨架构块移植检验"计算是否通用"。
9. **对我们（候选 1）**：
   - 含义：在 Qwen3.5 与 Granite-4.0-H 中，绑定的"值"在 KV、"问谁"在递归块状态。候选若在 hybrid 上找 binding ID，需要预期 ID 若存在会出现在**注意力的 key（实体/属性 token 上）与递归层构造的 query** 之间，而不是在递归状态里作为"外积键值表"。
   - **没有做**：多实体–多属性绑定；位置无关 binding ID 的加性检验；覆盖/重绑定；纯 SSM；Falcon-H1（并行 hybrid）。
   - 资产：代码 github.com/yuang-chen/LinearQuery；Granite-4.0-H 公开 checkpoint：350m、1b、micro、tiny、small（各有 base，HF 已核对）。
