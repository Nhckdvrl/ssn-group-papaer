# Beyond State Capacity: Why Retrieval Breaks in Mamba（arXiv 2610.19709，Yarden, Ben-Artzy, Schwartz，Hebrew Univ.，预印本 2026-10-14，未见评审）`[证据级别：全文]`

1. 论文形态：失败模式 + 机制定位（信息流诊断）
2. 背景与压力：Mamba 在 in-context retrieval 上落后 Transformer，通常归因于固定大小状态装不下（Jelassi 2024、Waleffe 2024、Arora 2024）。但 query 放在 context 前面（query-first）时容量不该是瓶颈，Waleffe 2024 已显示 Mamba 仍落后，缺一个机制解释。
3. 改变的前提：瓶颈不只是容量，而是"写入时门控还不知道这个 token 相关"。选择门 Δt 只由当前 token 表征算出，相关性信号要经过很多层才混入 token 表征，到那时关键的状态写入已经发生。
4. idea 来源：RECONSTRUCTED（从 Waleffe 的 query-first 失败出发，用"加一个局部 relevance flag"的受控对照定位）。
5. 与最近邻的距离：Arora JRT 2407.05483（顺序影响记忆选择，靠重复/非因果缓解）——本文给出 query-first 下的门控机制；Arora 2505.15105（SSM 机制评估）；Lee 2609.33093 / Afendulev 2609.04434（线性注意力记忆）。增量类型：换证据类型（门控 + 状态探针 + 门 patching），不是新方法。
6. 方法 / 实验：合成 query-first phonebook（20–200 条目），带/不带 "target" 旗标两个变体。模型：Nvidia Mamba-2 8B（base）、Codestral-Mamba 7.3B（instruct），只有两个。逐层线性探针探"目标信息在状态里能否解码"（用 20 个职业的闭集）；Δ 门均值差（目标 vs 干扰）；门 patching（10 个 token 的门值把准确率拉到另一变体水平）；oracle 门放大 0.8–3×使准确率近 0 或近满。
7. 证据强度与短板：因果干预干净（门 patch），但只有 Mamba-2 两个模型，纯合成 key-value 检索；未涉及 RWKV/DeltaNet 等 delta-rule 型状态（门控机制不同）；未涉及"状态被改写"的任务。
8. 可迁移的研究动作：用"局部提示旗标 vs 无旗标"的最小差分对照定位写入时机；探针读状态 + patch 写入门，分开"写"与"读"。
9. 对我们：直接支持"循环模型的状态在读到 token 时就必须决定写什么"（写入时刻决策），这正是 eager/lazy 问题的循环侧前提；但它测的是"检索"而非"世界状态更新"。给出可用的工具：逐 token 状态快照 + 线性探针 + 门 patch。它说明 Mamba 的"eager"不是主动全局整合，而是由当前 token 局部表征驱动的选择性写入——若后面的 query 才决定哪个实体相关，Mamba 在没有局部线索时倾向写错或丢失。留下的压力：这是 Mamba-2 的结果，不能直接外推到 Gated DeltaNet / RWKV-7（有显式 erase/overwrite）。
