# Unable to Forget: Proactive Interference Reveals Working Memory Limits in LLMs Beyond Context Length（ICML 2025 Workshop on Long Context Foundation Models，workshop，分数 —）`[证据级别：全文]`

arXiv 2506.08184 v3（2025-07-31，abs 页已核对）；Chupei Wang（UVA）, Jiaqiu Vince Sun（NYU）。代码数据：github.com/zhuangziGiantfish/Unable-to-Forget。2026-11-25 读正文 §1–9 与附录（模型版本表、Fig. 15–20）。

1. 论文形态：benchmark / 构念引入 + 测量（认知心理学 PI 范式移植），无机制分析。
2. 背景与压力：长上下文评测（NIAH、Michelangelo、MRCR）把“搜索难度”与“干扰”混在一起，难度主要靠拉长输入。
3. 改变的前提：目标位置固定为“每个 key 的最后一次赋值”，搜索难度最小，只操纵同 key 旧值的数量（干扰负载）。
4. idea 来源（DOCUMENTED）：A-B, A-C, A-D 配对联想 PI 范式；Oberauer & Vockenberg 2009（人类会主动 unbind 旧绑定，PI 曲线到平台）。
5. 与最近邻的距离：Lost in the Middle（位置）→ 本文固定相对位置、操纵同 key 旧值数；MRCR / Michelangelo（长度）→ 本文用固定长度对照把干扰与长度分开。后续：Chattaraj & Raj 2603.00270（加 RI 条件）、Guo et al. 2609.38866（stale binding 机制）、SleepGate 2603.14517（方法）。
6. 方法 / 实验 / 数据：
   - **任务**：46 个类别 key（visual art、tools…），每类 400 个词作为值；更新流随机交错、同 key 不相邻；最后问所有被追踪 key 的当前值，生成式回答，正则抽取。
   - **操纵**：(1) 每 key 更新次数 3→400（46 key 固定）；(2) 被更新 key 数 U=1→46（每 key 125 或 350 次）；(3) 固定长度下被追踪 key 数 T=1→46；(4) 值长度（多个词拼接，1→40 词，更新次数 20）；(5) 顺序模式（同 key 更新成块）vs 随机模式；(6) 干预提示：per-key forget、forward focus、relevance meta-prompt、soft session reset、mock-QA reset。
   - **模型**：35 个左右，0.6B（Qwen3-0.6B）到 DeepSeek-V3/R1、GPT-4o/4.1 系列、Claude-3.5、Gemini、Grok-3、Llama-3.1/3.2/4、Qwen2.5/3、Mistral-small、Nemotron；**全部是 Transformer（含 MoE），没有任何 SSM / 线性注意力 / hybrid**。API 推理，截止 2025-05-05。
   - 指标：每 key 正确率；IES = 准确率对 log 更新次数的 AUC；bootstrap 95% CI。
7. 关键数字：
   - 所有模型随更新次数近似 log-linear 下降；M 组（50–150B）在 400 次更新时几乎全部 0%，L 组仍较高；XS 组下降最快。
   - IES 回归：参数量级别显著（t=3.03, p=0.005, N=30），上下文窗口长度不显著（t=−0.144, p=0.886），R²=0.261；128k–131k 窗口子集内 Spearman ρ=0.673（p=0.0016）。MoE 不如同总参数 dense。
   - 固定长度实验（T 变化）与变长实验曲线几乎相同 → 干扰而非长度；Llama-4-Maverick 追踪 2 key 近 100%，46 key <5%。
   - 值长度 1→10 词使所有模型 <40%，40 词 <5%。
   - 顺序模式：两平台阶跃（阈值前近满分，阈值后近 0）。
   - 错误分布三阶段：低干扰时错误集中在紧邻最终值之前的旧值；中等时分散到更早旧值并出现少量幻觉；高干扰时大量幻觉，同时保留对最早几次更新的 **primacy 偏好**。
   - 自然语言 forget/focus 提示改进 <10 个百分点，per-key forget 反而使错误聚集在提示注入位置；只有伪造对话轮次的 mock-QA reset 明显改善（Gemini-2.0-Flash 在 150 次更新时达到基线 30–45 次的水平）。CoT 不改善（4 对中 3 对持平或更差）。
8. 作者承认的局限：prompt 措辞影响绝对准确率（只强调相对趋势）；推理模型因延迟被排除在回归之外；闭源模型参数量不确定；mock-QA reset 是 hack，不是可用方案。
9. 对“架构 × 覆写”方向关键的“没做的事”：
   - **没有任何递归 / SSM / delta-rule 模型**；作者在讨论里把限制归因为“transformer-based architectures”的固有性质，但没有对照。
   - 最小更新次数是 3（且 46 个 key 同时更新），没有 k=1/3/5、少变量的低负载区；前沿模型在这一区间基本满分。
   - 没有“原值是什么”（RI）查询；没有未被更新的旁观变量损伤读数；没有 logit 级或内部分析。
   - 旧值互不相同；没有“同一旧值重复 k 次”的条件。
10. 证据强度与短板：模型覆盖广、曲线稳健；但纯行为、API、单一模板族，因果解释（“工作记忆容量”）是类比。
11. 可迁移的研究动作：固定目标相对位置、只操纵同 key 旧值数；用“固定长度、变追踪数”对照把干扰与长度分开；按错误来源位置分箱看错误分布的相变。
12. 对我们：探针 A 的“覆写后问当前值”在 Transformer 上已被大规模测量（下降 + 错误来自旧值）；架构对照是空白。可直接复用其词典与 IES 读数，但低负载区（k≤5）需要小模型或更多 key 才不会顶到天花板。
