# Do Language Models Track Entities Across State Changes?（ICML 2026 Main，分数未核对）`[证据级别：全文]`

arXiv 2605.30233（2026-05-28）；Zilu Tang*, Qiao Zhao*, Gabriel Franco, Derry Wijaya, Aaron Mueller, Sebastian Schuster（Boston University / Monash / Vienna）。代码数据在 GitHub（文中给出）。2026-11-25 读主文与附录 A–I 的主要部分。

1. 论文形态：机制发现 + 由机制预测的新失败模式 + 干预修复。
2. 背景与压力：binding 机制研究都不含状态变化；玩具模型（Merrill 2024、Li et al. 2025）研究“极限”下的状态追踪，不是自然语言、非玩具模型。
3. 改变的前提：问“模型是否增量地构建世界状态”。H1：从左到右增量构建全局状态（最后 token 应能解码所有 box 的状态）；H2：只在查询出现时并行汇集与被问 box 相关的信息。H3/H4：层间是否按操作顺序逐步处理。
4. idea 来源（DOCUMENTED）：Kim & Schuster 2023 boxes 数据集的行为结果 + Prakash 2024/2025 的回路与 lookback。
5. 与最近邻的距离：Prakash 2024（静态 description 回路）；Li et al. 2025（玩具排列追踪，层间逐步聚合——本文结论相反，作者归因于实体在上下文中被显式提及）；Oh & Demberg 2026（2606.08644，单次 swap，结论一致：读出时解析）；Gur-Arieh 2025。增量：多操作（PUT/REMOVE/MOVE）、非玩具模型、预测失败模式。

6. 方法 / 实验 / 数据：
   - **模型**：Gemma-2-2B、CodeLlama-13B（主结果）、Llama-3.1-70B（多操作分析），全部 Transformer，0-shot completion。
   - **数据**：7 个 box、100 种物体；DESCRIPTION 后接 PUT / REMOVE / MOVE 序列，查询“Box 1 contains the”。
   - **探针**：最后 token “the” 的残差流，逐层训练 100 个全局 8 分类探针（每物体在哪个 box 或不存在）、100 个局部二分类探针（物体是否在被问 box）、mention 探针；报告只计被提及物体的 non-trivial accuracy。先前状态探针检验层间顺序处理。
   - **回路**：路径 patching 得 A–D 四组头（沿 Prakash 2024 命名），比较 DESCRIPTION 与 PUT 回路的重叠（overlap coefficient）与 leave-one-out 功能相似性；DCM 子空间 patching。
   - **REMOVE**：logit/rank 差分析；700 个（物体, box）三分类探针 {不存在, 存在, 已移除}；用 INLP 式零空间投影逐层抹除“remove tag / exist tag”并 roll out。
   - **预测的失败模式**：No-op Remove、多 box 共享同名物体、移除后重新引入；各 300 句，贪心解码，报告 recall、precision、退化率 DR，以及最佳单层干预成功率 IS。

7. 关键数字：
   - CodeLlama-13B：全局探针 non-trivial accuracy 始终 <0.3（机会≈0.12），局部探针≈0.9（机会≈0.5），mention 探针高 → 支持 H2（不构建全局状态）；先前状态与最终状态在同一批层出现 → 支持 H4（层间并行而非顺序）。
   - PUT 与 DESCRIPTION 回路：A、B 组头重叠不小，C、D 组几乎不重叠，但 D 组功能可互换（LOO 最高）。
   - REMOVE 通过对**物体 token** 上的全局 remove tag 间接抑制（box ID token 上的 tag 不起因果作用），即使 REMOVE 针对的是别的 box 也会抑制该物体。box-ID 上的 tag 信号随操作数线性衰减。
   - 失败模式（表 1，recall/precision/DR/IS）：No-op Remove 13B 0.50/0.61/0.84/0.66，70B 0.60/0.63/0.49/0.59；共享标签 13B DR 0.56、70B 0.27；重新引入 13B DR 0.62、70B 0.01。
8. 作者承认的局限：REMOVE 的完整回路未找到（附录 H.14 负结果）；CodeLlama-13B 多操作行为准确率有限（选它是为算力和单操作表现）；没有回答“为什么偏好退化的全局机制”。
9. 对候选 1 关键的“没做的事”：
   - **只有 Transformer**。其核心结论“不增量构建状态、查询时并行汇集”依赖注意力可回看全部上下文；纯递归模型在查询前就必须把状态压进固定大小的记忆，H1 式增量更新几乎是被迫的。这是候选 1 最强的架构对照点，但未测。
   - 没有 binding ID 差向量干预，只有探针与零空间抹除。
   - 讨论中作者明确把“如何在架构约束下实现全局追踪”留作开放问题。
10. 证据强度与短板：探针 + 因果抹除 + 行为预测闭环，且机制预测被行为验证；但主模型行为偏弱，70B 只用于部分分析。
11. 可迁移的研究动作：用“全局探针 vs 局部探针”区分“已构建世界状态”与“查询时汇集”；从机制推出行为上的新失败测试（No-op Remove 等），再用干预部分修复。
12. 对我们：候选 1 的动态部分可以直接复用这套“全局/局部探针 + No-op Remove 类行为测试”。对 SSM，可预测的结果是“全局探针在最后 token 上更高”（被迫增量）；不可预测的是它用什么数据结构（每实体槽位、加性 ID、还是覆写式 key–value）实现，以及覆写是否也呈现 Transformer 那样的全局 tag 退化。
