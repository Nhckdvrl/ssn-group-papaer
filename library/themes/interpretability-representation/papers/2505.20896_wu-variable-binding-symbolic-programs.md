# How Do Transformers Learn Variable Binding in Symbolic Programs?（ICML 2025，分数未核对）`[证据级别：全文]`

arXiv 2505.20896；Yiwei Wu, Atticus Geiger, Raphaël Millière。交互平台 variablescope.org。2026-11-25 读全文（HTML 版）。

1. 论文形态：受控从头训练 + 发育轨迹 + 因果机制。
2. 背景与压力：经典架构用可寻址内存实现变量绑定；连接主义是否能学到系统性的变量绑定一直有争议；已有 LM 中 binding ID / 回路工作不研究**能力如何在训练中出现**。
3. 改变的前提：在完全受控的符号程序上从头训练，看变量解引用机制的出现轨迹。
4. idea 来源（DOCUMENTED）：Fodor/Pylyshyn vs Smolensky 的变量绑定之争 + 残差流作为“可寻址内存”的观点。
5. 与最近邻的距离：Davies et al. 2023 / Prakash 2024（掩码找绑定回路）；Feng & Steinhardt 2024（binding ID）；Dai 2024。增量：换设定（多跳变量链 + 干扰链）+ 发育视角。

6. 方法 / 实验 / 数据：
   - **模型**：GPT-2 式 Transformer，37.8M 参数，12 层、每层 8 头、head dim 64、d=512，pre-LN、RoPE、GELU、dropout 0.1，不共享输入输出嵌入。仅此一个架构、一次训练（未见多种子）。
   - **数据**：50 万个 17 行程序（45 万训练 / 1,000 验证 / 4.9 万测试）；每行 4 token “var = const|var \n”，变量 a–z、常数 0–9；30% 右侧为常数、70% 引用已定义变量；按链长立方加权采样以造长干扰链；查询行“#var:”；解引用深度 1–4 均衡。文中没有提到同一变量被重复赋值（覆写），未核对生成代码是否允许。
   - **干预**：根常数替换的 interchange intervention，(1) 所有层所有 token 的残差流，(2) 单个注意力头在特定 token 的输出；按“解引用深度”动态选择 RHS token 位置；度量为新数字成为 top-1 的比例与归一化 logit 差。
   - **子空间**：RHS token 残差 PCA 512→256，L1 逻辑回归选出常数子空间（10 个成分）与变量名子空间（26 个成分），只在子空间内做 interchange。

7. 关键数字：三阶段——0–800 步约 12%（只学会输出数字）；1,200–14,000 步跃到 56%（“第 1/2 行常数”启发式）；34,000–105,400 步跃到 99%，最终测试 >99.9%，各深度与答案位置均稳定。逐跳头：第一跳 6.5（及 7.7）、第二/三跳 7.2、8.3、9.4（8.3 两跳共用）、输出 11.2/11.3/11.7。子空间 interchange 成功率：常数 92.17%，变量名 87.08%。最终模型在答案位于第 1 行的程序上仍沿用早期启发式（层 2 冒号位置补丁成功率 >80%）。
8. 作者承认的局限：未设独立局限节；探针结果显示模型只追踪解引用所需信息，不维护完整程序状态。
9. 对候选 1 关键的“没做的事”：只有 Transformer；没有覆写/重赋值（“x=1 … x=9”）；只有单一小模型、单次训练；机制依赖注意力头跨位置路由，不适用于纯递归模型。
10. 证据强度与短板：干预效应清楚、平台可复查；单种子、单架构，发育轨迹的普遍性未知。
11. 可迁移的研究动作：在符号程序上把“变量名”与“值”分成两个子空间分别做 interchange；用发育轨迹区分启发式与系统机制（以及二者共存）。
12. 对我们：候选 1 的“x=1, y=2 / now x=9”正好是本文任务加上覆写；同一数据生成器加入重赋值、换成 Mamba/GDN 从头训练即可得到架构对照。但按组内规则（2026-11-24：不做自训练），这条只能作为参照，不能作为主证据。
