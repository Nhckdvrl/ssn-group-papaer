## A. 原文

找具体 Topic
找题第一步应该是大量泛读各式各样的最新的顶会论文（ICML，ICLR，NIPS，CVPR，ICCV，ACL，EMNLP，NAACL等等）从中可以了解近期趋势以及大家关心的方向和问题。（可以参考这个论文网站 https://papernotes.org/ 这里面把很多论文分了类，可以分门别类的看，并且很多都用 ai 生成了简要介绍，适合快速大量泛读，但不要完全依赖，因为论文可能不太全，ai总结也有局限性，信息不全面）
然后找具体方向的时候，不适合选择一个非常拥挤的，人人都在卷着做，arxiv上新论文层出不穷的 Topic，因为一方面论文太多，就有很多滥竽充数的低质量论文，另一方面会有很多有资源，人多的大组投身其中，我们没法和他们卷速度和质量。
因此我们一开始就应该选择一个相对热度偏中低，有探索空间的具体方向。
找具体方向，意味着我们自己要找有探索空间的方向，但并不意味着要找完全空白的研究空间，这不可能，因为现在ai领域太拥挤了，不可能找到完全空白的题目，所以不应该把寻找的目标定的特别特别高，硬要找到一个明显0人碰过的问题和空间，这样容易啥都找不到，也可能找到一个完全无人关心的，没有意义，不重要的问题。也不能找一个已经充分被解释，明显没有啥空间的领域（你可以参考hakaze cho的研究，他研究的从来不是一个完全没人碰过的问题，但他擅长寻找存在解释空白的空间，并通过深刻新颖的实验设计来探索，挖掘，最终得到更深刻的全新的解释，这个解释有时候不光针对这个未被充分解释的空间，反而能完整解释整个问题，比以往的解释更全面深刻，这真的很好）
然后就是要从具体方向收敛到研究问题，这里要注意一些尺度的问题，因为选定了中低热度的具体方向，只是圈定了一片"矿区"（例如：Agentic RL 中的信用分配、推理模型在特定表征上的演化）；接下来必须在这片方向里锚定一个具体的研究问题（Research Problem）——即一个具体的认知矛盾、主流方法的失灵现象、或未被拆解清楚的机制黑盒。
在研究范式上，科研通常分为 Method-driven（拿着锤子找钉子，比如某个新 RL 算法火了就拿去套各种垂域）和 Problem-driven（锚定一个重要问题或现象去突破）。
结合我们的导师偏好与硬件条件，我们最好以 Problem / Phenomenon-driven 为主轴，并在确立问题时严守三条红线，防止选出"过窄、平庸、无人关心"的烂题：
结合我们的研究目标（区分导师线与个人独立线）与硬件条件，我们最好以 Problem / Phenomenon-driven 为主轴，并在确立问题时严守三条红线，防止选出"过窄、平庸、无人关心"的烂题：

1. 价值与共鸣红线（防过窄/防自嗨）：这个问题不能是我们为了发论文生造出来的边角料，它必须挂钩领域内大家真正在乎的核心假设、主流范式或关键瓶颈（判断标准：如果把这个问题搞清楚了，同行会因此改变某个默认认知或做法吗？它本身是否足够让人兴奋？）。
2. 自然度与鲁棒性红线（防控制变量地狱 + 双轨模式切换）：通用底线是问题与实验验证必须简洁、真实、自然，绝不选需要强行拼凑四五个控制变量才能让现象显形的脆弱题目。在此基础上按轨道切换：
   * 若走【导师线】：严守导师品味，避开纯靠堆算力刷 Benchmark 分数的工程题，聚焦于"小切口、深机制、反直觉"的解释性或现象级真问题；
   * 若走【个人独立/实习线】：放开题材与范式限制，完全可以围绕我关心的 Agent / RL / 多模态方向，去做直击痛点的方法改进（如改进 GRPO 效率或信用分配），或是为尚未被评估的新方向（如游戏 NPC、全双工音频/视频 Agent）定义清楚问题并构建高质量的新 Benchmark。
3. 算力适配红线（契合单机多卡低通信）：不去碰需要多节点高速互联的大规模预训练或纯粹比拼 Scale 的问题；优先选择能充分发挥我们"单机卡多、适合高并发铺开独立实验"优势的问题（如机制解耦对照、中小规模 Post-training / Agentic RL 动态分析、多 Agent 交互仿真、表征探针与反事实干预）。

为了找到符合上述标准的研究问题，需要大量精读相关论文：先看综述建立全局观，再精读最新一期的顶会论文（ICML, ICLR, NeurIPS, CVPR, ICCV, ACL, EMNLP, NAACL 等，尤其优先看刚出的 NeurIPS 2026），最后有甄别地看强校强组的最新 arXiv 论文以把握前沿技术。
但要注意：绝不能把"读文献"和"找问题"分成两个阶段，只在读的时候被动理解。 在精读论文（了解背景、Idea、方法、实验、数据、Baseline）并推测其 Idea 来源、尺度及与 Related Work 距离的同时，你可以戴上以下**五个"捕题透镜"去主动挑刺和挖掘问题：

1. 批判性质疑透镜（鸡蛋里挑骨头）：边读边主动追问"如果这篇论文换个更自然的数据分布、去掉某个隐含假设、或者改变评测方式，它的结论还成立吗？"
2. Failure Case 透镜（从主流方案的失败中找机会）：思考和观察当前主流方案（如现有的 Agent 框架、GRPO 等后训练方法）在什么简单、自然的场景下会稳定失效？主动寻找、复现这些 Failure Case，深挖背后的共性瓶颈。
3. 机制反推透镜（Reverse-Engineering "为什么有效/真的有效吗"）：盯着那些效果很好但缺乏解释的方法，或者领域内习以为常的默认操作，追问"它内部到底在做什么？"。这种以确定现象为锚点去反推机制的问题（例如追问 RL 到底有没有激发超越 Base 模型本身的推理能力，或检验 ROME 的定位信号到底能不能指导编辑层选择），切入口极其明确，最容易做出导师喜欢的深刻发掘。
4. 文献矛盾透镜（矛盾与不一致驱动）：在阅读时高度敏感于"两篇论文设定相似，但得出了不同甚至相反的结论"。矛盾本身就是一个已经被"半定义"好的绝佳研究问题——为什么 A 和 B 不一致？是数据、评测还是某个隐藏变量导致的？我们只需要设计精准的对照实验去定位分歧根源。
5. 真实场景痛点倒推（从实践与实习中抽象）：结合我们在 Agent 构建或企业实习中遇到的真实卡点（而非假想的学术玩具），看哪些反复出现的工程痛点可以被干净地抽象、剥离为一个底层的研究问题。

所有通过上述透镜精读过的论文资产，都要仔细整理、分类维护成当前 Workbench 的知识库（明确标记出领域整体画像、已有共识、未解矛盾与潜在切口）。这不仅是找题阶段的地图，也是做题阶段本地 Agent 建立深度理解、跨领域检索迁移方法、防止实验跑偏的核心参照。
找到一个开放的，值得我们去深入，领域内关心，有意义的问题，探索空间，然后我们就可以通过复现baseline，或者铺开多个高信息量的精准实验（围绕想要探究的问题精心设计，可以web search寻找并设计各种新方法，新实验的思路）等等研究手段，然后通过观察分析结果，数据，进行探究，寻找线索，追加实验，追加分析，等等正式进入 Idea 的深度挖掘阶段。
挖掘 Topic idea
对于人

* 要想做研究还是得有足够的输入，大量的输入可以帮助建立起 taste，学习创新点，idea 来源，方法的来源，实验的设计...
* 这样一方面自己可以试着提出新的 idea，另外对于 ai 提出，挖掘到的 idea 也能进行有效的 review，有效降低做烂的概率。
* 输入的内容质量要高，比如 mika 推荐是看找最新三大会录用的 oral ，outstanding 论文，列大概 20 - 30 篇自己觉得有意思的论文，每个都写几个点；同时合作者给的题目和 idea 必须要先自己先调研，阅读论文，熟悉这个领域，了解常见方法和 baseline，从而理解合作者的核心 idea 是想做一个什么东西。

选好了探索空间，就像是有了一片矿场，我们还需要在这片区域继续深入挖掘。
本地 agent 绝对不能是个单纯的执行者，只会机械执行我们找题安排的种种挖掘实验，必须要深入阅读选题阶段创建的知识库并通过持续的 web search，去理解领域整体画像，最近工作关注重点以及各种实验设计和方法，不断加深对探索空间的理解，同时也可以跨领域可参考或迁移的类似观点，实验设计，知识，insight...
正式干活必须充分利用我们的资源。因为我们选题阶段就已经会思考一些探索实验，所以一般都是先写做好实验设计，写好代码，把初步探索实验给做了。
但是必须要注意，实验的设计和代码书写必须要保证一个原则，那就是高信息量和精确，实验要能准确反映我们的问题，并尽可能多暴露出足够的信息。
这样我们就可以通过铺开多个高信息量的精准的实验，获得很多可观测的结果和数据。然后通过分析，抓住线索，建立猜想，追加实验，验证猜想，追加分析....直到挖掘到一个好的idea。
同时在写代码的时候如果选题阶段思考的探索实验不够好，或者有更好的，更大的方式可以挖掘更多东西，那毫不犹豫自己来，不要机械执行，硬搬教条。
然后找idea的时候，不能随便挖掘到什么能 work 就行了，而是要认真衡量一个 idea 的好坏，一定要对齐相关顶会论文，他们 idea 的尺度，novelty，与 related work 的差距，是否有意义，是否 trivial ，有无 excitement 等等方面。尤其是如果我们挖掘出的东西缺乏意义的，或者脆弱，让人懂了后觉得 so what 那么也许不适合当成严肃的idea对待（这个观点比较主观，需要对齐顶会论文）一个好的 idea 有一个比较好的标准就是：证明出来以后，到底有多值得兴奋？ 应该是一个 interestingness / significance 的问题，而不是完全的 feasibility 的问题。 如果是找了一个一般的题目做出来，也有一定意义，但可能比较"理所当然"，并且大多数人可能都早就做过了，如果是自己现在把完整故事听清楚以后，也觉得结果出来不会特别兴奋，可能就没必要硬做。
一些关于好 idea 的想法

* 分析，发现类的 idea：
想要有比较好的发现还是比较难的，可以看到顶会的类似论文要么是加深了对某个问题的理解，要么是发现了什么反直觉现象颠覆了什么认知，并通过分析发现更深度的东西。我们实操的时候不能一上来假定自己能获得什么，但必须要正确评价我们获得了什么，并且从已经获得的东西中看看能否看到出更大更值钱的方向。
我当前关于 分析／可解释性论文的好 idea 有一定的归纳：它通常是一项新的认识，以及让这项认识能够被检验的切入点。
它可以表现为：解释一个重要现象背后的计算或学习过程，找到比现有指标更能反映问
题的测量方式，揭示一个被广泛使用的推断其实不成立，找到几种看似不同现象的共同结构，明确一个重要规律成立与失效的条件。这些不必同时具备，也不一定需要另做一个提高分数的方法。比如 NeurIPS 2026 的评价规范 (→ neurips.cc)明确承认加深理解的原创性，也说明有意义的负结果不必同时给出修复方案，但"某个实验没成功"本身不够 。 因此，如果我们只是发现某个 head／latent 有一个奇怪性质，通常只是线索；真正要继续问的是：它会改变我们对哪个重要问题的理解，现有解释为什么不够，以及怎样知道我们没有误读它。
* 方法类的 idea
方法类的相对简单好入手，搞一些 baseline 跑跑，分析分析，找找普遍性和局限性，多迭代几版方法，在 benchmark 上提点（注意不能过度工程兜底，必须依赖于实际的瓶颈和局限性孕育的改进思路），然后跑些分析和消融，就好写故事。
当然方法类也卷很多，大家都能提点，看谁的实验，谁的思路，谁的故事更好。

所以对于一个idea，可以分开问四层问题：
第一层，空间：这里究竟有什么重要的未知，现有文献为什么还没有解决？
第二层，线索：目前观察是否足够可信，并且存在值得做的下一步？
第三层，主张：现在究竟知道了什么，还有哪些解释同样符合结果？
第四层，贡献：如果最可靠的结论成立，同行会因此改变什么认识、测量或研究选择？
研究早期不必回答完第四层的全部证据问题，但也不能完全不考虑它。一个很实用的检查是：即使这个现象完全是真的，我们为什么要关心？如果答案只剩"以前没画过这张图"，就应警惕。
好 Idea 的 Taste 锚点：Solid、Significant、Novel，反直觉是非常有吸引力的加分项。
好 Idea 的核心是能够提供可靠、有意义、相对于已有文献确实新颖的贡献。反直觉发现尤其值得追求，但并非必要条件。解释重要现象、揭示机制、修正主流推断、建立更合适的测量方式、找到具有普遍意义的规律，或提出真正解决重要瓶颈的方法，都可能构成优秀贡献。不能在研究开始前强求反常，也不能因为一个结果符合直觉就直接否定其价值。
例如：

1. Attention Is All You Need：当时默认序列建模离不开 RNN/LSTM 或卷积，但它证明只靠 Attention 就能做得更好；
2. Grokking：当时默认训练集拟合而测试集不涨就是过拟合，继续训纯属浪费，但它发现泛化能力会在极晚阶段突然涌现；
3. Scaling Laws：当时学术界沉迷精巧的架构设计与 Task-specific 技巧，但它证明性能直接由规模决定，大力出奇迹优于复杂技巧。

这些工作在发表时都让人产生"原来还能这样？"的惊喜感。目前直接让 LLM / Agent 凭空读论文提 Idea，大概率提不出这种反直觉的想法——因为 LLM 的训练目标是与人类已有数据 Align（迎合共识），这导致它们仅靠论文摘要提出来的 Idea 大多是浅显、直接、套路化拼凑的，缺乏惊喜感。所以更有效的方式是让 LLM 深入理解领域、文献、代码和实验结果，参与批判、假设生成、竞争解释构建、实验设计与跨领域迁移。无论 Idea 来自人还是 AI，都必须通过文献和实验检验其价值。
从"研究问题"到"好 Idea"：
既然明白了高标准的 Idea 不能靠 LLM 读摘要瞎编，那么在实际推进中，我们该如何从选定的研究问题出发，真正长出有分量的 Idea？主要有以下三条路径（对应从现象挖掘到方案构造的不同切入方式）：
路径一：代码级复现与机制逆向工程（最易产生反直觉发现）
大多数反直觉的、Novel 的 Idea 都是在真实代码和实验中"撞"出来并深挖出来的，因为复现代码提供的信息密度远高于阅读润色后的论文（参考 PPO 论文叙事与真正让它 Work 的代码 Trick 之间的巨大鸿沟；注：对不开源代码的论文要保持警惕，可能存在造假或实际不 Work）。

* 吃透细节跑猜测：彻底吃透一到多篇核心论文后，围绕其边界条件提出猜测并跑实验，捕捉有意思的异常现象作为落脚点。基于真实观察到的现象去改进方法，大概率能顺理成章地涨点，完全不需要硬编故事会。
* 改代码变体 + LLM 逆向解释（Why it works）：让本地 Agent 先深度复现 Baseline 代码，基于真实代码逻辑揪出潜在漏洞、隐式假设或值得关注的模块，测试各种变体。一旦发现某个变体意外有效或出现反常，利用 LLM 强大的"逆向解释（Reverse-Engineering）"能力去辅助推导 Why it works。相比于从零空想 Idea，LLM 更擅长在给定反常实验结果后协助排查假设、反推底层机理。这种逆向解释的过程本质上就是最真实的科学探索。

路径二：第一性原理建模与跨界方法迁移
针对已经观察到的现象、瓶颈或领域一直存在的痛点，不要急着乱试和盲目缝合模块，而是结合以下四种破局思路深入思考：

1. 数学化与问题重构（开创型破局）：优先尝试从数学或第一性原理角度推导公式、抽象问题本质（就像 AlphaFold 重构蛋白质预测问题一样）。从数学角度出发提出的方法往往更本质，可解释性和逻辑性极强——即便最后实验不 Work，它也帮我们干净地从逻辑上证伪并排除了一个方向，依然能顺利往下推进，绝不会像"盲目缝合怪"那样一旦不涨点就彻底卡死、不知道下一步干嘛。
2. 内核同构迁移（迁移型破局）：通过广泛阅读与跨领域 Web Search，从其他成熟领域（如传统控制论、信息论、认知科学或其他 AI 子领域）借鉴问题内核相同的理论或技术，迁移过来解决当前 Agent / 后训练领域尚未解决的痛点（类似 ViT 将 Attention 从文本迁移到视觉）。
3. 机理互补融合（结合型破局）：思考能否将方法 A 和 B 做具有创新性的深度结合（类似 DQN 结合深度学习感知与强化学习决策）。注意这绝不是为了水论文而硬拼凑模块，而是必须明确 A 的机制瓶颈恰好能被 B 的核心特性所弥合。

关键保障：当探索实验不 Work 时的排错与转化闭环
即使实验不 Work，也不代表 Idea 本身完全不行，此时严禁直接放弃或盲目乱改参数，必须按以下逻辑链条在本子上（或与 AI 共同维护的排查文档中）逐层剥离：

1. 先查实验设计与实现：实验设置本身是否合理？代码实现是否有隐蔽 Bug？评测指标是否掩盖了真实变化？
2. 再查现象本质与切入角度：如果实验设计没问题，那说明我们对之前所依据的那个"现象"本质还没有完全吃透。此时应该退一步，先设计消融实验或诊断实验去搞清楚"这个现象到底是怎么产生的（Why）"——把所有可能的影响因素全部列在本子上，像侦探一样通过精准实验一点点排除变量。
3. 将"不 Work"转化为新认知：一旦把"为什么不 Work / 现象到底受谁控制"彻底理清，原本的失败就变成了高价值的垫脚石，新的改进方法或更深刻的分析视角往往就会在这个排除过程中自然浮现。

另外还有一点就是我总是让你时刻去读优秀论文，去学习优秀论文的idea的来源，他们的尺度等等，但其实根据 Steinhardt 的 Film Study for Research (→ jsteinhardt.stat.berkeley.edu)正面指出，论文很难展示真实思考和思路，学习研究过程需要寻找讨论、批评和过程材料。你可以参考下面这些例子：
Othello-GPT：Neel 在自己的过程复盘 (→ www.lesswrong.com)里记录了从注意力分析进展不大，转向具体反事实和神经元检查，再发现"己方／对方"可能比固定黑白颜色更合适，随后直接测试这个表征假设的过程；Grokking：他在作者访谈 (→ 这里值得学的是转折：一个具体观察改变了研究对象或测量方式，继而让更大的问题变得可研究 kiang。它们仍是作者整理过的自述，不是完整原始实验记录，我没有把论文的章节顺序冒充发现顺序。
还有一个特别好的例子：研究"证据能说明什么"，也能产生强 idea：ROME 把事实定位与知识编辑联系起来；后来的 Does Localization Inform Editing?（NeurIPS 2023） (→ research.google)专门检验：对于同一个事实，定位信号能否预测在哪一层编辑更有效。它发现，在所研究条件下，两者的对应关系远没有直觉上那么强。这里的贡献并非宣布 ROME 无效，而是拆开了几个容易混淆的问题：哪里参与原有计算、哪里能够被修改、哪里最适合修改。 这符合一种尺度，就是从具体结果出发，追到领域经常依赖的一座"推理桥梁"，再用精准实验检验这座桥是否成立。研究对象可以很具体，改变的认识却很重要。我们的idea要对齐。 此外，"反常"必须相对于相关文献中最强的已有认识，而不能只是相对于 agent 自己不知道的东西。持续阅读最重要的作用之一，就是不断修正这个参照系。
还有关于高信息量实验，不等于多跑配置、多存日志：例如，假设发现某个 latent 在错误答案上激活很高，这只是一个说明方法的虚构例子。它可能响应错误本身，也可能响应否定措辞、罕见答案、位置或格式。如果下一步只是换几个数据集继续画相关性，信息可能增加得很慢；更有价值的尝试是把正确性与措辞等因素分开变化，观察激活到底跟谁走。但也不能把所有探索都强制变成预先列好的 A/B 假设检验。有时我们根本还不知道该问什么，认真看样例、换一种表示、增加一个观测量，才是最有价值的实验。Freeman 的 How to do research (→ people.csail.mit.edu)就建议通过简化问题、让失败更明显来理解系统，而不只是报告它失败了。
对每个关键实验，你都必要思考好：为什么现在做它，哪些结果会改变判断，以及实际结果改变了什么。如果无论结果怎样，它都能写成支持同一个故事，那就没有真正更新认识。
理解文献中的问题、用实验获得新认识、判断这些认识是否值得继续投资。
具体而言：
初始探索实验是起点，发现更好的问题或观测方式时可以主动改
新异常、关键失败和准备宣称 novelty 时，要回到文献里重新核对
记录事实、解释和推测的区别，不能靠流畅叙述填补证据缺口
有希望的探索结果，随后用未参与挑选的证据或新的运行确认
多 GPU 用来并行真正独立的问题，关键串行实验还没回来时，不盲目铺开所有后续分支
允许结束一条坏线，也允许把失败转化为更重要的问题；沉没算力不构成继续理由
另外，强研究者也不是同一种取向：Neel/GDM 的实用路线 (→ 的基础科学愿景 (→ transformer-circuits.pub)更愿意从微观结构、好奇心和抽象中寻找长期价值。我们应借鉴它们各自的判断方法，而不是把某个团队的研究目标当成唯一标准 。
所以，最终评价进度，应该看它是否持续让重要问题变得更清楚，是否能识别并抓住有分量的知识增量，而不是它跑了多少实验、生成多少候选 idea，或者能否把每个结果包装成好消息。

## B. 主会话判断：对当前 MoE 线（division）哪些适配、哪些不适配（2026-11-09）

**直接适配、立即采用：**
- "推理桥梁"尺度（Does Localization Inform Editing）：我们这条线的正确定位就是检验 MoE 分析里一座被默认的桥——"路由统计 ⇒ 学到的专家分工 / 功能分层"。E178/E179 已检验了语言轴上的这座桥（层剖面来自几何，路由器只加常数倍）。下一步按此尺度找其余的桥（跨语路由对齐 ⇒ 跨语迁移；路由早饱和 ⇒ 分工固定；专家级解释 ⇒ 剪枝 / steering 有效）。
- 文献矛盾透镜：MoE 分析史里矛盾很多（Mixtral"不按主题"vs 领域专家；OLMoE"按 token id"vs 语义；Fan"路由器不分语言"vs Bandarkar 语言专家；"早饱和"vs"三阶段"）。每条矛盾都是半定义好的问题，派 lit 系统盘点。
- 机制反推透镜：盯住"效果好但缺解释"的方法——把跨语路由对齐当训练目标的 RA-MoE / SARA：它们起效是因为对齐了路由，还是因为对齐了表示（路由只是读数）？
- 四层问题（空间 / 线索 / 主张 / 贡献）与"即使现象是真的，我们为什么要关心"：对每张实验卡的判决表都要能回答第四层。E180 的两个分支都能回答（"语言专家 = 文字专家"会改写三篇论文的读法和两类方法的动机）。
- "无论结果如何都支持同一个故事的实验不做"：这正是 R5 + 预登记判决表的理由。
- 关键串行实验没回来前不铺开分支；沉没算力不构成继续理由（11-09 冻结训练平台即按此执行）。

**部分适配，需改写：**
- "找中低热度方向"：MoE 可解释性是中等热度且上升（2026 年一个月数篇），但"零模型 / 分析稳健性"这一切口确实人少（Melton 单作者预印本、Myth 只论证）。按"拥挤里的空白"（[[crowded-is-not-dead]]）而不是按热度选。
- "代码级复现路径一"：对我们不是复现训练代码，而是**复现已发表的分析读数**（Bandarkar、Chen、OLMoE §5.4、Antoine）并加对照——信息密度同样远高于读论文，E178/E179 已证明一天内可做。
- "算力红线：单机多卡铺独立实验"：适配，但当前线是推理为主，≤ 2 卡 / 实验；训练多个小 MoE 已被判为平台条件下的描述（DIRECTION §15）。

**不适配、不采用：**
- "个人独立 / 实习线"（Agent / RL / 多模态、GRPO、新 Benchmark）与"真实场景痛点倒推"透镜：不属于本 workbench；不混入。
- "方法类 idea：跑 baseline 提点"：导师线不做刷分方法；只有当机制结论自然指出一个方法时才做，且方法必须由测到的瓶颈孕育。
- "泛读 papernotes.org 建立趋势"：对已收敛到具体问题的本线不是当前步骤；保留给找新方向时。
- 反直觉举例（Attention/Grokking/Scaling）是尺度参照，不是对本线的要求：不预设反常，按 [[idea-value-checks]] 只报测到的。
