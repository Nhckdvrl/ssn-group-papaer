# L34 — Prospective Encoding

**Status:** **KILL — 2026-09-14; no E02 authorized**  
**Reason:** E01 suffered a first-stage construct failure, and the subsequent Selection audit found that the original relation-family manipulation plus `NEW - OLD` estimand does not uniquely identify prospective encoding.  
**Target was:** ACL / EMNLP / NAACL Main

> Does knowing *how a fact will later be accessed* selectively change how a language model encodes that fact when it is subsequently learned?

## Final decision

L34 is closed as a candidate. The E01 run does **not** reject the scientific hypothesis; it failed to instantiate the intended access-policy manipulation. But the candidate is still killed because repairing that manipulation is not enough: the experiment used different relations rather than two access functions over the same fact, and the large `NEW - OLD` interaction can be generated by an answer/readout prior whose effect is stronger on recently learned facts.

Therefore:

- do not run E02;
- do not escalate to 7B/8B;
- do not revive L34 by grounding PIT persons and rerunning;
- do not revive it by only adding the missing post-document/order-control arm;
- do not prompt-search, repartition attributes, or model-shop.

The broader PIT pressure is retained only as an **unregistered search seed**. Any successor must enter Selection as a new candidate with same-fact access functions, matched outputs, a demonstrated first-stage access construct, an update-level estimand, and a fresh owner audit. See `SELECTION.md`.

## E01 outcome

The preregistered G1 access-specialization gate failed:

- held-in `CROSSOVER_postP1(OLD) = -0.1554` [-0.1853, -0.1266];
- held-out `-0.0844` [-0.1136, -0.0552];
- both PIT arms made their own trained family worse;
- the disjoint city-pool control created the largest interference cell.

The final `PROSPECTIVE` interaction was numerically large (+0.4215 held-in; +0.8134 held-out) but is **void as evidence** because the construct gate failed. It is preserved only as a warning that a strong, paraphrase-robust three-way interaction can still be non-identifying.

Also note the correction in commit `ee7bfe2`: `NO_PIT` is not Jiang et al.'s PIT baseline. The parent comparison is about training order, with QA/instruction present on both sides.
