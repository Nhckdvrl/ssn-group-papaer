# 笹野组研究标准与本项目执行要求

2026-11-26。来源：此前用户要求对研究室多频道、不同学生、不同年份的导师反馈进行调查，结合本仓库研究流程和本次用户明确要求提炼。**以下是对实际反馈的中文转述与我们自己的操作化，不是导师发布的正式评分表，也不是导师已认可 LM Head 题目。** 仓库为公开仓库，因此不在这里新增内部 Slack 原文、私人学生讨论内容或内部链接；此前已有的内部出处可由有权限的人在内部追溯。本次不重新进行全量 Slack 调查。公开方法范例：[Tsukagoshi & Sasano, ACL 2025](https://aclanthology.org/2025.findings-acl.1330/)。

## 1. 导师到底在要求什么？

此前调查的关键区别不是“必须做解释性”“必须反直觉”或“必须创新算法”。导师看的是研究能否得到一个**值得知道且证据真正支持的结论**，或能否解决一个**真实且重要的已有问题**。研究领域可以宽，研究问题必须准；技术可以简单，贡献必须实在。以下 12 项是综合提炼。

| 标准 | 具体要求 | 应用于 LM Head |
|---|---|---|
| 1. 问题的意义先于方法 | 先说明什么答案值得知道、为什么；避免先选技术再找理由 | 不因为 LM Head 是线性层就做所有消融。说明测量如何区分几何限制、功能变化和学习问题 |
| 2. 不能仅是尝试 | 改 prompt、改模型、调参数并报告分数，不自动构成研究 | E01 不能只有模块 norm/SVD；需功能读数。E02 不能仅报告 V≫d 的投影损失 |
| 3. 实质性新颖性 | 有相近工作不必马上放弃；要能指出未解决的困难及具体新增知识/方法。差异太小可及时止损 | 核心两篇已发现/质疑梯度瓶颈，不能把它们重新做一遍当论文；首轮是工具和发现阶段 |
| 4. 非自明、但不强求反直觉 | 至少应有值得研究者注意的结果；常识可预测的方向需进一步找量级、边界、解释或实践价值 | CE 与 RL 单 token 共线是校验，不是发现。前向限制不等于反向危害；不要预设冻结一定坏 |
| 5. 结果要有可解释意义 | 分析研究不同结果均应能更新理解；方法研究可以如预期改善，但必须针对真实问题 | E01/E02 决策表允许 null；不要求正负两边都能写论文。若出现具体瓶颈，允许提出简单修复 |
| 6. 可靠性与控制 | 结果不能主要由提示、数据设置、seed、采样、模型家族、精度或指标任意性决定 | 同 token 输入、真实模型谱系、dtype/softmax、mask、rollout replay、组内权重、有效训练样本要固定或记录；题目级配对 CI |
| 7. 指标有含义 | 解释读数为何支持结论、多少变化才有意义；不以自定阈值代替论证 | ρ 是投影能量，γ 是增益，不是“有害信息比例”；权重稀疏率不是优化因果；有效秩结合噪声与功能 |
| 8. 有深度而非只跑更多 | 找到现象后追查必要条件、具体来源、边界、竞争解释；有价值时才做机制干预 | 从真实 E01/E02 异常定位 token/层/阶段或奖励抵消；按信号决定 E03，不直接堆全面网格 |
| 9. 简单方法可以是强贡献 | 如果极简操作揭示有意义的性质或保留性能并降低成本，实际价值可能很高 | 如果少量 head 自由度能稳定恢复实际训练损失，简单方法可成立；但必须有公平 baseline 与真实成本 |
| 10. 已知问题上的方法改进完全允许 | 问题已明确、针对性方法能解决、效果可靠，就有研究价值；不必刻意找反常结果 | 不局限 Understanding AI；观察到真实瓶颈后可以 Improving AI，不能只以比弱基线好来证明贡献 |
| 11. RQ 与 finding 一一对应、主线简洁 | 结果再多也不等于贡献更大；引言需要让人既觉得合理又感兴趣 | 每个重要图对应明确问题；不为凑实验或主张数加新轴；论文形态从数据长出 |
| 12. 区分探索/修士/主会证据要求 | 初步 pilot 可帮助找方向；论文级主张要可靠、可泛化、定位清晰。导师并非只允许一种 NLP 研究形态 | E01/E02 首轮不需要论文级原创性或所有近邻查完；主会主张按仓库 L0–L5 与人审推进，不擅自承诺录用 |

此前调查还显示：导师认可模型输出相似而内部处理不同的研究，认可简单降维保留性能的实际意义，重视 prompt/数据条件改变后结果是否稳健，也明确区分技术比较与真正的科学结论；这些是研究审美线索，而非要求每个项目都做内部机制。发现类、方法类、评价类都可以是好研究。不要推断导师排斥 RL、Agent 或多模态；相关领域的接受度须就具体问题判断。

## 2. 两种平等的研究形态

Discovery-first：已知研究中存在一个值得回答的未知问题；观察结果具有新认识；用可靠测量、控制与必要干预支撑。例：输出头改动在权重空间很小但功能空间表现出某种稳定差异，且普通解释不够（尚未观察）。

Problem-first：已有明确病灶；强现有方法仍有不足；最小改动有可靠收益，并能说明成本、适用边界及为何值得采用。例：冻结头确实造成实际学习问题后，再尝试极低成本的解锁/干预（尚未观察）。

不要把 Discovery-first 理解为必须制造悖论，也不要把 Problem-first 理解为任意增加模块再报提升。塚越范式的真正价值是简单操作下的任务差异与明确实践意义；问题驱动的方法改进同样符合导师以往的判断。

## 3. 本项目的八条正式晋级门槛（我们的操作化，不是导师原文）

1. 与最强近邻有实质不同的问题、知识或方法增量。
2. 能一句话说清研究成功后会改变什么理解、预测或技术选择。
3. 不以数学同义反复、信息上限不同或定义必然结果作为发现。
4. 实验能够区分主要竞争解释，而不只是画相关性图。
5. 在单节点资源约束内可复现，不依赖不可得数据/大量人标/复杂系统。
6. 指标真正对应研究对象（能力、学习、真实计算开销等）。
7. 有明确的适用范围、反证/停止条件和不确定性。
8. 研究纵深自然来自观察与问题，而非堆叠模块或事后拼故事。

**只在从 pilot 向正式主张、论文形态及候选项目晋级时执行完整门槛。** 首轮实验无需事前证明全部八条；这是用户反复强调的核心纠偏。探索阶段要有清晰的比较和工具校验，但不要求每一项就是一篇独立论文。

## 4. E01/E02 的最低质量线：能开跑，不是纸面阻碍

| 执行前 | 运行后 |
|---|---|
| 写清楚本次问题与哪种结果会改变下一步 | 先报告真实数字、样本数、波动、失败与不确定 |
| 核对两篇核心论文、固定模型/数据和实际梯度定义 | 解释这批读数能支持什么，不能支持什么 |
| 合成工具阳性对照、小样本真实模型复算 | 看是否超出数值/重复噪声，不能把定义当发现 |
| 先单卡 smoke，记录算力与版本 | 有信号再选择最小复核或干预；无信号也保留结果 |
| 不自动扩展到 E03、多个模型、代码/数学/语言全任务 | 按真实结果补查直接近邻，更新 CLAIMS/PAIN_LOG 与人审 |

具体技术口径见 [RESEARCH_PLAN.md](RESEARCH_PLAN.md)。E01 原生坐标下的 head 反事实不能直接定位知识存储；E02 聚合 logit 梯度不是参数梯度；E03 冻结与否不能直接区分前向和反向。若读数显示真正的训练问题，再考虑独立干预与方法。没有数据前不制造机制故事。

## 5. 汇报与自查（每次有新数据时）

用一页或短报告回答：

- 本次研究问题是什么？为什么值得问？实际用了哪些模型、样本、对照和多少算力？
- 最重要的实测数字、误差范围、正负结果及失败样本是什么？
- 与已知结果相比，究竟多知道了什么？是否只是公式直接推出、输入不同、尺度不同、保存精度或评价协议导致？
- 哪个替代解释尚未排除？哪一个最便宜的实验能够区分它？如果结果反转，下一步是否会变？
- 是否存在真实实用意义？如果暂时没有，能否诚实地作为探索性观察保留？
- 需要用户决定的是什么：继续最小复核、根据数据调整方向、还是停下评估；不要自行更改工作台状态。

正式汇报前逐条对照 12 项，而非按平均分掩盖关键缺陷。一句 RQ 对应一句 finding；结论措辞必须匹配实际证据等级。负结果不是必须淘汰整个空间的理由，工具不可靠也不是现象不存在的证明。人审依仓库规范执行。

## 6. 用户本次明确的研究策略（优先于机械流程）

此前经历了两种极端：没有明确问题就铺大量实验；以及在纸面反复讨论所有可能性、因可能撞车而拒绝开始实验。用户明确要求两者之间的平衡：**先选择有意义且可行的研究空间，设计少量有信息量的探针，然后从数据挖掘具体科学问题。** E01/E02 已达成开始探索的共识。不得继续以重复查重、理论辩论、填卡数量、等待 100% 新颖性保证阻塞运行；也不得为了证明方向有价值而只报告漂亮图表。深挖由真实结果触发。
