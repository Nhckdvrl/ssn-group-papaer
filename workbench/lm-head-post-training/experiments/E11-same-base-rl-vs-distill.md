# E11：同一底座上，纯 RL 与蒸馏给 Base 加的是不是同一种东西？（2026-11-28）
- **状态：** RUNNING
- **类型：** PILOT / 对比轴（监督来源）
- **对应：** I05；接 E07（选择效应随难度切换，Qwen 蒸馏）、E08（前缀可继承）、E09（OLMo RL-Zero 开头之后无差距）
- **问题（一句话）：** 在同一个 Qwen3-8B-Base 上，纯 RL（DAPO，无 SFT）带来的增益，和强到弱蒸馏（官方 Qwen3-8B）带来的增益，在“开头模式 / 去随机化 / Base 不会做的选择”以及“能否被 Base 继承”上是否相同？
- **为什么重要：** E07–E09 的两个家族恰好用了两种后训练（Qwen 蒸馏、OLMo RLVR），底座与监督来源混在一起。“RL 只是锐化”与“RL 提供新决策”的争论是关于 RL 的；蒸馏从更强教师那里带来新决策是意料之中。同底座对照能把两者分开。Tandem RLVR（2606.28166）报告普通 GRPO 模型与原模型交替推理时会掉点，预测 RL 的推理比蒸馏更难被 Base 接续；Qwen3 技术报告表 21 报告在 8B 上在线蒸馏优于 RL。
- **模型：** Qwen3-8B-Base；Qwen3-8B（蒸馏，已有 E07/E08 全部读数）；caiyuchen/DAPO-step-27（Qwen3-8B-Base 在 DAPO-Math-17k 上的 DAPO 最后存档，与 2510.00553 同一作者，模型卡写明 base_model 为 Qwen3-8B-Base）。所有提示一律用 Qwen3-8B 的 `qwen_chat` 模板渲染（`--render_tok qwen3-8b`），保证与已有锚点逐字相同。
- **设置（与 E07–E08 完全相同的口径）：** T=0.6/top-p 0.95；总生成上限 8192；题集 MATH Level 5（同 300 题）、AIME 2022–2025（120 题）、MATH-500 Level 1–3（238 题，易题）。
  1. 锚点：DAPO 采样每题 8 样本；看其开头是否有固定 cue（若有，加强制开头对照）。
  2. 选择效应：B2_DAPO = Base 在高熵位置取 DAPO 首选（两模型同步解码），与已有 B1 配对；`math_l5` 与 `m500e`。
  3. 交接：DAPO 前缀 → Base / DAPO；Base 前缀 → DAPO（L = 32、256、50%，每题 2 个前缀）。
  4. pass@k 与等算力投票（复用锚点）。
- **读数：** 与 E07/E08 中蒸馏模型的同名读数并列：参照差距、去随机化、选择效应、同前缀续写差 G(s)、pass@8 覆盖、按结果分组的长度。
- **阳性对照：** 同模型重新续写与锚点一致；同步解码工具与 B1 的 vLLM 实现已在 E07/E08 验证。
- **噪声地板：** 同 E07/E08（`math_l5` 单条件 CI 约 ±5 点）。
- **混杂审计：** DAPO 的训练数据（DAPO-Math-17k）与评测题的重叠（MATH 测试集不在其中，AIME 2022–2023 是否在其中需核对）；DAPO 训练时的提示格式与我们的模板可能不同（若 P0 明显低于该模型报告的水平，先排查模板）；DAPO 与蒸馏模型的增益大小不同，比较各读数时同时看“占参照差距的比例”。
- **决策表（跑之前写）：**
  - DAPO 在难题上也有显著的选择效应、易题上 B1 就接近 DAPO，且其前缀同样能被 Base 继承 → E07/E08 的形态是后训练的一般性质，不只是蒸馏；论文可写成“后训练在什么条件下提供新选择”，监督来源作为稳健性维度。
  - DAPO 在难题上的增益主要由去随机化取得（B1 接近 DAPO，选择效应小），而蒸馏需要新选择 → 监督来源决定后训练给的是锐化还是新决策，同底座的这一对比本身就是核心结果（直接回应“RL 是否只是锐化”的争论，并解释为什么带蒸馏或教师信号的模型看起来像“新决策”）。
  - DAPO 的前缀比蒸馏的前缀更难被 Base 继承（G(s_DAPO) 在 50% 时仍明显为正）→ 与 Tandem RLVR 的“沟通代价”一致：RL 的推理更难被 Base 接续，这是 RL 与蒸馏的一个功能差别。
  - DAPO 的总增益很小（P0 − B0 < 5 点）→ 该存档不适合，换更强的 RL 模型或检查模板。

- **开头 cue 对照（看到 DAPO 锚点后加，POST-HOC 设计）：** DAPO 的回答 52% 以 “Alright, I have this …” 开头（另有 13% 先写 “Assistant: Alright”），与 2610.24663 在 Qwen3-4B GRPO 上看到的 “Alright” 相同。加 Base + 强制 “Alright, I have this problem” 开头的锚点（每题 8 样本，上限 4096），用于在开头之后比较 DAPO 与 Base。
- **交接实验（锚点之后加，跑之前写）：** 2510.00553（ICLR'26，与 DAPO 存档同一作者）报告：RL 模型写的前 20 个 token 交给 Base 续写即接近完整 RL 的表现；RL 主要改变开头（“Alright”“Let”）和转折处（“But”“Wait”）的少数 token；与蒸馏、SFT 不同，RL 几乎不改变 Base 对 RL 推理链的困惑度。由此得到一个可检验的同底座预测：DAPO 的短前缀（L=32）就能让 Base 接近 DAPO，而蒸馏模型需要约一半（E08：L=32 只补 39%）。
  - 题集：OlympiadBench 300 题（主，干净）与 MATH Level 5 中 DAPO 没见过的 143 题。
  - 组合（每题 2 个前缀，每个续写 1 次，L = 32、256、50%，总上限 8192）：DAPO 前缀 → Base / DAPO；Base 前缀 → DAPO；在 OlympiadBench 上同时补蒸馏的 Post 前缀 → Base / Post 与 Base 前缀 → Base，使两种后训练在同一题集上可比。另以“Base + 强制 ‘Alright, I have this problem’”作为开头 cue 的对照。
  - 决策：DAPO 前缀在 L=32 时 G(s_DAPO) ≈ 0（Base 续写≈DAPO 续写）且明显超过强制 “Alright” 的 Base，而蒸馏模型在 L=32 时 G 仍大 → RL 的优势集中在开头少数 token 建立的状态上，蒸馏的优势在更长的推理过程中逐步建立；两者对“锐化还是新决策”给出不同答案。若 DAPO 在 L=32 也需要 Post 续写才能达到 → 与 2510.00553 不一致，记录差异（模板、预算、题集）。
