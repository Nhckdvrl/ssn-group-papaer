# E08：后训练模型的优势能否交给 Base 继承？（前缀交接，2026-11-27）
- **状态：** RUNNING（第一阶段：Qwen `math_l5`、AIME 完成，OLMo 运行中）
- **类型：** PILOT / 机制检验（单模型 vLLM 为主）
- **对应：** I05；接 E05（单分叉价值）、E07（选择效应的条件）
- **问题（一句话）：** 由一个模型写出前 L 个 token、交给另一个模型续写时，答对率取决于谁写了前缀、还是谁在续写？Post 写的前缀能否被 Base 继承，Base 写的前缀能否被 Post 挽救，这在易题、难题和两个家族上是否不同？
- **动机：** E05 中单个分叉上换哪个候选几乎不影响结果，换谁续写影响大（0.73 vs 0.64）；E07 中难题上 Base 只在高熵分叉处取 Post 首选（约 41 处）就接近 Post。近作已经报告短开头（2610.06851：OLMo 开头 cue、两 token 交换）、前段替换（Shen et al. 的 early-only）、稀疏替换（2610.24663）能恢复多少增益，但没有在同一组题上同时测：多个前缀长度、两个方向、同一前缀上两个模型的续写能力差，以及它与 B2（分散分叉）的比较。
- **设置：**
  - 模型对：Qwen3-8B-Base → Qwen3-8B；OLMo-3 Base → RL-Zero-Math（Base 一律强制开头 “.\n\nOkay, let's”，即 2610.06851 的 cue，交接从开头之后算起）。
  - 题集（第一阶段）：Qwen：`math_l5`（与 E07 相同的 300 题子集）、AIME 2022–2025（120 题，`build_inputs.py --export-aime`）；OLMo：`math_l5` 300 题。第二阶段视结果加 `m500e`、`olymp`。
  - 解码：T=0.6、top-p 0.95；每条回答（前缀 + 续写）最多 8192 个生成 token；同一个 verifier。
  - L=0 锚点（`e04_generate.py`）：Base、Post、**B1**（Base 在 T=1 熵 ≥0.5 处取首选，其余照常采样；`--fork_argmax 0.5`，单模型实现，处理器在温度之前执行），Qwen 每题 8 个样本，OLMo 每题 4 个。
  - 交接（`e08_handoff.py`）：前缀取自锚点的前 2 个样本；L ∈ {32, 256, 该回答长度的 50%}；前缀中已出现 `\boxed` 或 “Answer:” 的不用（不交出已完成的解）。续写组合：Post 前缀 → Base / B1 / Post；Base 前缀 → Base / Post。每个前缀续写 1 次。
- **读数：**
  - V_M(s)：模型 M 从前缀 s 续写的答对率。同一前缀上的续写能力差 G(s) = V_Post(s) − V_Base(s)，分 Post 前缀与 Base 前缀、按 L 报告（按题配对 bootstrap）。
  - 继承：V_Base(s_Post, L) 相对 Base 自身（L=0）与 Post 自身的位置；挽救：V_Post(s_Base, L) 相对 Post 自身的下降。
  - Post 前缀 → B1 与 → Base 之差（交接后随机性的代价），并与 E07 的 B2（分散分叉，每题 1 样本，上限 4096，口径差异需注明）对比。
  - 长度与截断：交接后续写的长度是否保持来源模型的长度。
  - 等算力：B1 的 8 个样本做多数投票（maj@k），按平均总 token 数与 Post 单次、E07 的 B2 比较。
  - 前缀合格率按 L 报告（越长的 L 合格的回答越少且偏难，比较只在同一前缀上做配对）。
- **阳性对照：** Post 前缀 → Post 续写应与 Post 自身（L=0）接近（同模型重新续写）；Base 前缀 → Base 续写同理。B1 的 vLLM 实现与 E07 同步解码的 B1（`math_l5` 53.0%，单样本）应在噪声范围内一致。
- **噪声地板：** 每个 L、每个组合约 600 个前缀（300 题 × 2），按题聚合后单条件 CI 约 ±4 点；AIME 只有 120 题，CI 约 ±6–8 点，只作方向参考。
- **混杂审计：** 前缀合格条件随 L 变化（选择偏差，只做同前缀配对比较）；50% 相对位置依赖回答长度（Post 回答更长，其 50% 位置在绝对 token 上更靠后）；OLMo 的强制开头本身就是已知的大效应（2610.06851），所有 OLMo 比较都在开头之后；Qwen3-8B 是强到弱蒸馏（先离线、后在线蒸馏 Qwen3-32B/235B 的输出与 logits；技术报告 §4.5，无 RL 阶段），OLMo RL-Zero 是纯 RLVR。
- **决策表（跑之前写）：**
  - Post 前缀在 L ≤ 256 时就使 G(s_Post) ≈ 0（Base 续写追平 Post 续写），且 V_Base(s_Post) 接近 Post 自身 → Post 的优势主要通过早期建立的推理状态传递，可被 Base 继承；下一步比较这种继承与 B2 的分散分叉，问“多早、多少”。
  - 即使 L = 50%，G(s_Post) 仍明显为正（≥ 参照差距的一半）→ 优势需要持续的续写决策，不能靠前缀继承；与 E07 的 B2 一起说明是持续而非一次性的作用。
  - 双向不对称：Post 能挽救 Base 前缀（V_Post(s_Base) 接近 Post 自身）而 Base 继承不了 Post 前缀 → 后训练的优势在于续写/纠偏能力；反之（Post 也挽救不了，但 Base 能继承）→ 路径依赖、早期状态决定结果。
  - 以上在易题与难题、Qwen 与 OLMo 之间不同 → 记录条件依赖，作为第二阶段的重点。
  - 所有曲线平滑、且能被长度/预算简单解释（例如 B1 多数投票在相同 token 数下追平 Post）→ 如实接受，不为交接曲线构造贡献，回到 E07 的选择效应。
- **算力预算：** 第一阶段约 15 GPU·时（7 张空闲卡并行，fvcrc10/11/12/21），超出 20 先停下汇报。
- **结果（第一阶段，Qwen `math_l5` 300 题；`results/e08/summary_q_math_l5_300.json`）：**
  - **锚点（每题 8 样本，上限 8192）：** B0 48.5%（长 1182，截断 5.2%）；B1 52.9%（vLLM 单模型实现，与 E07 同步解码的 53.0% 一致）；P0 69.1%（长 1491，截断 1.7%）。
  - **阳性对照：** 同模型重新续写与锚点一致（Base 前缀 → Base 47.3–49.8%；Post 前缀 → Post 68.7–69.8%）。

| L | Post 前缀 → Base | → B1 | → Post | G(s_Post) | Base 前缀 → Base | → Post | G(s_Base) |
|---|---|---|---|---|---|---|---|
| 32 | 56.5 | 58.5 | 69.8 | +13.3 [9.0, 17.8] | 47.7 | 67.2 | +19.5 [14.8, 24.2] |
| 256 | 63.3 | 60.9 | 69.5 | +6.2 [2.5, 10.1] | 49.8 | 61.4 | +11.6 [7.6, 15.7] |
| 50% | 66.0 | 66.5 | 68.7 | +2.7 [−0.7, 6.0] | 47.3 | 57.1 | +9.8 [6.4, 13.3] |

  - **继承：** Post 写到一半的前缀，Base 续写与 Post 续写无可测差别（+2.7，CI 含 0）；Post 前缀越长，Base 越接近 Post（32 token 时已比 B0 高 8 点）。交接后 B1 与 Base 续写无差别（+2.0 / −2.4 / +0.5）。
  - **挽救：** Base 写的前缀越长，Post 续写越差（67.2 → 61.4 → 57.1），但始终比 Base 续写高约 10 点。
  - **按原回答对错（前缀所来自的那条回答是否答对）：** 原回答错的前缀（L=50%）：Base 前缀上 Post 续写 33.8%、Base 续写 13.1%；Post 前缀上 Post 25.4%、Base 24.6%。原回答对的前缀两模型都在 83–89%。
  - **更正（同题控制，POST-HOC）：** 上面的对比混入了题目难度：原回答错的 Base 前缀包含许多 Post 本来会做的题，原回答错的 Post 前缀多是 Post 也做不出的题。只看两类走偏前缀都存在的同一批题（约 110 题），Post 的续写优势在 Base 走偏前缀上 +7.8 [2.8, 13.3]、在 Post 走偏前缀上 +4.6 [−3.2, 12.4]，差 +3.2 [−5.0, 11.5]（L=32、256 时差 +2.2、+1.8，均不显著）。所以**“Post 的优势只在 Base 产生的状态上”不成立**；成立的是：Post 写的前缀更常在正轨上（前缀所来自的原回答答对的比例：Post 约 69%，Base 约 46%），这种状态能被 Base 继承；面对走偏的状态，Post 只能小幅挽救，与是谁写偏的无关。G(s_Base) 大于 G(s_Post)，主要是因为 Base 前缀里走偏的比例更高。
  - **等算力（多数投票）：** B0 投票 8 次 61.4%（约 9460 token）；B1 的样本高度相同，投票饱和在约 55%；P0 单次 69.1%（约 1490 token）。E07 的 B2（上限 4096）为 67.0%、约 1413 token。Base 用 6 倍 token 自己投票也达不到 Post 单次。
  - **按决策表：** 第一行（Post 前缀在 L ≤ 256 内就使 G≈0）不成立，G 在 50% 处才接近 0；第三行的“不对称”在表面读数上成立（Base 能继承 Post 的前缀，Post 只能部分挽救 Base 的前缀），但同题控制后，它主要来自两类前缀走偏比例不同，而不是 Post 专门擅长纠正 Base 的状态。第五行不成立：等算力下 Base 追不上。
  - **Qwen AIME 2022–2025（120 题，`results/e08/summary_q_aime.json`）：** 锚点 B0 9.7%、B1 12.7%、P0 20.9%（Post 回答平均 3385 token，Base 1975）。Post 前缀 → Base：10.0 / 15.8 / 18.3%（L=32 / 256 / 50%）；Post 前缀 → Post：18.8 / 20.4 / 21.3%；G(s_Post) = +8.8 [4.2, 13.3] / +4.6 [0.4, 9.2] / +2.9 [0.0, 6.3]。Base 前缀 → Post：21.3 / 16.0 / 12.5%；G(s_Base) = +10.4 / +4.6 / +3.8。交接后 B1 与 Base 续写无差别。Base 投票 8 次 14.3%（约 15800 token），P0 单次 20.9%（约 3380 token）。形态与 `math_l5` 一致；L=50% 时 Post 前缀 → Base 的截断升到 32%（前缀约 1700 token，加上 Base 续写超过 8192 上限），该点的继承读数偏低。
  - **作废的推论：** 曾据未控制难度的读数推测“Post 的优势来自纠正 Base 自己会走进的状态（on-policy 纠正）”；同题控制后没有支持，不再作为下一步的依据。
