# 讨论文档：后训练在下一 token 分布上改变了什么（2026-11-27）

> 本文件是本工作台唯一的讨论文档，每轮在原处更新，不另起文件。细节、命令和全部数字见 `experiments/E04-*.md`、`experiments/E05-*.md` 与 `results/e04|e05/`。

## 0. 一句话

在 Qwen3-8B（多阶段后训练）与 OLMo-3-7B RL-Zero（纯 RLVR）两条谱系上，数学能力的提升有约七成可以由“让 Base 在分叉位置做确定性选择”拿到。但真实的后训练模型并不是这样做的：它在确定位置更尖锐，在分叉位置不变尖锐，而是把 Base 的第二候选提到第一（RL-Zero 多为 Wait/Therefore/no 这类反思标记）。这些改选是否沿着 Base 的“软价值”方向，是下一步要回答的核心问题（E05，进行中）。

## 1. 这一轮问了什么、怎么做的

起点是上一轮讨论：后训练的输出变化中，有多少是与上下文无关的全局成分（全局词表偏置 b、全局温度 τ），有多少是上下文相关的修正？去掉或加入全局成分会发生什么？为避免“X 占多少”式的分解，所有问题都落到可直接测的干预上：

- A：在留出上下文上拟合 τ·z₀+b，并做跨上下文来源的迁移。
- A2/A3：逐位置的最优温度（分叉位置 vs 确定位置），以及分叉处改选了什么。
- B：MATH-500 上的生成干预：Base 加入全局成分、Post 去除全局成分、降温剂量曲线、熵门控降温。
- C：选择题上把“全局答案偏好”和“题内区分”分开。
- D：分叉交换解码，两个模型同步生成，只在分叉处换人做选择（进行中）。
- E05：分叉改选的价值检验（进行中）。

## 2. 主要发现（数字均为单任务 pilot，L1）

**2.1 “全局”成分依赖上下文家族，行为上主要是控制 token，不能独立移植。**
- 同类上下文内留出检验，τ+b 能去掉 26–58% 的 KL；但跨来源迁移经常失败（RL-Zero：数学生成上拟合的 b 用到中性文本，KL 增大 22 倍）。
- 把它加到 Base 上生成：全部失败（MATH-500 2.9–14.6%，过早停止或脱轨循环）。
- 从 Post 去掉它：准确率 79.5→71.7%，但 96% 不再停止（`<|im_end|>` 偏好被去掉）；标题、Final Answer 等结构保留，`✅` 从 83% 降到 39%。
- 实现位置：OLMo RLVR 的全局成分在骨干的公共偏移里，头几乎不动；Qwen 的在头里（ΔW·μ）。这是原“LM Head”问题留下的定位结果。

**2.2 降温（锐化）能拿到约七成增益，而且收益来自分叉位置。**
- Qwen：Base T=1/0.7/0.5/0.3 = 46.5/61.5/67.7/70.6%，Post 79.5%：33 点中拿到 24 点（73%）。
- OLMo：Base 43.0%，RL-Zero 81.2%，Base T=0.5 70.5%：38 点中拿到 27.5 点（72%）。
- 熵门控（Qwen）：只在 Base 高熵位置（H≥0.5）降温 → 64.3%；只在低熵位置 → 50.4%；min-p 0.1 → 61.7%。
- 这与熵最小化（2505.15134）、序列级锐化（Karan & Du 2510.14901；Huang et al. 2412.01951）的结论一致。熵门控本身在解码文献中已有先例（EDT 2403.14541；CoT-decoding 2402.10200），这里只作为诊断工具，不是方法贡献。

**2.3 但真实后训练模型不是“锐化后的 Base”。**
- 逐位置：Qwen Post 在 76–80% 的位置更尖锐（集中在低熵位置）；RL-Zero 同样（66–86%）。但 KL 的 68–74% 集中在分叉位置，那里后训练模型不更尖锐（τ≈0.9–1.0），而是改变首选（30–42% 的分叉）。局部温度只能解释分叉处 KL 的 11–32%。
- 改选的内容：子模型的新首选有 50–71% 是 Base 的第 2 名，前 3 名合计 67–88%，排在 10 名以外的只有 3–12%。RL-Zero 典型改选是 So→Wait、Let→Wait、So→Therefore、but/maybe→no；Qwen 是行文结构与格式（To→We、`---`、`:\n\n`）。
- SFT（OLMo Instruct-SFT）在分叉处反而更平（τ 0.79–0.87），不属于锐化。

**2.4 选择题：全局答案偏好 vs 题内区分。**
- OLMo Instruct-SFT：Base 48.9%（去掉字母先验后 57.0%）→ SFT 65.5%（65.1%）。+16.6 点中约一半是纠正全局答案偏好，一半是题内区分能力。
- Qwen：74.2%（77.0%）→ 77.8%（77.6%）。+3.6 中 +2.8 来自先验纠正。

**2.5 分叉交换解码（D，Qwen，MATH-500 全部 500 题）：约 10–15% 的位置决定了后训练的大部分数学增益。**

| 条件（两模型同步解码，分叉 = Base 熵 ≥0.5） | 准确率 [95% CI] | 分叉占 token |
|---|---|---|
| Base | 43.6% [39.2, 48.2] | 31.7% |
| Post | 78.8% [75.4, 82.6] | 23.7% |
| Base，分叉处取 Base 众数 | 71.6% [67.6, 75.8] | 9.8% |
| Base，分叉处取 Post 众数 | 75.8% [72.2, 79.6] | 14.7% |

- 只让 Base 在分叉处果断（取自己的众数），就补上 35.2 点差距中的 28.0 点（80%）；改用 Post 在分叉处的众数，补上 32.2 点（91%），与 Post 的剩余差距 3.0 [−0.2, 6.4] 不显著。
- Post 的分叉选择比 Base 的众数好 4.2 点 [0.4, 8.0]，小但显著；分叉处两模型众数只有约一半一致。
- 混杂：取众数会把解析失败从 13.6% 降到 2.8%，部分增益来自答案格式。

## 3. 与已有工作的关系

- “RL 主要是锐化/重加权”：Yue et al. 2504.13837、RL Squeezes 2509.21128、Invisible Leash 2507.14843、Karan & Du、熵最小化、Huang et al.。这些工作看的是 pass@k、采样方法或训练目标；我们在真实模型上逐 token 地拆开“锐化”与“改选”，并用解码干预检验哪一部分承载准确率。
- 高熵分叉 token：Wang et al. 2506.01939（RLVR 主要调整高熵 token 的熵）、Bigelow et al. 2412.07961（forking tokens）。我们补上的是分叉处具体改选了什么，以及这些改选的价值。
- 理论锚点：KL 正则 RL 的最优修正是软价值 log Z（Cohen et al. 2607.22837 式 4）。E05 在真实 RL 模型上直接检验这一预测。
- 原 LM Head 线：Tomihari 2601.04670 已做 head/backbone 的 NTK 分解；我们的定位结果（RLVR 的全局成分在骨干、Qwen 的在头）只作为附带发现。

## 4. 需要讨论的问题

1. **方向是否就此收敛到“后训练在分叉处做了什么”？** 我认为这是首轮以来第一个同时满足以下三点的问题：结论对两种结果都有信息量；与一个主流争论（“RL 只是锐化吗”）直接相关；能用便宜的干预直接检验。但它已经离开了 LM Head，工作台名称与 README 需要相应调整（由你们决定）。
2. **尺度与近邻风险。** “RL≈锐化”这块已经很拥挤。我们的增量能否站住，取决于 E05：如果 RL 的分叉改选确实沿软价值方向，而 Base 降温只是近似，那么“同样的准确率、不同的机制”就是一个清楚、可预测的结论；如果改选与价值无关，那么故事会更接近“RL 的剩余增益来自别处”，需要重新组织。
3. **是否需要第三个谱系**（例如 DeepSeek-R1-Distill 或 Qwen2.5-Math 的公开 RL 版本）来避免只有两点？这会涉及新模型下载。
