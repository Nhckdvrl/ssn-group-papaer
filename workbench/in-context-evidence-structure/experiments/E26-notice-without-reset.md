# E26：察觉到变化却不重置？——逐条删除 demo 的影响曲线（2026-10-05）

- **状态：** PLANNED
- **类型：** PILOT（idea 的决定性实验）
- **对应：** idea I02“noticing is not resetting”（候选）：输出侧的变化点检测与输入→输出关联的累积是两个不互通的系统；察觉到变化不会让旧关联失效。
- **问题（一句话）：** 在 8A→8B 的序列里，模型对 query 的预测还依赖多少变化前的旧 demo？这种依赖在“察觉到变化”的格式通道与映射通道之间是否不同？
- **设置：** E22 同源 base（数字 small/large、SST 两极），200 base/任务，新种子 SEED0=760000。两种呈现：`plain`（无标记，2 候选）与 `marked`（B 段大写，4 候选，同 E22）。三种模式：`suffix_8`（AAAAAAAABBBBBBBB，有变化点）、`disp_8`（ABAB…，计数相同、无变化点，作位置核基线）、`allA`（参照）。每个 (base, 模式) 打分完整提示 + 16 个“删去第 t 条 demo”的提示。
- **读数：**
  - 删除影响 `inf_t = logit P(新映射 | 完整) − logit P(新映射 | 删去 t)`；`marked` 另算 `P(大写)` 通道的同一量。
  - 按 (段：变化前 A / 变化后 B) × (与 query 同类 / 异类) 汇总。
  - **重置指数** `R = mean|inf| over 变化前 A demo / mean|inf| over 变化后 B demo`，在 suffix_8 与 disp_8 分别计算（disp_8 中按相同位置集合 1–8 vs 9–16 分组，作为纯位置核）。`R_suffix / R_disp` < 1 表示旧 demo 因变化点而被额外打折（重置）。
  - exact meta oracle 对每个删除提示都算（同一 λ×ε 网格），给出规范的 R。
- **阳性对照：** 标签流 / 格式通道：E22 中格式通道是规范的，预期在 marked 的 P(大写) 上看到重置；oracle 提供规范量级。
- **噪声地板：** bf16 batch 噪声 ~0.1 nats/条；单条删除效应可能很小，故按 200 base × 8 位置汇总，bootstrap over base。
- **混杂审计：**
  - 位置核：disp_8 基线与 suffix_8 同计数、同位置集合 — 已控制。
  - 内容相似度（最近邻）：按同类/异类拆分；同一 base 的 demo 输入在模式间相同 — 已控制。
  - 删除改变长度：所有删除提示同为 15 条 demo — 在条件间相同。
- **决策表（跑之前写）：**
  - 格式通道 R_suffix/R_disp ≪ 1 且映射通道 ≈ 1 → “察觉但不重置”成立，成为 I02 的核心证据；下一步做检测→关联的因果介入（patch 格式通道的变化信号能否让映射重置）。
  - 两通道都 ≈ 1 → 格式通道的“规范性”来自别的机制（比如对大写串的复制而非变化点后验），重写 E22 的解释。
  - 映射通道也 ≪ 1 → 映射通道其实会重置，只是更弱；需与 E22 的“平坦”对照，重新表述。
- **算力预算：** (1+16)×3 模式×200 base×2 任务×2 呈现 ≈ 41k 提示/模型；7–8B 单卡约 1 小时。模型：Qwen3-8B、Qwen2.5-7B、Mistral-7B、Llama-2-7B（先 4 个）。
