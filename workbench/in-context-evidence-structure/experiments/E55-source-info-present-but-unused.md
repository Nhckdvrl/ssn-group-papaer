# E55：来源信息在锚点表示里吗？检索用不用它？——“存在 → 使用 → 因果”链条的前两步（2026-10-09）

- **状态：** DONE（2026-10-09）
- **类型：** 机制（解释缺口：Cho et al. ICLR'25 的 ICL 电路——前导 token 编码输入、语义并入标签 token、query 按相似度检索标签 token 并复制——没有回答上下文变量（谁、何时）能否把证据分开；我们的 E36 / E48 显示检索几乎不按来源选、分隔只在读出层面发生）
- **对应：** E36（读标签头：内容 ×2–69 ≫ 标注者 ×1.5–2.6）；E48（换词后对他人锚点注意力保持 81–88%，贡献降到 3–12%）；C13；Cho et al. 2025（arXiv 2410.04468）、Cho et al. 2026（arXiv 2509.21012）
- **候选解释（竞争）：**
  - H-absent：来源信息根本没进入锚点表示（“Annotator: X” 没有被编码进标签 token）→ 检索无从使用。
  - H-unused：来源信息清楚地存在于锚点表示中，但读标签头的检索子空间（W_Q^T W_K）与它近乎正交 → 存在但不被使用。
  - H-weak：来源被使用，只是相对内容相似度太弱（与 E36 的 ×1.5–2.6 一致），在多数提示中被内容压过。
- **设置：** Qwen3-8B（eager），E46 的前 40 对、mixed（同词）条件、前 20 个 query，A 与 B 两种身份。
  - 第 1 步（存在）：每个提示中 16 个标签 token 的残差（每 4 层取一层），按对分组交叉验证的逻辑回归解码“该 demo 的标注者名字”（Alex / Sam）；对照：解码该 demo 的标签（toxic / safe）与内容（bge 聚类）。
  - 第 2 步（使用）：E48 的另一人贡献最大的 10 个头 + E36 的读标签头，答案位置对 16 个标签 token 的注意力取对数，在提示内中心化后回归到 [同一标注者, 与 query 的内容相似度（bge 余弦）, 同一标签, 位置]，比较标准化系数。
- **结果 → 判断（事先写）：** 名字解码 ≤ 0.6 → H-absent；名字解码 ≥ 0.9 且注意力中“同一标注者”系数 ≤ 内容系数的 1/3 → H-unused（进入第 3 步：把来源方向注入检索子空间，检验能否因果提高分隔）；名字解码高且同一标注者系数与内容相当 → H-weak（转向“为何检索后仍不分开”：读出层面）。
- **算力：** 40 × 2 × 20 = 1600 个提示，单卡约 30 分钟。

## 结果（2026-10-09；Qwen3-8B；`results/e55/Qwen3-8B_analysis.json`）
- **第 1 步（存在）：** 标签锚点上解码标注者名字（按对分组 5 折）：层 0 0.50、4–8 **1.00**、12 0.99、16 0.91、**20–28 0.78**、32 0.84、36 0.90；标签本身各层 1.00。→ 来源信息在早期完整进入锚点，在检索发生的中后层明显减弱。
- **第 2 步（使用）：** 注意力对数（提示内中心化）回归的标准化系数：内容选择性最强的 20 个头（18–23 层）平均：标签 0.92、位置 −0.85、内容相似度 0.24、同一标注者 0.10（同一标注者 / 内容中位数 0.30）；E48 的泄漏承载头（30–34 层）：同一标注者 0.10–0.18、内容 0.05–0.11。
- **按表：** 介于 H-unused（内容检索头：来源系数约为内容的 1/3）与 H-weak（泄漏头：来源被少量使用）之间；且两者都远小于“锚点标签是什么”与位置的作用。来源信息在检索层只有约 0.78 的可解码度。
- **逼出的问题 → E56：** 检索层中残存的来源信息，是否足以支撑按来源检索？用一个只能改变 query（读哪里）的低秩模块做构造性检验。
