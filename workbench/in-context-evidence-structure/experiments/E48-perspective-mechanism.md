# E48：真实视角提示中，另一位标注者的影响从哪里进入答案？换词修复发生在注意力还是读出？（2026-10-08）

- **状态：** DONE（2026-10-08）
- **类型：** 机制中介（E46 的候选主张进入候选前所缺的一环）
- **对应：** E46 / E46b / E47（同词混合只保留 27–49%，换词完全恢复）；E36–E39（读标签头按内容读取标签锚点，是上下文映射主通路）
- **问题（一句话）：** 在 E46 的真实提示中，每个头对答案方向（query 词表的毒性 − 安全）的直接贡献，有多少来自另一位标注者的标签锚点？换成远义词后，下降的是注意力（不再读另一人的锚点）还是读出（照读，但其 value 写向与 query 词表正交的方向）？
- **事先预测（I04）：** 同词时另一人锚点的贡献显著且方向与该人倾向一致（泄漏的直接通道）；换词后该贡献降到 ≈ 0，但**注意力份额基本不变**（读出层面的修复）。竞争预测：换词后注意力也大幅下降（模型按词表分组注意）。
- **设置：** Qwen3-8B（eager），E46 的前 40 对、前 20 个 query；条件 mixed 与 mixed_far；query 身份 A、B。按来源位置分解：自己的标签锚点 / 另一人的标签锚点 / 其余位置；同时记录答案位置对两组锚点的注意力质量（逐层逐头）。脚本 `scripts/mech_perspective.py`。
- **读数：** 全部头合计的“另一人锚点贡献”（按该人倾向定号：A 为 +、B 为 −）在两条件下的均值与 CI；贡献最大的头上，对另一人锚点的注意力质量在两条件下之比。
- **结果 → 判断：** 同词时另一人贡献 ≥ 自己贡献的 30% 且换词后降到 ≤ 10%，同时注意力比 ≥ 0.7 → 支持“读出层面的修复”（I04 的按输出存放）；注意力比 ≤ 0.4 → 修复主要在注意力层面（模型按词表分组注意），I04 的机制叙述需改为“注意力按输出词分组”。

## 结果（2026-10-08；Qwen3-8B；40 对 × 20 query × 2 条件 × 2 身份；`results/e48/Qwen3-8B_analysis.json`）
| 条件 | 自己锚点贡献（按倾向定号） | 另一人锚点贡献 | 另一人 / 自己 | top-10 头对另一人锚点的注意力 | A − B 区分 |
|---|---|---|---|---|---|
| 同词 mixed | 6.57 | **4.83**（95% CI 4.10–5.56） | **0.73** | 0.184 | 3.67 |
| 远义词 mixed_far | 3.21 | **0.33**（0.32–0.35） | **0.10** | 0.162 | 7.39 |
- 另一人贡献最大的头：34.2、32.3、32.5、30.27、33.29、34.1、33.16、30.9、32.7、34.3（30–34 层）。
- **按表：** 同词时另一人贡献 = 自己的 73%（≥ 30%）；换词后 10%（≤ 10%，在边界上）；注意力比 0.88（≥ 0.7）→ **支持“读出层面的修复”**：换词后这些头仍在读另一人的标签锚点，但读到的 value 写向与 query 词表正交的方向。泄漏的直接通道就是读标签头读入另一人的锚点。
- **意义：** 模型并非“不看是谁标的”——它照样读所有人的标签；证据按输出标签存放，所以只有输出词能分隔来源（I04 的机制版本，在真实数据上）。
