# E56：只改变“读哪里”的小模块，能否让上下文证据按来源分开？——能力 vs 默认使用（2026-10-09）

- **状态：** DONE（2026-10-09）；后续 E56b
- **类型：** 构造性判别（受 Cho et al. ICLR'26 “单独训练一个低秩模块检验可行性”的思路启发，但针对本问题改造：限制模块只能改 attention query，从而区分“信息存在但默认不用”与“信息不在检索通路上”）
- **对应：** E55（锚点中来源可解码度：早期 1.00，检索层 ~0.78；检索主要按标签与位置）；E47（交互型视角同词保留 0.27–0.48）；C13
- **问题（一句话）：** 冻结 Qwen3-8B，只在答案位置给第 16–35 层的 attention query 加一个秩 8 的修正（只能改变读哪些锚点，不能直接写答案），能否在未见过的评论上把交互型来源区分恢复到单一来源上下文的水平？
- **设置：** Measuring Hate Speech 中针对种族 / 性别的评论，按 70 / 30 切分训练 / 测试池；A：种族→toxic、性别→safe；B 相反；每个上下文 16 条 demo（每人 8 条）、16 条 query（8 种族 + 8 性别），A、B 两种身份。训练 400 个上下文 × 2 轮，测试 80 个新上下文（新评论）。四种设置：
  - none：默认模型（混合）+ 单一来源上界（只放该人的 8 条）；
  - query：只改 query 的秩 8 模块（16–35 层，每层一个）；
  - resid：在第 16 层输出处改残差的秩 8 模块（可以写任何东西，上界）；
  - query_shuffled：只改 query，但训练数据中 demo 的名字随机（来源无信息，下界：只靠更好的内容检索能得到多少）。
  脚本 `scripts/e56_query_adapter.py`。
- **读数：** 测试集交互区分 I_A − I_B（同 E47）与准确率；保留 = 区分 / 单一来源上界。
- **结果 → 判断（事先写）：**
  - query ≥ 0.8 × 上界，且 query_shuffled ≤ 默认 + 0.1 → **存在但默认不用**：来源信息足以支撑按来源检索，默认路由没有用它。
  - query ≈ query_shuffled（差 < 0.1）而 resid ≥ 0.8 → **不在检索通路上**：来源信息在检索可用的 key 中不足，需要写入式修改。
  - 三者都低 → 8 条样例的交互规律本身学不到（此设定不可判定）。

## 结果（2026-10-09；Qwen3-8B；测试 80 个新上下文、未见评论；`results/e56/Qwen3-8B_*.json`）
| 设置 | 交互区分 | 准确率 | 训练损失（末段） |
|---|---|---|---|
| 默认（混合） | 1.29 | 0.54 | — |
| 单一来源上界 | 3.76 | 0.62 | — |
| **query（只改读哪里，秩 8）** | **12.55** | **0.91** | 0.11–0.37 |
| resid（改残差，秩 8） | 10.30 | 0.85 | 0.19–0.56 |
| query_shuffled（名字随机） | 0.01 | 0.51 | 0.69（未学到） |
- **按表：** query = 3.3 × 上界（≥ 0.8 ×），query_shuffled ≤ 默认 + 0.1 → **存在但默认不用**：冻结表示中的来源信息足以支撑“内容 × 来源”的双键检索，只需改变答案位置的 query；默认路由不用它。名字与角色的对应在每个上下文中随机，模块无法记住“哪个名字严格”，只能在上下文中按名字读取。
- **待排除（E56b）：** 模块学到的是通用的“读同一来源”，还是该任务特有的读法——不重训，迁移到规则反转、E46 真实标注者、GoEmotions（不同标签词）。
