# E41：顺序方差由谁承载？——证据方差与顺序方差的组件地图（2026-10-08）

- **状态：** DONE（2026-10-08）
- **类型：** EXPLORE（高信息量测量；由 E40 的反常逼出）
- **对应：** E40（同一组 demo 换顺序，答案移动 ~1.2 logit，与规模无关，与标签时间特征无关）；E36（读标签头）；E39（读标签头是上下文映射主通路）；Lu et al. 2022（顺序敏感）
- **问题（一句话）：** 顺序带来的答案波动，在模型内部是由读取证据的同一批读标签头产生（读取本身的抖动），还是由另外的组件产生（与证据无关、可以单独分离的噪声源）？
- **事先预测：** 最强的已有认识是顺序敏感来自位置偏置 / 注意力分配；E36 显示读标签头的注意力不看位置，所以朴素预测是：顺序方差**不在**读标签头里，而在别处（例如更早的层或 MLP）。
- **谁依赖：** 所有处理 ICL 顺序敏感的方法（校准、排序搜索、多顺序集成）——它们默认顺序方差是一个需要整体平均掉的黑箱量；若它集中在少数可识别组件里，可以直接定位或消除。
- **设置：** Qwen3-8B（eager 注意力，bf16）；数据 `data/kernel_perm`（E40：240 个 base × 8 种顺序 = 1920 个提示；更正：全部为 clean 结构，覆盖 3 种词表，见 E43）。每个提示记录：每个头与每层 MLP 在答案位置对 W_U[c1] − W_U[c0] 方向的直接贡献（DLA，按最终 RMSNorm 缩放）；答案位置对 16 个标签 token 的注意力（每层每头）。脚本 `scripts/mech_order.py`，分析 `scripts/analyze_order.py`。
- **读数：**
  - 每个组件 c 的贡献 x_c(b, o)。把答案 ld 的方差分成 base 内（顺序）与 base 间（证据）两部分；组件份额 = Cov(x_c, ld) / Var(ld)，分别在 base 内与 base 间计算（份额之和 ≈ 1，DLA 重建检验）。
  - 两张份额图的排名相关；顺序份额前 20 的组件与证据份额前 20 的重合；按层 / 按组件类型（头 vs MLP）汇总。
  - 读标签头内部：顺序变化时，注意力在 16 个标签之间的分配如何变化（熵、对同类 / 异类标签的份额），以及它与该头贡献波动的相关。
- **阳性对照：** DLA 求和重建 ld（E36 r = 0.9997）；证据份额应集中在 E36 的读标签头（预期 ≥ 50%）。
- **噪声地板：** 按 base 自助法给份额的 CI。
- **结果 → 问题（事先列出）：**
  - 顺序份额也集中在读标签头 → 顺序敏感就是“按内容读取标签”的抖动；下一步问抖动由什么决定（注意力在同类标签之间的分配？）。
  - 顺序份额集中在另一组组件（非读标签头 / MLP）→ 顺序噪声与证据通路可分；下一步消融或均值替换这些组件，看顺序 SD 是否下降而准确率不变（可解释性 → 方法）。
  - 顺序份额弥散在大量组件里 → 顺序敏感是分布式的“混沌”，不存在可定位的来源；如实记录。
- **算力：** 1920 个提示，单卡约 20 分钟（不含加载）。

## 结果（跑完后填写）
（2026-10-08；Qwen3-8B；`results/mech/e41_Qwen3-8B_perm_order.json`）
- DLA 重建 r = 0.99993。ld 方差：base 内（顺序）1.76，base 间（证据）19.7。
- **同一批组件：** 份额图相关 r = 0.957；顺序份额前 20 与证据份额前 20 重合 14 / 20；E36 的 20 个读标签头承担顺序方差的 98%、证据方差的 93%；MLP 合计为负（−0.26 / −0.18，抵消）。顺序份额全部集中在 29–35 层。
- **抖动 = 读到哪些标签：** 顺序份额最大的头 33.31（23%）与 30.25（20%）的 base 内 DLA 波动，与“注意力加权的标签极性”相关 0.86 / 0.72，与读到的标签总质量几乎无关（−0.06 / 0.06）；部分次要头（33.24、33.12、33.25）的波动则跟随总质量（|r| 0.6–0.8）。
- **按“结果 → 问题”：** 第一档——顺序敏感就是按内容读取标签锚点的抖动，不是另一个位置偏置机制。逼出的下一个问题：换顺序后读标签头为什么选中不同锚点？（因果上下文改变锚点内容 vs RoPE 相对位置改变匹配分数）→ E42。
