# E40：证据核图谱——把“每条 demo 对答案贡献多少”整体测出来（2026-10-08）

- **状态：** DONE（2026-10-08）
- **类型：** EXPLORE（高信息量测量；目的不是验证一个预设问题，而是测量整个对象，再从拟合残差中找问题）
- **对应：** I04（按输出存放证据）；E26（逐条删除影响，只在 suffix 结构上做过）；E30 / E33（标注者交互、标签语义泄漏）；E21（看最近邻不看最近期）
- **为什么现在做：** 前 38 张卡各回答了一个窄问题，拼起来是 I04。但没有一次实验同时变化 demo 的所有属性，所以 I04 解释**之外**的结构（交互、竞争、规模趋势）从来没有机会出现。人 2026-10-08 要求：用高信息量实验把更有价值的问题逼出来，而不是注册一个想象的问题再验证。
- **设计（随机化析因，每条 demo 的属性独立变化）：** 数字任务（small/large，阈值 50），每个提示 16 条 demo、1 个 query。
  - 每个 base：映射方向 s ∈ {正, 反}；**结构 τ ∈ {clean, ann（Sam 的 demo 全反）, time（后 8 条全反）, noise（随机 3 条反）}**；**Sam 的标签词表 v ∈ {same: small/large, near: little/big, far: A/B}**；query 标注者 ∈ {Alex, Sam}；query 类别 ∈ {0, 1}。完全析因，每格 10 个 base，共 960 个 base。
  - 每条 demo：类别（总体 8/8）、标注者（总体 8/8、每类 4/4）、位置随机；数值在类别区间内均匀抽取 → 与 query 的数值距离自然变化。
  - **读数：** 每个 base 打分完整提示 + 16 个“删去第 t 条 demo”的提示（共 16,320 个提示 / 模型）。ld = logit(query 词表的第 1 极) − logit(第 0 极)。demo t 的**支持度** s_t = (ld_full − ld_del_t) × (2·ℓ_t − 1)，其中 ℓ_t 是 demo t 显示的极性；s_t > 0 表示该 demo 把答案推向它自己显示的那一极。
  - 模型：Qwen3 0.6B / 1.7B / 4B / 8B / 14B（同一家族的规模轴）。
  - 脚本：`scripts/build_kernel.py` → `data/kernel/`；`scripts/score_ld.py`；`scripts/analyze_kernel.py`。
- **先拟合的已知解释（I04 的最简形式）：** s_t = w(|x_t − x_q|) · g(词表匹配) · h(同一极的 demo 数)。也就是：支持度只取决于输入相似度和输出身份，与位置、标注者、结构 τ 无关。用一半 base 拟合，在另一半上计算残差。
- **残差中可能出现的模式 → 它会逼出的问题（事先列出，不是判据）：**
  - 支持度随位置变化，且只在 τ = time 时变化 → 模型其实部分感知时间结构，E22 的“平坦”是平均掉了。
  - 同一极 demo 越多，单条支持度越小（归一化 / 竞争）→ 证据汇总是 softmax 式的分配，不是相加；这会预测“多数类稀释少数类证据”。
  - 标注者匹配 × 词表的交互（同词表时标注者不起作用、不同词表时起作用）→ 输出身份是绑定上下文的唯一钥匙，可以写成“上下文只能通过输出词进入”的定律。
  - 相似度核的宽度随规模变化（变窄 = 更像最近邻）→ 规模定律：模型越大越局部，concept drift 越看不见？
  - 支持度为负的 demo 系统性地出现在某类条件下 → 存在“反证据”通路（类似 E26 格式通道的负支持）。
  - 其他未列出的大残差：逐条看样例。
- **噪声地板：** 同一提示在 batch 构成不同时的 bf16 噪声约 0.1 nats / 条；按 base 自助法汇总；拟合用一半 base、评估用另一半。
- **混杂审计：** 删去一条 demo 会把后面的 demo 前移一个位置（E21 / E28 显示位置斜率 ≈ 0，作为残差项检查）；属性独立随机化，避免共线；query 数值与 demo 数值不重复。
- **算力：** 每模型 16,320 个短提示；0.6B–8B 各约 5–15 分钟，14B 约 30 分钟（不含从 NFS 加载）。

## 结果（跑完后填写）
（2026-10-08；Qwen3 0.6B / 1.7B / 4B / 8B / 14B；`results/kernel/`、`results/kernel_perm/summary.json`、`results/kernel/fit.json`）
- **测量本身：** 单条删除效应可重复（8B 换 batch 重测 r = 0.99996），但**所有 demo 属性**合计只解释约 2%（饱和汇总模型；GBM 1.5%）。
- **原因（追加控制，POST-HOC）：** 240 个 base × 8 种随机顺序（同一组 demo，只改顺序）。答案的顺序 SD 在各规模都约 1.1–1.4 logit，**大于**单条删除效应（0.7–1.1）→ 单条删除读数主要反映顺序敏感，单个 base 上不能当证据权重；只有在大量 base 上平均才有意义（E26 是 200 base 平均，结论不受影响）。
- **顺序敏感与规模：** 顺序 SD 不随规模变化（1.25 / 1.10 / 1.39 / 1.23 / 1.12），证据带来的 base 间差异随规模增大（1.73 → 4.79）。顺序效应与标签时间特征的相关：0.6B 反近因（最后一条标签 r = −0.40），1.7B / 8B ≈ 0，4B −0.12，14B 出现弱近因（后 4 条 +0.12，近因平衡 +0.19）。
- **I04 在完全随机化设计中复现：** 按标注者分组的映射（Sam 用 B、Alex 用 A），同词表时分离只有 0.85–1.57 logit，换成 near / far 词表时为 1.7–6.5（各规模）；8A→8B 的 concept drift 在所有规模都停在约 0（−0.21 到 +0.23），而 clean 条件为 −1.2 到 −3.9。
- **残差中没有出现：** 位置 × 结构、标注者 × 词表的系统残差（ΔR² ≤ 0.006）。
- **它逼出的问题：** (1) 每个提示上存在一个与规模无关、约 1.2 logit、且与时间特征无关的顺序成分——它来自哪里，是否就是“看不见 concept drift”的另一面？(2) 时间加权的符号随规模从反近因翻到近因（0.6B → 14B），需要 32B 和其他家族确认。
- **算力实际：** 约 3 GPU·时。
