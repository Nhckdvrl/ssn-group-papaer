# E27：换任务 vs 翻映射——时间推断发生在“任务识别”还是“按输入路由”？（2026-10-05）

- **状态：** PLANNED
- **类型：** PILOT（idea 的决定性实验）
- **对应：** idea I02（候选）“ICL 的任务识别像变化点检测器，任务学习像可交换记忆”；与 C02 的旧划分（全局变换 vs 按类别映射）正面竞争
- **问题（一句话）：** 当新 regime 是“另一个可识别的分类任务”（同样按输入路由、同样的 yes/no 标签）时，模型会像对待标签流/±3 那样做规范的变化点推断吗？还是像对待“同一任务翻标签”那样可交换地汇总？
- **两个竞争解释的预测：**
  - 旧划分（全局变换 vs 按类别映射）：切换与翻转都按类别路由 → 都时间盲。
  - TR/TL 划分：切换 = 任务识别改变 → 规范（成簇>0、前缀噪声使信任下降、后8≫前8）；翻转 = 同一任务的映射改变（任务学习）→ 时间盲。
- **设置：** 数字 10–89，属性 even（奇偶）与 large（≥50）。16 条 demo，四格（偶小/偶大/奇小/奇大）各 4 条；标签 yes/no。四种 base 类型（各 300，SEED0=780000）：
  - `switch_pm`：A=“偶数→yes”，B=“≥50→yes”；`switch_mp`：A 与 B 互换。
  - `flip_p`：A=“偶数→yes”，B=“奇数→yes”；`flip_m`：A=“≥50→yes”，B=“<50→yes”。
  - query：A 与 B 给出不同答案的格（切换：偶小或奇大；翻转：同样从这两格中抽，保持 query 分布一致）。
  - 模式：allA、allB、single_1、single_16、suffix_3、suffix_4、disp_4、noise_2__suffix_3、suffix_8、prefix_8、block_start4。
  - exact oracle：两属性规则空间（attr × polarity，4 个假设）+ λ×ε 网格；切换与翻转在 oracle 下都是同一假设空间内的跳变。注意切换中只有一半 demo（A、B 分歧的格）携带 regime 信息，oracle 自动计入。
  - 构造：程序化的数字与 yes/no 标签，无需人工审计。`scripts/build_taskswitch.py` → `data/taskswitch`。
- **读数：** logit P(B 的答案)；成簇 suffix4−disp4、噪声 noise_2__suffix_3−suffix_3、后8−前8、陈旧块 block_start4−allA；与 oracle 对比的归一化指数（CSIn、NDIn）。allA/allB 准确率（任务能否被学会）。
- **阳性对照：** 同一批模型的标签流与 ±3（已知规范）。
- **混杂审计：**
  - 任务可学性：allA/allB 准确率需明显高于 0.5，否则不可判读（按任务分别报告）。
  - 信息量不同：切换中只有一半 demo 携带 regime 信息 → 用 oracle 归一化（CSIn/NDIn）而不是原始效应比较。
  - 标签词先验（yes 偏置）：A/B 角色在 base 间平衡。
- **决策表（跑之前写）：**
  - 切换规范、翻转时间盲 → TR/TL 划分成立：时间推断发生在“任务状态”上，与是否按输入路由无关。I02 成为主 idea。
  - 两者都时间盲 → 旧划分（按输入路由 = 可交换）成立；I02 改写为“路由映射一律进入可交换的关联存储，不论任务是否可识别”。
  - 两者都规范 → 数字域的分类本身就能被时间推断（与 E15 的奇偶/大小翻转矛盾），需查 yes/no 标签相对 even/odd 自然标签的差异。
- **算力预算：** 13200 条 × 6 模型，每模型单卡 ~10 分钟。
