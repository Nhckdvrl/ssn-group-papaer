# E29：被过滤的边缘统计是“标签 token 频率”还是“输入-输出关系的边缘分布”？（2026-10-06）

- **状态：** RUNNING（卡片在结果前写下）
- **类型：** PILOT
- **对应：** I03（候选）；E28 的推广
- **问题（一句话）：** 输出全是普通数字（无重复的标签 token）时，若映射翻转改变了“y−x 偏移”的边缘分布，模型的时间结构是否同样集中在“与 query 无关的偏置”上？
- **设置：** 条件算术（±2）：A：偶数→x+2、奇数→x−2（base 间取反平衡）；B：互换。16 条 demo 中多数奇偶类 12 条、少数类 4 条；每个 (base, 模式) 一个多数类 query、一个少数类 query。300 base，SEED0=800000，11 个模式，同 E28。`FMTS=condarith OUT=imbal_ca python build_imbal.py`。程序化数据，无需审计。
- **oracle：** 一属性（奇偶）规则 HMM，“升/降”作为二值标签——与 E28 同构。
- **读数：** 同 E28（`DATA=imbal_ca analyze_imbal.py`）：多数/少数 query 的时间结构；偏置成分 =（多数−少数）/2（= 偏向“新多数方向”的偏移）；条件成分 =（多数+少数）/2。
- **竞争预测：**
  - 关系边缘（y−x 分布）被过滤：偏置成分规范（噪声<0、后8−前8>0），条件成分时间盲，少数类 query 符号反转——与 E28 相同。
  - 只有标签 token 频率被过滤：两成分都时间盲（无重复标签 token 可计数）。
- **混杂：** 平衡版条件算术（conf_condarith）已知时间盲（13 模型），作为基线。
- **决策：** 关系边缘也被过滤 → I03 的“边缘统计”指的是输出侧特征（含关系特征）的分布，不是 token 计数；与 ±3 被规范追踪统一。否则 → I03 收窄为“标签 token 流”，±3 的规范性需另找解释。
