# E32：把 concept drift 变成输出漂移——新 regime 换用新标签词后，时间上的 concept drift 能被追踪吗？（2026-10-06）

- **状态：** RUNNING（卡片在结果前写下）
- **类型：** PILOT（I04 机制的建设性预测）
- **对应：** I04；E31（交互泄漏经由共享输出标签：nonce 词表时溢出 0.00）；E22（大写：8B 不分组，32B 分组）
- **问题（一句话）：** E22 中小模型“写大写却不用新映射”，是因为大小写变体不够“不同”；若 B regime 改用两个审计过的 nonce 标签词（映射同样取反），模型会规范地选择新词表、并在新词表内使用新映射吗？
- **设置：** E22 同构（数字 small/large、SST 两极，300 base，11 个模式，SEED0=860000），B demo 的标签换成每个 base 随机抽取的 2 个 nonce 词（`data/lexicon.json`，step-5 审计通过），映射取反。4 个候选：[旧词·旧映射, 旧词·新映射, 新词·旧映射, 新词·新映射]。`MODE=nonce OUT=relabel SEED0=860000 python build_marked.py`；分析 `DATA=relabel analyze_marked.py`（“upper”列即“新词表”）。
- **预测（I04：证据按输出标签存放）：** P(新词表) 规范（成簇>0、噪声<0、后8≫前8，与 E22 格式通道同型）；P(新映射 | 新词表) 在 suffix_8 下接近 1（新词表只从 B demo 学），因而 P(新映射) 继承新词表通道的规范时间结构——即使在 1.7B/2B 模型上。
- **对照：** E22（大写）同模型；E16 无标记。
- **决策：** 预测成立 → concept drift 盲的充分条件是“新旧 regime 共用输出标签”；“输出漂移可见、concept drift 不可见”被统一为一个机制（按输出身份存放的关联 + 规范的输出边缘通道）。不成立（新词表内仍混用旧映射）→ 关联不只以输出身份为键，需回到输入侧解释。
