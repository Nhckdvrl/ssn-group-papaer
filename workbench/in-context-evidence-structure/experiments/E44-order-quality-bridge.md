# E44：“好的顺序”好在顺序，还是好在碰巧的位置几何？——顺序选择方法的桥梁检验（2026-10-08）

- **状态：** DONE（2026-10-08）
- **类型：** 桥梁检验（由 E42 逼出）
- **对应：** E42（只改位置编号、token 与因果顺序不变，答案跳动与完整换序一样大，且二者近乎独立）；E43（抖动是对任何配置变化的通用敏感）；近邻：Lu et al. 2022（顺序敏感，用熵挑顺序）；Order Matters（arXiv 2511.09700：顺序方差 ≈ 换样例集，可用开发集识别强顺序）；PLR（arXiv 2603.21373，学习顺序分布）
- **社区在用的推断：** 某些顺序本身更好；在开发 query 上挑出的好顺序可以复用到新 query 上。
- **问题（一句话）：** 在固定的 demo 集合上，开发 query 上测出的“顺序好坏”能否迁移到测试 query？如果能，这种好坏在只改位置编号（插入位置间隔，内容与因果顺序完全不变）后是否保留？
- **事先预测：** 依据 E42，位置编号本身就会引起与换序同样大的跳动，因此我预测：好坏的一部分可以迁移（顺序确实影响读到的锚点），但在位置扰动下会大幅丢失。也就是说，好顺序很大一部分是位置几何。
- **设置：** Qwen3-8B、Qwen2.5-7B；两个任务：数字（Number / Label: small, large）与 SST 二分类（Review / Label: negative, positive；E07 的句子池）；每个任务 60 个 demo 集合（16 条，类别均衡），每个集合 40 个 query（20 个开发 + 20 个测试，类别均衡，与 demo 不重复），16 种随机顺序；两种位置模式：orig（连续编号）与 gap（每个块之间插入 1–8 的随机位置间隔，按集合 × 顺序固定，内容不变）。读数 = 朝正确标签的 logit 差（margin）。脚本 `scripts/e44_order_quality.py`。
- **读数：**
  - 顺序质量 = 某顺序在一组 query 上的平均 margin（减去该集合所有顺序的平均）。
  - (1) **迁移：** 开发与测试 query 上顺序质量的相关（每个集合内 16 个顺序；报告中位数）；开发集最好与最差顺序在测试集上的差距。
  - (2) **位置稳定性：** 同一顺序在 orig 与 gap 两种位置模式下（都用测试 query）的顺序质量相关；在 orig 开发集上挑的最好顺序，换到 gap 模式后在测试集上的优势还剩多少。
  - (3) 参照：同一顺序在 gap 模式下开发→测试的迁移（位置几何换了一套之后，顺序质量是否重新可迁移）。
- **结果 → 判断（事先写）：**
  - (1) 高（中位相关 ≥ 0.5）且 (2) 高（≥ 0.5）→ 顺序质量是真实的、与位置几何无关；E42 的位置跳动是 query 特异的噪声，不影响顺序选择。
  - (1) 高而 (2) 低（< 0.3）→ **好顺序主要是位置几何**：顺序搜索方法挑中的是碰巧有利的位置配置，任何改变位置的提示修改（加系统提示、改说明句长度）都会让它失效。这是对顺序选择方法的反例，并有机制解释（读标签头 + RoPE）。
  - (1) 低（< 0.3）→ 在此设定下顺序没有可迁移的质量，“强顺序”不可识别。
- **算力：** 60 × 16 × 40 × 2 模式 = 76,800 提示 / 任务 / 模型；8B 单卡约 40–60 分钟 / 任务。
