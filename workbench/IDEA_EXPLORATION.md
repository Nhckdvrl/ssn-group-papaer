# 探索 idea — 在驻留中把想法推出来、筛出来

**版本：v4（2026-09-30）。** 配套：[`EXECUTION.md`](EXECUTION.md)（实验卡、证据等级、混杂审计）、[`../templates/idea_card.md`](../templates/idea_card.md)。

## 0. 一句话

> **idea 不是先猜再验证，而是从测量和痛点里，用成熟的“研究动作”推出来；用最便宜的决定性 pilot 筛；按证据等级爬升；没被证据否定的 idea 只“搁置”，不“杀死”。**

v1/v2 的 idea 来自概念二分、“X ≠ Y”模板和单篇论文的 future work，所以几乎必然有近邻、多半测不出东西（诊断 §2）。v3 把选题改成“选领域 + 驻留”，但没有规定驻留时 idea 从哪里来、怎样筛——这会让驻留要么退回“猜现象”，要么滑向“再搭一个框架”。本文件补上这一段。

---

## 1. idea 的合法来源（idea 卡必须写明是哪一种）

1. **痛点**（PAIN_LOG 的 P##）：在强基线上真实遇到的坏掉、不稳定、慢、指标不一致。
2. **测量异常**（实验卡 E##）：领域标准测量表里的离群格、非单调曲线、对角线之外的异常（例：交叉配对矩阵里某一列整体塌陷）。
3. **强基线的成功**：强基线为什么在旧方法失败的地方成功？哪个旧瓶颈消失了、哪个设计变得不必要？
4. **近邻自认的局限或近邻之间的分歧**：来自定位表，而不是单篇论文的 future work 句子。

**不合法的来源**（出现即退回）：概念二分 / “X ≠ Y”模板；单篇 anomaly 或 future work；“A + B 还没人试过”；“最新模型还没在这个数据集上测过”。

## 2. 研究动作（把来源变成 idea 的操作）

每条来源至少试 2–3 个动作，各写一个 SEED。范例取自本仓库题材库与顶会论文（详见 `library/README.md` “生长模式”与各题材的论文卡）。

| 动作 | 问法 | 顶会范例 |
|---|---|---|
| 强基线翻案 | 现象是不是因为基线没按当代配方训练 / 没做等算力对照？ | ResNet Strikes Back；多智能体辩论在等算力下不稳定胜过 self-consistency（ICLR 2025 的评测分析） |
| 定位 | 问题出现在哪个阶段 / 层 / 位置 / 规模 / 训练时刻？ | Lazy Agents → Dr. MAMR（ICLR 2026：推理智能体的因果影响随训练下降，根源在归一化）；视频线：网格平移与阶段定位 |
| 命名失败 + 最小修复 | 能不能给失败起名、说清根因、用最小改动修好？ | Dr. MAS（梯度范数不稳 → 按智能体归一化）；TeamTR（“移动靶” → 信赖域） |
| 重新归因 | 大家归功的机制是不是真正起作用的那个？ | RLVR 学习信号的分解；*The Softmax Bottleneck Does Not Limit…*（ICLR 2026） |
| 引入成熟构念 + 测量 | 别的领域有没有现成的构念和测量方法？ | *Teams Hold Experts Back*（组织心理学的 strong synergy）；HiddenBench（hidden profile）；ZSC 的交叉配对 |
| 干预 / 反事实 | 删掉、替换、平移某个成分，结果按预测变化吗？ | *The Narrow Gate*（NeurIPS 2025：消融单个 token 即崩、可定向干预） |
| 设计空间分解 | 很多技巧互相作用时，哪些假设在承重？ | EDM |
| 改变数学对象 | 瓶颈是不是在优化问题的表示方式？ | DPO |
| 规模 / 频率扫描 | 换规模、频率、长度后，哪个抽象成了新瓶颈？ | FAST |
| 成功案例解剖 | 成功来自哪一部分？ | *Cross-environment Cooperation*（ICML 2025 oral：单伙伴 + 多环境也学到通用协作规范） |
| 评测协议修正 | 现有评测是不是恰好避开了问题？ | HiddenBench（接收）；*The Telephone Game*（ICLR 2026 拒 5.33：评测型首投常因规模 / 机制不足被拒） |
| 失败 → 下一篇修复 | 命名的失败本身是后续工作的入口 | *Teams Hold Experts Back*（ICML 2026）→ 同一作者的 *Self-Organizing Agent Teams*（2609.22682） |

## 3. idea 的生命周期

| 状态 | 进入条件 | 下一步 |
|---|---|---|
| **SEED** | idea 卡写好：来源、动作、两种结果各意味着什么、3 个近邻与增量 | 设计决定性 pilot |
| **PILOT** | pilot 的实验卡写好（含阳性对照、噪声地板、决策表） | 跑 pilot |
| **PROMISING** | pilot 落在“继续”分支；相关主张 ≥ L1 | 在 `CLAIMS.md` 建主张 C##，按 `EXECUTION.md` §3 往上推 |
| **CLAIM** | 主张在账本里，正在推进 | 由主张账本跟踪 |
| **PARKED** | 暂不推进：排序靠后、成本太高、与形态卡不符、等资产 | 写原因与**重开条件**；不是 kill |
| **REFUTED** | 阳性对照通过的前提下，pilot 给出否定结果 | 写证据与学到的事实；可能变成新痛点 |

- **阳性对照没通过 ≠ 否定**：工具无效时 idea 回到 SEED，换工具再测。
- **近邻出现 ≠ 否定**：按 `search/README.md` §3 调整增量（换设定、换证据类型、加方法、加理论）；只有“同 claim + 同证据类型 + 同设定”的已发表工作才算撞车，而且先改增量。
- 每个 workbench 同时保持 **3–6 个活跃 idea**（SEED / PILOT / PROMISING），**同时在跑的 pilot 不超过 2 个**，保证算力集中。

---

## 4. 决定性 pilot 怎么设计

1. **问“哪个结果会改变下一步做什么”**。不会改变决定的实验，不是决定性 pilot。
2. **先做阳性对照**：在已知有效应的地方，工具测得到吗？
3. **再测噪声地板**：同一条件重复测量的波动；预期效应至少是它的 2 倍，否则先想办法降噪或放大效应，不要直接加 n。
4. **n 按决策需要来定**：让置信区间半宽小于“两个决策分支之间的差距”的一半；不要一开始就追求论文级 n。
5. **复用资产**：优先用已有 harness 与开源框架；pilot 用能分出决策分支的最小算力（写进实验卡）。
6. **决策表写在跑之前**（`EXECUTION.md` §2）。

## 5. idea 环节（每次人审时做）

1. 过一遍上次人审以来新增的痛点 P## 与实验中的异常。
2. 对值得的条目各试 2–3 个研究动作，写 SEED。
3. 按下表给活跃 idea 排序（**这是排序，不是判死**）：

| 维度（1–3 分） | 问法 |
|---|---|
| 证据 | 现在有多少证据（L0–L2）？ |
| 增量清楚度 | 相对最近 3 个近邻，增量能一句话说清吗？ |
| 形态匹配 | 它落在 territory 形态卡里的哪种可行形态上？ |
| 成本 | 决定性 pilot 多便宜？（越便宜分越高） |
| 可完成性 | 在单节点算力下，把它推到 L3 需要多少实验？ |
| 两种结果都有用 | 为真与为假是否都能进论文或改变方向？ |

4. 选前 1–2 个进入 PILOT；其余保持 SEED 或写明 PARKED 的原因。

---

## 6. 从 idea 到论文主旨

当一个 idea 的主张到 L2：
1. 在形态卡写一句话主旨，检查它**比上一版更简单**；
2. 检查两种结果的论文形态都成立（territory 卡的“可能的论文形态”）；
3. 更新定位表（`templates/positioning.md`）；
4. ACL 系会议加做 Sasano 标准检查：一个 RQ 对一个 finding；引言既 納得 又 面白い；“そうだよね”测试。**这些检查用在主旨阶段，不用在 SEED 阶段。**

## 7. 两个示例

**视频线（RECONSTRUCTED，依据其 README 与评估文档）**：起点是一个宽的诊断视角（时间压缩 / 控制带宽），不是一个猜好的现象。冻结模型上按块内位置测控制响应（测量）→ 块首几乎无响应（测量异常）→ 网格平移一格，失聪跟着块走而不跟着绝对时间走（定位 + 干预）→ 在训练阶段中定位到因果化（定位）→ 真人按键时序下的丢失（后果）→ 推理端块重叠（最小修复）。每一步都是一个研究动作作用在上一步的测量结果上。

**多智能体线（`workbench/multi-llm-collaboration/ideas/`）**：压力 P2（ZSC 教训）与提示式 LLM 对陌生伙伴较稳的事实相遇 → I01“主流框架训练出的团队的交叉配对矩阵”（引入成熟构念 + 测量）。决定性 pilot：同一配置不同种子训练两个 2 人团队，互换成员，比较自配对与交叉配对的准确率；阳性对照是未训练团队（交叉配对应与自配对无差异），噪声地板是同一团队的重复评测波动。两种结果都有论文形态（territory 卡 §2.7）。
