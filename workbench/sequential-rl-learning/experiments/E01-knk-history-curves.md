# E01：数学 RL 之后再学 KnK，学习过程和从 Base 起学有没有不同？（2026-11-28）

- **状态：** PLANNED（等空卡）
- **类型：** EXPLORE（只推理；公开检查点）
- **对应：** I01（SEED）
- **问题（一句话）：** 同一个 Qwen3-1.7B-Base，一条直接用 RL 学 KnK，一条先在数学上 RL 1000 步再学 KnK；两条 KnK 学习曲线（各难度、外推、长度与格式、数学保留）有没有超出噪声的差别，差别在哪里。
- **为什么值得做：** 现有“RL 之后难学”的证据（Tiwari）没有起点匹配和同步数从头对照；这组配对的起点几乎相同（Sheng 表 6：KnK pass@1 2.1% vs 3.4%），学习空间大（Base 起训 1000 步到约 70%），天花板混杂小，且不需要训练。
- **设置：**
  - **检查点：** 两种算法（MaxRL-DPPO、GRPO-DPPO），每种两条起点（Base / MaxRL-Polaris-1000）。MaxRL 对取 KnK 步数 0、100、200、400、700、1000；GRPO 对取 0、200、500、1000。步数 0 = 起点模型本身（两种算法共用）。共 18 个检查点（id 见 README 资产位置）。
  - **评测集：** (a) `max-rl/knk_n3_12` eval 1000 题，人数 3–12 各 100；按与推断训练集的关系分组：训练内人数（3,4,5,7,8,9）、未训练的中间人数（6）、外推（10–12）。(b) `ftajwar/knights_and_knaves_fraction_reward` test 1000 题（人数 10），作为与原作者口径对照。(c) 数学保留：MATH-500 中按难度分层抽 200 题。
  - **提示与模板：** 先审计。主口径用推断的训练提示（fraction_reward 的提示尾），用各检查点自带 `chat_template.jinja`、`add_generation_prompt=True`、不传 `enable_thinking`（与 verl 训练时一致，不插空思考块）；把 eval 题改写成该提示尾。另跑一次数学式提示尾（n3_12 原样），检查提示敏感性。数学题用 Polaris/maxrl 的数学提示。
  - **解码：** T=1.0、top-p 1.0（`generation_config.json` 没写温度，只有 max_new_tokens 2048；按 RL 采样惯例用 T=1，另在一个检查点上用 T=0.6 抽查敏感性）；每题 4 样本；上限 8192（Sheng 的 KnK 设置）；vLLM。
  - **判分：** 取最后一个 `\boxed{}`，按 reasoning_gym `_normalize_answer` 解析为（名字, 角色）集合，与 ground truth 相等为 1（同数据卡）。同时记录“没有可解析答案”的比例，单独报告。
- **读数（一张图，不压成一个数）：**
  1. 每个检查点、每个人数的 pass@1（4 样本均值）与 pass@4。
  2. 学习曲线：准确率对 KnK 步数；派生两种比较——(i) 从起点到某一准确率所需步数（含先前 1000 步数学 RL 时总成本另记）；(ii) 两条曲线进入相同准确率区间后，每 100 步的增量。
  3. 训练内人数 vs 中间人数 vs 外推人数的差别是否随起点不同。
  4. 回答长度、截断率、无可解析答案率（把格式问题和推理问题分开）。
  5. 数学保留：两条起点各检查点的 MATH-200 pass@1（Base 起训一侧同样测，对称）。
  6. 自身样本的平均 token 对数概率（vLLM 采样时顺带返回），作为分布变窄的粗读数。
- **阳性对照：** Base 起训 MaxRL 最终检查点在 fraction_reward test 上应接近 Sheng 表 6 的 KnK pass@1 69.7（若该检查点就是 Sheng 的在线 MaxRL KnK 专家；未核对）；起点 Base 的 KnK 应接近 2.1。若相差超过约 10 点，停下审计模板与判分，不解释曲线。
- **噪声地板 + MIE：** 评测抽样噪声：整体 1000 题 × 4 样本，pass@1 的 SE 约 1–1.5 点；单个人数 100 题约 4–5 点，用题目 bootstrap 给 CI。**训练种子噪声无法从公开数据估计**（每条起点只有一次训练）：这是本实验最大的限制。最低限度的重复是看两种算法方向是否一致；任何差别都只当作“这对公开训练里出现了”，不当作 RL 历史的效应。
- **混杂审计：**
  - 起点准确率：已基本控制（2.1 vs 3.4，本实验复测）。
  - 训练超参是否两条一致、是否加 KL、`dppo` 含义：未控制（未公开），写进限制；如能从作者处查到再补。
  - 训练集：推断为 fraction_reward，未核对；评测集与其逐字重叠为 0（11-28 核对），同构重叠未查。
  - 格式适配：用“无可解析答案率”单独读出。
  - 训练种子：未控制（见上）。
  - 数学 RL 本身的提示格式与 KnK 相同（同一 maxrl 指令尾）：两条起点面对的 KnK 提示相同，无关。
- **决策表（跑之前写）：** 只写下一步，不写机制解释。
  - 阳性对照不过 → 停，查模板与判分，不看曲线。
  - 两条曲线在所有读数上都落在 CI 内，两种算法一致 → 这对公开训练里看不到先前数学 RL 对学 KnK 的影响。下一步：不推断任何机制；写自训练设计（分叉自 `max-rl` 数学轨迹的不同历史长度、多种子，并加一个与数学格式差别大的目标任务），交人审。
  - 某些读数有超出 CI 的差别，两种算法方向一致 → 记录差别出现在哪（速度 / 上限 / 外推 / 格式 / 保留），补中间检查点与 4B 的 100–400 步核对方向；然后写自训练设计（同上，重点是种子方差与历史长度的剂量），交人审。
  - 两种算法方向相反 → 记录为算法相关的现象；下一步同样先写多种子自训练设计，交人审，不先下结论。
  - 只有格式（无可解析答案率）不同 → 单独记录，曲线比较改用“可解析样本内准确率”再看一次。
- **算力预算：** 18 个 1.7B 检查点 × 约 3000 次生成（KnK 2000 题 × 4 样本 + 数学 200 × 4 + 提示敏感性子集）；先用 1 个检查点测吞吐再定，预计 ≤ 8 GPU·时，单卡独立任务，可分到多张空卡并行。权重放节点本地 `/tmp`，不在 NFS 上轮询。　**实际：** —
