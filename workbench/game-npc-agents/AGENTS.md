## 通用知识与资产

- `knowledge/` 保存领域论文与跨方向综合；B–E 保留各自的问题地图。**本工作台根目录** `CLAIMS.md` / `PAIN_LOG.md` / `ideas/` / `experiments/` / `logs/` 用于新研究，历史实验与主张仍仅在 `mine-a-persona-strategy/`。不把 A 的实验或旧编号迁移、续跑或记入新账；B–E 本身尚无实验。
- 一篇论文只保留一张现有权威卡；通用与专属目录互相链接，不复制两套。仓库`library/`已有卡继续按原位置引用。
- 原作者事实、代码事实、我们的解释与未排除解释分开；阅读范围和身份如实记录。用整体问题与证据链判断增量，不逐组件压缩主张，不以相关工作自动关题。
- 角色表达、情境意图、实际动作、物理后果及玩家体验分开；不把任务分数、Give或服从当全部角色利益。
- 大raw／模型／源码cache保留原位置，Git存轻量结果、来源和复算代码。迁移不得改写历史JSON的输入路径、hash、指标或证据等级。
- 新主线聚焦单角色与玩家的 Role-playing，不以多人博弈、社会模拟、通用游戏微操作取代人物研究；语言与有意义的叙事行动可同时评价。不得把隐式效用阈值、模拟玩家或 LLM Judge 自动当作人物心理或玩家体验的金标。
- 旧矿区 A 的 Step Token Plan 限制、节点、环境及历史权限留在 A 原有[执行规则](mine-a-persona-strategy/AGENTS.md#资源权限与资产)，**不会自动转移给新驻留**。新研究如开始实验，仍依仓库根[执行协议](../EXECUTION.md)建立独立实验卡、明确研究目的、预算与授权；本次仅完成注册/文件整理。
