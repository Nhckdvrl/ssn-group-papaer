# CPDC 2025：更接近角色工具决策的数据，但公开样例不是完整游戏引擎

更新：2026-10-13。来源：[官方挑战说明](https://www.aicrowd.com/challenges/commonsense-persona-grounded-dialogue-challenge-2025)、[Multi-Expert NPC 技术报告](https://arxiv.org/html/2511.01720v1)、[公开参赛实现](https://github.com/MahammadNuriyev62/CPDC-challenge-2025-solution)。本轮读官方任务定义、报告主体方法/训练/评价及指定代码路径。属于 Wordplay/EMNLP 2025 workshop/shared-task 相关工作，**不是 EMNLP main 论文**。没有检查私有官方评测服务器。

## 一、为何值得进入我们的知识库

Task 1 面向工具调用，Task 2 面向人物/背景对话，混合任务强调兼顾二者。官方没有把 Task 3 另附的一套独立混合训练集当作资源。角色、worldview、知识、state、工具 schema 与对话同时出现，比只有角色回答的任务更接近 NPC 的调用决策问题。

**DOCUMENTED 方法：** 技术报告用专门化组件分担工具选择、无工具回答及人物对话；部分分支移除工具信息或抑制调用。**RECONSTRUCTED：** 当一个模型同时背负“像人物”和“按协议行动”的目标，作者不是先设计复杂世界模型，而是让执行路径不同的任务分工。这既是可复现基线线索，也是不能再冒领的 ownership。

## 三、为什么这些区别会直接改变实验设计

同一批自然对话可以回答“给定正确历史时，NPC 能否选择正确的工具”；它不能单独回答“错误行动发生以后，NPC 能否在后续世界中恢复”。两个问题都值得做，但推断范围不同。

若对调用列表排序，顺序敏感动作就不能靠该读数判断执行等价；若先前状态来自 gold，模型自己的错误不会自然传导。不能用这样的测试宣称长程闭环可靠性。这里限制的是我们使用这份样例的解释，不是对整个竞赛质量作判断。

## 四、数据比马上训练更优先

报告的增强保留原对话/调用骨架。后续应记录 original conversation 与衍生样本的 lineage，按源对话/场景分组划分，而不是把换措辞的样本当成独立证据。当前尚未完成发布文件的全量去重、许可证、原始/增强关系审计，因此不宣称已得到一个可直接发表的测试集。

第一项数据工作是统计：调用/不调用比例、合法动作集合、每类角色约束、任务状态、参数类型、消息历史、可确定性标签与歧义。已有文件不自动拥有“哪些 persona 信息真的影响选择”的标注。抽样阅读自然样例后，再决定是否能低成本补足这层标注。

## 五、最强近邻不能漏掉

[Talk Less, Call Right](https://arxiv.org/html/2509.00482v1) 已讨论角色工具代理的多说/少行动问题；[Deflanderization for Game Dialogue](https://arxiv.org/html/2510.13586v1) 已针对过度人格化和任务表现采取干预。本轮对这两篇为摘要/定向正文阅读，不冒称完全精读。它们足以否定“首次发现角色妨碍工具调用”的空白假设，但不自动否定更细致的因果/测量研究。

## 六、当前决定

CPDC 是**优先做数据审计和离线工具决策诊断的候选**，不是已经选定的最终 benchmark，更不是已跑通的在线游戏。我们优先问哪些角色信息应影响行动、哪些只应影响表达；若样例缺少足够自然的两类对照，就调整问题或换资产，不靠大量人造角色把故事硬造出来。完整代码/权重/许可复现、正式分数和任何 GPU 实验均未完成。
