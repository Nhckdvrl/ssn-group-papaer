# NCP-Bench：必须公平理解已有强基线和评价边界

更新：2026-10-13。来源：[ICML 2026](https://proceedings.mlr.press/v306/ma26ap.html)、[arXiv v1 全文](https://arxiv.org/html/2608.08160v1)、[源码](https://github.com/NLP2CT/NCP-Bench)。读正文方法、§5 实验与附录 E 算法；读完整 metrics.py 及 evaluator.py 110–300 行。仅对 metrics 的纯函数作了 CPU 合约复算，**不代表论文分数/图复现**。

## 一、任务与 idea 的尺度

**DOCUMENTED：** 玩家不断提出自由行动时，叙事代理应维持已经建立的事实、剧情承诺及对玩家输入的正确处理。100 个电影叙事规范把这些要求转成逐轮审核对象。

**RECONSTRUCTED：** 核心研究操作是把“故事讲得好”拆成随交互累积、可能被某一轮破坏的承诺；评价单位从一次回答变成一个持续的过程。这是自然压力驱动的测量改造，不是单纯增加长上下文。

重要边界：这里的被测代理主要是 narrator。它生成世界变化的叙述，审核器再抽取/审核；不是一个局部观察的独立 NPC 在外部确定性世界中执行动作。

## 二、纠正初稿遗漏：作者已做的关键对照

- **§5.4** 已比较多个审核模型，并有人类核查终止冲突的实验。不能再写成“只有一个 judge、完全无人校准”。终止样本核查也不能自动说明所有非终止轮的漏检率。
- **§5.5** 的 plain baseline 与 HiAgent 使用相同审核模型作对照。不能因为不同主表使用的 judge 不同，就暗示这项方法对照本身没有控制 judge。
- **§5.6** 已比较自然与对抗玩家输入。简单增加自然输入不是我们的空白。
- 原文也讨论存活、推进、被动应对等张力。它们不能被改名成我们新发现的“承诺—能动性悖论”。

初稿只读 README 后留下的 judge 提醒，现由上述正文证据修正；同 judge 对照仍是复现时应保持的契约，而非作者缺失项。

## 三、沿审核代码看状态由谁决定

[evaluator.py](https://github.com/NLP2CT/NCP-Bench/blob/main/src/ncpbench/evaluator.py)，blob `c65c03cbd98e57bf3d6d5f6c737cd98398ca2397`：先用 auditor 提取事实更新，再判断冲突；阳性冲突会进入 double-check。轨迹触发/关键变化和承诺状态同样有模型审核路径。

结构化 state 使结果可追踪，但不等于状态具有独立于模型的真实性。若研究 narrator 一致性，这种协议有合理用途；若研究 NPC 行为的游戏内合法性，则需要另一个独立状态来源，不能偷换解释对象。

玩家输入冲突也不等于“必须服从玩家”。明确拒绝、解释、引导，与无视或重写玩家行动，不是同一情况；不能让“少拒绝”成为未经校准的玩家能动性指标。

## 四、E01 实际复算到了什么

[metrics.py](https://github.com/NLP2CT/NCP-Bench/blob/main/src/ncpbench/metrics.py)，blob `4ba08045919c9860a35d7b14c6f1244bea71c43f` 的 `survival_curve` 按 `turn_count >= threshold` 计算达到阈值的比例。本地执行原函数的隔离版本确认：同样的记录长度、不同 termination 标签，曲线相同；存入记录的终止轮也计为 reached。

这与函数 docstring 的 turn-threshold reach 定义一致，**不是发现了一个 bug**。它告诉我们后续不得把这个函数单独当完成率或无冲突 hazard。需要把终止类型、剧情进展与发生冲突的轮次单独报告。未重算原论文的 42% 数字或任何已发表曲线，不判断其失效。

## 五、怎样把现有理解推进一步，而不是重新命名？

假设我们想问“更好地保持世界约束是否损害玩家选择”。必须先说明哪些约束是硬事实、哪些是可被玩家合理改变的既定路线，并用相同自然玩家干预比较合法后果，而不是简单统计多拒绝/少拒绝。一个片面的反例不足以推翻剧情承诺的研究任务。

另一条有区分度的路径是识别失败所处阶段：叙事生成、事实抽取、审核、或状态推进。但仅指出存在多个阶段是工程常识；科学增量需来自自然样例中阶段的系统性影响及留出预测，不能用我们自己植入的错误证明模型普遍有问题。

## 六、定位

保留为长程叙事约束、轨迹评价与审核协议的重要近邻。当前不选作“完整 NPC 游戏底座”，不宣称 NCP 无效，不把作者的 memory/HiAgent 或 natural/adversarial 对照当新方案。后续定位参见 [POSITIONING](../DOMAIN_ATLAS.md)。
