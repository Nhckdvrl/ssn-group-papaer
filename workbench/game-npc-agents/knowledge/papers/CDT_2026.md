# CDT：可执行的角色逻辑，不等于完整 NPC 的行动引擎

更新：2026-10-13。来源：[ACL 2026 正式页面](https://aclanthology.org/2026.acl-long.568/)、[正式 PDF](https://aclanthology.org/2026.acl-long.568.pdf)、[代码](https://github.com/KomeijiForce/Codified_Decision_Tree)。本轮读正文方法、主要实验/消融及附录 D/E，并查看表格；源码核查 `codified_decision_tree.py` 1–210 行、`run_benchmark.py` 1–265 行。未训练、未重跑模型，不宣称全部源码完成审计。

## 一、研究问题与方法的真实含义

**DOCUMENTED：** 用故事中的情境—行动资料形成条件化的角色决策逻辑，而不只把角色压缩成一段静态 profile。条件树在不同情境取出适用规则，再为行动生成提供依据。

**RECONSTRUCTED：** 人物“善良/果断”等总括描述对具体选择往往欠确定。一个更可检验的中间对象是：在什么条件下，人物倾向作什么选择？树将这个关系变成可检查、可比较、可局部细化的结构。值得学的是找到比抽象人物介绍更接近决策的表示，而不是“决策树”三个字本身。

## 二、顺着实际运行路径看

[run_benchmark.py](https://github.com/KomeijiForce/Codified_Decision_Tree/blob/main/run_benchmark.py) 的关键链路是：情境文本 → 条件语义判别 → 树遍历得到 grounding → 生成一句行动描述 → 以原作行为作参照评价。`check_scene` 使用分类模型返回 True/False/None；树的条件并非全部是由游戏引擎精确给定的布尔量。

评价将预测行动与原作行动的关系分为 entail/neutral/contradict，映射到 100/50/0。这能够研究角色行为预测，但**没有在此链路中执行库存、位置或任务状态的变更**。因此，“代码化”不等于把角色行动全部变成确定性游戏逻辑。

源码版本：构建脚本 blob `418db7bde3aca65e9e2251df4ba969d6766a5cb9`；benchmark blob `6d5318065014f21ebf37c6b473bdcb2ef29c1db8`。源文件有模型/API 的模块级初始化，未直接 import 到本地 CPU 审计中。

## 三、作者已经补过哪些重要证据

不能将本文写成只做单步离线复述。**附录 D 已有新起始情境下的多轮交互与人类偏好评价**；正文及附录也比较不同表示、规则组织、验证和模型配置。附录 E 单列构建/运行成本，提醒我们把生成树的代价与部署时的代价分开。

所以，“拿到新情境测一测”“把树与平铺规则比较”“看真人是否更喜欢”不是自动属于我们的新思路。若继续研究，必须明确原文哪一项干预仍不能区分我们关心的解释。

## 四、哪些推理仍需谨慎？

- 原作中某一次行动既受人物倾向影响，也受剧情安排、可用信息和行动机会影响。观察到情境—行动规律，不能直接把它叫作人物的因果动机。
- 相同情境可能存在多种符合人物的选择。与单条原作行为不相同，并不必然意味着脱离角色；而 neutral 与 contradict 的语义判别本身也需要校准。
- 树检索得到正确规则但条件判别错了，与树本身学错了，是不同的失败阶段。只报最终行动分数可能混淆二者。

这些是可进一步检验的边界，**不是已证实的原论文缺陷**。

## 五、实验设计逆向训练

在不知道树方法是否有效时，先把问题拆成三个可变因素：规则内容、条件判断、用于行动生成的方式。若真实失败发生于条件判断，给 oracle 条件标签比更大的生成器更有区分力；若 oracle 也无帮助，则应检查规则内容或生成阶段，而不是继续优化条件分类。

但这个诊断只能定位瓶颈，还不是论文贡献。真正值得追的是：这种分离是否改变我们对“角色知识如何影响决策”的认识，并能在未参与设计的新角色/情境上预言何时成功、何时失效。

## 六、对本 workbench 的具体作用

CDT 是角色逻辑/行为解释的强方法近邻，可作后续 grounding 对照，不直接充当在线 NPC 世界。我们暂优先调查**相关角色信息应改变行为、无关风格不应改变任务决策**的双向要求；不能只把 CDT 换一个提示词并包装成新方法。
