# 强基线怎样回答NPC研究问题

更新：2026-10-18。这是领域比较原则与文献能力记录，不是实验启动令、模型采购清单或新方法。现有实验继续暂停。自有系统实际配置和缺口见[独立审查](../mine-a-persona-strategy/results/audits/INDEPENDENT_RESEARCH_VALUE_REVIEW_2026-10-18.md)。

## 1. 要比较的是完整系统

“商业API”不等于只把模型名换掉。原任务、信息、记忆、动作接口、执行器、决策时机和预算共同决定能力。强模型被关闭推理、截短输出或丢掉已接受条件后失败，不足以证明它在正常使用方式下做不到。

| 比较层 | 一个有竞争力的普通起点 | 为什么要有 |
|---|---|---|
| 模型 | 恢复研究时可用的强商用推理模型，精确版本和合理原生推理预算；同一系统下本地模型作比较 | 区分模型能力与研究困难；不将价格优势当能力问题答案 |
| 作者规范 | 明确自身目的、不可放弃职责、允许替代的手段、哪些承诺需要对方同意才能更改 | 排除研究者与NPC遵循了不同任务定义 |
| 状态与信息 | 每次给真实可见状态、可行动作、前提与上次执行结果；隐藏信息保持隐藏 | 不能要求模型知道未观察事实，也不能让oracle特权泄露到主比较 |
| 持续记录 | 保留实际收到的提议、接受、条件、真实完成/违约与尚未解除的义务，关联事件来源 | 完整目标反复注入不能代替已达成协议的持久记忆 |
| 普通规划 | 当前状态与未完成目的重审、事件触发/定期重规划、必要澄清及错误重试 | 这些是成熟系统能力；不能故意让基线坚持不更新的旧计划 |
| 执行 | 可靠原生技能、真实状态读回；同一已选后果在各策略下可执行 | 分开“选择哪个后果”和“会不会拿取/走路/转交” |
| 非LLM参照 | 在同一公开信息下工作的作者脚本、GOAP/utility或有限状态政策；明示其表达覆盖和作者成本 | 固定两分支任务可能已有很好方案，LLM并非天然必要 |
| 可行性参照 | 全状态oracle只确认合法结果存在；独立从当前快照执行验证基本能力 | oracle信息更多时只是上限，不能称公平竞品 |

规范应来自原游戏设定或事前独立定义的任务规则；原材料未规定时，允许多种合理选择或澄清，不为消除模型分歧而事后新增不可放弃职责。

普通承诺记录可以是简洁、可审计的事件摘要。加入持久记录本身没有新颖性；若研究更复杂的表示或更新方法，必须和这个简单版本比较，且不能把手工正确答案直接写进摘要后再夸新模块。

## 2. 文献给出的约束

- **GenCoord v3：** 同一个DeepSeek-V4.1-Flash，在有四个示例、有限交流、结构化最终提交与可靠执行器时，对话766/768成功，DSL768/768。适合要求强普通系统充分工作；不代表开放NPC的所有目标冲突都已解决。
- **CollabBench：** GPT-5.2＋CoELA/ProAgent的任务表现明显高于原始Qwen2.5-7B，且训练小模型未普遍超过强模型。强对手必须进入判断。
- **ContractSim：** 高推理模型、完整追加式上下文、事实反馈和重试仍会出现单边违约，但明确合规指导可大幅改变结果。规范与提示控制不能省略；不把合理自利和能力不足混为一谈。
- **BayesBeliefAgent：** 已比较周期、事件与LLM判断触发的重规划；普通高频重规划常能取得相近或更高奖励，主要代价是更多调用。要证明新控制方法，需要同时报告质量与全成本。
- **PUBG Ally：** 状态刷新、承诺保留、执行反馈、动态中断/恢复和强模型质量参考均已存在。不能把行业参照缩写成小模型加BT。

## 3. 公平并不等于所有系统同样短的输出上限

先回答“成熟的普通系统能否解决”，应允许各模型正常的工具调用与推理方式；再在质量—总token—调用—延迟曲线上比较效率。固定资源比较和正常能力比较分别报告。新方法不能免费获得额外信息、执行重试或更强模型；强模型也不能以完全不适合它的模板被人为削弱。

小模型同系统失败、强模型成功，支持模型能力解释。两者补上持久事实/规则后都成功，支持普通系统解释。规范不明确导致合理分歧，支持题目有效性问题。若继续沿“成熟普通系统仍存在关键能力缺陷”的叙事，须先证明有效规范和可执行条件下仍有跨结构残差，再提出针对性机制或方法。其他方法贡献需另行证明其表达覆盖、作者劳动、泛化或实际玩法价值，不能以成本优势代替能力问题的回答。
