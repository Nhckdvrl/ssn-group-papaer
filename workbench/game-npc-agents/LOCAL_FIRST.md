# 研究室资源下的全本地 Game NPC Agent 研究（安全/社会/经济/训练通用）

更新2026-10-14。研究室十余张 A100、8 张 RTX PRO 6000，实习方16张 H20；网络/磁盘/跨节点通信差。**它们不是一台高速GPU mesh，也不能默认不同单位数据与节点可通用。**

## 全链条零付费推理 API
核心 NPC、玩家/攻击者、其他 NPC、总结/记忆、world judge、教师、攻击提示搜索和重复评估都在本地 vLLM/SGLang/llama.cpp 或 CPU/规则中完成。云 API 默认禁用，明确配置 endpoint/token和模型版本；断线失败不能自动回退 OpenAI/Anthropic/Gemini 服务。
模型在PCIE单节点推理可按角色/回合分配；不要因有16卡就强行跨节点同步训练大模型。代码/数据/权重优先节点本地盘顺序写入压缩 JSONL/Parquet，不在共享NFS写海量小文件。
从有结果的配置逐渐增加模型家族/场景/seed，并设置读数可信的独立留出任务，避免同时铺开所有方法×模型×攻击类型×NPC人数。存完整模型、tokenizer/chat template、API版本、action schema、上下文裁剪、重试/失败代价及GPUh。

## 不同研究线的实际成本
| 研究线 | 最容易漏算的成本 | 合理组织方式 |
|---|---|---|
| NPC被攻击与防御 | attacker 每次试探 + defender多轮历史 + judge + 反事实复测 | 先规则/手工自然输入和单本地模型，强攻击预算/普通玩法成功率相同成本核验，再独立更多模型 |
| 长期人格与关系 | 100+轮大量 KV cache、每个NPC记忆整理、伙伴模拟和行为judge | 先自然已存在的游戏轨迹、冻结状态回放与真实行动；不同时间点配对，必要时少量本地judge并人工校准 |
| 多NPC经济 | O(N·turns) 模型调用和CPU匹配/订单日志，密集经济动作会吞噬GPU | 世界/市场CPU结算；很多规则/小策略NPC + 少数本地LLM角色，分层采样与批处理；LLM只在有价值的谈判/策略时决策 |
| 行为学习/共享policy | 环境steps/s、actor数、CPU瓶颈、奖励设计和数据采样、训练seed | 先单节点 PPO/BC，记录真实吞吐、样本/人工设计量，再独立多种子 |
| Minecraft/视觉世界 | 服务器与渲染、8 agent LLM并发、视频 IO、Docker端口冲突、专有权重 | 先核已有日志/开源数据和一条本地完整游戏链；避免一开始全量视频训练 |

**具体案例：** Shiomi2025本地3.8B GGUF CPU单轮可做风险示例但不满足长程证明；KDD2025 MMOAgent论文主体用GPT-3.5、judge用GPT-4，切换自托管需要重建立口径；AI-Bazaar官方README已有 --service vllm/ollama，适合先做成本 profile；MineAmongUs官方demo 默认还用付费API、作者报告单match约15min，不可直接称0 API。以上不是在用户机器上的实测时间/费用。

## 证据与授权
游戏引擎记录/货币库存守恒与作者披露约束通常可作为客观指标；角色可信度与玩家体验需要人工/玩家校准，不能拿同源模型评分替代。玩家模拟器不能代表真实人类。禁止在未经授权的线上游戏、真实账户或真实玩家财产测试任何攻击；用虚构资产、隔离测试。必要的厂商数据、许可证和实习设备使用权限单独审查，不把信息公开进Git。
