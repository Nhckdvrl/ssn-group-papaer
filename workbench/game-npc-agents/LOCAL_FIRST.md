# 全链路本地研究：资源、API 与证据预算

2026-10-13 用户明确约束：大量付费 API 不可承受，优先自行部署。研究室十余张 A100、8张 RTX PRO6000；实习方16张 H20。具体空闲、显存型号、拓扑及使用许可必须现场核实；不把跨节点/跨机构资源视作一台集群。

## 1. 默认预算是零付费推理 API，不是“主模型本地就够了”

核心闭环的 NPC、伙伴/玩家模拟器、规划器、记忆整理、数据生成、教师、裁判与失败重试，都需要可在授权本地节点运行，或以规则/公开静态资产替代。外部 LLM 服务默认禁用；本地服务端点须显式配置，不允许脚本未配地址时回退云端。用户将来明确批准的少量外部校准单独登记，不能成为结果可复现的必要条件。

模型与公开数据的一次下载不等于推理 API 消费，但仍有网络、磁盘、许可与时间成本。免费/预览 API 不是稳定复现资产。对模型名称、SDK、环境变量做静态搜索只能发现入口，实际运行还要检查每个请求目标，不能用“没有 OPENAI_API_KEY”证明无外联。

## 2. 每个角色与环节都要入账

| 环节 | 起步默认 | 能证明什么 / 尚不能证明什么 |
|---|---|---|
| NPC 决策 | 单节点开放权重，固定 revision、输入协议与解码 | 对该模型/条件的行为，不自动代表前沿闭源能力 |
| 游戏世界 | 可离线执行的引擎/状态机 | 规则内动作与状态后果；剧情意义不一定全可符号化 |
| 伙伴/玩家 | 规则策略、公开政策、必要时另一独立本地模型 | 配对鲁棒性；模拟玩家不代表真实人类偏好 |
| 记忆/规划 | 简洁固定策略或同一服务的显式调用 | 必须计调用和 token，不能算免费 harness |
| 任务评估 | 真实终态/事件/约束优先 | 任务结果、合法性；不是自动人格/趣味金标准 |
| 语言与角色解释 | 本地独立 judge + 分层盲化人工校验 | 经校准的代理指标，不得未经验证写“更有趣” |
| 教师/数据 | 先用已有合法自然数据；必要时本地教师 | 记录生成成本/来源/错误，不能拿教师偏好当世界真值 |

总成本按所有环节的调用数、输入/输出 token、重复采样、wall time、GPU分配小时及 CPU/I/O 统计。world/partner/judge 共享同一模型可能产生自洽偏差；首先让状态事实独立，不靠再叠三个同源裁判制造可信度。

## 3. 模型与节点安排

先以7–14B级开放权重建立单节点 frozen-policy 测量，加入至少一个不同家族的参考；规模是初始部署范围，不是锁定所有实验只能用小模型。需要更强参照时，24–32B或单节点更大模型须通过显存/上下文/吞吐实测，不能仅凭参数量推算能跑。70B并非原则上禁止，但不能默认把每个玩家和judge都配置为70B。

推理能力不足先区分动作接口、基本任务技能与研究中的行为问题；不把小模型地板效应写成通用 NPC 规律。替换闭源模型是重新建立受控本地基线，不等于复现原论文成绩。SFT/LoRA/RL 在真实瓶颈出现后选择，不能为了“我们有卡”提前确定方法。

每个独立实验尽量在单卡/单节点完成。多卡用于互不依赖的场景、模型、伙伴和复现种子；串行的关键判别没回来前，不铺满整个笛卡尔积。一次缓存权重、紧凑轨迹与数据到节点本地盘，避免共享盘随机小文件与连续视频流。游戏模拟可能卡在 CPU 而非 GPU，必须一起测。

## 4. 已核查的成本反例（作者报告，不是本机测量）

- [Hypothetical Minds 论文B.1/表5](https://arxiv.org/pdf/2407.07086)：指定1000-step场景的GPT-4版本约$10一局，Llama3版本4卡；[README](https://github.com/locross93/Hypothetical-Minds)确实提供 vLLM 路径。可本地不等于便宜，更不等于直接用 README 的云端默认命令。
- [GAMMA附录E](https://liangyancheng.com/assets/pdf/NIPS2024OvercookedZSC.pdf)：全套主实验约3600 GPUh，还需要大量环境并行。它是小政策网络，却不能因为参数少就承诺全量复现低成本。
- [Proact-VL §5.1](https://arxiv.org/html/2603.03447v4)：约200 H100 GPUh主训练；多个评价依赖 GPT-5.1。不能把这一数字移植成A100/H20/PCIe单节点的工时估计。

以上只用于排除草率的可行性判断；没有实测之前不填本项目GPUh预算、不声称已部署。

## 5. 可执行的准入条件

在有环境的本地节点上，先完成一条不访问付费服务的 reset→局部观察→决策→行动→状态→评分流程，同时做已知成功/无效动作正负控制。随后验证原始自然数据可恢复、引用许可清楚、任务有足够的角色/伙伴差异、基线没有显著地板/饱和。少量流程样例只能证明可运行。

正式实验前冻结 source/model/data/evaluator 的版本和哈希，按源场景而非增强变体切分，记录场景内相关性、随机种子及失败。先从自然轨迹形成候选解释，再增加有区分度的干预与未参与选择的确认数据。不要因为本地 evaluator 难做，就把人工重要的概念改成最容易量化的函数格式。

## 6. 部署资源与研究目标不能混淆

[KRAFTON 的本地小模型方案](https://developer.nvidia.com/blog/how-krafton-built-pubg-ally-a-co-playable-character-powered-by-nvidia-ace/)说明低时延和游戏显存共存是真需求，不提供我们可直接继承的专有训练数据。我们可以在更大的研究GPU上探索规律，也可以研究小模型，但不能直接宣称达到商业游戏实时产品要求。

本轮无 GPU/模型/玩家运行；只完成文献与源码入口核查。实习方私有数据、模型、机器信息和凭证均不写入公开仓库。
