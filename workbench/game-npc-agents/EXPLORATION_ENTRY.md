# 当前探索入口：先进入真实NPC问题，不再执行CPDC预设切片

2026-10-13第三轮，覆盖第二轮入口的执行优先级。前版完整设计可从Git历史或[E02历史卡](experiments/E02-role-relevance.md)追溯；此处不是把旧假说换个名字重新启动。

## 1. 科学对象与当前优先调查

从[问题谱系](knowledge/PROBLEM_GENEALOGY.md)出发，首先调查**有自身目标、能与玩家交谈并通过行动影响世界的角色**。这一方向有LIGHT/goal-driven agents、设计者行为约束、角色逻辑和游戏开发需求的依据。还没有一个已经证明新颖、且由本地数据支持的具体论文问题。

优先审查LIGHT/quests能否提供自然、可审计的角色任务；同时理解当前强角色/协作系统的证据。不得因为一个游戏容易安装就定义它的所有错误都重要，也不得因为旧论文只有短轨迹就自动发明长程benchmark。

## 2. 开始运行前真正必须搞清的事情

**任务的含义：** 角色自己的动机是什么，玩家/伙伴要什么，游戏规则允许哪些路径，文本里的成功和世界里的成功是否相同。先直接阅读来自社区资产的完整任务和成功/失败轨迹，不机械挑一个我们预先期待的现象。

**完整本地链：** 角色、伙伴、环境、记忆、规划与评价逐项核对；参考[LOCAL_FIRST](LOCAL_FIRST.md)。没有付费API回退。独立规则决定客观动作后果，必要的语言评价使用本地模型并校准，不由同一模型给自己造世界又判胜。

**可比强基线：** 恢复作者任务和基线的定义；用当代本地生成模型、适用的规则/检索/规划对照重新建立能力边界。原版、模型替代、任务改造分开报告；不把换模型结果叫原论文复现。

**数据现实性：** 场景、角色、任务来源、许可和split可追溯；任务是否饱和、伙伴是否过于同质、原数据的游戏限制是否决定了现象。十来条样例只用于理解/流程检查，不承担科学结论。

## 3. 先观察，后决定是哪一种问题

不是要求以下现象一定出现，而是明确不同观察会把研究带到不同地方：

| 自然运行后发现什么 | 有价值的后续动作 | 不能怎样解释 |
|---|---|---|
| 模型连基本合法行动/任务都做不好 | 分离接口、世界知识、执行能力；提高基线 | 不能直接宣布“NPC不懂角色” |
| 成功率高但实际角色要求/玩家选择被破坏 | 先核查角色要求与玩家能动性的测量依据，再定位控制来源 | 不能凭LLM批评文字或自己写的道德标准决定失败 |
| 与某些伙伴成功，与另一些失败 | 对照已发表伙伴适应/零样本协作方法，分析任务依赖和行为变化 | 不能重新发现“队友分布重要”就命名新机制 |
| 历史或当前观测的差异预测后续选择 | 查任务状态、目标、信息可见性与既有记忆研究，再做区分性干预 | 不能把上下文更长/随机性直接归为长期关系 |
| 等待/推理使行动错过时机 | 分开状态变化、任务机会、LLM延迟与触发策略 | 不能把tokens/s提升直接写成玩家体验改善 |
| 没有重要失败，强基线已够用 | 记录成功边界，回到领域认识缺口重新定位 | 不能靠更苛刻构造和更多限制强制造困难 |

这些不是必须全部跑的配置表。样例阅读、新表示或新观测可以先于假说；关键实验要说明为什么此时做、哪个结果会改变判断，后续观察允许改变优先级。

## 4. 哪些条件会让我们不选当前底座

数据与当前引擎无法可靠对齐；公开的只有接口没有必要权重/语料；授权不清；本地模型和强规则都显示现有任务过于简单且无法代表要研究的问题；或者恢复工作变成了长期维护游戏平台。这些条件会改变资产/范围，不自动关闭NPC领域，也不回退到用户已否定的CPDC入口。

协作问题若更有信号，可转向本地MeltingPot/Overcooked的NPC伙伴任务，但先明确与角色问题的联系。Proact-VL是主动解说/指导参照，其公开资产可用性提升不意味着本项目要改成视频解说。

## 5. 从线索到论文

每个候选认识必须回答：最强已有解释是什么；为什么当前观察可靠；下一步如何区分实现/默认策略/真正行为机制；如果结论成立，别人会怎样改变控制、评测或训练选择。重要性不能只由“我们可以跑很多模型”支持。

没有强结果前不设置方法名，不预定SFT或RL，也不画胜利曲线。探索结果在未参与选择的场景、伙伴或模型上确认；CPU源码检查不升级行为主张。
