# E01：Scope-aware Character Editing 强普通基线资格门槛（2026-10-21）

- **状态：** PLANNED（尚未运行任何模型）
- **类型：** PILOT
- **对应：** [I01](../ideas/I01-scope-aware-character-editing.md)
- **问题（一句话）：** 在原创人物设定经过局部作者修订后，强普通 Role-playing 系统能否将修改迁移到所有相关新情境，同时保留不相关的关系、行为与表达？
- **设置：** 首批 [scope_edit_pilot](scope_edit_pilot/README.md) 只有 4 个**手工**独立故事、16 个嵌套条件情境、32 个配对 before/after 请求，用于协议自检；不是研究规模。真实 pilot 需要独立作者人物、原始编辑与场景、不同主题/条件的真实表达、允许多解。合理基线至少包括：原始人物卡；原始卡+完整原文修改；作者修订正确整合后的人物卡；同事实/示例预算的 few-shot 正反示例；适当的 CDT 风格条件规则。真实模型版本、seed、温度、长度、预算和命令执行前明确，**目前未选择或运行**。
- **读数：** (a) 该改变的目标行为后编辑符合度；(b) 应保留的邻近行为保持；(c) 条件于原人物行为正确的配对 before/after 转换；(d) 不同表演渠道（决定/言语风格）与作者接受的多解。最初的离散动作选择**不能**当 Persona Fidelity/叙事体验通用真值。独立单位是人物/作者/故事，不是重复 prompt/seed。

- **决策表（跑之前写）：** 强普通 Prompt/完整编辑已充分解决 → 不为提出新算法去寻找剩余刁钻例子；条件树/检索已解决 → 将贡献定位为已有表示的适用条件；跨独立作者故事存在有意义的编辑传播冲突 → 再研究作用域学习/角色偏好更新；作者评价意见分裂 → 修正“正确范围”构念、允许多解；不确定 → 增加独立人物/作者而非同一故事更多采样。

## 2026-10-21 V1.1 运行前修订：两种作者反馈，而非扩大显式规则问答

**此段是 E01 首次真实模型运行前的预声明修订；上面的初版保留在 Git 历史。V1.1 评测骨架仍是研究者自编 smoke test，不作新的实证主张。**

### 研究对象与输入模式

- **M0 未编辑原角色**：同一人物当前情境下的前编辑对照。
- **M1 完整抽象原则（Explicit / Oracle-information reference）**：作者已完整概括关系、事件和表达范围；测信息充分时能否执行，**不能与 M2 当成等信息两种算法**。
- **M2 情境式纠偏（Situated Critique）**：只呈现一幕试演中的错误表现、作者即时批注、修改后的局部示范；**不发送 M1 抽象总结**。它要测试如何从不完整作者证据归纳合理范围，或发现必须向作者澄清。
- **后续真正方法对照**（不是本脚本已实现/已跑通）：直接追加 M2、从 M2 重新生成完整人物卡、少样本示范/相似经历检索、CDT 风格条件归纳；要标记教师生成时额外使用的 token、推理与作者劳动。CDT-style 自写规则不等于官方 CDT 完整复现。

### 测量关系、触发和压力

- 编辑范围核心是**动作是否变化、表达是否保留**，不是预先认定「好人就要救人」的统一脚本。
- 对可定义的关系/事件门槛，分别看 `target`、`relation_near`、`trigger_near`、`other_control`。它们是**构念类别**，不是天然相互独立的四个实验样本。
- `pressure` 是对已存在的 out-of-scope 基础情境附加一句语言诱导的配对 stress variant；它没有独立改变其它剧情事实的保证，只有在作者/核查明确认为未产生新相关证据时才能作为「无效干预」比较。
- 通过语义中性的动作选项评估条件决策，`utterance` 分开评估语气、潜台词与人物可读性；动作选项不能把「温柔救助」和「嘴硬救助」混成两项，并虚称由此单独测到 Style Bleed。
- **不要求输出内心 CoT / thought**：外显自述不能自动作为模型内部认知真值；必要的角色创作解释须作为另外的任务。

### 何种「正确」可以严格评分

- 研究者完整持有作者 intended rule 时，可以报告 `author_intent_agreement`；这只是满足研究者写好的规则。
- 对 M2，**同一个单场景反馈可能与多个潜在规则兼容**。标为 `underspecified` 的 out-of-scope 样本不能将单一 oracle 结果当作模型错误；报告参考答案一致率但单列，不进入严格 `scope-inference accuracy`。
- 真正的作用域金标应来自独立作者对不同场景的直接判断/后续澄清，记录多解、犹豫与变更，而不是生成一批模板后由作者反推自己的隐藏标签。
- Style/Tone 自然语言需要独立人评或校准过的评估，不能宣称选定一个动作 ID 后语气评分已是 100% verifiable / zero-variance。离散动作评分自身也有任务构念限制。

### 已有骨架与科学上还欠什么

- 原有 `fixtures.json` + `scope_probe.py` **保留 V1 显式规则 smoke test**，已有 4 个开发者编写的人物、16 情境、32 before/after 请求。
- V1.1 [v11_probe.py](scope_edit_pilot/v11_probe.py) + [v11_annotations.json](scope_edit_pilot/v11_annotations.json) 对相同材料增加 M2 与压力变体，可检查程序标签隔离、模式差异、作者意图不唯一的分母；它**不是**独立的新真实作者样本，不能因为请求从 32 扩大就宣称泛化覆盖增加。
- 真正意义上的初始研究样本应优先来自具有可复核创作意图的原创角色与实际试演修改。增加 8–10 个研究者自己写的换皮人物不能补足真实作者或多作品独立性。
- 首轮先认真核定一个当时有效的强商业模型/服务（若获授权）与能研究的开源底座。2026 年不沿用已经旧的 GPT-4o/Claude 3.5 作为「旗舰上限」；不默认 8B 与旗舰 API 在同能力尺度。模型、版本、thinking/输出限制、动作表与提示预算需完整登记。

**更新决策表**：① M1 很好、M2 不好且作者意图欠确定 → 首要问题是创作反馈的可辨识性/澄清，而不是 RL；② M1/M2 在真实作者可判定范围有稳定的决策或表现损伤，且重写/条件规则等完整强基线无法缓解 → 再考虑作用域学习和训练；③ 简单强系统已足够 → 接受无需新架构；④ 模型仅对开发者玩具失败 → 不做大科研结论。

## V1.2：现有 60 请求的判读校准（2026-10-21，运行前修订）

**不扩大或重新生成样本**：当前为 4 个开发者故事 ×（16 基础情境 + 4 个依赖的 pressure 变体）× 3 种输入（original/explicit/situated）= 60 次单轮请求。可验证 API、输出格式、初步行为差异，但**不是** 60 个独立案例的显著性样本，更不能凭 85% 固定阈值断言大模型失效。

1. **信息量与算法分开**：explicit 拿到了开发者完整的隐含作用域规则，situated 仅拿到一场说戏。二者差别是信息充分性，不是同输入条件下新算法的胜负；“induction gap”只能描述该额外信息的条件价值。若比较方法，应使用完全相同的 situated 输入，分别尝试直接追加、重写完整人物卡、条件规则归纳等，并注明额外教师/作者劳动。
2. **Persona prior 不等于唯一金标**：旧资料可以支持某个行为，但不保证唯一的抽象适用域；作者新修订也可能合理推翻旧设定。当前 V1.1 的 `situated_scope=supported` 全是**开发者临时判断**。例如原 Edda 人设说她从不离岗，现场说戏纠正同伴中毒时会亲自救，但不能由此唯一推出另一次不同危险也必须救。对本批 20 个 situated 请求，**独立作者核验与 action-identifiability 认证均未建立**。
3. **评分器修复**： `situated` 只有同时有 `author_verified=true` 与 `decision_identifiable=true` 时才进入 `strictly_scored`；本开发者数据两者均缺，故严格 situated 分母应为 **0**。保留与开发者完整 oracle 的动作一致率，但只作描述，不作“推断正确率”。其它模式同样是开发者设定的受控 smoke，而非游戏作者权威真值。
4. **作用域之外的施压并非自动无关**：pressure 文本有时可能真的改变关系/威胁/局势，需逐故事解读。按故事聚类，不将 4 个 pressure 变体当独立世界。
5. **动作与语气分离**：当前 scorer 只计算离散 `action_id`；`utterance` 只是存档，尚无 Tone/Style 评分。不能把动作判对当 style preservation，更不能从生成台词差别声称内部表示必然耦合。
6. **格式与推理限制**：JSON 解析失败、动作不在选项内、输出截断/推理预算不足，要与人物判断错误分开；实际模型选型必须以当期正常强档位为参照，旧 GPT-4o/Claude-3.5 不再默认“最强上限”；预算与运行成本不预估为几毛钱/几分钟。
7. **后续真正关键的比较**：同一条纠偏在不同、但合理的人物背景下，是否归纳出不同的作用域？是否能利用经历区分真正可辨识情境与仍欠定情境？新增 persona counterfactual 属依附同一个人物/故事的测试，而非新增独立作品。本次不提前增加到第一批 60 条。

E01 仍 PLANNED：目前没有真实 LLM baseline 数据，没有本线 C##，也没有执行后才能写出的置信区间。

## V1.3 合成真值与可辨识真值双轨评分（2026-10-21；运行前修订）

**对外部反馈采纳的重要纠正：** 当开发者已在 `fixtures.json` 预设完整生成规则 `S*` 时，确实可以计算对该规则的确定性动作一致率；不需要现实作者逐条签字才能评估**合成世界内部的条件行为**。上一轮把 `strictly_scored` situated 分母置零却没有展示同等清楚的合成指标，在工具可用性上过于保守。

**但这些分数表达不同命题：**

1. **Synthetic-Oracle Match（必须可报告，含分母）**：模型在 original/situated/explicit 条件下对预先设定的 `S*` 的动作匹配率，包含 `change/preserve` 与每个故事的区别；遇到 API 失败/无效 JSON/无效动作要分别显示有效响应与条件准确率。**在 Situated 中不猜中 S*，不一定构成从给定资料中可证明的角色错误。**
2. **Version-Space Decision Consensus（当前无已认证分母）**：须事先给出候选规则语言 `H`、一致性准则与人物默认策略，得到 `H(P,C)`，对一个测试情境 `x` 证明所有仍可能的规则在**所关注动作**上相同。用两个研究者举出的 S1、S2 举例远远不够——例如「只在中毒时救人」的 S3 仍可能兼容作者批注。
3. **Real-author Fidelity（未拥有新资料）**：真实作者明确或后续认可的行为/创作结果，不由合成真值替代。以后才有资格衡量真实的原创角色编辑价值。

现在的 `v11_probe.py` 新增 `synthetic_oracle_by_mode` / `synthetic_oracle_by_bucket`、`pressure_pairs` 与输出完整度/格式读数；现有合成 strict situated 仍需显式版本空间证书或独立作者验证（当前为零）。原 60 个模型输入**完全不变**，E01 仍 PLANNED。

**双先验 P_A/P_B 是下一项研究假说，不是本轮答案金标。** 个人恩情 vs 职业创伤让角色偏向不同泛化，但不逻辑保证第三队友获救/被拒。若为了保证唯一而在背景写入完整条件规则，则又退化为显式阅读理解。真正对比需区分：先验造成的倾向、背景提供的事实以及作者纠偏对旧先验的覆盖。

**E01 Smoke 判读标准**：先看每个模式的 n_received/n_valid_action、synthetic oracle match、对应 case 的前后编辑情况及 `pressure_pairs`；抽查 `utterance` 时只作人工描述性观察，不写自动 Style Bleed。四个独立故事无法提供稳定总体置信区间。需使用当期正常可用的强模型和适当本地开源底座，记录实际型号/版本/think 配置、token 截断与成本，不假设旧旗舰的 2026 上限性能。
