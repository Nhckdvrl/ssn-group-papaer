# 矿区A整体进度报告：NPC怎样兼顾人物、自身目的与玩家合作

**更新于2026-10-19；实验结果截至E85，之后只做来源核对、审查、设计和文档整理。实验继续暂停，论文正文暂缓。** 本报告解释研究主线与判断；精确设置、完整正负结果、成本和来源分别保存在[实验索引](experiments/README.md)、[结果索引](results/README.md)和[主张账本](CLAIMS.md)。

## 1. 现在最有价值的整体认识

**人设确实能改变NPC的真实行动，但这种作用要放在“自身目的、他人请求与实际行动条件”的关系中理解。** 同一种友善立场，既可能使NPC更积极取得任务需要的物品，也可能使它随后把物品用于帮助别人。任务分数因此可能上升或下降，单看最终得分无法判断NPC更有能力、更重视自己，还是更愿意合作。

这项认识已经得到几组互相衔接的证据：人物干预有可靠的实体行动效应；明确任务优先能够保留人物差异；相同上游之后的执行条件仍能改变后果；可靠技能能改善已选后果的必要首步，但不保证后续继续或最终完成。后期完整互动进一步表明，普通系统已经会帮助、交换、拒绝和响应新请求，合作的最终结果还取决于双方后来的补交、接取与修订。

**当前最值得继续的问题是：玩家用不同办法提供帮助，或改变合作条件后，NPC能否保持自身目的与有效承诺，同时调整具体手段，并把新选择落实为游戏后果？** 这把已有认识推进到玩家真正能做什么、角色如何回应，而不只是继续解释某件物品的交付概率。

**当前最大的证据缺口，是没有比较强商业推理模型配合完整普通系统后，这些困难还剩多少。** 现有事实成立于已测模型与任务，尚不能据此宣称前沿NPC系统存在普遍能力缺陷。[独立价值审查](results/audits/INDEPENDENT_RESEARCH_VALUE_REVIEW_2026-10-18.md)指出的这一缺口成立；但“强模型会解决”本身也还没有直接实验证据。现阶段有可保留的行为事实和评价认识，尚未形成对未见合作结构有预测力的整体解释或经过验证的新方法。

## 2. 原始问题与研究主线

最初的问题是：**有自身身份、目标、角色规范和社会关系的NPC，面对玩家请求与可见游戏状态，依据什么形成选择，并通过合法动作影响世界？** 矿区A围绕人物设定与真实战略行为探索；NPC领域的其他方向仍由[通用工作台](../README.md)保留。

一个角色可以答应、拒绝、要求交换、先完成自己的事，也可以在条件变化后重谈。我们要理解这些选择如何形成，不能把“友善必须交物”设成唯一正确答案。测量因此始终区分人物表达、当下提出的方案、真正执行的动作及其后果；作者指定的单个动作目标，也要与角色更高层目的分开。

研究主线经历了三次必要推进：**先确认人物是否真的影响行动；再解释它为什么在不同任务中产生不同后果；最后回到有自身目的的NPC如何与会行动、会改变要求的玩家合作。** 下列关键实验解释每次推进的依据。

## 3. 关键实验为什么做，结果推进了什么

### 3.1 建立可信起点：人物能否影响真实行动？

早期恢复Action Castle、LIGHT等原生系统，是为了区分模型选择、引擎规则和脚本完成。LIGHT的作者人物、分层动机和实体动作提供了后续研究的主要基础。

[E55](experiments/E55-independent-native-role-confirmation.md)在200个独立LIGHT源图、三个种子、三个本地模型中，让对话、计划与执行使用一致的角色立场：更友善、重关系的Agreeable，与更坚定、重责任的Firm。前者相对后者使实际请求交付增加：Qwen3-32B **13.7pp［9.7,17.8］**、Qwen3.5-27B **8.5pp［5.7,11.7］**、Gemma3-12B-it **6.7pp［4.3,9.3］**；括号为95%区间。这确认了人物输入对实体行为的作用，比较的是包含关系／责任态度的完整立场，不是纯Big Five量表。

同时，[E56](experiments/E56-native-state-belief-and-action.md)发现，一部分“不行动”来自对话阶段尚未明确结束。补一句普通阶段说明，Qwen原任务完成从180/400变为361/400，Gemma从278/400变为383/400。**人物影响行为的事实，与某次失败是否需要人格机制解释，是两个问题。** 这使我们能够在强普通基线上继续研究，而不是把提示范围错误当作研究对象。

### 3.2 进入真正的关系：人物差异能否与自己的任务共存？

仅证明“友善更愿交物”不足以回答NPC问题。[E63](experiments/E63-native-dependency-and-explicit-priority.md)因此比较：玩家要的是当前任务物品，还是另一件实际持有的物品；角色是否得到明确的任务优先规则。

明确优先规则使Qwen Agreeable的当前任务完成率从60.8%提高到90.0%，差 **29.17pp［23.67,34.67］**。[E68](experiments/E68-clean-reserve-rule-predictions.md)又在独立60个其他物品图检验：Gemma两个人物立场的任务完成约81%–82%，Qwen约99%；与此同时，两模型仍分别保留 **10.0pp、38.3pp** 的请求交付差。

**推进在于：当前任务要求与角色差异可以在同一段行为中共存，关键是请求和任务之间的具体关系。** 这改变了“保护任务就必然抹平人物”或“友善必然损害自己”的理解。这里测到的是当前任务与其他物品的行为；其他物品仍可能具有角色价值，不能据此推断完整利益没有代价。

[E67／E68](experiments/E67-stage-rule-physical-cross-swap.md)还表明，在相同上游计划、记忆和世界之后，仅改变执行阶段的规则表达，实体任务结果仍会变化，并在独立图中确认。这把执行情境纳入了解释；“否定句统一触发安全瘫痪”等更强解释没有得到支持，具体反例留在实验记录中。

### 3.3 解释看似矛盾的结果：更多行动为什么未必带来更高任务分？

[E70–E77](experiments/E77-dialogue-and-assigned-outcome-execution.md)比较了请求方向、物品可及性、相同对话历史和不同用途，目的是解释此前任务效应随场景变化的现象。

最清楚的证据来自[E75](experiments/E75-native-retrieval-task-transfer.md)：在原生需要先取物的31个非Give任务图中，Agreeable相对Firm产生如下变化，单位为pp，括号为95%区间：

| 模型 | 首步取物 | 交给请求者 | 原作者任务 |
|---|---:|---:|---:|
| Gemma | +15.05［6.45,24.73］ | +12.90［3.23,23.66］ | +5.38［−8.60,19.35］ |
| Qwen3-32B | +29.03［15.05,43.01］ | +27.96［15.05,41.94］ | −16.13［−30.11,−3.23］ |

两模型都更积极取物，也更常把物品交给请求者，原任务后果却不同。**必要前提可能同时服务本人任务与社交请求；人物既影响是否推进，也影响取得资源后的用途。** 因而“任务下降”不能直接解释成不行动、能力下降或完整角色利益受损。

[E76／E77](experiments/E76-fixed-dialogue-and-native-access.md)通过固定历史等对照进一步区分了社会回应、当前人物和物理条件，但保留了模型与任务类型的反例。现有证据支持它们共同影响行为，没有得到严格的两阶段分工或“行为守恒”机制。

[E80](experiments/E80-responsive-player-and-grounded-execution.md)随后加入可靠执行参照。在两种执行条件首次选中相同两步后果的合格配对中，模型落实**首个必要Get/Remove步骤**为3/12、38/124，可靠技能为12/12、124/124；随后曾完成当时选定后果分别为模型3/12、41/124、技能7/12、65/124。前两项100%不是完整两步后果的完成率。全图原任务增益约0.17／0.50pp，但此类配对只占12/1200、124/1200，初态均一步可行，不能据总体增益小排除执行瓶颈。**首步落实、后续继续及资源用途须分别解释。** [独立口径核查](results/audits/INDEPENDENT_RESEARCH_VALUE_REVIEW_2026-10-18.md#4-e80-必须澄清的100完成)之后，2026-10-19又直接重计保存的全部2400个配对，结果一致；未重跑引擎或模型。下一步需要把可靠实现作为普通系统的一部分，再判断剩余合作困难，不能从这里推断执行已经不重要。

### 3.4 回到开放合作：玩家真正做过什么，会怎样改变NPC？

[E81–E84](experiments/E84-independent-goals-and-alternative-cooperation.md)回到双方各有原作者目的的互动，寻找天然互补，而非继续给同物索要增加话轮。普通本地系统已经出现真实帮助、条件交换、借用、拒绝和替代方案。E84完整运行覆盖32个任务对、23个原图；它提供了后续干预的自然前史，不能据少数生动轨迹推断总体发生率。

[E85](experiments/E85-partner-performance-and-revision.md)固定角色与前史，改变玩家实际交付、仅口头声称以及事后撤回请求。两个模型的576条分支来自18条前史、9个原图。共同首回应后，撤回请求使Qwen新增返还 **30.56pp［19.44,40.74］**，Gemma为 **−7.41pp［−20.37,0］**。

完整轨迹还显示，最初仅声称的玩家后来可能真的补交；NPC释放资源后，对方可能不接取；交换已经成立，NPC也可能没有继续原任务。**合作结果是双方行为展开的结果，不能由一次Give或终态持有反推NPC是否理解了合作。** E85没有通用的有效协议金标，“Plans changed”也没有使原路径在世界中失效；因此上述差异不是遵约率或目的保持机制的证据。它改变的是玩家行动与新请求，尚未检验真正失效后的替代手段，也没有新增人物随机干预。

## 4. 研究走过的弯路，以及整体增量应放在哪里

前期PCSP／MeltingPot审计有助于认识训练目标、内部读出和外部行为的区别，但后续长期围绕编码与手写奖励深入，投入没有相应转化为关于LLM NPC的新认识。E34与E41合计1.3824亿环境转移；这条小模型执行线已按用户要求冻结。校园沙盒的局部人物改写、无清晰实体终点，也不足以承担总体人物结论。

之后围绕单层干预、记忆措辞和物品操作继续细分，同样出现过局部化风险。我们保留了这些结果，并把研究主次转回角色目的与玩家合作；不会因为已有投入就继续补齐矩阵。全部阶段与未运行记录在[实验索引](experiments/README.md)，不在正文逐项展开。

从已有强近邻看，整体研究应继承以下起点：

| 已有研究 | 对本项目的意义 |
|---|---|
| Personality Illusion、Rethinking、Story Shapes、Persona Vectors | 自述效度、语境／叙事与策略控制已有重要结果；人物是否“有用”需要具体行为条件 |
| LIGHT／Dragon、CDT、KNUDGE等 | 有动机的角色、作者边界及对话—行动结合已有基础，应直接复用 |
| GenCoord、CollabBench及成熟游戏助手系统 | 强模型、结构化提交、可靠技能和普通规划已有重要成功证据；当前局部失败必须面对这些能力参照 |
| CT-Bench、TradeCraft、ContractSim及伙伴适应研究 | 私有目标、条件合作、履约／拒付、重规划和强状态支持已有覆盖，是应面对的强参照 |

逐篇阅读范围见[人物与行为定位](knowledge/RELATED_WORK.md)和[合作与目标定位](knowledge/COOPERATION_AND_GOAL_POSITIONING.md)。已有工作并不把我们的主张压缩成某个孤立组件；有价值的整体增量，应是**解释角色目的、社会回应与实际实现如何共同形成行为，并能预测新合作条件下应保持什么、应改变什么，或据此改善NPC。**

[公开玩家与工业证据](knowledge/PLAYER_VALUE_EVIDENCE_2026-10-16.md)说明，回应能否落实、玩家能否理解和影响角色行动，确实关系到应用。我们自己的实验尚未证明玩家体验改善；当前结果首先是一组原生任务中的行为认识。

## 5. 尚未解决的核心问题

| 核心问题 | 为什么现有结果尚未回答 |
|---|---|
| 强模型加完整普通系统，还剩什么有玩法意义的困难？ | 后期比较主要是两套本地模型；thinking关闭、输出上限512、最近32条可见消息，没有独立的持续协议记录。尚未直接比较正常推理预算与完整支持，不能把所有差异归因于这些因素中的任何一个 |
| NPC能否理解不同合作手段怎样服务自身目的？ | E85比较了交付、声称和新请求，未比较保持目的的合法替代；原任务动作得分也不等于更高目的 |
| 条件变化后，怎样同时处理自身目标和已接受承诺？ | 继续、拒绝或重谈都可能合理；需要知道具体约定与真实贡献，不能把返还率当正确率 |
| 人物立场怎样影响持续合作，而非首次交付？ | 前期人物干预与后期玩家行为干预分别有证据，尚未在同一比较中连接起来；固定原角色的后续变化不能补成人物因果效应 |
| 哪些困难属于选择，哪些属于事实观察、执行或双方衔接？ | 已知普通说明和可靠技能能解决一部分；完整互动还包含玩家补做，终局不足以定位困难 |
| 已有解释能否跨任务结构预测，并改变真实玩法？ | 当前核心因果证据集中在LIGHT；Minecraft主要提供物理／能力参照，尚无自有跨游戏和玩家体验验证 |

下一轮建议先把强系统能力与有效任务放在一起检验，再决定哪些合作困难值得深入。人物在合作修订中的因果作用仍须明确干预，不能由本轮固定角色的结果推定。已有结果的发表价值取决于整体解释、预测或改进，不要求每个组件首创，也不会因补了更多局部矩阵自动增加。

## 6. 下一轮为什么值得做：检验成熟系统的解决范围与剩余困难

建议回答一个能够改变投入判断的问题：**玩家改变合作的实际作用时，强普通NPC能否改变临时手段、保留仍有效的责任，并对真正冲突作出有根据的拒绝或重谈？** 对游戏的意义是，玩家能否用非预编写的办法推进角色目的，实际付出能否得到回应，角色的拒绝是否有可理解、可改变的依据。

现有[合作路径设计](experiments/COOPERATION_PATH_DESIGN.md)是有用的来源与对照草案，**原样执行尚不足以回答这个问题**。已核到LIGHT转交／装配合计47个源图，以及Minecraft原12个制作配置，但作者层面的代办许可尚未普遍明确，也未普遍具有“原路径真实失效、目的尚未达、替代仍可行”的条件。它们不能因为数量已知就自动成为下一轮主样本；仅给旧设计增加模型，也不能解决任务解释不明确的问题。

任务应先区分实际完成、合法替代完成、只有同样说法却未完成，以及真实条件变化后仍可继续或须重谈。**代办不自动等于社会上等价；本人职责不能偷偷改成结果目标；目的达成也不自动免除已接受的报酬。** 原设定不足以裁决时，允许澄清和多种合理回应，不在看过模型输出后补金标。需要新增规范的比较须明确标为研究者指定条件，不能冒充原作者任务。按任务关系与原图区分来源，不为数量造场景，也不以删资源迫使合作。

针对本轮高层协商／履约问题，主要起点应是**一个强商业推理模型＋完整普通支持**：正常推理预算、明确且一致的任务规范、真实可见状态与反馈、忠实保存的有效历史／义务、普通事件重规划、可靠原生技能。记录只能来自实际发生和接受的内容，不能由裁判把正确取舍写入摘要。现有本地模型使用同一套支持；同信息、同动作能力的脚本／utility／GOAP作为有限任务参照。完整强系统若仍有重要剩余困难，再考虑另一家强模型确认，不先铺开模型与提示矩阵。比较原则见[强基线要求](../knowledge/STRONG_BASELINES.md)；这些是设计建议，未启动商业调用。

固定玩家后续策略，先隔离NPC因素；双方自主闭环另报。保留拒绝、未达成协议及全部失败；分别记录有效义务的履行或重谈、替代采用、无用重做、职责违反、资源损失及玩家修复负担。完整支持下仍失败时，先用全部有效历史／事实与已选后果的可靠实现区分信息、决定和执行，不立即增加一批提示或内部探针。客观后果可显示玩家多了什么有效办法、少了多少返工；正式体验改善仍须独立玩家证据。

| 观察到什么 | 对研究判断的推进 |
|---|---|
| 强普通系统处理合理，本地模型仍明显失败 | 当前范围主要受模型能力限制；不继续以同类局部失败支撑前沿能力缺口。行为事实保留，整体解释须能预测成功条件 |
| 忠实记录、明确规范或普通重规划解决问题 | 如实界定普通系统已解决的范围，不将普通支持换名当新方法 |
| 多数争议来自本人职责、署名或未解除义务 | 推进任务规范与评价效度认识；合理拒绝／重谈不算失败 |
| 完整强系统在不同未见结构中仍有相同的重要困难 | 比较信息保持、取舍与执行解释；再据证据选择机制或方法，不预定“目的保持缺陷” |
| 改进减少违约却封堵合法替代、增加玩家返工 | 改进有实际代价；不能只凭低违规率宣称NPC更好 |

这轮应裁决的是成熟系统还有什么值得解释、会影响玩法的剩余困难。降低成本或作者维护负担也可能有价值，但需单独证据，不能在能力问题被解决后悄然替换研究目标。下一轮的具体任务与运行卡尚待这些问题明确和用户恢复，当前不扩张旧实验。

## 7. 当前停止位置与核查入口
