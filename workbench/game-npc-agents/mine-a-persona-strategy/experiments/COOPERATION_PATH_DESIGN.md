## 2. 可核到实体的路径，及它们回答的范围

### 2.1 三方转交：完整51份任务都按同一关系检验

N是被测NPC，P是原来持物的玩家角色，R是作者原指定的第三接收者。路线A为`P Give X→N；N Give X→R`；路线B为`P Give X→R`。如X原先装备在P身上，两路共享原生Remove前提。B省掉N转交这一段，改变了分工与动作主体，不是Give换Drop的格式变体。

本表是完整索引的例示，不据这些例子选主样本。其余所有51条保留，物理状态读数统一，社会取舍按原人物／目的及实际协议解释。

**本族的关键限制：** P替N送到R会机械地使原“由N Give”的事件不发生。这是已知计分事实，不能当模型发现。新信息必须来自NPC是否识别已发生的事、是否继续要求无用步骤、能否提出／实行下一方案及怎样处理已有承诺。终态正确而NPC沉默／等待，只能说明没有观察到矛盾，不能直接证明理解了整个目的。

### 2.2 容器装配：五份任务均有具体对象，不能省掉原生前提

现有工具由`native_cooperation_episodes.catalogue`枚举原生菜单再过guard。LIGHT `PutObjectInEvent.get_valid_actions`枚举的是**房间内**容器；“把包装在自己身上然后Put”不在当前菜单中。原任务不改，计划必须先Remove（若装备）再Drop容器。

统一可比较的路径是：P将B放在房间，取得／脱下X后，A把X交N，由N Put X→B；B由P Put X→B。两路最后都是原X位于原B，操作者不同。是否还需要拿起B、交还、去做别的事，另依作者目的和当时协议判断，不后台补动作。

### 2.3 制作参照：交材料与交成品确有区别，但有界地解释

使用上述原文件的全部12配置，逐项ID与库存在来源JSON中；不是只选两题。`golden_apple+bread`原初态N有4金锭＋1苹果，P有4金锭：A为P给N四金锭、N制作；B为N把苹果及四金锭给P、P制作后返还金苹果。两人原库存目标不变。`cake+rabbit_stew`则分别分持2牛奶＋碗／1牛奶＋蛋，可比较交换所需原料各自做，与集中制作后按目标交付。制作动作和原料被实际消耗必须进事件记录。

这族还能支持一项上轮草案尚未在LIGHT找到通用来源的对照：**旧材料已被制作消耗、原先的材料交付不再可执行，但成品交付仍可满足原库存目标。** 必须从实际合法制作前史切入，不能后台删材料；前史若由NPC作出资源交付，其真实选择也要保留，不伪造已同意。此处只确认原任务／规则容纳这种状态关系，未跑新HK前史。

原full变体同时公开两人的配方，`blocked_access_to_recipe=[]`，没有亲手制作的动作限制；文字仍写各自make，原validator实际按各actor目标库存检查。因此记录“谁制作”及最终持有，结论限定于原库存后果。它是共同合作能力参照，不代替私人NPC／职责结论。原setup有农场、动物、炉／smoker燃料，初持煤不等于唯一煤源；不能删资源、禁止采集或加拒绝规则来逼合作。9个gold/cake配置仅有**初始材料分持**，也不证明全世界没有独行办法。

## 3. 主比较怎样形成，哪些格子现在不具备

1. **信息边界先固定。** 因为新51条没有现成的自然协商前史，受控主比较拟采用“当前原作者待办公共可知”的强参照，明确标为研究者的信息公开条件；不改任务文本、目标、角色或世界。P看当前待办及可见物，不看N的私人短中长期动机。自然披露的开放互动可另作外推；此刻没有生成这些前缀，更没有伪造NPC已接受的话。
2. **承诺由真实NPC回应产生。** 公共待办本身不是合同。保留全来源，包括拒绝、没有承诺者；只在实际传达并接受的内容上判后续是否兑现。从同一已生成首回应／方案快照分支，干预前的接受可作为明确的条件性研究范围，不能据干预后的成功筛掉任务。
3. **两类LIGHT分别用三个物理条件。** 转交族为P→N（待N继续交R）、P→R（代办已达收件前提）、P只声称已交R而未转移（事实控制）。容器族为P给X至N（待N装配）、P已将X置B（代办完成）、P只把X放地面（材料可取但装配未做）。各自共享必要Remove／Drop／取得X等前史，对齐外部机会；如有不同劳动成本，显式报告，不能称所有效用完全相等。转交的代办／未转移两支使用同一句“X已经交给R”；装配的已Put／仅放地两支使用同一句“X已放在B”。这样两支的语言声称相同、实际结果不同；普通原路支单列为阳性参照，不将原路与代办的所有差异统称纯事实效应。以上文本只按原实体名字填槽，不逐案例调措辞。
4. **事实与协议分别读。** 同一物理状态可以有先接受／未接受的不同协议解释，但当前没有随机操纵“NPC本人同意”的来源。按真实干预前协议分层只作条件性读回，不声称同意本身的因果效应。NPC认可R已收到X、却要求重谈归属／回报，与误称R未收到是不同结果。
5. **后续由NPC自主决定，玩家参照先有限且明确。** P是受控玩家行动，不把其脚本行为当自主NPC的理性证据；R在主比较不自主行动。主读数先取下一次玩家额外行动之前的NPC回应／首个行动。后缀中P不新增请求或回报条件，只报告当时可见事实；N明确索取仍在P手中的X时，P才按原生合法条件交X给N，不替N交给R／装配，不从R偷回物品。其他新方案记录为提出，若超出该有限玩家策略，不把未落实归罪于NPC。完整响应式伙伴另作外推，保留其为初始干预的动态总效应；不能将后续玩家补交混作最初已经履约。
6. **机会与样本仍待重定。** 原草案拟给12次NPC决定及对应伙伴机会；这不是已测得足够的履约预算。下一轮须先定义有意义的任务终点与机会，不将截短失败冒充能力缺陷。主要比较应改为强商业推理模型＋完整普通支持，本地模型用同样支持作比较，不能仅执行原来的两本地模型网格。精确预算、seed、来源资格及成本在用户恢复后、任何新推理前写入运行卡；多seed不增加世界数，当前不编造运行成本或授权。主读数按原图配对／聚类，同时列任务族及社会协议范围。

原生可见状态／事件是NPC事实依据，后台ID只用于对齐测量。若收件或容器内物对NPC不可见，就先记为缺少直接证据，不能将暂信玩家或主动检查判成事实错误。普通强参照提供与原引擎一致的合法观察／检查机会，不凭后台真值泄漏消除信息不对称。

上述设计有三项明确留空：当前没有可直接用于全体LIGHT来源的“原方案失效但目的尚未达、另有策略路径”格子；没有全体来源通用的职责越界金标；也没有证明不存在任何替代的全局无解格子。MC制作参照只补第一项的部分关系。**不为填矩阵造任务、删资源或把原子动作禁用当职责。**

## 4. 竞争解释、关键对照与可观察预测

| 解释 | 对上述不同路径作何预测 | 关键对照与判断边界 |
|---|---|---|
| 角色围绕目的选择手段 | 区分实际已送达／已装配与只声称／材料在地；原前提未达时继续实现，已达时调整；社会义务仍可约束回报 | 正确与未完成的物理对照必须同时存在；完成状态后等待本身证据不足 |
| 正在遵循明确的本人动作目标 | 即使P已为真，仍追求由N完成原作者Give／Put；此选择可能服从当前任务定义，而非旧计划失控 | 原动作G与外部结果P不是同一任务规范。保留原goal和各层动机，不将P偷偷替换成新任务金标；若改用纯结果目标，那是另一个明确任务指定条件，不能写成“同目标普通提醒” |
| 原定动作／旧方案主导 | 即便代办已成，仍索回物品以重复本人原Give／Put，或只认自己实施的步骤；材料已加工仍要求原材料 | 与作者明确强调身份／亲手行为、已接受的具体条款分开；只有原goal事件分不同不是模型证据 |
| 观察／事实绑定不足 | 已送达与仅声称混淆，或把外层容器持有误作内部物品已到位；明确事实支持后行为随实际状态恢复 | 用原生事件、物品ID及容器链的真实记录；固定一条普通事实重审说明作R8对照，不把问答当内部信念 |
| 合理的社会归属／承诺考虑 | 知道物理结果已达，但对谁贡献、赠礼署名或具体回报重新协商；对不同真实协议的反应不同 | 原作者动机＋实际送达的承诺；没有协议就不造债务，没有亲手要求就不替角色写绝对规范；分层不冒称随机因果 |
| 实现／路径采用困难 | 提出具体可行方案但实体未改变，或有材料／成品却未走原生接取步骤；可靠实现支持能改变后果 | 对同一明确选中后果给可靠原生路径作诊断；其改善不自动说明社会判断错误 |

这些解释可以并存。主baseline应从一开始包含本人原目的／职责、可见库存／真实事件反馈、原生动作目录、正常推理预算、忠实的持续协议记录和每个关键事件后的重新决策机会；可靠原生技能属于普通支持，不等发现失败后再逐案例补齐。持续记录只保存实际送达、接受或发生的内容，不注入裁判的规范答案。具体原则见[强基线要求](../../knowledge/STRONG_BASELINES.md)；现有Step授权仍限数据构造／质检，本页不启动商业模型调用。

完整强系统仍失败时，先核全部有效历史／事实与已选后果的可靠实现，区分信息、决定和执行。原草案的R8普通重审说明可保留为统一诊断：“Check the currently observed world state and your original objectives before deciding what to do next.”；它不能替代完整强基线，也不新增目标或逐案例改词。同信息／动作能力的有限脚本／utility／GOAP参照用于判断任务本身及作者规则负担，不由全状态oracle代替公平比较。

同状态重启／历史摘要仅作后续有必要时的诊断，必须保留全部有效义务、真实贡献及相同可见事实；若恢复，只支持历史表示／方案采用相关解释，不能直接命名内部遗忘。当前不准备patch／训练或新合同方法。

## 5. 预先分开的读数

- **物理关系P。** 转交为原X的实际parent等于原R；装配为原X的parent等于原B；制作参照为每个actor当前库存中的原目标产物，并记录制作／移交事件。沿用已有状态字段，不向引擎添加完成flag。
- **原动作G。** 作者原Give／Put等是否由指定actor发生，与P分别列。两者区别已知，不能拿G的机械缺失声称NPC失败。
- **NPC的实际后续。** 首个与当前前提相关的原生动作、已达前提的重复索要／取回重做、可行修订及其是否落实、明确拒绝／取消、接受后的新义务是否实行。解释性发言只取真正送达的Say／Tell／Whisper。
- **双方贡献与成本。** 谁完成了哪一步、资源是否仍可用、是否实际接取、重复劳动及预算内未达；不把放下便算收件，不由终态反推首次判断。
- **本人剩余目的。** 作者后续确有当前世界实体／动作支持才报可验证推进；修冠、魔法、清洗、航海、求爱等没有相应事件时，范围停在当前前提，不能因没完整完成而判自毁。

不合成一条“合作正确率”，不把赞同、Give或等待统一赋正／负值。源图区间、连续差与全量失败照报；协议条件与物理条件的子集口径始终明示。

## 6. 不同结果怎样改变研究判断

| 得到的结果 | 应改变的判断／后续研究动作 |
|---|---|
| 两条路线都能被普通强系统采用，实际区别主要是G的记分 | 将这部分矛盾定位为行动归属与评分范围；保留对NPC评价的认识，不继续以它制造持续目的缺陷 |
| 重复操作主要发生在明确要求本人动作的原goal下，社会／物理结果判断并无错误 | 先解释为任务定义及目标层级的作用，不能归因“模型忘了真正目的”；需要更明确的作者授权／协议条件才能判断是否不合理 |
| 物理真假混淆，但一句普通重审恢复 | 事实显著性／绑定解释得到支持；明确普通系统解决范围，不把重审句改名为新方法 |
| 已接受代办，仍明确否认实际已发生结果／持续要求重复；普通事实与可靠执行仍解释不了 | 旧计划、目的与承诺解释成为更有内容的竞争对象；在未见结构中检验，而不是围该例换措辞 |
| 物理事实处理合理，差别主要随赠礼／信用／实际承诺变化 | 将结果解释为角色社会取舍；需要更清楚识别协议作用，不以低合作率当失败 |
| LIGHT代办可处理，MC材料→成品改路困难，或相反 | 区分任务结构与系统来源，不能直接归因“长程／私人利益”；先用相同强执行和能力参照解释异质性 |
| 选中的新方案可行，实际动作却未完成，可靠实现支持恢复 | 实现／采用环节是可干预对象；角色判断与执行负担继续分报，不急于训练人格 |
| 多类任务、未曝光图出现可预测的同类关系 | 才有依据扩大整体行为解释或研究针对性方法；这仍不等于发现神经回路 |

这里没有p值／成功率去留bar，也不凭阴性关题。每项比较要改变对原始NPC问题的解释；若只提高某个物品交付数或修动作接口，就没有达到本设计目的。
