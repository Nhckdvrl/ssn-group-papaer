# 矿区 B 研究地图：可塑造、可延展的角色扮演

状态：问题与文献建设；未进入实验立项。本页的 RQ、方法和设计均未运行，不构成研究状态变更。

## 1. 主问题与我们希望获得的认识

作者能够写出一段人物设定，不等于能够稳定塑造其在各种处境中的表演；一个角色在既定原作中表现准确，也不等于能承接玩家带来的新经历。反过来，模型偏离初始设定不一定是错误：创作者可能接受一个原先没想到、却符合人物的新解释。

本矿区要理解的是**作者意图、人物的既有经历、当前处境与玩家介入，怎样共同约束并扩展角色的表现**。最终有价值的认识应告诉我们哪些角色能力已经可由强普通系统实现，哪些能力需要更好的表示、学习、编辑或交互方法，以及怎样判断一段表演对作者/玩家成立。

判断不能只靠一个角色分数。已有作品提供不同证据：Crab 支持可配置生成，MDRP 支持结构提示，ArcANE 支持预定阶段的响应，ORIBA 支持作者把角色对话纳入实际创作；每项都没有替其余项完成证明。[最近邻证据表](POSITIONING.md)

## 2. 理论与技术谱系

| 脉络 | 已有认识/方法 | 带入 B 的问题 |
|---|---|---|
| 可信角色与戏剧表演：Bates、Oz | 具体人格要贯穿行为、情绪和表达；可信由观众感知，内部状态与观众解释可不同。 | 怎样让作者想表达的细节真正可见？怎样允许风格化、缺点和笨拙角色？ |
| 作者控制：Hap、后来的作者工具 | 处境化行为、作者规则和试演使具体人物可被塑造；生成自由与作者控制存在取舍。 | 何种编辑单位适合具体人物，如何在新的处境中保持作者能理解的控制？ |
| 人物条件生成：RoleLLM、OpenCharacter、Crab、SimsConv | 大规模角色资料与训练已支持无需逐角色再训练的配置。 | 原创人物的罕见组合、例外与修订，能否超出训练分布但仍被正确执行？ |
| 经历与人物逻辑：Character-LLM、CDT、PsyMem、MDRP | 经验、心理特质、条件规则、处境分面和检索可引导表演。 | 效果来自信息补齐、结构本身还是专门学习？何种普通表示已够用？ |
| 阶段与动态人物：DPC、ArcANE | 变化本身可以合理；小说阶段能用于约束和比较同一人物的不同行为。 | 玩家改变经历后，怎样形成尚未预写的后续人物，而不偷偷提供完整未来答案？ |
| 作者与角色共同发展：ORIBA、Orchid、Elsewise | 创作者可用互动试演、查看可能空间、接受或修改新内容。 | 作者何时要求忠实执行，何时欢迎角色反过来启发作者？如何保留这种区分？ |

历史依据见 [Bates](../../../library/themes/game-npc-social/papers/BATES_BELIEVABLE_EMOTION_1994.md)、[Oz](../../../library/themes/game-npc-social/papers/OZ_CENTRIC_REVIEW_1997.md)；现代工作见 [角色学习页](../knowledge/ROLE_LEARNING_AND_EVALUATION.md)及本矿区定位。Hap 在本轮主要经 Oz 作者综述理解，其完整语言论文/学位论文尚需追溯，不能算独立全文阅读。

### 两个必须修正的直觉

**“长提示和更多内心独白一定更好”不成立。** ArcANE 的短阶段标签对两个基础模型接近完整 Arc；MDRP 在强 Qwen3-Max 上几乎无增益；Thinking in Character 中更多通用思考也可能降低角色分。应该检验提供了什么信息和引起什么行为变化。[ArcANE](https://arxiv.org/pdf/2606.05553v2)、[MDRP](https://aclanthology.org/2026.findings-acl.1175.pdf)、[Thinking in Character](https://papers.nips.cc/paper_files/paper/2025/file/aacca7b6a20d157112205a44f42821c8-Paper-Conference.pdf)

**“严格维持初始设定就是正确角色扮演”也不充分。** RoleBreak 已指出问题服从与角色保持的冲突；ORIBA 的作者会主动修订角色并认可意外的新表现。需要问谁有权修改、修改什么、发生在创作层还是世界内，以及作者如何判断该变化可接受。[RoleBreak](https://aclanthology.org/2025.coling-main.494.pdf)、[ORIBA §5](https://arxiv.org/pdf/2512.12630v1)

## 3. 能力空间：同一角色的不同变化不宜混在一起

下表是待检验的分析区分，不主张人类/角色一定遵循固定层级，也不预先指定神经网络结构。

| 变化 | 例子 | 应保留的区分 |
|---|---|---|
| 作者修订 | 作者把“冷酷”改为“避免亲近以保护别人” | 修改角色意图；可影响多项行为，不要求所有修改都严格局部。 |
| 当前处境下的表现 | 同一个人私下安慰、公开调侃、遇险沉默 | 表现变化不自动等于人格改变。 |
| 新知识/信念 | 发现玩家当时没有背叛，只是消息被截断 | 世界事实、所获证据、人物信念可能不同；归因可错但应有来源。 |
| 情绪/关系过程 | 愤怒平复，但信任恢复可能需要更多经历；新的责任证据也可能迅速改变信任 | 由 D 深入建模；B 检查其是否成为可信、人物特有的表演。 |
| 人物长期转变 | 原本只相信自己的人逐渐愿意托付别人 | 需要经历和作者允许的方向，但不必只有唯一正确弧。 |
| 作者接受的新解释 | 试演中出现符合人物的幽默习惯，作者决定保留 | 系统并非仅执行固定答案；创作过程会扩大可接受范围。 |

变化的来源应可区分，但不应机械地各存一个彼此孤立的分数。同一事件可能同时影响认知、关系、情绪和后续行为；共同记录的事件与解释应跨 B/D/C 使用。

## 4. 五个值得深入的 RQ

### RQ1：什么人物表示能让作者塑造具体而多样的角色？

目标是让作者表达“他怎样对待别人、何时有例外、怎样显露/掩饰自己”，包括很难由单一人格量表描述的细节。

可比较的路线包括完整自然语言人物资料、示例与反例、处境分面、CDT 风格条件行为、心理属性加例外、可检索的生活经历，以及从作者纠正中学习人物逻辑。先用相同有效信息比较，再检验每种表示给作者造成的表达/维护负担。

可能产出是可编辑表示或从少量作者示例学习的方法，也可能是“哪些角色要求只需普通资料，哪些需要行为例子”的能力边界。如果收益只因给了更多人物事实或更强教师，它属于信息/工程改善，不能归给新结构。既有 [CDT](../knowledge/papers/CDT_2026.md)、[PsyMem](../../../library/themes/game-npc-social/papers/PSYMEM_2026.md)、[MDRP](../../../library/themes/game-npc-social/papers/MEMORY_DRIVEN_ROLEPLAY_2026.md) 都必须成为参照。

### RQ2：作者怎样修改人物，并知道系统理解了修改？

先区分作者在“纠正错误表现”、主动重写人物、试探新解释，还是只改当前场景。合理修改可能牵连多方面；研究目标不是机械追求最小编辑，而是**变化范围与作者意图相符，并且作者能够看懂和修正结果**。

方法空间包括编辑影响预览、对照试演、变更来源与历史、条件规则冲突说明、作者接受/拒绝示例学习和低负担纠正。可产生新的作者工具或局部/连贯修改方法，也能产出“作者真正需要哪些控制、现有角色分遗漏什么”的实证认识。

ORIBA 已允许配置修改与不同身份试演，Orchid/Elsewise 已研究更完整创作过程。新增工具需要与同样信息、同样可编辑人物资料和普通强模型比较。若复杂表示增加负担而普通编辑足够，应该记录这个结果并换问题。[ORIBA](../../../library/themes/game-npc-social/papers/ORIBA_2025.md)、[Orchid](../../../library/themes/game-npc-social/papers/ORCHID_CREATOR2026.md)、[Elsewise](../../../library/themes/game-npc-social/papers/ELSEWISE2026.md)

### RQ3：玩家带来的新处境，怎样成为人物的合理后续？

关键区分是：接续已经给定的发展阶段，和处理一段真正未预写、会改变角色理解与选择的新经历。玩家可以解救、误导、嘲讽、示弱、共同冒险，也可以扮演错误身份；人物不必总赞同、总惩罚或立刻永久改变。

方法空间包括经历的解释与来源、人物规则的受限修订、按当前已知信息选择表演策略、维持多个可接受后续而非唯一弧，以及作者对后续方向的干预。D 的情绪/关系机制可以提供候选解释，B 检验这些解释如何形成仍可辨认的人物，C 检验是否形成合适的故事后果。

需要防止普通遗漏信息成为“长期角色困难”。完整历史、可靠摘要/检索、短阶段/处境提示、普通反思和重规划若已够用，就不能主张新记忆机制必要。ArcANE 是最接近的阶段参照，但其单角色盲评与源文本参照尚不回答自然玩家影响。[ArcANE](../../../library/themes/game-npc-social/papers/ARCANE_2026.md)

### RQ4：角色的“像”体现在哪里，作者和玩家能否辨认？

台词内容、措辞、动作、沉默、视线、节奏和反应时机可以共同构成人物。内部状态分得很细，观众却看不出来，不能算已经实现了创作目标；观众也可能给偶然行为读出不同的意义。Bates 的实践对此有直接提醒，但不是现代量化验证。

方法空间包括协调多种表现渠道、从作者示范学习表演、允许风格化的角色目标，以及用于预演的行为解释。评价需要覆盖人物辨认、情境适切、感知变化与作者意图；无需把每项简化成“猜中角色名”，也不应以更拟人或更讨好为统一好处。

与 E 的分工是：B 保持角色表达对象具体；E 深究玩家获得了怎样的理解、预期和可操作自由。若人类看不出指标改善，或只对记住的台词敏感，要修订测量和方法目标。[Bates](../../../library/themes/game-npc-social/papers/BATES_BELIEVABLE_EMOTION_1994.md)、[Crab 评价限制](../../../library/themes/game-npc-social/papers/CRAB_2025.md)

### RQ5：哪些即兴是合适延展，哪些是破坏人物/世界？

不能把所有越出初始文本的内容归为幻觉。人物可能撒谎、误认、讲笑话或虚张声势；玩家可能在共同创作中提出合法新设定。相反，模型为迎合玩家凭空改写已经发生的经历，会破坏角色与玩法。

可研究作者给定的即兴权限、世界事实与人物说法的分离、对模糊输入的角色化澄清、不同创作契约下的响应策略。可产生表达与事实约束的协调方法，也可能给出适用于不同游戏的设计原则。不要让统一拒绝降低所有错误，也不要靠补写背景让每个要求都看似成立。

RoleFact、TimeChara 和 RoleBreak 已分别提供核查、时空边界与叙事容纳；只有超出合理组合后的新证据才有方法价值。[RoleFact](../../../library/themes/game-npc-social/papers/ROLEFACT_2024.md)、[TimeChara](../../../library/themes/game-npc-social/papers/TIMECHARA_2024.md)、[RoleBreak](../../../library/themes/game-npc-social/papers/ROLEBREAK_2025.md)

## 5. 进入时首要高信息量设计：作者带入人物，跨处境试演与延展

**这是未运行的研究设计草案。没有招募、生成场景、使用 API 或启动实验。未来是否实证及样本量仍需独立立项；本轮仅将设计做成可审阅问题。**

目的不是先证明某个模块，而是同时回答：作者到底要什么、强普通系统还有没有稳定困难、自动人物评分和实际表演判断是否相符。

### 设计骨架

| 环节 | 收集/比较什么 | 排除什么简单解释 |
|---|---|---|
| 作者带入原创人物 | 多位创作者带入已有角色和创作材料，包含不同题材/风格；先记录明确意图、例外、允许变化与未知处 | 知名 IP 记忆或研究者单一口味 |
| 信息对齐的试演 | 完整人物资料、示例、当前处境、已知事实与历史都提供给强普通系统；记录每次修订及有效信息 | 缺提示、漏世界状态、上下文不对等 |
| 有针对性的变化 | 同角色换对话对象/公开私下处境；作者意图性修改；玩家带来新经历；另设内容相近但意义不同的对照经历 | 简单复述、仅检测情绪词、所有事件都触发同样变化 |
| 两种后续任务 | 固定历史下续演以定位因果；有限自然互动检验玩家输入、纠正和持续反馈 | 只有固定问答，或只有不可比较的开放展示 |
| 分开的人类判断 | 作者判断意图和接受范围；独立玩家判断角色/变化是否可理解及互动价值；自动分只作辅助 | 把作者个人喜好、人类多数和LLM评分当同一真值 |
| 留出与分析 | 留出作者/人物/处境组合，按作者与人物聚类；记录分歧、负面实例和编辑负担 | 派生问法充当独立场景，局部提示调到测试案例 |

配置相同并不代表信息相同。自然段、分面和示例必须核对实际包含的事实/条件；如果某表示自动补充了新人物知识，应单列这项贡献。作者也可事后接受新解释，因此要保留“原意符合”与“被启发后接受”两份记录，不在事后悄悄重写原始判断。

### 首轮应包含的强普通参照

至少包括当时可合法获得的强商业模型，给完整人物资料/处境/记忆；再补具有可靠事件记录、检索/摘要、MDRP 式分面或 ArcHint、普通反思/核查和有限重试的系统。模型版本、有效信息、推理与上下文预算应记录一致；“本地便宜”不能替代能力比较。

加入已有可配置角色模型或条件行为表示，是检验专门角色训练/结构是否真的必要；作者的多种可接受续演可作解释参照，不作为唯一标准答案。不必在未看到困难前预设自家方法或再训练一个小模型。

### 什么结果会改变投入判断

- **完整普通系统已普遍满足作者意图及玩家理解，修订负担也低：** 不制造剩余失败；技术路线收缩。若有清晰新的设计认识，可以形成研究，但不能硬写新机制。
- **错误主要由缺失资料/普通检索或边界判断导致：** 先记为已知系统能力问题；依据 TimeChara/MDRP 等参照检查是否只需工程修复。
- **自动人物分提高，作者/玩家却不认可，或角色变得同质/刻板：** 指标与目标可能错位；优先理解构念和互动，不继续刷分。
- **作者想要的控制与系统开放表演存在稳定冲突：** 在多个作者/人物上明确冲突类型，可进入表示、编辑或人机共创方法。
- **同信息强系统在新经历后反复出现可解释的身份/表演破坏，方法能跨作者/处境改善，并保持可接受惊喜：** 才有较强的方法研究依据。
- **人类意见本来就分裂：** 分析不同创作契约和角色解释，不把分歧粗暴压成唯一 gold。

## 6. 当前证据够支持什么，还欠什么

足以支持继续挖掘问题：角色作者需要塑造、理解和扩展人物；既有技术已远超过一条 persona prompt；角色的记忆、阶段、知识、表达和人类理解存在可分开的证据对象。

不足以支持：强普通系统在本矿区一定失效；任何专门训练/记忆/心理结构必需；所有作者或玩家喜欢同一演绎；文字高分能稳定预测长时游戏关系与体验。

后续优先补：Hap/演员式创作原始论文与具体编辑实践；长期原创人物/角色扮演社群的第一手研究；跨语音、动作和时间组织的可见表演；已有系统的完整普通提示与作者版本日志。Believable Acting 2022 目前只读第一方摘要，全文获取仍有欠账。
