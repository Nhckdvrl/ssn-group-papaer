# 高信息量实验的设计工具箱（不是按顺序运行的菜单）

## A. 先固定要被解释的语义

一个候选关系修订结果至少包含：旧命题是否被源支持？后证据是否在逻辑上反驳它？**完整新依赖**（事件、主体、宾体、从句内容、时间/条件）由哪些观察支持？存在允许省略或隐式指称吗？随后问的任务是否需要这条依赖？

如果缺一步，不能用“旧角色类正确”或答 Yes 代替。“原问题应该 No” ≠ “原命题被世界证伪”。沿用 E107 的 EXPLICIT/IMPLICIT/UNBOUND/INITIAL/OTHER 和 source-sha 盲审方法，同时保留裁决协议，不要因为新标签看起来严格就宣布其他自然表述错误。

## B. 从一个判别式实验反推出最少的控制

| 核心问题 | 至少两种解释 | 有信息量的操纵 | 关键 readout 和必须留住的反例 |
|---|---|---|---|
| 为什么只撤回而未建立替代关系？ | 表征没形成 vs 已形成但不能消费 | 新证据相同、提供/不提供明确新依赖的可用“oracle”；**再换未提过的用途** | 显式新依赖生成、独立问句/自然行为，其他关系不被损坏 |
| 为什么 hint 直接有效但 source-bank 无效？ | source 表征缺失 vs 提示在回答端直接教答案 | 匹配同一 hint 信息但调整编码与回答时可用通路；有权重时针对清晰机制做 patch | 仅 source 可用时多个用途是否迁移；自替换及 cue 反向作用 |
| 为什么前缀评分偏旧解释？ | 真实旧 belief vs 文本生成/长度偏好 | 固定两个相反候选，改变观察 **仅语义是否要求修订**（词面/长度成对控制），以及独立评分上下文 | 前/后 credit 加和，held-out 源的准确候选排序；自然候选能否产生 |
| 为什么 oracle 恢复却真实策略无效？ | 不会生成好候选 vs reward 漏选 vs 只会少承诺 | 在同一个源下先核 good-in-pool→score rank→下游消费 | 所有源整体、eligible coverage、真实 final dependency，而非只挑 matched pairs |
| 为什么问答正确但自由解释错？ | 任务诱导错误构造 vs 输出格式/理解层差异 | 阅读前给目标、阅读后才给、独立先自由记录再问答；内容相同、全位置对照 | 同源“QA正确且误角色”与新依赖使用；不同映射不能挑一边 |
| 为什么跨领域 cut 失效？ | 机制语义未迁移 vs 切点不是修订证据 | 先从任务来源认证哪条事实否定何条 prior，再选择 **语义证据** 的切点 | 结构性 then 不够，观察分层分析但不靠扫描找显著 |

## C. 十个防错要点（不是无穷尽的防御链）

1. 先确认真实有效任务输出（E93 在约25.706 GPU·h后才发现前向接口大规模 cap）。
2. 严格区分预注册、看到结果后的新维度（E107 是 POST-HOC 启发，原主读数留存）。
3. 不筛最佳模型、最佳提示、最佳 token 窗口或最有利 Gold 层。
4. 控制长度/来源/采样池/一条观察多用途时必须按 source cluster 统计。
5. 正向、反向干预和 self/无关对照共同解释 causality；整个 residual 干预仍非单一语义机制。
6. 同一 pool 需区分 proposal availability、scorer selection、output content、downstream use 四个失败点。
7. 读数有 floor/cap/unknown/tie/合格样本覆盖，直接报告，不能把不可用当 0 能力。
8. 看到漂亮先问原题与负控制是否一起坏了，cue 变差不是 GP 恢复。
9. 至少一个“即使完全正结果也可能平庸”的审稿人解释，并设计推翻它的实验。
10. 单次高信息量 batch 应给出多个可靠观测层，但不要堆过多变量让因果识别失败。

**算力/实施：** 首先重用现存原始结果与合法外部数据做 CPU 分析。若有授权 GPU，单节点/独立卡优先；重复小 pilot 的测量精度和输出格式先过，再扩大。这个工具箱不会自动解除 2026-10-08 的 GPU 释放限制，也不会自动成为新 E109。
