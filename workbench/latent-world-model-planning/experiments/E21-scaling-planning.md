# E21：规划能力的缩放规律——模型规模 × 数据 × 测试时规划算力（2026-10-07）

- **状态：** RUNNING（训练已启动 2026-10-07 03:05 JST；评测协议在看任何训练模型结果之前写定，见下）
- **类型：** PILOT（I15 的决定性实验）
- **对应：** idea I15（规划是否随规模提升；训练算力与搜索算力的交换）；痛点 P04/P05（预测改善不转化为规划）
- **问题（一句话）：** LeWM 家族世界模型变大、数据变多时，预测损失下降，规划成功率是否跟着上升？更多测试时搜索在小模型和大模型上的作用是否不同？

- **设置：**
  - 模型：LeWM 目标（下一帧 latent MSE + 0.09·SIGReg），官方 predictor / action encoder / projector 模块；encoder 用 HF ViT 按宽度缩放。尺寸 XXS/XS/S/M/L = 1.7M/4.1M/17.9M/71.4M/285M 参数；S 即官方 LeWM 配置。latent 维度 = 宽度（另设固定 latent 192 的对照，见后续批次）。
  - 输入 64×64（官方 224；64px 下 TwoRoom 的点与墙、PushT 的 T 与目标都清晰，见 scratch 图）、patch 8、history 3、frameskip 5、batch 128、AdamW lr 5e-5 wd 1e-3、2k warmup + cosine、bf16、grad clip 1.0。
  - 数据：官方 TwoRoom（10k episodes）/ PushT（18.7k episodes）HDF5，按 episode 划分 5% 留出（split_seed 0，所有模型共用）。第一批全量数据；第二批 S 尺寸 1/16、1/4 数据。
  - 训练：60k 步，检查点 2k/5k/10k/20k/40k/60k；种子 0（fvcrc20 RTX PRO 6000）、种子 1（fvcrc10 A100）。
  - 代码：`scaling/wm.py`、`scaling/train.py`、`scaling/eval_plan.py`、`scaling/launch.sh`。

- **读数（预先写定）：**
  1. 留出预测损失（latent MSE；SIGReg 把 latent 规范到近似单位方差，跨模型可比性有限，另用状态探针误差作模型无关读数）。
  2. 闭环规划成功率：留出 episode 上 n=200 个起点，goal offset 25 与 50（TwoRoom 另加 100），预算 = 2×offset 环境步，CEM 300 样本 × 30 迭代、top-30、horizon 5、整段执行后重规划，评测种子 0。所有模型使用同一组起点/目标。
  3. 规划算力扫描（offset 50）：CEM {30×3, 100×10, 300×30, 1000×30, 3000×30}。
  4. （第二阶段）固定候选库上的排序质量：每个起点 64 条候选动作序列，模拟器给出真实结果，测模型选择的 best-of-N 真实质量随 N 的曲线（Goodhart 曲线）。
  5. （第二阶段）同 latent 上训练 GC-IDM（摊销策略），对比搜索。

- **阳性对照：** 评测器用官方发布 LeWM（224px）在相同协议下：TwoRoom offset25 n=50 → 88%（论文约 84–87%），PushT → 76%（GC-IDM 论文 CEM 82.5–89%）。结果 `/tmp/latent-wm-runs/scaling_eval/released_*.json`。64px S 尺寸应接近官方数字，否则先修管线、不解读缩放。
- **噪声地板：** n=200 时成功率标准误约 3pp；训练种子方差由种子 0/1 给出（VIScore 报告同配置种子间 PushT 成功率差可达 14pp）。只有超过种子间差异的规模效应才解读为规律。
- **混杂审计：**
  - 学习率未按尺寸调：未控制 → 若大模型变差，先做大模型 lr 扫描再下结论。
  - 固定步数下大模型可能欠训练 / 小数据下过拟合：用 2k–60k 检查点曲线和留出损失区分。
  - latent 维度随宽度增大（规划代价空间变化）：第二批加固定 latent 192 对照。
  - 64px 与官方 224px：用 S 尺寸与发布模型对照，并在结论阶段补 224px 锚点。
  - GPU 共享导致墙钟不同：只影响速度，不影响数值；计时不作为结论。
- **决策表（跑之前写）：**
  - A. 规划成功率随规模单调上升且与预测损失同步 → 方向转为“训练算力与搜索算力的交换率”（Jones 式等效曲线），重点测算力扫描。
  - B. 预测损失随规模下降，但规划成功率持平或下降（解耦 / 反向缩放）→ 这是主线发现；下一步定位原因（latent 维度、优化地形、被搜索利用、欠训练），用候选库排序与固定 latent 对照拆分。
  - C. 种子方差大于规模效应 → 增加种子到 ≥4，把“欠约束随规模如何变化”作为对象（方差是否随规模缩小）。
  - D. 64px S 尺寸明显差于官方 → 先修管线（分辨率 / 训练步数），暂停解读。
- **算力预算：** 第一批 20 次训练约 60 GPU·时（L 尺寸占大头），评测约 20 GPU·时。**实际：** 待填。

## E21b 追加臂：规模 × 技巧（2026-10-07 06:20 写定，结果未出）

- **问题：** 2026 年 LeWM 后续论文的代表性改进（逆动力学辅助损失 `idm`、时间拉直 `straight`、多步开环预测 `multistep`）在不同模型规模下的增益，是否小于把模型放大一档（约 4×）的增益，且随规模缩小？
- **设置：** 与 E21 相同的训练管线；PushT XS/S/M × {idm, straight, multistep}（权重 0.1 / 0.1 / 1.0，取各原文常用量级，不调参），TwoRoom S × 三种；种子 0，后续补种子 1。
- **读数：** 同 E21（n=200 闭环成功率，offset 25/50；候选库排序；诊断）。
- **决策表：**
  - 技巧增益 < 放大一档的增益，且在 M 上 ≤ 噪声 → 支持“规模胜过技巧”，作为论文第二主轴，补种子与 Reacher。
  - 技巧在所有规模上都有稳定增益且与规模可加 → 报告为互补，技巧与规模的交换率作为结果。
  - 技巧只在大规模上有效 → 记录为反向，查原因（欠训练 / 容量）。
- **混杂：** 各技巧未调权重（按原文量级）；只代表“这一类目标”，不代表原论文完整方法。
