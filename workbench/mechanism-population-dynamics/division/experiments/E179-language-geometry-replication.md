  - `allenai/OLMoE-1B-7B-0125-Instruct`：16 层，64 专家 top-8，d = 2048，`mlp.gate`（无偏置，softmax 后 top-8），sdpa。

- **数据与语言：** 与 E178 完全相同——FLORES-200 dev 全部 997 句 × 20 语（eng arb asm bam ben fra hin lit ory pes srp tha zho deu spa jpn kor swh rus tam），校准集 devtest 前 25 句 × 20 语（只用于偏置重拟合与 N_T 温度拟合）；每句单独一条序列，不加模板、`add_special_tokens=False`，右补齐不计。
- **采集（`scripts/e179_capture.py`，以 e178_capture.py 为底，不改 e178 脚本）：** 每个 MoE 层路由器挂 forward hook，取其输入 h（= 路由器看到的隐状态）。T 的 logits：Qwen3 / OLMoE 取 gate 输出；GPT-OSS 在 hook 内以与模型相同的 bf16 `F.linear(h, W, b)` 重算（与模型实际 top-4 比对，见阳性对照）。零模型只打分、不干预。存：计数、逐句计数（T 与各族第 0 个 draw）、逐句 R4，另存 **G 用的隐状态统计**：每层每（语言, 句）的 h 句内均值（19,940 × d，fp16 落盘），以及每层一份 20,000 token 子样本（每语言 1,000 个，从该语言全部测量 token 中均匀无放回抽，种子 179；fp16）。
- **路由器（同一隐状态、模型自身 top-k）：**
  - **T**：训练路由器。
  - **N_A**（Melton 式）：W·R，R 为 O(d) Haar，每层每 draw 独立，8 draws；**偏置**：Qwen3 / OLMoE 无偏置；GPT-OSS 保留训练偏置 b 不变（只换朝向）。
  - **N_B**（仓库 N1，`moe_measure.py` 原代码）：W_c V Q Vᵀ，偏置在校准集上重拟合到 T 的校准集负载，8 draws。
  - **N_G**（补充，不进决策表，同 E178）：Frobenius 匹配高斯门 + 偏置重拟合到均匀负载，8 draws。
  - 随机数：每层 `torch.Generator().manual_seed(178000 + l)`，抽取顺序同 E178（N_A → N_B → N_G）。
  - **N_T（新，锐度匹配零模型）**：取 N_B 第 j 个 draw 的 logits z = h W_Bᵀ + b_B，乘以标量 s_{l,j} > 0：N_T logits = s_{l,j} · z。s_{l,j} 在**校准集**上用对 log s 的二分（区间 [e⁻⁶, e⁶]，60 步）选定，使 **N_T 的全 softmax（E 个专家）平均熵 = T 在校准集上的全 softmax 平均熵**（T 含其偏置）。选全 softmax 熵作主定义，因为要排除的混杂在 R4 上，而 R4 正是对全 softmax 分布算的。
  - **N_Tk（补充）**：同上，但匹配的是 **top-k 重归一 softmax 的平均熵**（只在被选的 k 个 logits 上 softmax；即任务描述中的例子）。
  - **构造性事实（跑前写明）：** top-k 选择对 logits（含偏置）的正数缩放不变，所以 N_T / N_Tk 的专家计数与 N_B **逐 token 完全相同**，R1 / R2 / R5 与 N_B 恒等。"训练门更尖"因此不可能解释 R1 上的常数倍；N_T 只对 R4 有检验力。R1 图里画出 N_T 只为展示恒等（计数恒等也作阳性对照检查）。
  - **N_perm**：语言标签置换地板，同 E178（T 200 次；N_A0 / N_B0 / N_G0 各 50 次）。
- **算力：** 三个模型各约 1.6M token；GPT-OSS 推理时 HF 实现对 32 专家全算（≈ 21B 参数稠密），估计 ≤ 0.5 GPU h；OLMoE ≤ 0.2；Qwen3 ≈ 0.3；G 分析在 GPU 上做 logistic 回归 ≤ 0.3。合计估计 ≤ 2 GPU h（上限 12，并发 ≤ 2 卡）。日志 `results/e179/_logs/`，原始数组 `~/mechpop_cache/e179/<model>/`（不进 git）。

## 阳性对照与 sanity
- **训练路由器自一致**：同一英文 batch 前向两次，T 的 top-k 集合逐 token 完全一致率（预期 1.0）。
- **N_B 负载匹配**：校准集上 N_B 负载与 T 负载的总变差，**均值 ≤ .01**（E174 口径）；最大值照报。
- **hook 正确性**：fp32 重算 h Wᵀ(+b) 的 top-k 与模型实际 top-k 的重叠率（GPT-OSS 与模型返回的 `router_indices` 比）。
- **N_T 计数恒等**：N_T / N_Tk 计数与 N_B 计数逐元素相等（差 0）；N_T 熵匹配残差（校准集上 |H̄_NT − H̄_T|）≤ 1e-3 nats。
- **Qwen3 重采一致**：重采的 T、N_A、N_B 的 R1 逐层与 E178 `summary.json` 最大绝对差 ≤ .002。
- **G 的阳性 / 阴性对照**：置换语言标签后 G1（token 级，层 0 与末层）应 ≈ 5%（报一次）。
- **不做**：E178 的"零模型负载 ≤ 2× 均匀"检查（E178 已发现训练路由器自身在 FLORES 上就不均衡、该检查对 N_B 不适用）；改报 T 自身 max 负载（见读数）。

## 决策表（跑前写死；主会话 11-09 指定，原文照录）
- **(i) replication**: U-contrast of T vs nulls within 0.85–1.15 of each other and Spearman(T, N_B) ≥ .8 on both models → the geometry origin generalises across the published model set;
- **(ii) constant factor**: ratio T/N_B in edge layers vs middle layers within ±20% of each other → depth-independent multiplier replicates; if the edge/middle ratio differs by > 20%, report as model-specific;
- **(iii) sharpness**: if T/N_T on R4 falls within 0.8–1.25 → the R4 excess was sharpness; if T still exceeds N_T by ≥ 1.5× → excess is not sharpness;
- **(iv) geometry**: if the layer profile of G1/G2 has Spearman ≥ .8 with the N_B R1 profile → the "U-shape is geometry" statement is directly supported; also report Spearman of G1/G2 with T's R1 profile.
- **执行口径（跑前补写，不改上面）：**
  - (i) 用 R1：U_T / U_null ∈ [0.85, 1.15] 对 N_A 与 N_B 都要成立（U_null = 8 draws 的 U 均值），且 Spearman(T, N_B) ≥ .8；"both models" = GPT-OSS 与 OLMoE。Qwen3 重采同表报（E178 已知），R4 的 U 对比并列报、不进 (i)。
  - (ii) 用 R1，|edge 比 / middle 比 − 1| ≤ 0.20 → 复现；逐模型判。
  - (iii) 用 R4 逐层 T/N_T 的全层中位数：∈ [0.8, 1.25] → R4 超出来自锐度；≥ 1.5 → 不是锐度；∈ (1.25, 1.5) → 部分 / 不定，照报；< 0.8 → 锐度匹配零模型高于 T，照报。逐模型判（三个模型都判，含 Qwen3）。N_Tk 同报，若与 N_T 判读不同，两者都报、不选边。
  - (iv) 主读数 G1（token 级准确率）与 G2（句均值离散度）都对 N_B R1 有 ρ ≥ .8 → 直接支持；只有一个 → 部分支持；都不 → 不支持（此时随机路由器的 U 形不能用"语言线性可分性 / 质心离散度"解释，需另找几何量）。饱和的读数不解读。逐模型判（三个模型）。
- **以上都不是关线 / 开线条件**；结果交主会话，是否立题由人定（R2）。

## 结果（跑完后填写；上面内容不改）

- **按决策表执行：**
  - **(i) 不成立**（"both models"要求两个新模型都过）：GPT-OSS 只过 N_B 一半（U 比 0.90、ρ .96），N_A 的 U 比 1.37 超出 0.85–1.15；OLMoE 上 N_B 的 U 比 0.95 在范围内，但 N_A 0.71、ρ(T, N_B) .56 都不过。Qwen3 重采按同一规则成立（1.01 / 1.01 / .95）。
  - **(ii) 三个模型都复现深度无关常数倍**（edge/middle 1.02 / 0.90 / 0.97，均在 ±20% 内；均值之比版本 1.01 / 0.90 / 0.96）。倍数本身随模型不同：T/N_B 中位 1.58 / 1.16 / 1.85。
  - **(iii) 三个模型都"不是锐度"**（T/N_T 中位 1.66 / 1.73 / 2.63 ≥ 1.5；N_Tk 1.58 / 1.66 / 2.74 同判）。训练门确实更尖（全 softmax 熵低于 N_B，s 中位 1.18–1.47），但把零模型调到同样尖只把 R4 上的 T/零 比从 1.86 → 1.66（Qwen3）、1.75 → 1.73（GPT-OSS）、2.50 → 2.63（OLMoE）。另：R1 / R2 / R5 对 logit 缩放构造性不变，"门更尖"不可能解释 R1 上的常数倍。
  - **(iv)：Qwen3、GPT-OSS → (iv-a)**（全维 token 探针 ρ .87 / .88 ≥ .8，且 G2 句均值 .92 / .96 ≥ .8；原口径"直接支持"）。**OLMoE → (iv-c) 不支持**（G1 token .11、G2 句均值 .44；G2 句均值本身呈 U：2.51 → 1.17 → 2.15，但 OLMoE 的 N_B R1 剖面锯齿状、第 1 层陡降，不跟它走）。
  - **补登记期望检验**（N_B R1 与 G2、G3-主空间 ρ ≥ .8，与 G1 全维 < .5）：G2 ≥ .8 在 Qwen3 / GPT-OSS 成立、OLMoE 不成立；G3-主空间（句均值离散度）同样 Qwen3 / GPT-OSS 成立，G3-主空间 token 探针只在 GPT-OSS 成立（Qwen3 .70）；**"G1 全维 < .5"在 Qwen3 / GPT-OSS 不成立**（.87 / .88；OLMoE .11 成立但其他也不成立）。按措辞规则：Qwen3 / GPT-OSS 用较简单的"U 形是几何"措辞，不需要"主方向几何"措辞。

- **意外：** (1) 全维 token 级探针在 Qwen3 / GPT-OSS 上呈 U（首尾 .97、中层 .92），与稠密模型 Holmström 2609.04819 的"全维探针平坦"不同；句均值级 PCA 拆分里，中层的语言身份在主空间（k₅₀ 主空间探针 ≈ 1.0）而残差空间探针跌到 .12–.29（Qwen3），方向与"语言身份搬到低方差残差子空间"相反——测量层级（token vs 句均值、20 语 12 文字）不同，不能直接说与 Holmström 矛盾。(2) OLMoE 的训练路由器几乎没有 U 形（R1 首尾 / 中层 1.11），而隐状态的 G2 有；OLMoE 上 Bandarkar 原读数 R4 的层剖面与 N_B 不相关（ρ −.16）。(3) 零模型族翻转在新模型上换了方向：GPT-OSS 上 N_A 的 U 比 T 平（U 2.31 vs 3.16），OLMoE 上 N_A 比 T 更 U（1.55 vs 1.11）；N_B 在三个模型上都贴近 T 的 U 值（2.34 / 3.51 / 1.17 vs 2.35 / 3.16 / 1.11）。(4) token 级 k₅₀ 残差空间探针在若干层低于机会（.023–.04 < .05），原因未查（可能是约 2,000 个低方差方向逐维标准化后的过拟合）；不进任何判决。(5) 三个模型在 FLORES 平行语料上都极不均衡（T 最大负载中位 6–11×），不只 Qwen3。
- **事实判决（两句）：** 在 Bandarkar 的三个单卡模型上，训练路由器相对负载匹配随机路由器的语言专属度倍数在深度上恒定、且不能由门的锐度解释；但"随机路由器复现首尾层 U 形"按预登记标准只在 Qwen3 上成立，GPT-OSS 只对负载匹配零模型成立、OLMoE 的训练路由器本身就几乎没有 U 形。在 Qwen3 与 GPT-OSS 上，路由器输入的语言可分性（全维 token 探针、质心离散度）直接测得与随机路由器剖面同形（ρ .87–.96），OLMoE 上不同形。
- **主张变化：** 无升降（C24 仍 L1；本卡给 C24 的适用范围补证据：常数倍三模型复现、锐度排除；"U 形是几何"在 GPT-OSS 依零模型族、在 OLMoE 不成立）。由主会话决定如何改写 C24。
