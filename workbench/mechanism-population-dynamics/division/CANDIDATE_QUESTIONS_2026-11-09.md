## A. 文字 vs 语言：语言路由读的是哪一个（首选）

- **问题：** 在平行句上，"同一语言、换一种文字"的两份文本和"同一文字、换一种语言"的两份文本，哪一对的路由更接近？各层答案是否不同？
- **对手假设（两边都有信息）：** H-文字：每一层都是同文字异语言的一对更近（所谓"语言专家"其实是文字 / 词表专家），和稠密模型里语言单元编码的是文字而非语言结构（2604.05090）一致。H-语言：某些层（预期在中层）同语言异文字的一对比同文字近亲语言更近，即路由在这些层带着脱离文字的语言身份。前者要求重读 Chen 的独占专家和 Bandarkar 的首层"语言专属"；后者是 MoE 路由层面第一份"语言身份不随文字变"的证据，并且给出具体层位。
- **读数：** 逐层 R1 型路由 JSD，算在四类配对上：同语异文、异语同文（按语言亲疏分档）、异语异文、同语同文（两半句子互比，作噪声地板）。主统计量 = 交叉层集合，即 D(同语异文) < D(异语同文 · 最近亲) 的那些层。辅读数 = 同一 token 类型的跨语言路由 JSD：只取在 ≥ 2 种语言里出现的 token 类型，零模型 = 在 token 类型内部打乱语言标签。
- **对照：** T vs N_A / N_B（判断训练路由器的超出量落在文字轴还是语言轴）；每句抽相同数目的 token，抵消文字间的切分长度差；按句做 bootstrap；后几层再加一个"按下一个 token 分层"的版本，因为深层按预测 token 路由（OLMoE §5.4），同语异文的输出 token 本来就不同。
- **数据（天然语料，按记忆规则不需要 step 审计）：** 主配对是塞尔维亚语。FLORES-200 的 srp_Cyrl 加一份确定性转写的拉丁版（两种文字在现实中都通用，西里尔↔拉丁一一对应；FLORES+ 里有没有现成的 srp_Latn 未核对），对照组：拉丁文字的 hrv / slv / ces / pol，西里尔文字的 mkd / bul / ukr / rus。次要配对：hin_Deva vs urd_Arab（印地语 / 乌尔都语，书面词汇有差异）、zho_Hans vs zho_Hant（部分 token 共享）。另外 FLORES 里有两种文字的 ace / bjn / min / kas 作补充（都是低资源，模型可能不认识）。
- **模型：** Qwen3-30B-A3B、Qwen3-30B-A3B-Base、GPT-OSS-20B、OLMoE-0125-Instruct（单卡，E179 脚本）。
- **够一篇的结果：** 交叉层在 ≥ 2 个模型上复现，并且训练路由器的超出量在两条轴上稳定地落在同一边（例如超出量全在文字轴上，或者中层的超出量只出现在语言轴上），形成"训练让路由在几何之上放大的是 X"这样一句话。**只够一条注记的结果：** 每一层都跟着文字走，而且 N_B 也一模一样地跟着文字走——那只是把 2604.05090 的稠密结论搬到路由上确认一遍。
- **近邻与差距：** 2604.05090（稠密模型的 LAPE 单元编码文字而非语言结构，ACL'26，未核对）；2603.08869（用塞尔维亚语双文字研究 SAE 特征，稠密）`[摘要]`；Khandelwal 2605.29714（OLMoE 续训后，路由相似度与词表重叠相关 ρ −0.56，只是相关分析）；Bandarkar 2510.04694（用 token 重叠解释首尾层，未检验）；NeurIPS'25 "Towards Democratizing LLMs"（OLMoE 续训，同文字的低资源语言复用高资源语言的专家；arXiv 号未找到）。**我们的差距：** 在 MoE 路由上做受控的 2×2 设计（同 / 异语言 × 同 / 异文字），用天然双文字语料，逐层给结果，并与零模型路由器对比。
- **主要科学风险：** 深层路由按预测 token 走，而输出 token 依赖文字，所以深层几乎必然落到 H-文字；有信息的层只剩中层，而 E179 显示中层的语言专属度本来就低（Qwen3 R1 约 .07–.15），效应可能贴近地板。印地语 / 乌尔都语算不算"同一语言"有争议，所以只当次要配对。

## B. 常数倍由哪个子空间承载（我方结果 1 的可测形式）

- **诚实评估：** "与深度无关"的准确含义是首尾层与中层的倍数没有趋势（edge/middle 1.02 / 0.90 / 0.97），逐层倍数本身并不恒定（Qwen3 1.10–1.95）；GPT-OSS 只有 1.16×，偏小。这个问题能做成可测形式，但单独拿出来只是一节分析，不够一篇。
- **问题：** 只把训练路由器在语言判别子空间里的分量移植给零模型，能不能恢复训练路由器的语言专属度？如果能，那个子空间是不是各层共用的？
- **读数：** 第 l 层的 S_l = 正则化 LDA 得到的 19 维语言判别子空间（在一半句子上拟合）。混合路由器 W_H = W_B + (W_T − W_B)P_S，在另一半句子上算 R1。判据是二元的：W_H 的 R1 是否落到 T 的 ±10% 以内。跨层：用第 m 层的 S_m 去移植第 l 层，得到矩阵 r[l, m]，再看 S_l 与 S_m 之间的主角。
- **对照 / 对手：** 同维的方差匹配子空间（从前若干主成分里随机取）；同维的 **token 身份子空间**（各 token 类型均值做 PCA），作为对手载体。结果分三种：只有对角线能恢复 → 各层方向各不相同，常数倍只是各层训练增益碰巧相同；整个矩阵都能恢复 → 有一条持续存在于残差流里的语言子空间，各层路由器以相同增益读它（Chang 2205.10964 报过中层语言轴稳定）；语言子空间恢复不了而 token 子空间能 → 超出量其实是 token 身份，直接接到 A。
- **数据 / 模型 / 成本：** `~/mechpop_cache/e179/<model>/{gateW,toksub,sentmean}.npy`，三个模型都有，不用重新采集，≤ 0.5 GPU h。每个语言 1,000 个 token 上算的 R1 噪声较大，要先和全量 R1 对一次账。
- **近邻：** 2605.12476（路由器与专家的几何耦合）；2604.09780 Myth（路由反映几何，负载均衡压制共享方向，只有论证）；2401.05792（低秩语言子空间）。**差距：** 在训练后的路由器行上、对保留子空间的零模型做定向移植检验。**风险：** 超出量可能分散在很多方向上，没有低维载体，这时结果是阴性但信息量小；d = 2048、每层 20k token 时 LDA 的类内协方差病态，必须加正则并交叉拟合。

## E. 哪一级分析单元经得起零模型：神经元 / 注意力头 / 专家（领域外延，导师兴趣内）

- **问题：** 稠密文献的"语言神经元集中在首尾层"（Tang 2402.16438、Kojima 2404.02431）、语言注意力头（2511.07498、2602.08625）和 MoE 的语言专家 U 形，是同一份残差流几何被三种组件分别读出来的吗？三类组件里，哪一类训练后的层分布偏离它自己的零模型？
- **对手假设：** H-继承：三类的层分布都被零模型复现，"组件级语言专精地图"是一个几何事实。H-组件：只有某一类（预期是有特权基的神经元）偏离零模型、而且偏离的层形状不同，这就说明分工确实落在哪一级单元上。两种结果都直接回答导师关心的"分工落在哪一级"。
- **读数 / 零模型：** 神经元用 LAPE 原判据，零模型 = 门控行做 Haar 旋转（范数与偏置匹配，激活函数不变）；注意力头用前向的输出语言可分性（不用需要反向传播的 LAHIS），零模型 = W_V/W_O 或 W_Q/W_K 做旋转（保留 RoPE）；专家沿用 R1 加 N_B。每一类都报 U 比、与零模型剖面的 Spearman、训练/零模型倍数的 edge/middle 比。
- **模型 / 数据 / 成本：** Llama-3.1-8B 或 Qwen3-8B（稠密），再加 Qwen3-30B-A3B（头和专家都有）；FLORES 20 语；约 1 A100 天。
- **够一篇的结果：** 三类组件之间出现干净的分离，并在 ≥ 2 个模型上复现。**只够注记的结果：** 三类都是继承来的，只能当一条方法学提醒，而且和 Melton（Zenodo 预印本，未评审）、Gurnee 2401.12181（随机旋转基线）有压缩风险。
- **近邻：** 2402.16438、2404.02431、2503.17456（语言神经元对迁移没用）、2604.05090、2511.07498、2602.08625、2401.12181。**差距：** 在同一批隐状态上，用同一族零模型横比三类组件；检索范围内（arXiv API + Web）没找到对语言神经元层分布做过随机基检验的工作。**风险：** 神经元的零模型不是标准做法——"神经元"本身就是靠特权基定义的，旋转会改掉它的定义；E179 已经看到零模型族会翻转判决，所以必须跑前固定零模型族、两族一起报。

## F. token 类结论过零模型，加上 OLMoE 训练轴

- **问题：** OLMoE §5.4 的"浅层按输入 token、深层按预测 token 专精"（原文没有对照）和 Antoine 2412.16971 的 POS 专精，在负载匹配零模型 N_B 和 Haar 零模型 N_A 下还成立吗？在 OLMoE-0924 的 checkpoint 轨迹（20B → 5T token）上，从哪一点开始超出零模型？
- **对手假设：** 几何继承（零模型复现，和语言 U 形同一种情况）vs 路由器学到（T 超出零模型，且层形状不同）。先验：自训平台 E176 里"token ID 决定专家"是唯一一条在 step 0 不成立的结论，所以预期输入 token 专精能过、POS 专精不一定能过。这种"一条过、一条不过"的结果本身就是一条对比轴。
- **读数：** Spec_POS（UD English-EWT；加上多语 UD 之后，就能看 POS 专精是否随语言变化）、N(x,E)/N(x)（分输入 token / 预测 token），T、N_A、N_B 都报；沿 6–8 个 checkpoint 画曲线。
- **够一篇的结果：** 输入 token 专精与预测 token 专精在零模型下分离（一条是继承来的，一条是学到的），而学到的那条在第一个 checkpoint 之后才出现。**只够注记的结果：** 全部是继承来的，只能当纠偏表里的一行，和 Melton 只差一个读数类别。
- **近邻：** Melton（只审了话题）；2412.16971；2409.02060；2604.17182（token 身份分解，只做了代码、Qwen3.5）；2604.09780。**风险：** checkpoint 轨迹左删失（第一个点在 20B token，原文说那时路由已经约 60% 饱和）；压缩风险高。

## C. 路由器何时跟随几何（我方结果 2 的可测形式）

- **诚实评估：** E179 里已经有一条线索，不用再跑：OLMoE 上全空间随机路由 N_A 读出了 U（1.55），而训练路由器 T（1.11）和保留行空间的 N_B（1.17）都读不出，说明 OLMoE 的行空间在首尾层的语言方向上是**贫化**的；GPT-OSS 正好相反（N_B 3.51 > N_A 2.31，富集）；Qwen3 是中性的。所以"何时跟随"可以落到一个可测量上：行空间对语言判别方向的富集比。
- **读数：** A_l = tr(P_W Σ_between) / tr(P_W Σ_total)，除以同维 Haar 随机子空间上的同一比值；再加一个方差匹配版本（随机子空间只在前若干主成分里取），用来把"语言方向"和"高方差方向"分开。二元判据：显著低于随机（主动避开）还是落在随机范围内（无所谓）。
- **能从公开权重读出、不需要训练的相关量：** 训练量（OLMoE-0924 checkpoint 轨迹）；base vs instruct 配对（Qwen3-30B-A3B-Base / 指令版、OLMoE-0924 / 0924-Instruct、0125 / 0125-Instruct、DeepSeek-V2-Lite / Chat、Qwen1.5-MoE-A2.7B / Chat）；路由饱和度和熵（直接测）。**只能从技术报告里查、没法测的：** 负载均衡损失的粒度（Qwen 系列从 2501.11873 起用 global-batch，Qwen3 是否采用凭记忆、未核对；OLMoE、GPT-OSS 未核对）、多语数据占比（只有宣称值，没有数字）。
- **对手假设：** H-避开：按序列或微批计算的负载均衡把路由器行从"整条序列共享的方向"（语言均值就是这种方向）上推开，这时贫化应在早期就出现并保持，和 Demons 2501.11873 的"微批 LBL 压制领域专精"同一机制；H-无关：英文为主的数据让语言方向变得无关紧要，富集比会落在随机范围内而不是低于随机；H-后训练：base 与 instruct 配对之间有差异。
- **成本：** OLMoE 每个 checkpoint 约 0.1 GPU h，取 8 个点；配对模型约 2 GPU h；合计 ≤ 0.5 A100 天。
- **够一篇的结果：** 贫化在 OLMoE 轨迹上稳定出现，起点或增长可以定位，并且在 ≥ 2 个家族里和某个有文档的训练选择方向一致。**只够注记的结果：** 只有 OLMoE 一个模型偏离，而 Bandarkar 原文已经把这一点归因于 OLMoE 多语能力弱。
- **近邻：** 2604.09780、2501.11873、2604.04230（用 OLMoE checkpoint 测负载三阶段，不测专精）、2605.29714。**风险：** 跨模型比较只有 4–6 个点，而且家族之间什么都不一样，只能算相关；真正干净的只有 OLMoE 时间轴和 base/instruct 配对，而时间轴又是左删失的。

## D. 语言负载不均：不建议单独作为问题（我方结果 3）

- **是否已知：** 系统方向早就报过专家冷热不均。2303.06182 在 NLLB 式的 MT 负载上看到少数热专家，并且报告"各语言的激活模式相似"`[摘要+检索]`；2601.14050 报告低资源语言更依赖独占专家；2610.13370 用按类别加的选择偏置来补偿数据不均。
- **我们这个数里的混杂：** (1) 负载是把所有语言的 token 合起来算的，而各语言的 token 数差约 10 倍（Qwen3 上 ory 25.6 万、eng 2.6 万），过度切分的文字占了大头；(2) 不带偏置的全空间随机路由 N_A 本身就有 5.4× / 3.1× / 2.7× 的不均，所以大部分不均是隐状态分布的性质，任何路由器读出来都会这样；(3) T/N_A 的不均倍数（约 2.1 / 2.0 / 2.8）和 (b) 的倍数排序只能在 3 个点上比较，信息量不够。
- **处理：** 转为对照。后续每张卡都报每种语言等 token 数下的逐语言最大负载，以及它与 N_A 的比值。能做的注记只有一条："过载专家是否集中在被切碎的文字（ory / asm / tam）上"，属于切分方面的注记。**重开条件：** 等 token 平衡之后，逐语言热专家仍明显超出 N_A，而且这些专家正是 steering / 路由对齐方法干预的那批。

## 跨候选的共同风险（写在这里，免得每节重复）

1. 零模型族会翻转判决（E178/E179 已经见到），所以每张卡都要跑前写死 N_A + N_B 两族，只报二元判决，不把"超出多少"当作主张。
2. 所有候选都只回答 what / which / when，不回答"有多少归因于几何"这种分解问题（11-05 已否）；B 和 C 的读数也写成二元判据。
3. A、B、C 可以共用一次采集（E179 脚本加上 token id 和下一个 token 的 id）。开哪一项、要不要登记成候选，由人定。
