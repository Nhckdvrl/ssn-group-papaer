# E223：同数据、同词表的 7 个架构，在自然文本的每个 token 上预测得一样吗？分歧是否按计算机制成组？（2026-11-24）

- **状态：** DONE（约 23:00 写定，在任何 E223 运行之前；约 23:40 跑完）
- **类型：** MEASUREMENT（不干预，只做前向；不推进主张等级）
- **为什么做：**
  - E217–E222 显示，在异质部件上做切断，容易落到两种结果：要么"由设计可推"，要么被分布偏移（注意力汇聚点）削弱。
  - 用户 11-24 晚贴来的外部意见（Gemini 第六份）建议换成不做干预的测量：同数据、同词表的不同架构，在每个 token 上的预测分布差异有多大，这种差异是否按计算机制成组。
  - E222 后对 OLMo / Granite 两对的零 GPU 初看显示：平均净差很小，但单 token 差异很大、方向对半。所以要问的是差异本身的结构，而不是谁赢。
  - fla 库 7 个 1.3B 模型据称同数据（100B token）、同词表（32,000），是现成的对照组；数据是否完全相同由文献子代理核对（结果见文末）。
  - 这是讨论前的一次低成本探路，用来判断这个方向有没有信号；跑完不扩展，等集中讨论。
- **问题（一句话）：** 同数据、同词表的 Transformer、Mamba、DeltaNet、GLA、GSA、HGRN、RetNet，在自然文本上的逐 token 预测分歧，是否按计算机制成组？

## 设置
- **模型：** fla-hub 1.3B / 100B 的 transformer、mamba、delta_net、gla、gsa、hgrn、retnet。Mamba 用 transformers 自带的类加载，其余用 fla，同 E202。文档开头加 BOS。
- **文本：** EWT 第 0–99 段，每段 ≤ 511 token。先核对 7 个模型的分词器对这些文本给出完全相同的 id，不同则停。
- **读数**（每个位置、每个模型的完整预测分布）：
  - 每对模型（21 对）的逐 token JS 散度（以 nat 为单位）；
  - 每个模型的逐 token NLL 与熵；
  - 两两之间 NLL 的相关系数。

## 读法（跑之前写定；阈值只作标记）
- **控制 token 本身的不确定性：** 按 7 个模型的平均熵把 token 分成 10 个等量组，在每组内分别算每对模型的平均 JS。
- **控制模型水平：** 报告每对模型平均 NLL 之差，以及成对 JS 与它的相关；若相关很高，则 JS 结构可能只反映水平高低。
- **事先写定的三种分组：**
  - P1：Transformer 对 6 个循环模型。若 Transformer 与其他模型的平均 JS ≥ 1.2 × 循环模型两两之间的平均 JS，且在 ≥ 8/10 个熵组成立，记为"Transformer 自成一类"。
  - P2：带短卷积（Mamba、DeltaNet）对不带短卷积（GLA、GSA、HGRN、RetNet），只在 6 个循环模型内比较。若组内平均 JS 比组间小 ≥ 20%，且在 ≥ 8/10 个熵组成立，记为"按卷积成组"。
  - P3：固定衰减（RetNet）对数据依赖衰减（其余 5 个循环模型），标记方法同 P1。
- **聚类：** 平均 JS 矩阵的层次聚类（平均连接），只作描述。
- **不能做的事：** 没有同架构不同种子的模型，所以没有绝对的噪声地板，只看相对结构。假定种子噪声对每一对大致相同，则成组结构本身就是架构效应的证据；这一点在结论中写明。
- **R5：** 跑完不改分组、阈值和读数；新加的分析一律标 POST-HOC。

## 混杂审计
- 7 个模型的整体水平不同，水平差距大的一对 JS 自然更大，所以报告 JS 与水平差的相关，并在熵组内比较。
- Mamba 用不同的加载类，若它的 NLL 明显异常（远高于 E202 的值），则排除它。

## 算力
- 7 次前向，每次 100 段，1.3B 模型每次约 1–2 分钟；完整分布 fp16 每模型约 3 GB，存节点本地 `/tmp`。离线计算 21 对 JS 约 10 分钟。共 < 1 GPU 小时，1–2 张卡。
- 逐 token 结果不进 git，只提交汇总。

## 结果
- 文件：`results/e223/e223_js.json`（`scripts/e223_dump.py`、`scripts/e223_js.py`）。完整分布在节点 `/tmp/xiang_e194/out223/`，不进 git。
- 7 个模型对这 100 段给出完全相同的 token id（20,406 个预测位置）。平均 NLL：DeltaNet 2.78、GSA 2.79、Mamba 2.82、Transformer 2.84、GLA 2.85、RetNet 2.85、HGRN 2.85。Mamba 正常。
- **结论：事先写定的三种分组都不成立。21 对模型的平均 JS 都在 .055–.073 nat 之间，几乎一样大；Transformer 与循环模型之间的距离，并不比循环模型彼此之间更远。逐 token NLL 的两两相关为 .94–.97。只有 HGRN 与所有模型都稍远（.069 对其余 .059）。**

| 分组 | 比值（整体） | 满足阈值的熵组数 | 判定 |
|---|---|---|---|

- JS 与成对水平差的相关为 −.24：差异不是由模型水平高低造成的。
- 按熵分组：熵最低的一组平均 JS .003，中间一组 .054，熵最高的一组 .121；每组内各对之间相差不大。分歧主要由 token 本身的不确定性决定，而不是由哪两种架构决定。
- 层次聚类（只作描述）：GLA–RetNet、DeltaNet–GSA 最先合并（.055），之后是 Transformer，然后 Mamba，最后 HGRN（.069）。

### 能说和不能说的
- 能说的：在 1.3B 参数、100B token、同数据、同词表下，这 7 种架构在自然文本上的逐 token 预测分歧几乎是均匀的，没有按"注意力 / 循环""有无卷积""固定 / 数据依赖衰减"成组。
- 不能说的：没有同架构不同种子的噪声地板，无法判断 .06 nat 的分歧是"架构差异，但对各对一样大"还是"与换种子差不多"。后一种若成立，结论会是"架构在逐 token 预测上没有留下超出种子噪声的指纹"，那就需要噪声地板来支撑。
- 外部意见（Gemini 第六份）设想的"7 个架构按机制抱团"在这组模型上没有出现。

### 事后观察（POST-HOC）
- HGRN 与所有模型都稍远。HGRN 是逐通道的标量门控循环，没有键值外积状态，这可能是原因，未验证。
- OLMo 一对（OLMo-3 对 OLMo-Hybrid，E221 已存的 NLL）分歧最大的 5% token 主要是人名、网址、邮箱、首字母大写词：大写词首占全部 token 的 13%，在这 5% 里占 23%；标点反而更少。这些多是两个模型都没把握、各自猜不同的 token。

### 文献核对（跑完后由文献子代理读全文核对）
- fla 库：同一个 SlimPajama 100B 子集，同训练配方（GSA 论文附录 C.1、DeltaNet 论文）。分词器是 Mistral 32k，不是 Llama。HF 上的权重是否就是论文中那次运行、数据顺序是否相同，未核实。
- OLMo 一对并不同数据：OLMo-Hybrid 用的是 OLMo 3 32B 的改进配比，token 数和学习率计划也不同。Granite 一对训练 token 数不同（15T 对约 18T）。
- **撞车风险高：** Michaelov et al.（2510.24963）已在 Pythia / Mamba / RWKV 各 6 个种子、约 2B token 的小规模上发现，不同架构的逐词预测从早期起就收敛（相关 ≥ .93）。本卡的"几乎均匀、Transformer 不自成一类"与之一致。Li & Merrill（2606.20936）已发表 OLMo-3 对 OLMo-Hybrid 的逐 token 损失差分析。
- **可用的噪声地板：** 2509.26643 用 PolyPythias 测过种子间逐 token KL；Michaelov 的多种子 Pythia / Mamba / RWKV（是否公开未核实）。关于 PolyPythias"初始化有缺陷"的说法没有找到出处。
