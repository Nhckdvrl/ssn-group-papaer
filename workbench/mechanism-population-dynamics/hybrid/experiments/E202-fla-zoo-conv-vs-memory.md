# E202：同配方的循环模型库里，没有短卷积时，各种循环记忆会不会自己拼词（fla-hub 1.3B，2026-11-23）

- **状态：** PLANNED（09:00 写定，在下载和任何运行之前）
- **类型：** PILOT（只推理；不推进主张等级）
- **对应：**
  - E199 中，没有卷积的 Ring 由记忆拼词，但只有一种记忆类型，"有没有卷积"与"记忆类型"混在一起。
  - E201 的自训小模型桥接失败，没能拆开这个混杂。
  - flash-linear-attention 团队公开了一组同配方模型（fla-hub，约 13 亿参数，1,000 亿 token，分词器与数据相同）：带短卷积的 DeltaNet、Mamba；不带短卷积的 GLA、GSA、HGRN、HGRN2、RetNet；以及 Transformer。各 config.json 已于 11-23 核对 `use_short_conv` 字段。除 Transformer 外，这些模型都没有注意力。
- **问题（一句话）：** 在同一份数据、同一配方下，五种不同的循环记忆在没有短卷积时，是否都在最初几层把词拼好？带卷积的模型关掉卷积后，是否同样拼不起来？

## 设置
- **模型**（bf16，只推理；HF main 分支，记 revision）：

  | 键 | 模型 | 层数 | 短卷积 | 读数层 |
  |---|---|---|---|---|
  | TF | fla-hub/transformer-1.3B-100B | 24 | 无，全注意力 | 第 2 层 |
  | DN | fla-hub/delta_net-1.3B-100B | 24 | 有，宽 4 | 第 2 层 |
  | MB | fla-hub/mamba-1.3B-100B | 48 | 有，宽 4 | 第 5 层（层数是其他模型的两倍，取相同的相对深度） |
  | GLA / GSA / HGRN / HGRN2 / RET | fla-hub/gla-、gsa-、hgrn-、hgrn2-、retnet-1.3B-100B | 24 | 无 | 第 2 层 |

- **运行前修订（09:40，未看任何读数）：**
  - 只用 m = 2–6 都齐全的词（修正后为 600 个）。
  - fla 的 Transformer 需要 flash-attn，已装预编译包 2.8.3。
  - 环境：transformers 4.57.6、fla 0.4.0。
  - **条目 bug（10:00 发现并修正）：** Llama 的 SentencePiece 分词器会在每个单独编码的字符串前加词首符号 "▁"。原条目脚本把每一片单独编码，续接片因此变成了词首 token，拆开的词看起来像几个独立的词。第一次 TF 运行的 R1 在所有层都贴着机会水平，我看到这个数字后查出了原因。已改为按词表直接查 id（首片带 ▁、续接片不带），全部 8 个模型重跑；E194 的读数定义没有任何改动。其他模型（OLMo、Granite、Qwen、Falcon-Mamba、Ring）用的是不加词首符号的 BPE 分词器，不受影响。条目数变为 600（原 599）。
- **条目：** E194 的规则（EWT、单 token 词人为拆成 m = 2–6 片、种子 194、600 个词），用这组模型共同的 Llama 分词器（3.2 万词表）重建。
- **读数：** E194 的 R1（同一上下文 32 个候选；拆分 / 前缀打乱 / 只剩最后一片），逐层报告。另报 50 段 EWT 上的每 token NLL。
- **干预：** 只对带卷积的 DN、MB 做 `noconv`。做法是把读数层及之前各层里所有短卷积模块的邻位抽头置零，只保留当前抽头。不带卷积的模型没有其他跨位置混合部件，不需要干预。

## 判据与决策表（跑之前写定）
- **桥接：** TF 读数层的拆分 R1（m = 2–5 平均）≥ .5。不过就说明这个规模不拼人为拆开的词，其余不解读。
- **Δ：** 读数层的拆分 R1（m = 2–5 平均）减去同层"只剩最后一片"的平均。

| 问题 | 结果 | 条件 | 记录 |
|---|---|---|---|
| 问 1：无卷积模型 | **多种记忆都会拼** | 5 个无卷积模型中至少 4 个 Δ ≥ .30 | "没有卷积时由记忆来拼"不限于某一种记忆类型，E199 的混杂大部分解除 |
| | **都不会拼** | 至少 4 个 Δ ≤ .10 | 记忆一般拼不了词，Ring 是例外，"谁来拼"的说法要收窄 |
| | **中间** | 其他 | 按记忆类型逐个描述 |
| 问 2：带卷积模型 | **卷积必要** | DN、MB 的 `noconv` 在读数层的 Δ ≤ .10 | 在同配方模型上复现 E196 / E198 |

- **R5：** 跑完不改读数层、阈值和条目规则；新加的分析一律标 POST-HOC。

## 混杂审计
- **数据、配方、规模、分词器：** 同一套，已控制。
- **记忆类型：** 本卡有意让它变化（五种），以检验结论是否依赖单一类型。
- **同一种记忆有没有卷积：** 这组模型里没有，属未控制。仍需 PhysicsLM4.2 或更大的自训。
- **Mamba 层数：** 是其他模型的两倍，读数层按相对深度取。

## 算力
- 8 个模型，每个约 3–5 GB。推理每个约 5 分钟。只用空闲卡，白天最多 8 卡。预计 < 2 GPU 小时。

## 结果（2026-11-23 10:00 填写；上面的内容未改）
- **桥接不通过。** TF 第 2 层的拆分 R1（m = 2–5 平均）为 .12，下限 .11。这组 1.3B / 100B 的模型拼词发生在中层，第 2 层读数不适用。按卡上规定，本卡不解读，中层的问题另写 E203（10:20 登记；写卡时只看过 TF 的 m = 2、m = 4）。
- **加载检查：**
  - 正常（每 token NLL）：TF 2.81、DN 2.76、GLA 2.81、GSA 2.77、HGRN 2.84、RET 2.81。
  - 不正常：HGRN2 为 6.01，续写异常；MB（Mamba）为 20.92，续写是乱码。推测与我们用的 fla 0.4.0 不兼容，两者都排除。
  - GSA 原仓库的分词器配置要求慢速 SentencePiece，改用 TF 目录中的快速分词器文件（与它的 `tokenizer.model` 逐字节相同）。
- **第 2 层的数字（描述）：** 拆分减下限（m = 2–5 平均）：DN +.16，GSA +.22，HGRN +.08，GLA / RET / TF ≈ 0；DN 只关前三层卷积后为 −.01。
