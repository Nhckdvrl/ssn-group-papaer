# E204：卷积被重置为恒等后，混合模型多快能重新学会早期拼词，谁来补位（Qwen3.5-0.8B 继续训练，2026-11-23）

- **状态：** PLANNED（卡内时刻按提交记录校正为近似值）（约 09:50 写定，在下载和任何运行之前）
- **类型：** PILOT（继续训练 + 只读读数；不推进主张等级）
- **对应：**
  - README "它能解释的"一节里的推论：Bandarkar et al. 2609.35378 把 Transformer 蒸馏成混合模型时，短卷积按恒等初始化（附录算法 1：κ_j ← δ_{j,K}）。按 E196、E198、E203，卷积是早期拼词的必要条件，所以学生模型在训练早期拼不了词，"第一层放全注意力"的排法因此占优。
  - 这条推论尚未检验。他们的学生模型没有公开。
  - 本卡用一个原生训练好的混合模型，把前三层的卷积重置为恒等，再继续训练，直接看：
    1. 卷积能不能很快重新学会拼词；
    2. 卷积冻结时，记忆会不会补位；
    3. 第一个全注意力层（第 3 层）会不会接手拼词。
- **问题（一句话）：** 卷积被重置为恒等的混合模型，在 2 亿 token 的继续训练中，是靠卷积重新学会早期拼词、靠记忆补位、靠第一个注意力层接手，还是一直拼不了？

## 设置
- **模型：** Qwen/Qwen3.5-0.8B-Base。24 层；第 3、7、11……层为全注意力，其余为 GDN（卷积宽 4）。
- **数据：** FineWeb-Edu sample-10BT 第一个分片，用 Qwen3.5 分词器切分。序列长 512，与 E201 同一份文本。
- **三个变体**（训练设置相同：AdamW，学习率 5e-5，预热 100 步后不变，bf16，每步 128 条 × 512 token，共约 2 亿 token，种子 204；全部参数可训练，除非另说）：

  | 变体 | 做法 |
  |---|---|
  | `ctrl` | 不改，直接继续训练 |
  | `id_train` | 第 0–2 层的短卷积设为恒等（当前抽头 = 1，其余 = 0），卷积可训练。对应蒸馏初始化 |
  | `id_frozen` | 同上，但卷积冻结在恒等，只能靠记忆和其他部件补位 |

- **读数**（训练前，以及 1,000 万 / 5,000 万 / 1 亿 / 2 亿 token 时）：
  - E194 的 R1（Qwen 条目，600 个词，同一上下文 32 个候选），重点看第 2 层（最后一个 GDN 层）和第 3 层（第一个注意力层）的拆分 R1，m = 2–5 平均，减去"只剩最后一片"，记为 Δ2 和 Δ3；
  - 50 段 EWT 上的每 token NLL。

## 运行前修订（约 10:05；只看过第 0 步的桥接读数和第 25 步的训练损失）
- **桥接通过：**
  - `ctrl` 第 0 步 Δ2 = +.70；`id_train` 第 0 步 Δ2 = −.01。
  - 每 token NLL：`ctrl` 3.18，恒等卷积 13.49。恒等卷积的当前抽头是 1，而不是训练值，所以扰动比 E196 的 `noconv` 大。
- **预算缩减：** 实测吞吐只有每秒约 8,500 token（梯度检查点、卷积用 PyTorch 参考实现、24.8 万词表的 logits），2 亿 token 会使合计接近 20 GPU 小时。改为每个变体 1 亿 token，检查点取 1,000 万 / 5,000 万 / 1 亿。
- **判据相应修改：** "重学很慢"改为"1 亿 token 时 Δ2 仍 < `ctrl` 的 50%"。这比原定的 2 亿 token 弱，结论只适用于 1 亿 token 以内。

## 判据与决策表（跑之前写定）
- **桥接：**
  - 训练前的 `ctrl` 必须 Δ2 ≥ .30（0.8B 也在前三层拼词）。
  - 训练前的 `id_train`（恒等卷积）必须 Δ2 ≤ .10。
  - 不过就只描述。
- **`id_train` 在 2 亿 token 时：**

  | 结果 | 条件 | 记录 |
  |---|---|---|
  | **卷积很快重学** | 在 5,000 万 token 以内，Δ2 回到 `ctrl` 同期的 80% 以上 | 恒等初始化只是短暂的障碍。用它来解释 Bandarkar 的 10 亿 token 结果站不住 |
  | **重学很慢** | 2 亿 token 时 Δ2 仍 < `ctrl` 的 50% | 恒等卷积的混合模型长期拼不好早期的词。用它来解释 Bandarkar 的结果站得住 |
  | **中间** | 其他 | 描述 |

- **`id_frozen`（另记）：**
  - Δ2 是否上升：记忆补位。
  - Δ3 是否超过 `ctrl` 同期：第一个注意力层接手。
- **R5：** 跑完不改读数层、阈值、检查点；新加的分析一律标 POST-HOC。

## 混杂审计
- **继续训练的数据：** 不同于原训练数据（FineWeb-Edu 对 Qwen 的私有数据）。`ctrl` 同样经历这一变化，作为参照。
- **学习率与 token 量：** 远小于原训练，结论只适用于"短时继续训练"这一情形。
- **与 Bandarkar 设置的差别：** 他们是从 Transformer 蒸馏、只训练转换层；本卡是原生混合模型、全参数继续训练。本卡检验的是"恒等卷积能否很快重新学会拼词"这一环，不是完整复现他们的实验。

## 算力
- 3 次训练，每次约 2 亿 token。0.8B 全参数，预计每秒约 2–3 万 token，每次约 2–3 小时，合计约 7–9 GPU 小时，低于 20 GPU 小时的请示线。
- 白天最多 8 卡，本卡用 3 张，只用空闲卡。

## 结果（2026-11-24 约 00:50 填写；上面的内容未改）
- **桥接通过**（见运行前修订）。
- **Δ2 / Δ3 / Δ8**（第 2、3、8 层的拆分 R1，m = 2–5 平均，减去"只剩最后一片"）：

  | 变体 | 1,000 万 token | 5,000 万 token | 1 亿 token |
  |---|---|---|---|
  | ctrl | .70 / .76 / .80 | .69 / .74 / .79 | .68 / .74 / .80 |
  | id_train | .01 / .00 / .21 | .00 / .02 / .28 | .03 / .08 / .35 |
  | id_frozen | .01 / .00 / .21 | .00 / .02 / .28 | .04 / .08 / .36 |

- **每 token NLL：** ctrl 3.26 / 3.29 / 3.30；id_train 3.69 / 3.48 / 3.46；id_frozen 3.69 / 3.48 / 3.46。
- **按决策表判"重学很慢"**：1 亿 token 时 Δ2 = .03 < .34。第 3 层的注意力也没有接手（Δ3 = .08）；只有更深的第 8 层慢慢恢复了一部分。
- **但这个检验没有到位：** `id_train` 的卷积几乎没被训练，1 亿 token 后邻位抽头的最大绝对值只有 .016（训练好的卷积可达 1.76）。原因是学习率 5e-5 太低，而且权重直接用 bf16 训练，小幅更新被舍入。因此 `id_train` 与 `id_frozen` 几乎相同。
  - 本卡只说明：在"低学习率、bf16 权重"的继续训练中，恒等卷积不会自行恢复拼词。
  - 它不能检验"在蒸馏式高学习率下卷积能否重学"。
  - 改正版见 E208。
