# E210：同数据、同分词器的 RWKV-4 对 Pythia——宽度只有 2 的 token shift 也会独揽拼词吗？小模型在训练充分时会拼吗？（2026-11-24）

- **状态：** 停止，未运行（约 01:05 写定；约 01:15 按用户指示停在下载阶段，没有任何读数）
- **类型：** PILOT（因果 + 描述，只推理；不推进主张等级）
- **对应：**
  - 目前的结论是"谁来拼词，由架构在最初几层提供的局部混合部件决定"，但证据里的局部部件都是宽度 4 的短卷积。
  - RWKV 没有卷积，它的局部部件是 **token shift**：每一层的时间混合和通道混合，都把当前位置和前一个位置按学到的比例相加，宽度只有 2。它的记忆是 WKV 循环。
  - 宽度 2 一次只能看到前一片。拼 5 片的词需要逐层接力，或者交给记忆。这两种结果事先都说得通。
  - E201 的自训小模型（9 千万参数、5 亿 token）完全不拼人为拆开的词，原因可能是参数少，也可能是 token 少。RWKV-4 和 Pythia 从 1.6 亿参数起，都训了约 3,000 亿 token，可以把两者分开。
- **问题（一句话）：** 在同数据、同分词器训练的 RWKV-4 里，关掉最初几层的 token shift 或 WKV 记忆，哪一个会让早期拼词消失？在训练充分时，1.6 亿参数的模型会拼人为拆开的词吗？

- **读数：** E194 的 R1（同一上下文 32 个候选，top-1）。Δ = 拆分（m = 2–5 平均）− 只剩最后一片。逐层报告；另报 50 段 EWT 的每 token NLL。
- **RWKV 的干预**（只作用于第 0–2 层；RWKV 用 fp32）：

  | 条件 | 做法 |
  |---|---|
  | `none` | 不干预 |
  | `noshift` | 时间混合与通道混合的 token shift 都只保留当前位置（所有 `time_mix_*` 设为 1） |
  | `nomem` | WKV 只看当前 token（`time_first` 加 20、`time_decay` 加 20）。只加大衰减不够：RWKV-4 的 WKV 对前一个 token 不衰减，只改衰减会留下"当前 + 前一个"的宽 2 窗口。这样设定后与 GDN、Mamba 的 `nomem`（记忆只剩当前 token）对应 |
  | `noshift_nomem` | 两者都关 |

- Pythia 只做描述（逐层 R1），不干预。

## 判据与决策表（跑之前写定）
- **问 1：训练充分的小模型会不会拼。** 某个模型在前一半层里 Δ 的最大值 ≥ .30，计为"会拼"。
  - 若 1.6 亿的两个模型都"会拼"：E201 的失败来自 token 太少（5 亿对 3,000 亿），不是参数太少。记下，用于决定自训的预算。
  - 若都不会、而大模型会：参数是瓶颈。
  - 其他：描述。
- **问 2：RWKV 里谁来拼。** 只用桥接合格的规模：`none` 的第 2 层 Δ ≥ .30，且 `noshift_nomem` 的第 2 层 Δ ≤ .10。
  - **干净性：** 某个条件第 2 层"只剩最后一片"的下限（m = 2–5 平均）< 不干预时的 .75 倍，就记"该干预破坏表示"，不归类。
  - "消失"：第 2 层 Δ ≤ .25 × `none`；"保留"：≥ .75 × `none`。

  | 结果 | 条件 | 记录 |
  |---|---|---|
  | **token shift 负责** | `noshift` 消失，`nomem` 保留 | 宽度 2 的局部部件也独揽拼词，与带卷积的模型相同 |
  | **记忆负责** | `nomem` 消失，`noshift` 保留 | 宽度 2 不够，交给记忆，与无卷积的模型相同 |
  | **协作** | 两者都消失 | 都必要 |
  | **冗余** | 两者都保留 | 单关一条可以补上 |
  | **中间** | 其他 | 描述 |

  - 各合格规模分别判；规模之间结论不同就如实记录。
- **另报（不进决策）：** `noshift` 下，Δ 能否在第 L/2 层追回（后面的层是否补拼）；按 m 分开的 Δ，看宽度 2 对长词是否更吃力。
- **R5：** 不改层号、阈值和条件；新加的分析一律标 POST-HOC。

## 混杂审计
- RWKV-4 与 Pythia 的数据、分词器、token 数相同，但训练超参不同，规模也只是近似对齐；这里不比较两种架构的绝对 Δ，只看各自的规律。
- token shift 的系数是学到的，有些通道本来就接近 1（几乎不看前一位置）；`noshift` 只是把所有通道统一设成 1。
- 干预后的分布外问题与 E196 相同：用 NLL 报告损伤程度，只解释第 2 层和"能否追回"。
