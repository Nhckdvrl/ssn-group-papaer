# 从实验事故中提炼的可迁移规则

这些不是“我们非常严谨”的宣传，而是曾经真实改变了研究结论、甚至让数据丢失的工程事实。完整出处：[PAIN_LOG](../../PAIN_LOG.md)。

## A. 模型前向、因果干预的隐蔽失败

**P01 / E01：parent 代码行为≠论文/调用者字面意思。** 递归函数丢失参数，期望 abs 的调用实际执行 mul；随机 token 经 decode/re-tokenize 改变token数量且引入多个 BOS；hook_v 中缓存长度不匹配落入 except BOS-V 替换，不是说好的 mean ablation；命令行 --ckpt 被忽略加载 final。应查看有效的 runtime 分支和实际 tensor 形状，而不只检查函数签名。

**P03 / E01：随机头对照可以被一个病态头污染。** 70M 后期某个第0层头在 BOS-V/zero/mean 消融下符号和规模都可能不同，导致“我们的头并不比随机显著”的说法依赖错误基线。正对照应确认参考均值实际被使用，随机对照报告每个极端样本的影响。

**P05 / E28：hook执行了但没有命中被计分的序列位置。** 原操纵末 token 恰非概率计算所使用的 logits；消融无效但程序不报错。新增操纵必先做“全部相关头消融会改变被测量量”的 assert。图与表中任何效应=0都先检查位置对齐。

**P06 / E33：bf16的两个近似logit相减可能量化成同一个 margin。** 检查 hook是否生效应比较完整 logits 向量的变化；低差异的 per-example margin 需要 fp32 lm_head 读取。注意量化误差不只影响统计显著性，也可能使阈值/argmax翻转。

**P04 / E01：罕见token重尾。** 随机token后期平均loss可能被少数极罕见token吞没，但中位数显示不同情况。对自然/随机探针的“能力退化”，先画分布、分组，不凭一个均值讲机制。

## B. 统计、归因与公开模型数据完整性

**P08 / E35：平方和占比有自由度偏置。** 3 init ×25 recipe设计里初始化/数据/残差的df差异巨大，纯噪声也可能使数据项平方和大。原“数据解释41–87%”修正为适当均方/无偏方差分量。不要直接用SS占比比较不平衡因子。

**P09 / E44：PolyPythias weight-seed虽然发布step0不同，实际step1来自同一个标准初始化。** 初始化对比应核查早期训练权重轨迹。不能只相信模型 ID 或独立的step0文件。

**P11 / E58：Pythia 2.8B standard与dedup终点过度相似。** 该尺寸比较不能算真正独立训练的siblings；不是所有公开pair名义上都满足实验前提。

**P12 / E35：DataDecide 1B 的75个中有6个初始化标签不一致。** 按头图发现异常，再以发布初始化权重+早期权重证实。正确1B计数69。这里真正有意义的“异常发现”必须经独立权重核验，不能拿检测器自己确认自己。

**P13 / E81：OLMo-2的 main 不是 SFT/DPO/Instruct 的祖先。** 误判会制造“fine-tuning中所有头换了”的假现象。父子关系须核对真实 checkpoint、权重近似和公开训练 lineage，不只看名称。旧错误pair已剔除。

**E81/v3指标合同问题：** 单头ablation top3 additive transfer与DLA top3的joint transfer被文本表格混为一谈；见[专门测量审计](MEASUREMENT_AUDIT.md)。

**E83：同一个基准集时间线上看到“行为出现时已经选定”，在独立12个run的前瞻验证仅3/12。** 相似轨迹不是普遍发展规律；关键结论必须留出未参与挑选的训练分支。

**E86：完全相同rerun也让9/15 induction注意argmax易主。** 绝不把训练数据删减导致的top1变化直接归因于删数据。要比较整体角色、真正因果集合与最终行为。

## C. 运行与资产管理事故

**P07：while read 循环里 ssh吞掉STDIN使任务队列提前结束。** 用 ssh -n 或重定向stdin；同时别把“worker退出”当成模型无法训练。

**P10：在运行中的目录 stash/rebase、取消Git跟踪，可能删掉正在写的真实结果。** 不在 active outputs目录做rebase/stash/删除/移动。日志缺失不代表运行失败，研究数据应先稳妥归档。

**资产：** Git 中没有 v3 部分图依赖的原始 NPZ，不能声称纯 clone 可以完整重建；旧软件复现包已于 2026-10-23 删除（见[研究总档](../../RESEARCH_HISTORY.md) §9、§11）。

## D. 新进入者的操作顺序

审查一个新结果时，按成本递增走四步：
1. 看原始样例/结果分布，有没有极端位置、token、模板或无效条件。
2. 核查被执行的代码分支、hook张量与真正评测logits的对齐。
3. 核对模型权重谱系、训练/推理设置和统计单位。
4. 设计一个使竞争解释出现分歧的小干预，再考虑多GPU验证。

真实观察造成混乱，不是增加十个免责声明的理由；优先用一个小而具有分辨力的测试暴露机制。失败结论也应作为知识资产明确冻结。
