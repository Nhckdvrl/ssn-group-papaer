# 置换对称、训练谱系与跨模型对应：一个最小数学地图

**目的**：精确定义“同一个head”“同一个role”和“可迁移的head发现”，避免把对称性当口号。

## 1. 参数群作用与恒等函数

对含H个头的常规attention层，设头h的输出为 \(y_h=A_h(X)XW_V^hW_O^h\)。层输出为 \(\sum_{h=1}^H y_h\)。若对每个h把整个 Q/K/V 块与对应O块一起按置换 \(\pi\) 重新标号，得到的函数保持不变。

但注意：
- 不可以只交换输出O块而不交换其余块，再声称函数不变；
- 共享参数、多查询注意力等不同架构的合法重标操作可能不同，需要根据真实参数分组验证；
- 优化器轨迹在理想参数置换下可等变，不代表独立优化轨迹的实际 head 编号可以跨随机种子对照。

形式上，head索引是一个gauge。跨独立init不能把“编号h”视为有内在语义的单位。

## 2. 共享祖先的情况为何不同

两次训练若从同一初始参数张量出发，那么当前第h个head都可追溯到相同祖先参数块。这给出历史配对。共同置换两个模型，索引相似度仍然不变；分别对两个模型任意重排则会改变原编号对应。

因此：
- 不同init同编号相关≈0，是对称性兼容的基线；
- 同init跨数据正相关，不由对称性自动推导，表示训练轨迹保留了祖先关联；
- 但该正相关可能是许多弱偏向，不能自动说“每个头专职继承”。

最小例子：每层有16头，每头的induction强度从共享初始条件中获得小偏向，加上各自训练的噪声。成对层内Spearman可以正且显著，但最终最大头未必相同。一个自然的model-dependent random effect并不等于确定性功能分配。

## 3. 同编号、最优对齐、因果映射三个不同问题

**Index correspondence**：不做对齐，比较同层h对h。适合有真实同祖先的兄弟或后代；异init只能作为零基线，除非讨论历史身份不可得。

**Statistical matching**：逐层给source和target构建匹配。E72用8种roles做Hungarian后，留出第9种role的相关性较高。但9种role有效维度约2.5意味着所谓留出role和拟合特征可能共享潜在公共轴。因而“留出一个分数”不是充分独立因果预测。

**Causal correspondence**：匹配是否保持具体干预后果，例如移除这个head后，哪个候选、哪个下游接收者、哪条信息路径发生相同变化。可以是一头对一组、功能类别对应、路径对应，不必执着双射。

## 4. E72和E75合起来真正告诉了我们什么

E72：
- same init index: induction .32, previous .42, retrieval .31；
- different init经多角色对齐: induction .68, previous .74, retrieval .49；
- 与same-init经对齐的值相当；
- E72b第一主成分59%、有效维度~2.5。

这意味着统计角色在某种对齐后有共同组织轴，而不是“跨seed就完全没有功能头对应”。

E75：
- Pythia410M index迁移接近0；
- 在目标使用DLA参与映射后留出提示的联合消融恢复~.85/.94；
- 不使用目标因果读数的两种角色/类型匹配，无法在所有模型对上同时奏效。

两者一致地指向：**G1统计类型 ≠ G2主要因果承担**。尚未回答G3关系可迁移多少；这应该成为一项下一步实验的中心，而不是试图用某个新的match算法抹平差异。

## 5. 可证伪比较框架

假设 H-A：“统计匹配已经包含足够的因果信息，剩下只有测量噪声”；H-B：“单任务因果主要承担与通用统计角色的分配不同”；H-C：“某个head主要作用会随输入条件分配到不同伙伴”。

最节省信息的验证：
1. 选择因果作用明显、角色类别清楚的一对模型。
2. 使用目标未知因果标签的通用角色匹配，预测目标未参与匹配的单/组消融。
3. 针对失败的一小组头，分别测DLA和单头/联合效应，再用一条路径干预判断信息来自上游还是被下游补偿。
4. 如果一个简单source匹配与target-only一样好，不推断source解释可迁移；如果后者明显好，研究什么信息只有target有。
