> 当前推荐题目。之前的候选 C（上下文绑定跨家族复现）已撤回，旧提案留在 [ZEMI_PROPOSAL.md](ZEMI_PROPOSAL.md) 作历史。找题过程与撞车检查见 [TOPIC_SEARCH.md](TOPIC_SEARCH.md)。试测卡：[E229](experiments/E229-self-correction-blind-spot-origin.md)、[E230](experiments/E230-blind-spot-detection-vs-retraction.md)、[E231](experiments/E231-blind-spot-correct-answer-control.md)。

## 一句话

**语言模型为什么看不见自己刚写的错？——这个盲点来自“接着写”还是“是我写的”，来自预训练还是后训练。**

英文工作标题：*Blind to What You Are Writing: Where the Self-Correction Blind Spot Comes From*

## 1. 现象与为什么值得关心

同一个错误（“1+1 的答案是 3”），放在用户的话里，模型会纠正；放在模型自己的回答里，它往往接着说下去（Tsui, COLM 2026：14 个开源模型平均 64.5%；Chen 2606.05976：Agent 场景 23–93 个百分点）。

- **为什么重要：** 自我纠错是推理模型、Agent、自我审查（self-monitoring）共同依赖的能力。如果模型系统性地看不见自己正在写的错，那么“让模型检查自己的输出”这一类做法在部署时会比离线评测更不可靠（Khullar 2603.04582 在监视器场景里已看到这一点）。
- **现有解释都指向后训练：** Tsui 认为原因是 SFT 数据里几乎没有“犯错—改正”的序列，并找到一个“对话角色方向”；Chen 认为原因是指令微调对角色标签的处理。两篇都只测了指令模型，而且它们的“自己的错”都是在同一段里接着写，“别人的错”都是换一轮来回复——“是谁写的”和“接着写还是回复”从一开始就绑在一起。

## 2. 研究问题（三个子问题，各自的答案都是“是 / 否”或“哪一个”）

| | 问题 | 对照 | 可能的答案 |
|---|---|---|---|
| Q1 | 盲点要求“是我写的”，还是只要求“我正在接着写”？ | 同一错误、同一内容，三种放法：接着写（C）、同一说话人新一轮（S）、另一说话人回复（O） | S 像 O → 是“接着写”；S 像 C → 是“归属” |
| Q2 | 只做过预训练的 base 模型有没有这个盲点？在后训练的哪一步变化？ | base 用纯文本对话格式；OLMo-2 / OLMo-3 公开的 base → SFT → DPO → RLVR 各阶段（含 Think 线与 RL-Zero）；另两个家族的 base / instruct 对 | base 就有 → 现有“后训练造成”的说法不完整；base 没有 → 指出是哪一阶段造成 |
| Q3 | 接着写时没纠正，是**分不清对错**（敏感度），还是**对自己更宽容**（标准）？ | 三种放法都先写同一句检查语，拉平“改口代价”；再把错答案换成正确答案，测误报率（信号检测：命中率 − 误报率） | 敏感度下降 / 只是标准偏移 / 两者都有 |

三个子问题都是同一个现象的成因，不是分解“各占多少”：每个都由一个只改一处输入的对照回答，答案是类别性的。

## 3. 已有的初步证据（OLMo-3-7B 一个家族，pilot）

- **Q1（E229）：** 最终 Instruct 在 chat 格式下，错误留在自己上一轮、新开一轮时纠正率 0.86 / 0.94，与纠正用户（0.84 / 0.88）相同；只有接着写时低（0.51 / 0.26）。→ 最终模型的盲点主要是“接着写”，不是“自己的”。
- **Q2（E229）：** base 在纯文本对话里已有不对称：接着写 0.03 / 0.01，另一人回复 0.28 / 0.51，差值区间不含 0。接着写时能当场改口，只在 DPO / RLVR 之后的最终版出现。
- **Q3（E230）：** 三种放法都先写“Let me check whether this answer is correct.”之后，接着写时仍更少否定错答案（base +0.30 / +0.45，Instruct +0.23 / +0.20）。base 典型输出：“14 is smaller than 19. Yes, the answer is correct.”——事实算对了，结论仍认可自己刚写的 19。认可自己错答案的比例随阶段下降：base 0.79–0.90 → SFT 0.52–0.62 → Instruct 0.28–0.29。
- **E231（正确答案对照，进行中）：** 回答 Q3 里“分不清”还是“更宽容”。

（每格两个数分别为 SCLI5 简单题 / GSM8K 改错题；评判经人工校验，详见各卡。）

## 5. 对照导师的一般标准

| 标准 | 本题 |
|---|---|
| G1 不取决于我们的定义 | 三种放法只改一处文本结构；读数是“最终答案对不对 / 结论认可还是否定”，不设阈值 |
| G2 实验回答所问的问题 | 每个子问题对应一个只改一处的对照 |
| G3 每种结果都有信息量 | 见第 2 节表的最后一列；三问各自两种以上结果都能回答成因 |
| G4 结果不能事先猜到 | 已发表的两种解释（SFT 数据、角色标签）预测 base 没有盲点、新一轮的“自己的错”仍看不见；E229 与之相反 |
| G5 不是程度问题 | 主读数是方向（哪种放法更看不见）与类别（base 有 / 没有；敏感度 / 标准），不是某个超参决定的幅度 |
| G6 不硬拆互相决定的部分 | “接着写”与“谁写的”在输入上可以独立改变；命中率与误报率分别测量 |
| G7 值得好奇 | “为什么看不见自己正在写的错”直接关系到推理模型与 Agent 的自我纠错 |
| G8 有参照与对比 | 参照：同一错误放在别人那里（O）、正确答案对照；对比轴：放法 × 训练阶段 × 家族 |

导师偏好：观察为主（只改输入，不消融）；数字都作为某个变量（放法、阶段）的函数报告；至少两把尺子（纠正率、结论判定，加命中率 / 误报率）；全部开放模型，单个实验 < 20 GPU 小时。

## 6. 范围（不宽也不窄）

**包括：**
- 3 个家族的 base / instruct 对：OLMo-3（含全部阶段）、Qwen2.5 或 Qwen3、一个其它家族，例如 Granite / Falcon3。
- 2–3 种任务：Tsui 的三份数据；外加一种“判断对错”任务（类似监视器），检验结论是否只限于算术。
- 一个机制层面的检查：接着写的位置上，模型内部是否已表示“前面错了”（线性探针或对比激活）。这一项只在 Q3 指向“标准偏移”时做，用来说明“知道但不说”。

**不包括：** 训练模型（只用公开 checkpoint）；提出新的训练方法；闭源模型。

## 7. 风险与应对

- **“当然，模型不爱推翻自己刚说的话”（G4 风险）：** 应对是 Q2 与 Q3。如果盲点在 base 就有、且是标准偏移而非看不见，“为什么”就落在预训练的文本统计上（人写的文字里很少中途否定自己），这不是常识能直接推出的；如果是敏感度下降，结论更强。
- **只在 OLMo 上成立：** 补另外两个家族；OLMo 的价值在于阶段完整。
- **格式混杂（base 没有 chat 角色）：** 所有模型都跑同一套纯文本格式，后训练模型另跑 chat 模板；只在同一格式内比较。
- **评判误差：** 每个实验都有人工校验（E229 60/60；E230 新样本 38/40）。
