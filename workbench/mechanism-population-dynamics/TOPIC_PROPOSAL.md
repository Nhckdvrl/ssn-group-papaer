## 一句话

**语言模型改不了自己的错，一直被解释为后训练带来的“角色偏置”。它其实是不是预训练就有的“接着写的惯性”？后训练和 “Wait,” 这类修补手段，到底让模型更会分辨对错，还是只是让它更容易推翻自己（连对的也推翻）？**

给导师的日文版（草稿）：
> LLM が自分の誤りを直せない現象は「後学習による役割バイアス」と説明されてきたが、実際には事前学習の段階からある「続きを書く慣性」ではないか。さらに、後学習（SFT・DPO・RLVR）や “Wait,” のような手当ては、誤りを見抜く力を上げているのか、それとも正解まで覆すほど判定の基準をずらしているだけなのか。

英文工作标题：*Blind to What You Are Writing: Continuation, Not Authorship, Drives the Self-Correction Blind Spot — and Most Fixes Shift the Criterion*（标题里的结论待第 8 节的检验确认后再定）

## 1. 现象、现有解释与为什么值得关心

同一个错误，放在用户的话里，模型会纠正；放在模型自己的回答里，它往往接着说下去（Tsui, COLM 2026：14 个开源模型平均 64.5%；Chen 2606.05976：Agent 场景 23–93 个百分点）。

- **现有解释都指向后训练：** Tsui 认为 SFT 数据里几乎没有“犯错—改正”的序列，并找到一个“对话角色方向”；Chen 认为是指令微调对角色标签的处理。两篇都只测了指令模型；它们的“自己的错”都是在同一段里接着写，“别人的错”都是换一轮来回复，“谁写的”和“接着写还是回复”从一开始就绑在一起。
- **现有修补只看一半：** 自我纠错的研究（Tsui 的 “Wait”，以及推理模型 / RLVR 的反思研究）几乎只报“错的改对了多少”（命中率），不报“对的被改错了多少”（误报率）。只看命中率，分不清一个训练阶段或提示词是让模型**看得更准**，还是只是让它**更爱怀疑自己**。
- **为什么重要：** 推理模型、Agent 和自我监控都依赖“模型检查自己的输出”。如果盲点来自接着写的惯性，修补就该落在生成方式上（例如把输出放到新一轮再检查），而不是 SFT 数据；如果修补只是移动了门槛，它在部署时会以推翻正确答案为代价。

## 2. 研究问题

贯穿全文的读数是信号检测：**命中率**（错答案被否定）与**误报率**（正确答案被否定）一起测，再用不依赖门槛的分级读数（判定处 Yes / No 的概率在对、错答案之间的 AUC）区分“分辨力”与“门槛”。

| | 问题 | 对照（只改一处） | 答案的形式 |
|---|---|---|---|
| Q1 | 盲点要求“是我写的”，还是只要求“我正在接着写”？ | 同一错误三种放法：接着写（C）、同一说话人新一轮（S）、另一说话人回复（O）；另测错误是否为模型自己会犯的（on-policy / off-policy） | S 像 O → 接着写；S 像 C → 归属 |
| Q2 | 盲点在预训练模型里就有吗？后训练各阶段让它变好还是变坏？ | base（纯文本对话格式）与 OLMo-3 公开的 SFT → DPO → RLVR、Think 线、RL-Zero；另两个家族的 base / instruct 对 | 哪个阶段改变了它，方向如何 |
| Q3 | 接着写时没纠正，是分辨力下降，还是门槛更高（对自己更宽容）？各阶段与 “Wait,” 改变的是哪一个？ | 三种放法都先写同一句检查语；错 / 对答案配对；**把同一段验算文字原样接在 C / S / O 后面**，只读最后判定处的 Yes / No 概率 | 分辨力 / 门槛 / 两者 |

三个问题都是同一现象的成因，每个由一个只改一处输入的对照回答，答案是类别性的，不是“各占多少”。

## 3. 已有的初步证据（OLMo-3-7B 一个家族，pilot）

每格两个数分别为 SCLI5 简单题 / GSM8K 改错题；评判均经人工校验（见各卡）。

**Q1（E229，无检查语，纠正率）**

| 模型 | C 接着写 | S 新一轮 | O 回复别人 |
|---|---|---|---|
| base（纯文本） | 0.03 / 0.01 | 0.16 / 0.21 | 0.28 / 0.51 |
| SFT（chat） | 0.00 / 0.09 | 0.60 / 0.57 | 0.41 / 0.70 |
| Instruct（chat） | 0.51 / 0.26 | 0.86 / 0.94 | 0.84 / 0.88 |

- 最终 Instruct：错误留在自己上一轮、新开一轮时，纠正得和纠正用户一样好，只有接着写时低。
- 注意：chat 里的 S 是两条连续的 assistant 消息，中间没有用户插话。这对只见过交替对话的模型是不常见的格式，需要加“中间有一句中性用户话”的变体（第 8 节）。
- 与 Khullar 2603.04582 不矛盾：他们的“上一轮也放水”只在 on-policy（模型自己生成的内容）时出现；固定内容预填为 assistant 消息（off-policy）时，上一轮的 AUROC 为 0.99，和我们的 S 一致。这说明 on-policy 可能还有一层“熟悉自己写法”的效应，Q1 需要把它作为单独一维测。

**Q2（E229 / E230）**
- base 已有不对称，但无检查语时 base 回复别人会改掉 64% / 45% 的**正确**答案（E231），扣掉后差距缩小到 +0.13 / +0.24（仍不含 0）。
- 先写检查语再判定时（E230），接着写时“认可自己错答案”的比例：base 0.79 / 0.90 → SFT 0.52–0.62 → Instruct 0.29 / 0.28。盲点在 base 最重，后训练逐步减轻，而不是后训练造成的。

**Q3（E230 / E231，中性检查语）**
- 三种放法对正确答案几乎都不否定（误报率 ≈ 0），接着写时对错答案的否定却少得多：命中率 − 误报率，base 0.21 vs O 0.50，Instruct 0.70 vs 0.94，差值区间不含 0。→ 不是“对别人一律挑剔”。
- base 的典型输出：“14 is smaller than 19. Yes, the answer is correct.”——验算写对了，结论仍认可自己刚写的 19。
- “Wait,”：最终 Instruct 在自己答案后加 “Wait,”，会推翻约一半的**正确**答案（误报 0.49；回复别人时 0.03）。至少在 OLMo-3 上，“Wait” 带来的纠正有很大一部分是门槛移动。是否适用于 Tsui 测过的模型，要在其它家族上验证（第 8 节）。
- 还没分开：误报率在地板上，“分辨力下降”与“门槛更高”从比例上分不开，需要第 8 节的锁定验算文字 + AUC。

## 5. 对照导师的一般标准

| 标准 | 本题 |
|---|---|
| G1 不取决于我们的定义 | 放法只改一处文本结构；读数是“结论认可还是否定”与判定处的 Yes / No 概率；不用探针，不设阈值 |
| G2 实验回答所问的问题 | 每个子问题对应一个只改一处的对照；Q3 连验算文字都锁定，只换它接在哪里 |
| G3 每种结果都有信息量 | Q1：接着写 / 归属；Q2：哪个阶段、哪个方向；Q3：分辨力 / 门槛 |
| G4 结果不能事先猜到 | 已发表的解释预测 base 没有盲点、新一轮的“自己的错”仍看不见、“Wait” 提高的是纠错能力；pilot 三处都与之相反。真正不能由常识推出的是三件事合在一起：主流归因方向反了；明确要求检查也打不破；流行修补主要在移动门槛 |
| G5 不是程度问题 | 主读数是方向与类别，每个比较带置信区间 |
| G6 不硬拆互相决定的部分 | 接着写与谁写的在输入上可独立改变；命中率与误报率分别测量 |
| G7 值得好奇 | 直接关系到推理模型、Agent 的自我纠错与自我监控 |
| G8 有参照与对比 | 参照：同一错误放在别人那里、正确答案对照；对比轴：放法 × 训练阶段 × 对 / 错答案 × 家族 × 任务 |

导师偏好：只改输入、不消融；数字都作为放法、阶段的函数报告；至少两把尺子（命中率 / 误报率，加 AUC）；全部开放模型，单个实验 < 20 GPU 小时。

## 6. 范围

**包括：**
- 3 个家族的 base / instruct 对：OLMo-3（含 SFT / DPO / RLVR、Think 线、RL-Zero）、Qwen（2.5 或 3）、一个其它家族（Granite / Falcon3）。
- 三类任务：算术与多步推理（Tsui 的数据）；事实知识错误（对应幻觉滚雪球）；客观规则或代码判断（对应 Agent / 监视器）。每类 200–300 题。
- 修补手段：“Wait,” 等提示词、把输出放到新一轮再检查，各自的命中率与误报率。

**不包括：** 训练模型；提出新的训练方法；闭源模型；线性探针（“模型内部知道”取决于探针的定义，撞 G1；锁定验算文字后的 AUC 已能回答同一问题）。

## 7. 风险与应对

- **“当然，模型不爱推翻自己刚写的”（G4）：** 讲题时不把重点放在“base 不爱改口”，而放在“主流归因方向反了 + 明确要求检查也打不破 + 修补主要移动门槛”。
- **S 的格式不自然：** 加中间有一句中性用户话的变体；在所有阶段补齐 S。
- **on-policy 与 off-policy：** 注入的错误可能比模型自己犯的错更容易被看出（Khullar 的结果提示 on-policy 更盲），用模型自己真实答错的题做对照。
- **只在 OLMo、只在算术上成立：** 第 8 节的跨家族与非算术任务。
- **评判误差：** 每个实验都人工校验；判定处的 Yes / No 概率不依赖评判模型。

## 8. 定题前的三项便宜检验（全部只用推理，合计约 6–8 GPU 时，多卡并行；做完再定稿给导师）

1. **Q3 的分辨力 vs 门槛（最关键）：**
   - SCLI5：检查语后直接读 Yes / No 概率，按题算对、错答案之间的 AUC。
   - GSM8K：取模型在 O 条件下自己写的验算文字，原样接在 C / S / O 后面，只读最终判定处的 Yes / No 概率。C 的 AUC 仍低于 O → 分辨力受损；AUC 相同、只是整体偏向 Yes → 门槛移动。
   - 同时加入 OLMo-3 的 Think-SFT / Think（RL）与 RL-Zero，看推理训练改变的是分辨力还是门槛。
2. **Q1 补齐：** S 加“中间一句中性用户话”的变体，在 base / SFT / Instruct 全部补齐；加 on-policy 对照（模型自己真实答错的题）。
3. **泛化：** Qwen 与另一家族的 base / instruct 对，各跑核心的 C / S / O × 对 / 错 × N / V / W；加 200 道事实知识纠错题。
