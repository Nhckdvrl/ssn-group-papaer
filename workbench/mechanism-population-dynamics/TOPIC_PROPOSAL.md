## 一句话

**语言模型改不了自己的错，一直被解释为后训练带来的“角色偏置”。它其实是不是预训练就有的“接着写的惯性”？它的原因是分辨对错的能力下降，还是判定门槛偏了？后训练各阶段和 “Wait,” 这类修补，动的是分辨力还是门槛？**

给导师的日文版（草稿，11-25 晚按审阅意见修订：不把后训练与 “Wait” 绑在“推翻正确答案”一句里）：
> LLM が自分の誤りを直せない現象は「後学習による役割バイアス」と説明されてきたが、実際には事前学習からある「続きを書く慣性」ではないか。そして、その原因は正誤を見分ける力（識別力）の低下なのか、判定基準（閾値）の偏りなのか。さらに、後学習の各段階や “Wait,” のような介入は、識別力と基準のどちらを動かしているのか。

英文工作标题：*Blind to What You Are Writing: The Self-Correction Blind Spot Is a Criterion Shift Toward One's Own Text*

**目前的答案（pilot，三个家族）：**
1. **起源：** 盲点在只做过预训练的模型里就有，后训练各阶段在减轻它，而不是制造它。
2. **机制：** 只要验算写在眼前，模型在接着写时也能把对错完全分开（AUC ≈ 1）；“看不见”来自自己正在写的话把判定往“对”那边拉——接着写（C）与回复别人（O）之间有一个**相对门槛差**，而不是分辨力坏了。不给验算时，AUC 的差也只有 −0.06 到 +0.12，主导差异的同样是门槛。
3. **修补动的是哪一个：** 门槛移动本身不一定是坏事（把偏向“对”的门槛往回推，是在校准）。问题有两层：
   - **过冲：** “Wait,” 把门槛推过了头，在自己的**正确**答案上误报 0.49–0.61（回复别人时 0.03–0.46）；
   - **相对门槛差还在：** Think / RL-Zero 等推理训练整体推向“否定”，但 C 与 O 之间的相对门槛差大多仍在。只移动全局门槛的训练或提示词因此两难：要么回复别人时不误杀、接着写时仍看不见；要么把门槛推到接着写也能纠错，代价是整体过杀。
4. **边界：** 盲点来自“接着写”而非“所有权”——在不带接受信号的新上下文里检查，盲点大幅消失；但在真实多轮对话中，用户表示接受后，模型不会主动回头纠错（E233）。

## 1. 现象、现有解释与为什么值得关心

同一个错误，放在用户的话里，模型会纠正；放在模型自己的回答里，它往往接着说下去（Tsui, COLM 2026：14 个开源模型平均 64.5%；Chen 2606.05976：Agent 场景 23–93 个百分点）。

- **现有解释都指向后训练：** Tsui 认为 SFT 数据里几乎没有“犯错—改正”的序列，并找到一个“对话角色方向”；Chen 认为是指令微调对角色标签的处理。两篇都只测了指令模型；它们的“自己的错”都是在同一段里接着写，“别人的错”都是换一轮来回复。
- **现有修补只看一半：** 自我纠错研究（Tsui 的 “Wait”、推理模型 / RLVR 的反思研究）几乎只报“错的改对了多少”（命中率），不报“对的被改错了多少”（误报率），分不清一个训练阶段或提示词是让模型看得更准，还是只是更爱怀疑自己。
- **为什么重要：** 推理模型、Agent 和自我监控都依赖“模型检查自己的输出”。如果盲点是门槛被自己的文字拉偏，修补就应当针对门槛（例如把输出放到不带接受信号的新上下文里检查），而不是追求“更强的分辨力”；如果修补只是移动门槛，它在部署时会以推翻正确答案为代价。

## 2. 研究问题

贯穿全文的读数是信号检测：命中率（错答案被否定）与误报率（正确答案被否定）一起测，再用判定处 “incorrect” / “correct” 的对数概率之差（不依赖门槛）算 AUC，区分“分辨力”与“门槛”。

| | 问题 | 对照（只改一处） | 答案的形式 |
|---|---|---|---|
| Q1 | 盲点要求“是我写的”，还是只要求“我正在接着写”？换一轮的作用受什么限制？ | 同一错误放法：接着写（C）、同一说话人新一轮（S）、中间有一句 “OK.” 再新一轮（U）、另一说话人回复（O）；注入的错误 vs 模型自己真实写出的错误 | 接着写 / 归属；接受信号是否关闭检查 |
| Q2 | 盲点在预训练模型里就有吗？后训练各阶段让它变好还是变坏？ | OLMo-3 同一 base 的 8 个阶段（SFT / DPO / RLVR、Think 线、RL-Zero）；Qwen2.5、Granite-3.3 的 base / instruct 对 | 哪个阶段改变了它，方向如何 |
| Q3 | 接着写时没纠正，是分辨力下降，还是门槛偏移？各阶段与 “Wait,” 改变的是哪一个？ | 三种放法都先写同一句检查语；错 / 对答案配对；把同一段验算文字原样接在 C / S / O 后面，只读判定处的概率 | 分辨力 / 门槛 / 两者 |

## 3. 已有的证据（pilot）

评判均经人工校验（每张卡 35–60 条；事实题用修订后的规则 v2，37/40）。

**Q2：base 就有，后训练在减轻（E229 / E230 / E234）**
- 不加检查语时，三个家族的 base 都是接着写几乎不纠正、回复别人能纠正：扣掉误报后 O − C 为 +0.12（OLMo-3 SCLI5）到 +0.66（Qwen2.5 SCLI5），事实题 +0.28 到 +0.45，区间都不含 0。
- 先写检查语再判定时，接着写时“认可自己错答案”的比例：OLMo-3 base 0.79 / 0.90 → SFT 0.52–0.62 → 最终 Instruct 0.29 / 0.28。
- 在 instruct 上跨家族复现（中性检查语，H − F 的 O − C）：OLMo-3 +0.23 / +0.20，Qwen2.5 +0.27（SCLI5）/ +0.11（事实），Granite-3.3 +0.29 / +0.20。
- 不一致：Qwen2.5 base 在 SCLI5 + 检查语下反向（−0.22），原因未查；Granite base 与 OLMo-3 SFT 在中性检查语下有一格“检查语后什么都不写”，按规定不解释。

**Q3：门槛偏移，不是分辨力下降（E232）**
- 把同一段验算接在 C / S / O 后面，OLMo-3 的 8 个阶段在两类任务上 AUC 都是 0.96–1.00，三种放法之差都 < 0.012：验算写在眼前时，模型在接着写时也能完全分开对错。
- 但判定的偏向在接着写时一致更偏 “correct”：例如最终 Instruct 的 GSM8K，C −1.56 vs O +0.58；base −0.65 vs +0.14。
- 典型输出（E230，base）：“14 is smaller than 19. Yes, the answer is correct.”——验算对了，结论仍认可自己的 19。
- 不给验算直接判定时，AUC 的 O − C 只有 −0.06 到 +0.12，偏向的差则很大。
- 这修正了 E231 的初步判断（E231 因误报率在地板上暂记为“敏感度下降”）。

**Q3：“Wait,” 与推理训练主要移动门槛（E231 / E232 / E234）**
- 在自己答案后加 “Wait,”，推翻**正确**答案的比例明显高于回复别人：OLMo-3 Instruct 0.49 vs 0.03；Qwen2.5-Instruct 0.61 vs 0.34（SCLI5）、0.59 vs 0.46（事实）；Granite-Instruct 0.13 vs 0.02、0.42 vs 0.16。Tsui 报告的“加 Wait 后盲点缩小 89%”，至少有相当一部分是门槛移动。
- AUC 读数下，“Wait” 不改变 AUC，只把判定整体推向 “incorrect”。
- Think 线（尤其 Think-DPO）和 RL-Zero 也是整体推向 “incorrect”，但“接着写更偏向对”的顺序大多仍在：推理训练抬高的是整体的否定倾向，不是消除对自己的偏向。

**Q1：接着写，以及“接受信号”（E229 / E233）**
- 纯文本对话里：同一说话人新一轮（S），以及中间有一句 “OK.” 再新一轮（U），纠正都明显好于接着写，且两者接近（U − S 在 ±0.06 内）。
- chat 里：最终 Instruct 在连续两条 assistant 消息（S）时纠正得和纠正用户一样好；但如果用户先说一句 “OK.”（U），它就回 “Great! If you have any more questions…”，不再检查。加了检查语也常写 “I will use a calculator to verify”，然后不下结论。所以“换一轮就能纠正”在 chat 里依赖不自然的格式；正常多轮对话里，用户的接受信号会关闭回头检查。
- 与 Khullar 2603.04582 一致：他们的“上一轮也放水”只在模型评自己生成的内容（on-policy）时出现，固定内容预填为 assistant 消息时 AUROC 0.99。本题 on-policy 检验：base 的新一轮帮助从 off-policy 的 +0.21 降到 +0.13（边界，弱迹象）；Instruct 在 GSM8K 上真实答错的题多是它根本不会的题（回复别人时也只否定 10%），用这批题检验不了。锁题后改用“有时对、有时错”的中等难度题（见第 8 节）。

## 5. 对照导师的一般标准

| 标准 | 本题 |
|---|---|
| G1 不取决于我们的定义 | 放法只改一处文本结构；读数是“结论认可还是否定”与判定处的 “incorrect / correct” 概率；不用探针，不设阈值 |
| G2 实验回答所问的问题 | 每个子问题对应一个只改一处的对照；Q3 连验算文字都锁定，只换它接在哪里 |
| G3 每种结果都有信息量 | Q1：接着写 / 归属 / 接受信号；Q2：哪个阶段、哪个方向；Q3：分辨力 / 门槛 |
| G4 结果不能事先猜到 | 已发表的解释预测 base 没有盲点、“Wait” 提高纠错能力；pilot 都与之相反。真正不能由常识推出的是：主流归因方向反了；验算写对了结论仍被拉偏（AUC ≈ 1 而门槛偏）；流行修补主要在移动门槛 |
| G5 不是程度问题 | 主读数是方向与类别，每个比较带置信区间 |
| G6 不硬拆互相决定的部分 | 接着写与谁写的在输入上可独立改变；命中率、误报率、AUC 分别测量 |
| G7 值得好奇 | 直接关系到推理模型、Agent 的自我纠错与自我监控 |
| G8 有参照与对比 | 参照：同一错误放在别人那里、正确答案对照；对比轴：放法 × 训练阶段 × 对 / 错答案 × 家族 × 任务 |

导师偏好：只改输入、不消融；数字都作为放法、阶段的函数报告；至少两把尺子（命中率 / 误报率、AUC）；全部开放模型，单个实验 < 20 GPU 小时（E229–E234 合计约 15 GPU 小时）。

## 6. 范围

**包括：** 3 个家族的 base / instruct 对，OLMo-3 全部后训练阶段；算术、多步推理、事实知识三类任务；“Wait” 等提示词与“换到新上下文检查”的命中率 / 误报率 / AUC。

**不包括：** 训练模型；提出新的训练方法；闭源模型；线性探针（“模型内部知道”取决于探针的定义，撞 G1）。

## 7. 风险与应对

- **“当然，模型不爱推翻自己刚写的”（G4）：** 讲题时把重点放在三件不能由常识推出的事：主流归因方向反了；验算写对了结论仍被拉偏（分辨力完好、门槛偏移）；流行修补主要在移动门槛。
- **chat 里“换一轮”的结论依赖格式（E233）：** 作为 Q1 的边界条件陈述，不作为主要发现（用户说 “OK.” 后助手收尾，导师很可能觉得理所当然）；主结论（Q2、Q3）不依赖 S 的格式。
- **“验算都摆在眼前，当然分得清”（对 E232 的必然追问）：** 把锁定验算（AUC 0.96–1.00）与不给验算的直接判定（AUC 的 O − C 只有 −0.06 到 +0.12、偏向差很大）并排给出：两种情况下主导差异的都是门槛；再拿 E230 的例子说明“验算对了，结论仍不改”；自由生成的两步拆分留到锁题后。
- **门槛移动被误读成“坏事”：** 明确区分“全局门槛”（推理训练与 “Wait” 移动的）与“接着写 vs 回复别人的相对门槛差”（它们大多没消除的）。
- **锁定验算的 AUC 在天花板上：** “分辨力完好”限定在“验算在上下文中”的条件下；需要一个难度更高、AUC 不到天花板的任务来检验（例如更长的多步题）。
- **不一致的格子：** Qwen2.5 base 的 SCLI5 + 检查语反向；两个“检查语后什么都不写”的格子。需要解释或报告为限制。
- **评判误差：** 规则 v2 修订后各批人工校验 90–95%；判定处概率的读数不依赖评判模型。

## 8. 立题阶段到此为止

E229–E234 已足以立题：现象确实存在、跨三个家族复现，三个子问题都有了方向明确的初步答案，并且已经抓到可以作为研究对象的东西（“验算对了、结论仍被自己的文字拉向‘对’”的门槛偏移；“Wait” 与推理训练主要移动门槛；接受信号关闭回头检查）。**锁题前不再追加实验。** 下面几项是锁题之后、写论文时才做的，现在不做：
- **“分辨力完好”是否只是因为验算已给出：** 把自由生成的检查拆成两步统计——验算步骤对不对、验算对了之后结论改不改口；并用更难、AUC 不到天花板的多步题。（E230 的 “14 is smaller than 19. Yes, the answer is correct.” 已是“验算对、结论不改”的直接例子。）
- **on-policy：** 筛出模型采样时 pass@1 在 30%–70% 的题（它有时会错、但在独立上下文里能做对），用它自己真实写错的推理过程放进 C / S / O，做同样的命中率 / 误报率对比，补上 Khullar 留下的 on-policy 缺口。
- **跨阶段比较门槛大小：** 不同阶段的 logit 尺度不同（指令模型更尖锐），写论文时用标准信号检测量（d′ 与相对门槛 c / d′）做尺度标准化后再比较。
- 解释 Qwen2.5 base 在 SCLI5 + 检查语下的反向；OLMo-2 全部阶段、更多家族；把“换到不带接受信号的新上下文检查”作为门槛层面的修补，与 “Wait” 比较。
