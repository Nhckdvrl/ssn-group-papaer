# E72：头的编号是不是纯粹的坐标约定？跨初始化对齐后，被留出的角色能否对上？（2026-10-07）

- **状态：** DONE（2026-10-07）
- **类型：** CLAIM（直接回应“编号在置换对称下本来就是任意的，然后呢”）
- **对应：** C05；Li et al. 2016 / Ainsworth et al. 2023（置换对齐）；A09
- **问题（一句话）：** 每个头是否带有一组跨 run 都成立的“角色组合”（例如强 induction 的头也总是某种 sink / copy 特征）？若是，异初始化模型经置换对齐后应能互相预测；若否，只有共享初始化才能让组件对应。
- **设置：** DataDecide 1B 已核实模型，9 种角色。对每对模型、每层：用 8 种角色的层内 z 分数做特征，以匈牙利算法求使特征相关最大的头置换；在对齐后计算被留出角色的层内 Spearman（9 种角色轮流留出）。比较：同 seed 不对齐（原编号）、同 seed 对齐、异 seed 对齐、异 seed 随机置换（下界）。另报异 seed 对齐后在“用于对齐的角色”上的一致（上界参照）。
- **读数：** 留出角色的一致度，按配对类型。
- **阳性对照：** 同 seed 原编号的留出角色一致度应 ≈ Table 1（0.18–0.43）。
- **决策表：** 异 seed 对齐后留出角色一致度 ≥ 同 seed 原编号的一半 → 写“头有跨 run 的角色组合，编号是可以对齐的坐标；组件层面结论可以通过对齐跨初始化推广”；≈ 0 → 写“角色在头之间的组合本身也由初始化决定，跨初始化无法靠对齐恢复组件对应，只有共享初始化可以”。
- **算力：** CPU。

## 结果（`results/e70_72.json`；E72b `results/e72b.json`）
- 留出角色一致度（同 seed 原编号 / 同 seed 对齐 / 异 seed 原编号 / 异 seed 对齐）：induction 0.32 / 0.69 / 0.00 / 0.68；previous-token 0.42 / 0.76 / 0.00 / 0.74；sink 0.18 / 0.38 / −0.01 / 0.34；retrieval 0.31 / 0.51 / 0.00 / 0.49；OV copying 0.25 / 0.46 / −0.01 / 0.43。
- **E72b 对照：** 9 种角色在头之间的有效维度约 2.5（第一主成分 59%）；只用 1 种角色对齐即可得 0.32，4 种 0.47，8 种 0.54；只按 OV 复制分数对齐预测注意力角色 0.27。→ 对齐后的一致主要来自每层的头沿少数几个通用维度分布，而不是丰富的跨模型“头类型”。
- **E75 雏形（Pythia）：** 用通用角色剖面对齐不能恢复 IOI 组件：160M 标准版 top-3 IOI 头在去重版中 DLA 排名 3.7 / 144（不对齐），对齐后 72（随机 72.5）；在 seed1–9 中 59 → 60。410M：去重版 14 → 41；seed 187 → 134（随机 192）。
- 按决策表：异 seed 对齐后的通用角色一致度高，但这是通用维度的结果，且不能恢复 task circuit → 写“通用统计意义上的组件在置换下普遍；task circuit 的组件对应不能靠这种对齐恢复，只在共享初始化下成立”。
