# E98：损伤后损失很快恢复，能力为什么没跟上？——“慢”还是“卡住”（2026-10-16）

- **状态：** RUNNING（12:10 启动，预计 15:00 完成；fvcrc10:0、fvcrc12:0–1；13:20 时 1500 步）
- **类型：** CLAIM（方向 B 的核心问题：损失恢复是否代表能力恢复）
- **来源：** E97：完整重置 8.9 后，损失 25 步恢复一半、1000 步恢复 75%，而 IOI 前 400 步完全不动、1000 步只到 24%；重置 9.3 后损失恢复 92%，性别停在 60%。

## 设置
同 E97（Pythia-160M step100k，SDPA + fp32，batch 128 × 1024，学习率 2e-5，warm-up 200，init_seed 1234），延长到 5000 步（≈ Pythia 原训练 330 步的 token 量）；三组：C_long（对照）、L8.9_long、L9.3_long，同一数据顺序。每个评估步记录 42 个任务与损失；在 400 / 1000 / 2500 / 5000 步存权重，之后跑 E89 因果图。

## 登记的预测与决策（看结果前写）
- **只是慢：** 5000 步时 IOI、性别恢复比例 ≥ 0.8，曲线没有新的平台 → 能力恢复只是比损失慢（每个能力占损失的份额小、梯度小），平台是起步延迟。下一步问延迟由什么决定（能力在损失中的份额？依赖的前提组件？）。
- **卡住：** 2500 → 5000 步恢复比例的增量 < 0.05 且仍 < 0.6 → 存在“损失恢复、能力停在部分恢复”的稳定状态；用因果图看停在哪（哪个原有承担者到顶、缺的是哪一环）。
- **IOI 停滞期（0–400 步）在做什么：** 若 400 步因果图上某个上游组件（如 duplicate-token / S-抑制类头）先变化、IOI 随后起步 → 恢复有前提顺序（与原发育顺序比较）；若 400 步图与第 0 步图无差别 → 停滞是梯度太小，不是在重建前提。

- 两者都还在涨，暂时更像“慢”而不是“卡住”；性别在 400–1000 步有一段平台，1500 步又升。8.9 损伤的损失恢复本身停在 0.7 左右（总损伤只有 0.006 nat，评估噪声不小）。
- **IOI 停滞期（0–400 步）的因果图：** 训练造成的变化（扣对照与损伤瞬间的变化）最大的是负效应头 8.10 重新变负（−0.16；损伤前 −0.89，损伤瞬间回到零附近），同时 7.2（+0.15）、9.5（+0.10）、10.1（+0.10）、3.2（+0.09）增强——**正负两类变化相互抵消**，IOI 指标几乎不动。即：损伤瞬间靠“抑制头松开”得到的自修复，在训练中被部分收回，正向承担者要慢慢长起来补。到 1000 步 8.10 收回 −0.22。
- 只在 8.10 这一个头上看到“自修复被收回”；跨任务地看，损伤瞬间的变化大多保留到 1000 步（损伤组 − 对照组 对瞬间变化的回归系数 0.7–2.1），不能推广成“训练撤销自修复”。
- 性别 0–400 步：7.5（+0.47）、5.8（+0.32）同向增强，没有抵消，曲线也没有停滞期之外的异常。
- 13:07 补充（2000 步）：IOI 0.33（1000→1500 +0.07，1500→2000 +0.03，增速在降）；greater-than 0.72；损失 0.77。卡住还是慢，要看 2500→5000 步的增量（登记标准：< 0.05 且 < 0.6 算卡住）。

| greater-than（8.9） | 0.53 | 0.69 | 0.72 | 0.65 | 0.67 | 0.68 | 0.62 |
| 损失（8.9） | 0.74 | 0.72 | 0.77 | 0.76 | 0.76 | 0.76 | 0.70 |
| 性别（9.3） | 0.60 | 0.60 | 0.80 | 0.85 | 0.85 | 0.92 | 0.76 |
| 损失（9.3） | 0.83 | 0.87 | 0.91 | 0.95 | 0.90 | 0.93 | 0.93 |
（5000 步原始值：IOI 损伤组 2.14 / 对照 3.47；性别 1.83 / 1.95。）

**按登记标准：**
- **IOI：卡住。** 2500 → 5000 步只增加 0.02（< 0.05），且停在 0.40（< 0.6）。损失恢复同样停在约 0.7–0.76，greater-than 从 0.72 回落到 0.62。
- **性别：只是慢。** 2000 步后在 0.8–0.92 之间波动（5000 步 0.76 落在评估噪声范围内）。
- 也就是说，同样是完整重置一个头：9.3 留下的功能能被其他头慢慢补齐；8.9 的 IOI 补到 40% 就不再动了，而且这次损伤本身的损失也没能补完。
- **限制：** 学习率只有 2e-5，5000 步只相当于 Pythia 原训练约 330 步的 token 量。“卡住”只在这个学习率和窗口下成立。

**下一步（先看因果图再定）：** 比较 2500 与 5000 步的图——IOI 停住时，是现有承担者都到顶了，还是某一环（例如 8.9 原本承担的名字移动）没有人接？若是后者，“卡住”的原因就是缺一个能补位的头，而不是梯度不够。

- **8.9 的正向角色没有任何头接手。** 恢复回来的 IOI 几乎全部来自两个原本起反作用的头：8.10 从 −0.89“松手”到 0，9.5 从 −0.30 翻成 +0.54。真正增加的正向承担者只有 7.2（+0.17 相对对照）。
- 对照里 8.9 与 8.10 一起变强（+2.38 / −1.21），像一对“推 / 压”搭档；8.9 没了，8.10 的反作用也随之消失。
- **修正 13:20 的说法：** 400 步时 8.10 的 −0.16“被训练拉回”是暂时的，5000 步时回到 −0.04；没有“训练撤销自修复”。
- greater-than：5.9 是唯一被持续放大的头（+0.13 → +0.35），对照中不变。
- **对照性别（9.3 损伤）：** 原有的次级承担者 7.5（损伤前 0.84）、5.8 被放大，补齐了大部分功能。
- **暂定解释：** 能补回来的功能都有现成的部分承担者可放大（E96 的 3.4、E97 的 7.5、11.7、8.1）；IOI 的正向名字移动只集中在 8.9 一个头上，没有次级承担者，继续训练也没有从头招募新的头。这把 E96 / E97 / E98 统一成一个问题：**训练后期的修复只放大已有的东西，不从头建新的？** 下一步（E100）检验这是不是训练后期才有的限制。
