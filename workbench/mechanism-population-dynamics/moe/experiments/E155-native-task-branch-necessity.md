# E155：任务能力在条件专家与共享计算间的分担（2026-10-27）

- **状态：** DONE；9c8343b8冻结后全部12格完成，全部原始条件保留。
- **对应 / 类型：** C14/P32，能力层的依赖配置与训练阶段PILOT；零新训练。
- **问题：** 更好的子集部署背后，任务能力是否仍依赖条件专家，还是更多依赖始终激活计算；这种分担在公开成熟父状态到两个退火终点间怎样改变？

## 科学区分

E153已经确认同预算下B有实际任务正确率收益；E151显示B的语言预测对R零化较稳健、对S零化更敏感。仅这两项还不能判断任务正确率的依赖是否同样重组：语言分布损伤与正确选择之间并无等价关系。

因此直接在同一固定任务上比较完整模型、全R零化、全S零化，并纳入成熟父状态P。它区分R仍承担关键任务作用、共享路径保留较多能力、以及两类计算共同必需等解释。不会为了提高裁剪分数更换mask/预算/题目。该问题独立于E154的LM读数方向；不把数学低基线上的“不变”称为能力保留。

## 冻结资产与数据

- P/A/B为E154/E150已完整公开LFS核验的三个固定pins，同一作者声明谱系；非独立初始化或严格训练batch/optimizer链。
- E153同128题：生物/数学各64、原dev5示例、原RC cloze答案文本，最长475token。原data_plan/IDs/答案长度/题目顺序逐字节复用；无筛正确题、无新cal选择、无新训练。

- 原生参数统一FP32加载→GPU→全模型BF16，包括非persistent buffers。所有参数与buffer只读。P允许在E154 GPU0运行时另卡读取同一公开权重，但先完成其原生cal proof；避免并发大文件冷加载。

3. 另报每模型的R×S全因子交互(native−Rzero−Szero+bothzero)，区分条件路径、共享路径和D-only背景；作为非线性干预对比解释。
4. 两固定subject内question-paired bootstrap1000次，seed155001，macro等权；单科与全部条件均保留。题目CI不当模型seed或subject总体。

身份/native重放地板0；实际BF16程序，沿旧precision校准单列。数学raw native约20–23%，地板会限制其零化解释，故分科与per-char同时报告；生物基线约58–59%。不换题追阳性。输入为已有固定任务、预训练污染未知，原生分支零化也可能造成大OOD偏移；主张是实测依赖配置及能力保持，不能据此断言唯一语义单位或形成必要条件。
