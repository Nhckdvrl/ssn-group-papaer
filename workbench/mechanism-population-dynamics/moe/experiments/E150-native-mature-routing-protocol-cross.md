# E150：成熟原生路由协议分叉中的配套边界（2026-10-27）

- **状态：** 资产/接口可行性阶段；新模型推理尚未运行。流程生成器登记后按主题移动；以下在新模型读数之前固定。
- **类型 / 对应：** 驻留可行性 + 因果拼装PILOT；C11/C12/C13、P32。没有新训练，不将公开模型当独立初始化seed。
- **问题：** 从成熟原生模型继续训练、路由组织约束不同之后，哪些计算部分需要保持共同来源？这类配套边界是否只在路由专家内部，还是跨越共享专家和dense骨干？

## 为什么现在做这个窗口

E148的有限次序处理留有预测差异，但小于末期自身漂移；L9互换未检出NLL损伤。E149全网络8格也已完整读取，原始NLL范围2.951985–2.952440，配对损失交互尚未检出。它们不能识别“短程扰动太小”与“充分学习后仍保持祖先接口”的区别。直接追加自行训练剂量成本高，且并不保证形成可研究的组织。

新核实的EMO公开资产允许改问更重要的问题：**在真实成熟预训练和50B token协议分叉之后，组织约束留下的计算差异能否跨部件转移？** 它不是本地扰动扫描或寻找显著损伤；全部条件固定保留。EMO已拥有文档路由促进域级选择/组形成的贡献，本卡不重复认领。其“组合”主要指同一模型内的专家子集并用；我们检验跨公开训练历史的参数来源兼容性，不将不同定义的失败当对原论文的反驳。[论文](https://allenai.org/papers/emo)、[代码与谱系](https://github.com/allenai/EMO)。

## 冻结的16格干预

四组覆盖全部参数且不重叠：D=dense backbone、embedding/head、全部norm及非MoE参数/registered buffers；G=所有router；R=全部路由专家；S=所有始终激活的shared expert。**共享专家必须单独成组**，避免把其作用错误归给路由专家或dense骨干。

全部(D,G,R,S)∈{A,B}⁴共16格；AAAA/BBBB native角，其余14格均保留。物理槽位沿公开共同祖先，不拟合专家匹配/温度/增益。直接复用原生block的forward，更换参数所属模块，不改变topk、求和顺序或共享专家调用。配置/代码的前向超参数须相同；若不相同，先登记统一算子修订，不静默转成同构网络。

## 数据与读数

- 沿E148已固定64 held语言窗口和16 training-cal窗口，使用原OLMoE tokenizer精确decode，原EOS转双换行，其他规则随数据manifest锁定，再以两EMO共同tokenizer重编码。最多513输入token，短序列右padding并用实际target mask；保存文本/IDs/源窗口/长度SHA。它们是已参与探索的语言窗口，不宣称单一完整文档或新确认集；推理不启用训练时文档pool。
- **主读数：** 16格每序列真实标签NLL、两个native共同参考的双向全词表KL；均只在真实target位置平均。输入CI按原20个(source,file)簇成对bootstrap1000次，seed150001；不把输入CI当训练总体。
- **主对比：** G×R损失四格交互在固定D/S时全部报告，并预定对4个背景等权平均；R×S亦同；D×完整MoE(G/R/S共源)四角交互。配对代价=交叉来源两格均值−共源两格均值，等于对应有限差分的−1/2，只是同一读数的代数改写。全四因素的其它交互完整附表，不挑最大项，不能当机制责任百分比。
- native NLL差、native A↔B预测KL和各hybrid相对**两个**native的差全部并列；某hybrid只比其中一个native差，不能自动称配套断裂。

## 阳性对照

1. tiny原生EMO结构逐个检查16格全部参数来源、四组完整覆盖/不交叠、两native角输出逐位一致，16格之后两源参数/buffer不变；二阶/四阶差分使用已知多项式答案。
2. CPU检查数据target mask和变长序列统计的已知答案；held与cal来源列表/bytes锁定。
3. 单卡cal预检：原生BF16两次前向、同源重装逐位一致，单模型FP32与BF16预测差单列为精度尺度；actual CUDA UUID、显存/耗时、全部module被正确调用。
4. 真模型16格的AAAA/BBBB在全部held位置逐位匹配原生参考；实际源参数/buffer完整只读hash前后相同。L9 zero在cal上作为读出阳性，不用其大小筛层或输入。

## 噪声地板 + MIE / 混杂审计

精确自装配/重复地板与cal FP32/BF16尺度分开。所有科学读数按实际BF16程序报告；若效应很小，不将非零KL称模块机制或用精度差简单相减。无任意通过阈值或显著性后扩大剂量。公开谱系只是作者声明+我们核查源文件/代码；同架构、同mix不等于独立seed总体或唯一路由因素。shared expert单列；off-support调用、表示/下游漂移属于合法兼容性的路径，不能由此断言纯语义职责。

## 决策表（跑之前写）

| 观察 | 更新认识 / 动作 |
|---|---|
| G/R共源明显降低配对代价，D/S来源影响相对小 | 该成熟协议差异的相容边界较集中在路由MoE，进一步由已有任务读数判断含义；不宣称天然最小联盟 |
| 共享专家或dense骨干与路由专家的来源交互更大 | 单称“路由专家组”为完整工作单位不足；存在跨始终激活计算的接口约束，不证明其是分工产生的必要条件 |
| 16格均处在native差异尺度、配对交互弱 | 在充分学习协议分叉下仍有相当重用范围；保留结果，不继续扩大差异直到损伤 |
| 两方向损失互抵/某些hybrid更好 | 全报方向和双native参考；区分质量主效应与配套交互，不筛坏组合 |
| 资产或接口不足、native不能复现 | 如实记录可行性结果，修明确错误；不算科学阴性，不自动自训替代 |
