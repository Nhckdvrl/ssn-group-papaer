## 0. 这一轮讨论后的整体判断
1. **方向本身（导师说的“分工能否跨训练自发重现”）依然值得做，但原文档的论证有三处硬伤，两份反馈都独立指出了，必须改：**
   1. **原 Q1 第 3 步“几何预测”定义错了。** 它比较的是 A 的路由器对 A 的表示与对“对齐后的 B 的表示”的输出，测的只是表示对齐的上限，没有用到 B 的路由器。
      - 反例：两个模型表示完全相同、但路由器沿不同方向切分时，这一步仍得满分。
   2. **缺“随机几何路由器”基线。**
      - 在同一组表示上随机画负载均衡的线性切分，本来就会把相近的向量分到一起：随机超平面把两个向量分到同侧的概率是 1 − arccos(cos)/π。
      - 所以两个模型的共路由结构即使高度相似，也可能只是“共享几何 + 任何线性切分”的结果，与学习无关。
   3. **原 Q3“印刻”会把锁定编号误当成改变结构。** 把一个本来就会聚在一起的类别（如数字）强制送进 0 号专家，最后它留在 0 号专家，只说明锁住了编号——这正是头线 v0 的老问题。要干预的是输入之间的组织关系（谁和谁一起处理），而不是某类输入和某个编号的对应。
2. **“几何决定 vs 历史决定”不是对立的两个假说。** 表示、路由器、专家在训练中共同演化，早期历史本身就会改变后来的几何。可检验的问题应改写为：**控制住表示之后，不同训练历史是否仍能产生不同的组织；如果能，这种差异是否持续到专家承担的计算上。**
3. **“哈希 / 随机路由几乎一样好”只能当动机，不能当论证：**
   - Equifinality 的哈希和固定随机路由各只有一个种子，差距 1.1–2.1 PPL，大于种子噪声；
   - 而且它不看隐状态，与线性路由器不可比。
   - 它最多说明“损失对路由拓扑不太敏感”，不能证明存在多种功能等价的分工。
4. **“分工”至少要分四层：** 输入分配 → 输入组织（谁和谁一起处理）→ 计算职责（干预后哪些预测受影响）→ 机制。原文档实际只测了前两层，却用“分工”一词，有重演头线“推断桥”问题的风险。
5. **不押注。** 第一阶段应选择无论结果如何都能增进理解的观察（§5），先弄清楚“学到的路由组织比被动几何多出多少”，再决定是否训练多种子模型。

## 3. 对问题理解的加深：几组必须分开的概念
1. **“分工”的四层（采纳 GPT 的分层，加上头线教训）：**
   - 输入分配：哪些 token 去哪些专家，依赖编号；
   - 输入组织：哪些上下文被一起处理，不依赖编号（共路由矩阵）；
   - 计算职责：对专家组做等计算量的替换 / 干预后，哪类预测受影响；
   - 机制：专家与注意力等组件如何共同实现一项语言计算。
   - 导师说的「役割分担」至少在第三层。第一、二层是必要的入口，但单独不构成导师要的结论。
2. **三种“一致”：**
   - 同一 run 内的稳定（已有：OLMoE 路由饱和、Router Ossification）；
   - 同父分叉后的承诺（路径依赖，未知）；
   - 独立训练之间的重现（未知）。
   - 三者不能互相替代。
3. **两种“一致的来源”必须先扣掉：**
   - token 身份（导师说的“自然一致”）；
   - 被动几何（同一组表示上随便切都会有的一致）。
   - 扣掉之后剩下的部分，才是“学习选择了特定的组织”。
4. **编号锁定 vs 结构改变：** 任何干预都要带一个“只交换编号”的假干预作对照。
5. **几何与历史是同一个共演化过程的两个时间尺度。** 研究可以问“早期路由经历是否因果地改变最终组织”，不必把几何排除在因果链外。

## 4. 研究空间：候选的具体问题（不押注，各自标出无论结果如何能学到什么）
| 候选 | 问题 | 无论结果如何能学到什么 | 已知 / 近邻 | 最便宜的第一步 | 停止条件 |
|---|---|---|---|---|---|
| **C1 学到的组织比被动几何多出多少** | 在同一模型的真实隐状态上，学到的路由器产生的共路由结构，与负载、k 都匹配的随机线性路由器 / k-means 相比，多出多少？按层、按 token 类型、按上下文类型分解 | 多出很多 → 学习确实选择了特定组织，跨训练比较才有对象；几乎没有 → “专家分工”主要是几何的被动读出，跨训练一致是平凡的。两种都直接决定后面值不值得做 | Myth 2026 只给了上界关系；没人用随机几何路由器作零假设 | **只做推理**：OLMoE 或其他公开 MoE，取一批语料的隐状态，比较学到的路由器与随机路由器的共路由矩阵 | 学到的 ≈ 随机几何 → 跨训练一致性不作主问题 |
| **C2 上下文切换的跨训练一致** | 同一 token 在不同词性 / 词义 / 领域的上下文中，路由会切换；独立训练的模型是否在同样的上下文边界上切换？ | 一致 → 超越“词知识”的上下文分工重现（导师最可能认可的形式）；不一致 → 上下文分工是训练特有的；只在某些语言层次一致 → 回答“在什么条件下一致” | 单模型内的语义路由已知（EMNLP 2025、Myth 2026） | 先在公开 MoE 上测每层的上下文切换率，判断小模型需要多大规模才会出现切换（标定） | 自训小模型没有上下文切换 → 不在小模型上做 |
| **C3 路由一致 vs 职责一致** | 输入组织相似的专家组，干预后对同类预测的影响是否也相似？ | 一致 → 路由组织可以当作职责的代理；不一致 → “路由相同不代表职责相同”，对 MoE 解释研究有直接警示 | Expert Strikes Back（单模型内功能标签）；Misrouted | 单模型内先验证功能读数的信度（拆半、重复） | 单模型内信度不足 → 不做跨训练比较 |
| **C4 早期路由历史对最终组织的因果作用** | 从同一父模型分叉，早期短暂地促进两组输入“共处理”或“分开处理”（负载、计算量、剩余训练长度都匹配，含只换编号的假干预），撤掉后训练到底，组织与职责是否不同？ | 差异持续且性能相近 → 历史依赖 + 多种可行分工都有因果证据；差异消失 → 训练有收敛偏好，需要解释为什么偏好这一种 | Router Ossification（同一 run 内固化）；Routers Learn Geometry（耦合机制）；头线 E46 / E66 的分叉与扰动方法 | 需要训练；在 C1 / C2 给出“学到的组织确实超过被动几何”之后再做 | C1 显示学到 ≈ 随机几何 → 不做 |

| **C6 什么锚定一个模块的角色** | 头线发现：只重置读取参数角色会回来，旋转输出方向则不回来。MoE 里，专家的角色由路由器的选择锚定，还是由下游对专家输出方向的读取锚定？（分别重置路由器行、旋转专家输出、重置专家输入） | 与头线一致 → “下游耦合锚定角色”跨两类模块成立；不一致 → 专家（有显式选择器）与头的锚定方式不同，本身是一个对比结论 | Routers Learn Geometry（路由—专家耦合）；我们的 E96–E119 | 需要训练过的 MoE（可用 C5 的模型），成本低 | — |

| **C8 回到头（导师的第二步）** | 用与 MoE 相同的尺子（输入组织、上下文切换、随机几何基线）看头 | 视 MoE 结果而定 | Bali 2026、E89 | 等 MoE 第一阶段有结论后再设计；不复用 E89 的合成任务 | 构念不可比 → 不做 |

**观察：** C1 是其余候选的前提，几乎零成本，而且无论结果如何都有用——它决定“跨训练分工一致”到底是不是一个非平凡的对象。C2 是最贴近导师 NLP 期待的形式。C4、C5、C6 是机制层面的问题，C6 还能接上我们头线里最可靠的发现。
