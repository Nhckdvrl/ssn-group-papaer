# 全项目复盘：从“初始化与头”到 MoE（2026-09-30 – 10-31）

> 作者：Claude（应用户 10-31 要求）。依据：仓库全部入口文档、CLAIMS/PAIN_LOG、logs、导师 10-22 会议录原文、英文论文稿，以及本次检索的近邻论文（大多只读了摘要，标“摘要级”）。这是研究判断，不改变任何登记状态（R2）。

## 0. 结论先说

1. **当前 MoE 论文没有回答导师的问题，并且又掉进了旧的坑，只是换了新形式。** 导师问的是：*分别训练的模型，没人规定专家/头该做什么，它们会不会自发分出同样的工作？* 当前论文问的是：*EMO 公开 checkpoint 里，把一整套路由专家（16 层全部）移植到父模型后，低预算 NLL 会不会变好、共享专家是不是变得更重要？* 这两个问题之间没有“独立训练”，也没有“单个专家的角色”。
2. **按导师自己说的标准，当前几条主结论大多会得到「そうだよね」。** EMO 训练就是要让专家子集能单独用，模型因此更依赖始终激活的共享专家，这几乎是这种训练方式的直接后果；移植过来的部件离开原来的上下文就要付代价，也是 co-adaptation / model stitching 文献早就知道的事。效应主要是受限条件下的 NLL 差，正确率没有可分辨的差别（E164：+1.14pp，CI [−2.27, 4.55]）；OLMoE 的受限条件本身只有 22% 正确率，低于四选一的随机水平 25%。
3. **导师的原问题并不是做不了。** 卡住它的是两个决定，不是客观条件：①为了避免从头训练，先做了“冻结 dense 骨干、只插一层 MoE”的受控平台，结果这个平台里的专家几乎可以互换（E134），根本没有分工可比；②10-27 起定下“成熟 checkpoint 优先、不新训多 seed”，而公开 MoE 里没有多 seed 套件，于是问题只能跟着手头能测的东西走。按 `RESOURCES.md`，我们的资源（十几张 A100、8 张 RTX PRO 6000、16 张 H20、互联差）**最适合的恰恰就是多 seed 的独立单卡小模型训练**。
4. **领域里这个问题仍然空着，而且正在变得重要**（§6）：MoE 的专家正被当作可解释单元（*The Expert Strikes Back*, 2026），又有人说专家分工只是隐状态几何的反映（*Myth of Expert Specialization*, 2026），头跨 seed 稳定性已有人做（Bali et al. 2026），但**语言 MoE 的专家分工跨独立训练是否重现**，检索没有找到直接研究。
5. **建议：** 冻结当前 MoE 论文（存档、保留工具，不投稿），回到导师的原问题，用自己训练的多 seed 小型 MoE 正面回答，并用事先定义的“自然一致”基线解决导师 10-16 写下的“一致到什么程度才有意义”这个难点（§7）。

## 2. 导师眼里什么叫“有意义、有意思”

从 10-22 会议录原文提炼（括号里是时间戳）：

1. **结果不能是“自然的”**：能事先预料到的一致，得到的只是「そうだよね」（00:58–03:43、10:27–11:06）。
2. **知识一致是自然的，角色分工一致不是**：「単語の意味…似たものが出てくるのは自然」；「ヘッドごとに担当している役割が異なり、学習をやり直しても、その役割が同じように分かれるのであれば面白い」（04:01–04:44）。
3. **MoE 的价值在于分工没人规定**：「別々に学習したモデルでも同じようなエキスパートが対応しているのであれば…本来は一致するとは限らないものが強く一致している」（05:11–06:39）。
4. **数字要有意义**：「どの程度一致するかは…与え方によって変わります。その数値にどのような意味があるのか」（03:13–03:43）；10-16 书面意见：“一致到什么程度才有意义，可能很难主张”。
5. **“在这个条件下不一致”也可以更有意思**（07:23–08:04，原话针对回答相似性，但逻辑通用）。
6. **留在语言研究里，先查已有工作；题目在讨论中逐渐固定，不要每次换全新的题**（06:40–07:10、08:08–09:14）。

把它变成可检查的标准：**(a) 对象是跨独立训练的分工；(b) 有一个“本来不一定一致”的先验，且扣掉了自然一致；(c) 数字有参照（地板与天花板）；(d) 和语言有关；(e) 一句话讲给导师听，他不会说「そうだよね」。**

## 3. 当前 MoE 到底证明了什么（白话版）

在 Ai2 发布的 EMO 系列（同一架构；P=标准预训练父模型，A=标准退火，B=EMO 退火，F=全程 EMO）和 OLMoE 的两个端点上：

1. **同样的整体质量，背后的依赖不同**：B 和 F 文本 NLL 几乎相同（2.6218/2.6212），F 更耐专家子集化，但去掉共享专家的损伤多 1.85 nats。
2. **“带来好处的部件”和“必须保留的伙伴”不是同一个**：把 B 的整套路由专家搬进 P，低预算 NLL 变好、完整 NLL 变差；没动过的共享专家反而变得更重要。固定实际路由后依然如此。
3. **部件的输出离开原来的接收上下文会贬值**，而简单的范数/投影校正只能补回一小部分。
4. **OLMoE 上，整机曲线和部件性质方向相反**；**逐层一个增益系数**就能在 OLMoE 上复制低预算收益，在 EMO 上却不行。

按 §2 的标准打分：

| 标准 | 当前 MoE | 说明 |
|---|---|---|
| (a) 跨独立训练的分工 | ✗ | A/B 来自同一个父模型；F 与标准线的公开脚本用同一默认 init_seed（E162 卡），不能当独立初始化；干预单位是“16 层全部路由专家”一整块，没有单个专家的角色 |
| (b) 扣掉自然一致 / 非平凡先验 | ✗ | 结论 1 是 EMO 训练目标的直接后果（专家池按文档受限，通用计算自然移到共享专家）；结论 2、3 是 co-adaptation 的已知现象（Yosinski 2014 的“脆弱协同适应”、model stitching 系列） |
| (c) 数字有意义 | 弱 | 主要读数是受限条件下的 NLL；正确率差别不可分辨；OLMoE 受限条件正确率 22%，低于随机 |
| (d) 语言 | 弱 | 只有 MMLU 答案 NLL 和语言建模 NLL，没有任何语言学内容 |
| (e) 一句话 | ✗ | “学习历史组织着可选择的函数、响应接口和协作使用关系”这句话无法证伪，导师也听不出新知道了什么 |

**可以抢救的东西不多**：E162 的“同样表现、不同分工”最接近导师的问题，但它是由不同训练目标造成的，不是 seed，也是可以预料的。整体上**不建议投稿，也不建议在它上面继续加实验**。

## 4. 是不是又掉进了老坑

`heads/HISTORY.md` §7 总结了头线失败的根因。逐条对照当前 MoE：

| 头线的坑 | MoE 里是否重现 | 证据 |
|---|---|---|
| 对象选错了，而且一直没换（研究编号这种坐标，而不是分工） | **重现，形式变了**：对象从“专家分工”漂成了“EMO 端点的部署性质” | RESEARCH_DIRECTION 的“母问题”被改写为“哪些关系由任务约束…怎样影响组件重用” |
| 叙事先行 | **重现** | 提交信息 “Center MoE story on computational organization”；论文标题与摘要是抽象的组织叙事 |
| 追残差，越做越窄 | **重现，速度更快** | E144→E166 四天 23 个实验，每个实验都在补上一个结果的漏洞（固定路由 → 消息几何 → 增益匹配 → 共享置零） |
| 每次修补都加一个条件（止损规则） | **触发了，但没有执行** | C14 的“已知威胁”一栏比主张本身还长：仅 EMO、仅概率质量、准确率未区分、受限条件严重受损、两谱系机制不同…… |
| 近邻压缩 | 有 | EMO 本身、stitching、HOPE/CD-MoE 已经覆盖大部分直觉 |

还有两个新问题：
- **把精力花在了验证基础设施上，而不是选问题**：SHA 封存、上万项独立复算、逐文件 manifest，都很严谨，但严谨地回答一个不重要的问题，依然不重要。
- **文档越来越难读**：大量自造术语（性质载体、响应接口、协作使用）加上层层限定。这和用户记忆里“不要防御性措辞，要一个清楚的问题”的要求相反。

**根本原因只有一个：当“直接回答导师问题需要多次独立训练”这个约束出现时，我们选择换问题来适应工具，而不是去满足这个约束。** 用户记忆里 “Significance first：按领域影响选问题，而不是按手头工具能测什么选” 正好是这条。

## 5. 导师的原问题真的无法研究吗

| 当时的理由 | 核实 |
|---|---|
| 没有开源的多 seed MoE 套件 | **属实。** 检索没有找到；OLMoE 只有单 run 的中间 checkpoint（每 5000 步）；OLMoE-0125 是 0924 的继续退火（E143 卡已核实）；EMO 各端点共用父模型或默认 seed |
| 从头训多 seed MoE 太贵 | **不属实（量级估计，未实测）。** 约 1.6 亿激活参数 / 约 8 亿总参数的细粒度 MoE（64 专家、top-8，OLMoE 结构缩小版），按约 10 万 token/s/卡的保守估计，10B token 约 1 天/seed/卡。8–16 个 seed 用现有卡 1–2 天能完成。这类规模的多次训练在 MoE 消融论文里很常见 |
| 小模型里可能没有真分工 | **风险真实，但可以先测。** E130 失败是因为“冻结骨干只插一层”，不是因为规模小。全层从头训练的 MoE 普遍有 token/句法层面的专家化（ST-MoE、OLMoE 的分析），但小规模下是否足够强需要先测。用 E134 的“换成专家平均的损伤”作前置检查：达不到原生 OLMoE 的量级就先不比较 |
| “一致到什么程度才有意义”没有基线 | **这正是要贡献的东西**，而且 MoE 比头更好做：路由是离散的，几何零假设（E120 已验证的 N1）现成 |

结论：原问题之所以显得“无法研究”，是因为同时坚持了“只用公开成熟 checkpoint”。放开这一条，原问题就是一个资源匹配、设计清楚的实验。

## 6. 领域现状（与本题直接相关）

| 工作 | 说了什么 | 和本题的关系 |
|---|---|---|
| Bali et al. 2026, *Quantifying LLM Attention-Head Stability*（arXiv 2602.16740，摘要级） | 26 种架构多 seed：中层头最不稳定；越不稳定的深层头越重要；weight decay 提高稳定性；残差流相对稳定 | **头**的跨 seed 稳定性已有人做（表示相似度层面）；我们的 E89 是任务因果分工层面，不同 |
| Wang, Hayou, Nalisnick 2026, *The Myth of Expert Specialization in MoEs*（2604.09780，摘要级） | 路由器是线性的，所以专家使用的相似完全由隐状态相似决定；不同模型回答同一问题的专家重叠约 60%，和不同问题差不多 | 给出“自然一致”的主要竞争解释：**分工 = 几何**。我们必须扣掉它，或者正面检验它 |
| *The Expert Strikes Back*（2604.02178，摘要级） | OLMoE 等模型的专家比 dense 神经元更单义，是细粒度的语言操作/语义任务专家，可以在专家层面解释 | 如果专家是可解释单元，**这些解释能不能跨训练迁移**就直接决定专家级可解释性的价值 → 这就是“谁依赖这个结果” |
| PRISM 2026（2606.03444，视觉，摘要级） | Hungarian 对齐后，专家与 teacher 的亲和结构跨 seed 重现，早中层更清晰 | 视觉里有正面证据；语言 MoE 没有 |
| Tran et al., *On Linear Mode Connectivity of MoE*（NeurIPS 2025 oral） | 对齐专家置换后，独立训练的 MoE 之间存在低损失连接 | 权重层面的对应已有人做；“专家做的语言工作是否相同”没有 |
| Zhang et al. 2023, *Emergent Modularity in Pre-trained Transformers*（Findings ACL） | dense 神经元自发聚成功能专家，且早期就稳定 | dense 的隐式模块化；可作为“显式 vs 隐式模块”的对照 |
| OLMoE（ICLR 2025） | 路由在训练早期饱和；专家有领域和词汇偏好 | 单 run 内的形成过程；我们 E121 也见到深层在 0.4% 训练时与终点相关 0.5–0.6 |
| Geometric Asymmetry in MoE Specialization（2605.16349，摘要级） | 专家在函数上去相关，在表示上重叠 | 说明“路由一致”与“功能一致”要分开测 |

**缺口**：没有找到在语言 MoE 上、用多个独立 seed、扣掉 token 身份和隐状态几何之后，测专家分工（路由划分 + 功能）是否重现的工作。检索有限，正式立题前还要按 R6 做一次 venue corpus + 最新 arXiv 的定位表。

## 7. 建议的题目（回到原问题并升华）

### 7.1 一句话问题
> **分别训练的 MoE 语言模型，会不会自发分出同一套专家分工？分工里哪些是语言本身决定的、哪些是偶然的——用同样的尺子去量 attention head，答案是否一样？**

### 7.2 为什么导师会觉得有意思（对照 §2）
- (a) 对象就是导师说的：跨独立训练的分工，先专家后头。
- (b) 先验真正不确定，三种预测互相冲突：
  - **几何观**（Myth）：分工完全由隐状态几何决定 → 扣掉几何后的一致 ≈ 0；
  - **随机对称破缺观**（我们头线的经验：编号由初始化决定）→ 扣掉 token 身份后几乎不一致；
  - **规范分工观**（PRISM、Expert Strikes Back）→ 语言操作型专家跨 seed 强烈重现。
  哪个成立都不是「そうだよね」。
- (c) 数字有参照：地板（打乱、几何零假设路由器）和天花板（同 seed 换数据顺序、同 run 的相邻 checkpoint）。数字的意义是“落在地板和天花板之间的位置”，回答了导师 10-16 的书面质疑。
- (d) 语言：用词性、句法角色、语言操作（复制、数字、标点、格式、事实召回等）描述专家做什么。
- (e) 一句话能讲：“重新训练一遍，专家会不会还这样分工？”

### 7.3 怎么扣掉“自然的一致”（核心方法贡献）
1. **token 身份**：同一个词总去同一个专家，等于“词知识一致”。只比较**同一词形在不同上下文里怎样被分开**（E143 已设计的 T_ctx）。
2. **隐状态几何**：如果两个模型的隐状态本来就相似，任何线性路由器都会给出相似划分。用 E120 已验证的 N1 零假设（保留路由器读出子空间、随机旋转后重拟合负载）得到“同一几何下随便切能有多一致”，再看真实路由器超出多少；另外报告同一组隐状态上 k-means 换初始化的可重复性。
3. **功能而不只是路由**：每个专家的功能指纹 = 用候补顶替（不是均值钳制，E120 证实均值钳制有假阳性）对一组语言类别/任务的损伤剖面；在校准集上 Hungarian 对齐，在留出集上验证。
4. **后果**：把 seed B 中对齐好的专家移植进 seed A，对比随机专家；以及把专家级的自动解释（Expert Strikes Back 那种标签）从 A 迁移到 B，看准确率。分工重现与否，最终落在“解释能不能跨训练复用”上。

### 7.4 “在什么条件下不一致”
只选 1–2 个最可能改变答案的因素，不铺网格：
- **层深**：OLMoE 深层早饱和，Bali 发现头在中层最不稳定 → 专家是否也有“中层不稳定”？
- **共享专家有无** 或 **专家粒度**（8 个大专家 vs 64 个细粒度）。

### 7.5 第二步：头（导师原话“まずエキスパートで、その後ヘッドでも”）
同一批自训 MoE 本身就有 attention head；再加上 PolyPythias 的 10 个 seed 和已有的 E89 图谱。用**同一把尺子**比较：*显式模块（专家）比隐式模块（头）更可重现吗？* 这是一个干净的对比问题，也把头线最有用的结果（E89）重新放回有基线的框架里。

### 7.6 事先写好的结果分叉与止损
| 结果 | 解读 |
|---|---|
| 扣掉几何后仍强烈一致 | 存在规范的语言分工；专家级解释可跨训练复用 |
| 一致全部由几何解释 | 定量证明“分工 = 共享表示的切分”，并说明解释只能经由表示迁移 |
| 部分层/部分专家类型一致 | “哪些分工是普遍的”地图——最可能、也最有信息量 |
| 前置检查失败（小模型无分工） | 放大规模一次；仍失败就停，不换替代平台 |

止损：任何一次修补需要额外加条件才能保住结论，就停（memory: stop-loss-rule）。不再用“换平台”来回避约束。
