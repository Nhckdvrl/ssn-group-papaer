# E227：注意力模型与循环模型取回绑定实体时，用的是不是同一套算法（位置 / 词汇 / 反射）（2026-11-25）

- **状态：** DONE（11-25 写定于任何 E227 运行之前；08:30 跑完，结果见文末）
- **类型：** PILOT（题目 T1 的决定性试测；不推进主张；锁题由人决定，R2）
- **对应：** [TOPIC_SEARCH.md](../TOPIC_SEARCH.md) 的 T1。方法来自 Gur-Arieh, Geva, Geiger（ICLR 2026，arXiv 2510.06182，[卡](../../../library/themes/interpretability-representation/papers/2510.06182_gur-arieh-mixing-mechanisms.md)；全文 §3.1–3.3 已读）。前置：[E224](E224-binding-overwrite-competence-gate.md)（Falcon-Mamba-7B 与 RWKV-7 2.9B 叙述格式静态绑定 S4 ≥ 0.99）。

## 为什么做（给外人看的版本）

导师的问题是：独立训练的模型会不会形成同样的机制。我们的三层框架说，部件身份不会相同，表征几何的相同可以猜到，真正值得问的是**算法**。“记住谁拿了什么，再按问题取出来”有一套在 Transformer 上已经拆清楚的算法：Gur-Arieh 等人发现模型混用三种机制——按位置（第几组）、按词汇（用被问的人去找他那组）、按反射（直接指回答案那个词）——并设计了让三种机制各自指向不同答案的反事实输入，所以每次干预的结果都能直接归类，不需要我们定义或定阈值。

循环模型（Mamba、RWKV-7）没有可以回看的注意力，必须在被提问之前把一切写进固定大小的状态。它们取回绑定实体时，是走到同一套算法，还是换了一套？论文自己把反射机制解释为“注意力只能往左看”：问“谁爱 tea”时答案在提问对象前面，Transformer 用不了词汇机制。这一点在循环模型里正好可以检验。

两种结果都有信息量：相同 → 绑定检索的算法由任务决定，不由记忆机制决定；不同 → 记忆机制决定算法，并且能指出差在哪种机制。

## 设置

- **模型（3 个，本地已有）：** `Qwen/Qwen3-8B-Base`（注意力；Gur-Arieh 测过 Qwen2.5 系列，作阳性对照）、`tiiuae/falcon-mamba-7b`（加法规则循环）、`RWKV/RWKV7-Goose-World3-2.9B-HF`（delta 规则循环）。
- **任务：** 叙述式“谁爱什么”，n = 6 组，例如 `Ann loves ale, Joe loves jam, ... and Tim loves tea.`。人名与物品各取自两个词表，只保留在三个模型的分词器里加前导空格后都是**单个 token** 的词（运行前离线筛选）。前面放 1 个完整示例固定答题格式（用另外的人名和物品）。
- **两个方向（各 120 对）：**
  - A 问物：`What does Tim love? Answer:` → 答案是物品（答案在提问对象后面）。
  - B 问人：`Who loves tea? Answer:` → 答案是人名（答案在提问对象前面；Transformer 在这个方向用不了词汇机制）。
- **反事实对（按论文 §3.2 构造）：** 原始绑定矩阵 G 与反事实矩阵 G′，使干预后：
  - 位置机制预测原始输入里第 i_P 组的答案（i_P = 反事实问题所在的组号）；
  - 词汇机制预测原始输入里与反事实提问对象绑定的答案；
  - 反射机制预测反事实的答案词本身（它在原始输入里也出现，位于另一组）；
  - 三者两两不同，也都不同于原始答案。i_P、i_L、i_R 在 1…n 中随机（不重合），种子 227。
- **干预：** 先跑反事实输入，记下每一层输出在最后一个 token 上的残差流向量；再跑原始输入，在第 ℓ 层把最后一个 token 的残差流换成反事实的向量，读最后位置的输出。对每一层 ℓ 都做一次（层扫描，即论文 Figure 2 的做法）。
- **读数：** 在原始输入出现过的候选里（方向 A 为 6 个物品，B 为 6 个人名），取首 token logit 最大者，归类为：位置 / 词汇 / 反射 / 原答案 / 其它。每层报告五类的比例。
- **命令：** `scripts/e227_mixing_mechs.py`。

## 判定（跑之前写）

- **行为前提：** 不干预时的准确率，A、B 两个方向都 ≥ 0.9；否则该模型该方向排除。
- **干预起效层：** 原答案比例最低的那一层（并列取较浅的层）；在这一层读五类比例。
- **某机制“存在”：** 在起效层，其预测实体的比例的 bootstrap 95% 区间下界 > “其它”类按实体平均的比例（即 其它 / 其它实体数），且点估计 ≥ 0.10。
- **阳性对照：** Qwen3-8B 应复现论文的定性结论——方向 A 位置机制存在（n=6 时可能兼有词汇 / 反射），方向 B 词汇机制不存在或很弱、反射机制存在。达不到则先查脚本，不解读循环模型。
- **干预无效：** 某模型在所有层原答案比例都 ≥ 0.9（换掉最后 token 的残差流不改变答案）→ 该模型的检索不经过最后 token 的残差流，签名读不出；如实报告，不在本卡内改用别的干预。

## 混杂审计（只列相关项）

- 每类只有一个模型，规模、数据都不同：本卡只看定性机制集合，不比幅度；类别结论留给之后的重复。
- 分词：只用三个分词器都是单 token 的词，首 token logit 即完整打分。
- 层数不同：每个模型在自己的起效层读数，不跨模型对齐层号。
- 反射机制与“反事实答案本身”在本设计里不可区分（论文 §3.2 末尾承认，§3.4 另行验证）；本卡把这一类记为“反射 / 反事实答案”，不单独主张反射指针存在。

## 结果（跑完后填写；不改上面的内容，修改需注明日期）

**DONE（11-25 08:30）。** 实际约 0.1 GPU·时（三张 A100 并行，1–3 分钟）。结果 `results/e227/{qwen,falcon_mamba,rwkv7}.json`（逐层五类比例），共用词表 `results/e227/vocab.json`。

**行为前提（不干预时 6 组绑定的准确率，门槛 0.9）：**

| 模型 | A 问物 | B 问人 |
|---|---|---|
| Qwen3-8B（注意力） | 1.00 | 1.00 |
| Falcon-Mamba-7B（加法循环） | 0.85 | 0.66 |
| RWKV-7 2.9B（delta 循环） | 0.88 | 0.35 |

**按决策表执行：** 两个循环模型四格全部没过行为前提 → “循环模型前提不过：T1 的这一读数在循环模型上不可用，回到工作页重新评估，不在本系列内追加修补”。Qwen3-8B 方向 B 的词汇机制几乎为零（起效层附近 ≤ 0.03），与论文“答案在提问对象前面时用不了词汇机制”一致。

**卡片设计错误（如实记）：** 卡上规定在“原答案比例最低的层”读数。这一层落在答案已经形成之后（Qwen 第 24 层起反事实答案占 0.78–1.00），读到的“反射”其实就是把反事实的答案原样带过来——正是卡上混杂审计里写的“反射与反事实答案不可区分”。论文的读数层是“检索开始前的最后一层”。按 R5 不改读数，所以按卡规则得到的“起效层五类比例”（三模型都以“反射”为主）不作解读；逐层数据完整保留。

**POST-HOC（事后看逐层数据，单独标注，不作结论）：** 在“原答案比例第一次降到 0.5 以下”的过渡层，三种架构在方向 A 都先出现位置机制：Qwen 第 22 层（位置 0.60，词汇 0.08，反射 0.07）、Falcon-Mamba 第 36–38 层（位置 0.29–0.32）、RWKV-7 第 20 层（位置 0.33，反射 0.30）。没有位置编码的 Mamba 也带有“第几组”的信号，这一点若在前提过关的条件下成立，会是收敛的证据；但本卡不能下这个结论。

- 主张变化：无。

**11-25 09:40 更正（脚本 bug，事后发现）：** E224–E227 的脚本无条件在输入开头加分词器的 BOS token。对默认**不加** BOS 的分词器，这会改变输入。逐模型影响：
- Qwen 系列没有 BOS，Falcon-Mamba 的 BOS 为空：不受影响，数字不变。
- fla-hub 1.3B 的分词器默认本来就加 BOS：不受影响。
- RWKV-7 的 BOS 是文本结束符，默认不加：**受影响**。在 E226 / E227 的同一批题上按分词器默认处理重测：
  - E226 无变化时问“一开始”（W1 / W4）：0.83 / 0.88 → 0.82 / 0.86，仍低于 0.9，排除不变；
  - E227 门槛 A（问物）：0.88 → **0.97**（这一方向改为过门槛）；
  - E227 门槛 B（问人）：0.36 → 0.43（仍不过）。
- E224、E225 里 RWKV-7 的数字（包括 E225 事后观察里“74% 答成新位置”）是在强制 BOS 下得到的，未重测，引用时须注明。

结论层面：Falcon-Mamba 不受影响，RWKV-7 只在 E227 方向 A 一处改为过门槛，架构轴“现有纯循环模型能力不足以比较算法”的判断不变。E228 起脚本改为按分词器默认处理。检查脚本：`bos_check2.py`（节点本地，未入库）。
