# E133：计算输出匹配能否给出可用的跨训练专家对应（2026-10-26）

- **问题（一句话）：** 在相同输入上直接匹配专家的计算输出，尤其按目标router实际使用的输入加权，是否更能保留完整bank移植的预测？

## 固定设置与两种匹配
- 复用E132固定5条有向环（0←1、1←2、2←3、3←4、4←0）、真实62500步终点、同model-only banks、同512个UD cal输入与独立Dolma held512窗口/262144 token。不按前项效果选模型，不更换校准/测试集。
- 使用公共cal Htarget的512个目标位置，所有target/source专家都在这些相同H上前向。原始FP32参数不变，expert前向沿BF16 autocast，输出转float64作距离统计；不读取held函数或任务标签拟合对应。源与目标输入/下游坐标相同，不需内部神经元参数对齐。
- **全输入输出匹配：** `C_uniform[e,j] = mean_i ||fT_e(h_i) - fS_j(h_i)||²`，Hungarian最小化总成本，target slot e→source expert j。不先平均输出向量，不按范数/方差归一化。
- **目标支持加权输出匹配：** 从原target capture读取cal的稀疏门值`w[i,e]`（原softmax/top8、不再归一化，未选为0），`s[i]=sum_e w[i,e]`；`C_support[e,j] = mean_i s[i]*w[i,e]*||fT_e(h_i)-fS_j(h_i)||²`。Hungarian最小化总成本，不按expert频率重新归一化，不搜索权重幂次/混合系数。零校准支持的行显式报告为未约束，不删模型或择有利slot。
- **为何这个成本：** 对同一缓存上的实数加权求和，`||sum_e w_e δf_e||² <= (sum_e w_e)*sum_e w_e||δf_e||²`；所以任一置换的cal整层重建误差被相应总成本上界。代码用tiny已知答案和实际cal缓存核对方向/成本/界。它不是held预测保证，也不声称bf16程序严格等变；模型全序列推断仍沿E132精度。
- 专家输出缓存只在NVMe；小型成本矩阵、映射、cal重建误差与界可保存。所有两种对应都完成，不挑更有利者重命名为“功能对应”。

## 决策表与范围
- 加权优于全输入匹配和router→支持“在目标路由支持上的计算相似”对本移植更有用，不证明语义身份或新算法普遍优越；两输出法均有用而加权无额外收益→主要是函数表示而非支持权重；输出法仍弱而router更好→报告这些指标对实际接口的限制，不继续扫系数；cal界改善但held无改善→校准分布/输出几何与预测目标不一致，不能据界宣布成功。
