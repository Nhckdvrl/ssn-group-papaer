## 设置
- 模型：PolyPythias 14M / 31M / 70M / 160M / 410M × 10 个种子（原版 + seed1–9；14M / 31M 原版的数据来源有第三方提示可能不同，分析时单列）= 50 个 run。
- 检查点（17 个）：256、512、1k、2k、4k、8k、13k、20k、30k、43k、57k、71k、86k、100k、115k、129k、143k。
- 任务（42 个，`scripts/e92_atlas.py`）：Todd et al. 2024 FV 数据集 23 个抽象 + 12 个抽取任务（5-shot，100 个查询，首 token 准确率与对数概率）；E89 的 7 个初级对比任务；固定 48 篇文档的验证损失（发现 spike）。
- 检查点下载到运行主机 /tmp，用完即删；结果 JSON 小，进 git。

## 先登记的读数（不预设结论）
1. 每个尺寸 × 任务：终点准确率在 10 个种子间的分布（双峰检验：Hartigan dip / 两成分混合 vs 单成分 BIC），以及成功率随尺寸的变化。
2. 每个 run × 任务：首次“学会”的检查点、之后是否“丢失”（准确率回落到成功阈值以下并持续）。
3. 失败 / 丢失事件与验证损失跳升（spike）的时间对应。
4. 早期可预测性：用 ≤ 某步的读数（自身能力轨迹、其他任务、损失）预测终点成败，留一种子交叉验证。

## 什么结果会改变判断
- 若复杂任务普遍双峰、且失败多来自“学会后丢失 + 对应损失跳升”：现有“学习竞争导致种子双峰”的解释在真实预训练中不完整，优化事故是重要来源 → 追问事故为何只伤后期能力（与 E90 的“重学按发育顺序”相连）。
- 若失败多为“从未学会”且与 spike 无关：存在学习过程本身的分岔 → 用 E89 探针在分岔前后找机制差异（例如是否形成某个共用头）。
- 若基本不双峰、种子差异是连续小幅波动：410M 反义词只是个例，此线止于描述。
