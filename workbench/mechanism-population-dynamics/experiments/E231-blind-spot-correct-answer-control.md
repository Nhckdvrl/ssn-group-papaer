# E231：给出的答案是对的时候，模型会不会也“对自己宽容、对别人挑剔”？（2026-11-25）

- **状态：** PLANNED
- **类型：** PILOT（候选 D 的第三刀；补 E230 的设计漏洞；不推进主张）
- **对应：** [TOPIC_SEARCH.md](../TOPIC_SEARCH.md) 候选 D；前置 [E229](E229-self-correction-blind-spot-origin.md)、[E230](E230-blind-spot-detection-vs-retraction.md)。用户 11-25：“补，多卡跑”。

## 问题（给外人看的版本）

E230 里所有题给出的答案都是**错**的，模型在“接着写”时更少否定它。这有两种解释，E230 分不开：
- **看不出错（敏感度低）：** 在自己正在写的这段话里，模型分辨对错的能力变差了。
- **对自己更宽容（标准偏移）：** 分辨能力没变，只是对自己的答案一律更倾向于认可、对别人的答案一律更倾向于否定。

**一刀切开的对照（信号检测的标准做法）：** 同样的题、同样的位置，把错答案换成**正确答案**。
- 命中率 H = 答案错时否定的比例（E230 已有）；误报率 F = 答案对时也否定的比例（本卡新测）。
- **H − F** 衡量“分不分得清”；否定总倾向衡量“偏向认可还是否定”。
- 若“接着写”的 H 低、F 也同样低、H − F 与另两种条件相当 → 标准偏移（对自己宽容）。
- 若“接着写”的 H − F 明显更小 → 敏感度确实下降（看不出错）。

## 设置

- **模型、数据、格式、条件、知识门：** 与 E230 相同（OLMo-3-7B base / Instruct-SFT / Instruct；SCLI5 286 + GSM8K-SC 300；F1 / F2；C / S / O；知识门复用 E229 clean）。
- **给出的答案改为正确：**
  - SCLI5：“The answer is {正确答案}.”，与错误版逐字同构（只差那个数 / 字母）。
  - GSM8K：用数据集自带的标准解答（去掉 `<<…>>` 计算标注与 `#### N` 行，换行改空格）。风格与 GPT-4.1 改写的错误版不同，属于混杂，**GSM8K 只作辅助，主读数用 SCLI5。**
- **检查语：** N（无检查语，同 E229）、V（中性，同 E230）、W（“Wait,”，同 E230）。
- **读数：** 同 E230 的三选一结论评判（A 认可 / B 否定或改答 / C 没下结论）+ 认可短语规则。E229 式的无检查语条件同样用结论评判，不用“最终答案对不对”。
- **命令：** `scripts/e230_check_frame.py --correct --frames N V W`（加两个参数）；分片跑在 fvcrc20 ×3、fvcrc12 ×2、fvcrc13 ×1。

## 读数

- 每个模型 × 格式 × 数据 × 检查语 × 条件：F（正确答案被否定的比例）。与 E230 的 H 配对，算 H − F。
- **主比较（SCLI5、V）：** C 与 O 的 H − F 之差（配对 bootstrap，按题配对：同一题的错版与对版）。
- **辅助：** N 下的 F（E229 里 O 的高“纠正率”是否部分来自对别人的答案一律改掉）；W 下的 F（“Wait,” 是否只是把模型推向一律否定）。

## 阳性对照与噪声

- **阳性对照：** O 条件下，对正确答案的 F 应明显低于对错误答案的 H（模型在回复别人时确实分得清对错）。若 O 的 H − F < 0.2，说明连基本的分辨都不成立，本卡不解释。
- **评判校验：** 从正确答案版的输出里随机抽 40 条人工标注；评判 + 规则低于 90% 时，对分歧类别人工复核。
- **噪声：** 同前，n ≈ 190–280 时比例区间约 ±0.06；H − F 之差 < 0.15 不作为“有差别”。

## 混杂审计

- GSM8K 正确版与错误版文本风格不同（见上），主读数只用 SCLI5。
- 正确答案版里 S / O 的“否定”可能是模型把对的改成错的（附和的反面），也可能只是“换个说法重答”。三选一评判规则：只要最终答案不同或明说不对就记 B；最终答案相同记 A。
- 其余同 E230（单一家族、S 格式不自然、SFT chat + V + SCLI5 一格 E230 已无效）。

## 算力预算

约 3 GPU·时（三个模型 × 约 586 题 × 3 检查语 × 3 条件 × 1–2 格式，约 2.6 万条生成；加评判），6 张卡并行，墙钟约 30 分钟。为分片把 SFT 权重拷到 fvcrc20 / fvcrc12（各约 14 GB）。**实际：** 约 2.5 GPU·时。生成 6 卡并行，墙钟 25 分钟（15:41–16:06）。原定在 fvcrc13 GPU2 上做的评判，因该卡被他人进程占用（71 GB）而爆显存；把评判模型拷到 fvcrc20 / fvcrc12，5 卡并行重做，同时补做了 E229 输出的结论评判（无检查语那列的命中率要用）。

## 结果（跑完后填写；不改上面的内容，修改需注明日期）

**评判校验：**
- 主读数所在的 V 格：抽 11 条（随机 40 条中属于 V 的）+ 24 条（SCLI5、V，按条件分层），共 35 条，全部一致。
- 随机 40 条整体：38 条可判定中 30 条一致（79%），低于 90%。分歧几乎都在 W / N 格，且都是同一类：模型写 “I made a mistake” / “That's not right”，然后给出与原来相同的（正确）答案。评判按“最终答案相同”记 A，人工按“明说错了”记 B。这类分歧只会**少算** W / N 下的误报，所以下面关于 W 的结论偏保守。按卡要求对这一类做人工复核：未改动数字，只在解读里标明方向。

**按决策表执行：**
- 阳性对照通过：O 的 H − F 为 0.50（base）/ 0.94（Instruct）。
- **（11-25 晚补注：E232 用不依赖门槛的 AUC 重新检验后，结论改为“门槛移动”：锁定验算时所有阶段 AUC ≈ 1，接着写时判定整体偏向“对”。下面这一行是按本卡比例读数的原判断，保留不改。）**
- 落在“**敏感度下降**”一行：中性检查语下，三种放法对正确答案几乎都不否定（F ≈ 0），而接着写时对错答案的否定少得多。所以 E230 的差距**不是**“对别人的答案一律更挑剔”造成的。base 与 Instruct 落在同一行。
- **保留（重要）：** F 在所有条件下都接近 0（地板）。地板上，“分辨力下降”与“接着写时要更多证据才肯否定（门槛更高）”从比例上分不开；能排除的只是“对别人一律挑剔”。要彻底分开，需要不依赖门槛的分级读数：在检查语后直接读 Yes / No 的 logit，按题算错答案与正确答案之间的 AUC。只需前向传播，很便宜，留作下一步。

**辅助读数（POST-HOC 性质的解读，单独标注）：**
- **无检查语（N，即 E229 的设置）：** base 在“另一人回复”里对正确答案也有 64%（SCLI5）/ 45%（GSM8K）被改掉或否定。所以 E229 里 base 的“回复别人时纠正得多”，相当一部分是“一律唱反调”；扣掉误报后，O − C 的差距缩小到 +0.13 [.05,.21] / +0.24 [.08,.40]，但仍不含 0。最终 Instruct（F2）在 N 下几乎没有误报（O 的 F = 0.00 / 0.02），E229 对它的结论不变。
- **“Wait,”（W）：** 误报率很高，而且主要落在模型自己一侧：最终 Instruct（F2）的 F 在 C / S / O 为 0.49 / 0.48 / 0.03；base 的 C 为 0.85。也就是说，在自己的答案后加 “Wait,”，模型有一半左右会把**正确**答案也推翻。Tsui 报告的“加 Wait 后盲点缩小 89%”，很大一部分可能是门槛移动（更容易否定自己），而不是看得更清楚。评判对这一类是少算的，实际误报更高。
