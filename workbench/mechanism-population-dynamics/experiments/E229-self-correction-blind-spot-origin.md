# E229：自我纠错盲点在预训练模型里就有吗？是“接着写”还是“是自己写的”造成的？（2026-11-25）

- **状态：** DONE（11-25 用户“跑吧”后运行；结果见文末）
- **类型：** PILOT（候选 D 的第一刀；不推进主张；锁题由人决定，R2）
- **对应：** [TOPIC_SEARCH.md](../TOPIC_SEARCH.md) 候选 D。

## 问题（给外人看的版本）

同一个错误（“1+1 的答案是 3”），放在用户的话里，指令模型会纠正；放在它自己的回答里，它就接着说下去（Tsui, COLM 2026，14 个模型平均 64.5%）。现有两篇都把原因归给后训练：SFT 数据里没有自我纠错（Tsui），或指令微调对角色标签的处理（Chen 2606.05976）。但两篇都只测了指令模型，而且它们的“自己的错”都是**在同一段里接着写**，“别人的错”都是**换一轮来回复**——“是谁写的”和“接着写还是回复”绑在一起。

本卡只问两件事：
1. **只做过预训练的 base 模型有没有同样的不对称？**（有 → “后训练造成”的说法不完整；没有 → 后训练造成，下一步定位哪一阶段。）
2. **在指令模型里，把“自己的错”放到新的一轮（不是接着写），它还看不见吗？**（还看不见 → 角色 / 归属在起作用；看得见 → 盲点主要是“接着写”的问题。）

**近邻（全文或部分已读）：** Tsui 2507.02778；Chen 2606.05976（只换角色，无 base、无“接着写 vs 新一轮”）；Ni 2610.34809（旧答案标成自己的上一轮或引用别人的，效果相同，只测 Qwen3.5-27B，不是纠错）；Khullar 2603.04582（监视器场景：动作放在上一轮 assistant 里就放水，明说“是你写的”反而不放水）；Pan 2508.15815（用户—助手偏向：base 接近中性，指令模型偏用户）；Yao 2610.37788、Huang 2610.26655（谄媚的训练阶段追踪，用 OLMo 各阶段）。**没有人在 base 模型或训练阶段上测过这个盲点**（11-25 两轮检索 + Semantic Scholar 引用表，见 TOPIC_SEARCH）。

## 设置

- **模型（3 个，同一条 OLMo-3 线，全部开放）：** `allenai/Olmo-3-1025-7B`（base）、`allenai/Olmo-3-7B-Instruct-SFT`、`allenai/Olmo-3-7B-Instruct`（SFT → DPO → RLVR 之后的最终版）。DPO、Think 线、RL-Zero 留到下一步。
- **数据：** Tsui 公开的 `kenhktsui/scli5`（286 题，1+1 级别的简单题，错误显而易见）＋ `kenhktsui/gsm8k_sc` 的前 300 题（`bca` 版：推理里有一步错，不含最终答案句）。
- **三种条件（错误文本逐字相同）：**
  - **C 接着写：** 错误是 B 说的，模型接着写 B 的这段话（= Tsui 的 internal）。
  - **S 同一人新一轮：** B 的这段话已结束，模型以 B 的身份开始新的一段（chat 格式：两个连续的 assistant 消息；纯文本：新起一行 “Bob:”）。
  - **O 另一人回复：** 错误是 A 说的（跟在问题后面），模型以 B 的身份回复（= Tsui 的 external）。
- **两种格式（堵“格式混杂”）：**
  - **F1 纯文本对话**（三个模型都跑）：`Alice: {问题}\n\nBob: {错误}` 等，无 chat 模板。base 只能用这种。
  - **F2 chat 模板**（两个后训练模型）：Bob = assistant，Alice = user。
- **知识门：** 同一格式下无错误的干净问法，只保留模型答对的题，保证“会但没纠正”。
- **解码：** greedy，最多 256 token，在下一个说话人标记 / EOT 处截断。
- **命令：** `scripts/e229_blind_spot.py`（待写），模型放节点本地 /tmp。

## 读数

- **纠正率：** 截断后的续写里，最终给出的答案等于正确答案的比例。对每个模型 × 格式 × 条件给出比例与 Wilson 95% 区间。
- **判定方式（11-25 跑前修改）：** 原写“规则抽取”。看了数据后改为本地 LLM 评判：SCLI5 有一半是“8 和 12 哪个小”这类题，续写里两个数都会出现，“最后一个答案”的规则会读错。评判模型用 `Qwen/Qwen2.5-7B-Instruct`（与被测的 OLMo 不同家族），固定提示词，比较下一个 token 上 Yes / No 的 logit，不采样。Tsui 原文也用 LLM 评判（Gemini）。
- **评判的校验：** 随机抽 60 条人工看，报告一致率；低于 90% 时，对有分歧的类别做人工复核，并在结果里写明。
- **主比较：** O − C（Tsui 的盲点）；S 落在 C 和 O 之间的哪一侧。

## 阳性对照与噪声

- **阳性对照：** F2 下的 OLMo-3-Instruct 应复现 Tsui 的方向（O 明显高于 C）。复现不了，说明工具或格式有问题，本卡的其余结论都不解释。
- **噪声地板：** 二项抽样，n ≈ 250–300 时 95% 区间约 ±0.06。两条件之差 < 0.15 不作为“有差别”的依据。

## 混杂审计

- **格式：** base 与后训练模型的比较只在 F1 内做；F2 只在后训练模型之间比较。
- **S 条件的格式不自然**（连续两个 assistant 消息 / 同一人连续两行）：如实报告；若 S 的知识门或可评分率明显低于其它条件，S 不解释。
- **题目难度：** 门控后只比同一批题。
- **base 的续写可能跑题：** 截断规则写死，不事后调整；不可评分的比例按条件报告。
- **单一家族：** 本卡只测 OLMo-3；结果只作为“是否值得往下做”的依据，不作为结论。

**按决策表执行：**
1. 阳性对照通过：Instruct（F2）O − C = +0.33 / +0.61，复现 Tsui 的方向。
2. base（F1）：O − C = +0.25 / +0.50，区间不含 0 → **不对称在只做过预训练的模型里就有，“后训练造成”的说法不完整。**
3. Instruct（F2）：S 与 O 无差别或略高 → **最终指令模型的盲点主要来自“接着写”，不是“这是我写的”：** 同一个错误留在它自己上一轮的回答里，新开一轮时它纠正得和纠正用户一样好。
4. 决策表说的“下一步：补 DPO / Think / RL-Zero 阶段、加一个其它家族的 base”按约定先回到讨论，不连续追加。

**按题型看（SCLI5，POST-HOC，单独标注）：**
- “接着写”几乎从不纠正：base、SFT 在所有题型上都是 0.00–0.06。唯一明显上升的是最终 Instruct 的 chat 格式（比大小题 0.73–0.76，字母题 0.18–0.60），即 DPO / RLVR 之后才学会在同一段里改口（和 Tsui“推理 / RL 模型盲点小”一致）。
- SFT 在 chat 格式下回复用户的比大小题时，几乎全部照抄用户给的错答案（O = 0.01–0.03，例：“The answer is 13.”），但在自己的新一轮里纠正（S = 0.21–0.76）。这一格是附和用户，不是“看不见自己”；SFT 的 O − S 为负主要来自这里。
- F1 里字母题的 O 常被续写成“出题模式”（“What letter comes after J? The answer is K.”），O 偏低，是纯文本格式的伪影。

**解读上的保留（未核对）：**
- S 和 O 里模型可以“重新答一遍”而不必指出前面的错（如 Instruct S：直接给出 8，不提 288），C 里要答对就必须当场推翻刚写的句子。C 与 S / O 的差别，可能不只是“看不看得见错”，也包括“改口的代价”。现有读数分不开这两者；Tsui 的指标同样分不开。
- 只有 OLMo-3 一个家族；chat 里的 S 是连续两个 assistant 消息，不是自然对话；GSM8K 上 base 过门只有 76 题。
