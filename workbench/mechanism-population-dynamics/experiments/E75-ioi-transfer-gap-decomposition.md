# E75：410M 同初始化兄弟之间 IOI 迁移只有 0.05——是计算变了、同一计算换了承担者，还是测量造成的？（2026-10-08）

- **状态：** DONE（2026-10-08）
- **类型：** PILOT（方向 B 的判别实验：决定“跨 run 的因果计算对应”能否成为新中心）
- **对应：** C05（circuit 层只部分对应）；E73（410M 去重版 top-3 迁移 0.05，但参照 top-3 在目标中 DLA 排名平均 14 / 384）；E74；Tigges et al. 2024（算法一致、成分会换）；Wang et al. 2023 / McGrath et al. 2023 / Rushing & Nanda 2024（backup name mover 与自修复）
- **问题（一句话）：** 在 Pythia-410M 标准版与去重版（同初始化、数据近似）之间，参照模型最重要的 IOI 头在目标中“不重要”，究竟是 (a) 测量造成（比值分母、单头与联合不同）、(b) 同一计算仍在、只是贡献被下游自修复或换了承担的头、还是 (c) 目标模型用了不同的计算？
- **事先预测（用最强的已有认识）：** Tigges 等报告 Pythia 中 IOI 算法跨训练与规模一致、成分会换；IOI 中有已知的 backup name mover 自修复。→ 预测 (b)：同一组功能类（name mover、负 name mover、S-inhibition）在两个模型都存在，换了承担的头，参照头在目标中被自修复。若结果是 (b)，“异 run 之间计算不同”不能成为新中心。
- **谁依赖这个答案：** 把一个模型上发现的 circuit 用到同族兄弟 / 继续训练 / 微调模型上的研究（头编号或角色标签直接沿用）。
- **设置：** Pythia-410M 标准版（参照）与去重版（目标），step 143000；对照：160M 同样一对（E73 迁移 0.85）；异初始化参照：410M seed1。IOI 用 E14 / E73 的同一生成器（N = 200，seed 42），按提示编号奇偶拆为拟合半 / 留出半。脚本 `scripts/e75_transfer_gap.py`。
- **读数：**
  1. **测量分解：** 参照 top-3 在参照中的联合消融下降 vs 在目标中的下降 vs 目标自身 top-3 的下降（绝对值，不只比值）；每个头的单头消融下降之和 vs 联合下降。
  2. **直接 vs 总效应（自修复）：** 对一个头集合，直接效应 = 只替换该集合在 END 处输出、其余组件冻结在干净值时 logit 差的变化（DLA 路径）；总效应 = 普通均值消融。自修复比例 = 1 − 总 / 直接。
  3. **角色剖面：** 每个头在 END 处对 IO、S1、S2、END 自身、首 token 的注意力，DLA，以及 OV 名字复制分数（IO 名字嵌入经 OV 到反嵌入在 IO 上的 logit 相对其他名字）。把头按功能类分类（name mover：注意 IO 且 DLA > 0；负 name mover：注意 IO 且 DLA < 0；其他直接写者：DLA 大但不注意 IO）。
  4. **任务映射迁移：** 在拟合半上，为参照的每个 top-k 头在目标中找角色剖面（读数 3，在拟合半上计算）最近的头；在留出半上做联合消融，比较 原编号 / 任务映射 / 目标自身 top-k / 随机。
  5. **功能类层面：** 两个模型各自 name mover 类的联合消融下降占 logit 差比例；类成员数与层分布。
- **阳性对照：** 160M 对（E73 迁移 0.85）上，原编号映射本身就应接近任务映射；目标自身 top-k 消融 ≫ 随机。
- **噪声地板 + MIE：** 随机 k 头 20 组；留出半上 bootstrap（提示重抽 1000 次）给出比值的 95% CI；比值差 < 0.2 视为无差别。
- **混杂审计：** 拟合 / 留出分半（避免映射在同一批提示上自证）；均值消融用 ABC 提示的均值（与 E73 相同）；DLA 与消融读数口径不同，分别报告；只一对 410M 模型（单对是本 pilot 的范围）。
- **决策表（跑之前写）：**
  - 任务映射留出迁移 ≥ 0.5 且两个模型功能类结构相同 → (b)：**同一计算、换了承担者**；E73 / v2 中“circuit 只部分对应”须改写为“头标签不对应、计算对应”；方向 B 的“计算分化”中心不成立，停止。
  - 原编号迁移低主要来自自修复（参照头直接效应 ≥ 目标自身 top-3 直接效应的 30%，而总效应被自修复吃掉 ≥ 50%）→ (b) 的自修复变体：同上结论。
  - 参照 top-3 在参照中的下降本身就远小于目标自身 top-3 在目标中的下降（< 50%）→ (a) 比值分母造成大部分落差：修正 E73 的读数说法。
  - 任务映射也 < 0.2、且目标的功能类结构与参照不同（例如目标主要靠参照中没有的一类组件）→ (c) **计算不同**：方向 B 存活，下一步定位替代的步骤。
  - 其他 / 混合 → 如实报告，不追加设定（止损）。

## 结果（跑完后填写；不改上面的内容，修改需注明日期）
- 数字（留出半，联合均值消融 logit 差下降 / 目标自身 top-3 下降；括号为 1000 次 bootstrap 95% CI）：

| 目标（参照 = 标准版） | 原编号 | 剖面映射（含 DLA） | 逐提示 DLA 相关映射 | 随机 3 头 |
|---|---|---|---|---|
| 160M 去重版（同初始化） | 0.87（0.82–0.91） | 0.89（0.83–0.95） | 0.89 | ≈ 0 |
| 410M 去重版（同初始化） | **0.06（0.02–0.12）** | **0.85（0.80–0.90）** | 0.78（0.75–0.81） | ≈ 0 |
| 410M seed1（异初始化） | **0.00** | **0.94（0.89–0.99）** | 1.04（0.99–1.10） | ≈ 0 |

- **计算是同一个：** 三个 410M 模型（以及 160M）的 IOI 主力都是同两类头：(i) copy-suppression 型——在 END 注意 S2、OV 为负复制（−1.8 到 −2.0）、通过压低 S 产生 IO−S 差，是各模型 DLA 最大的头（标准版 11.4、去重版 12.12、seed1 12.2；160M 两兄弟都是 8.9）；(ii) name mover 型——注意 IO、OV 正复制。功能类成员数相近（name mover 11–14 个，负 name mover 2–5 个）。
- **换了承担者，原承担者休眠：** 参照的 11.4 在去重版中 70% 的注意力落在首 token、DLA 0.02；反过来去重版的 12.12 在参照中也休眠（首 token 0.58、DLA 0.00）。参照的 name mover 18.8、17.6 在去重版中仍是 name mover（注意 IO 0.44 / 0.34、OV 复制 1.28 / 1.36），只是权重变小；在 seed1 中则休眠。
- **测量分解：** 原编号迁移低主要来自主力头换人，不是比值分母（参照 top-3 在参照中的下降 1.28 并不小）。自修复存在但不是主因：去重版中参照 top-3 的直接效应 0.45、总效应 0.15（自修复 66%），而直接效应本身就只有目标自身 top-3 的 27%。单头之和与联合消融在 410M 去重版相近（0.17 vs 0.15；2.61 vs 2.45）。
- **POST-HOC 检查（看到主结果后加的，因为剖面映射含 DLA，可能循环）：** 只用注意力与 OV 复制特征的最近邻映射：160M 去重 0.92、410M 去重 0.84、**seed1 −0.06**（把 11.4 匹配到一个大多休眠、只有弱 S2 注意的头 13.15）；改用类型规则（copy-suppression 中 S2 注意最大者 + IO 注意最大的两个 name mover）：160M 0.92、seed1 1.06、**410M 去重 0.18**（选中 21.3 而非 12.12）。→ 每个功能类在每个模型里都有多名成员，**谁是主要承担者无法只从注意力 / OV 剖面稳定读出，需要因果读数**。按止损规则不再换映射方法。（`results/e75/role_only_*.json`、`type_rule_posthoc.json`）
- 结果文件：`results/e75/analysis.json`、`pythia-*.json`；脚本 `scripts/e75_transfer_gap.py`
- **按决策表：** 第一档（任务映射留出迁移 ≥ 0.5 且功能类结构相同）→ **(b) 同一计算、换了承担者**，与事先预测一致。方向 B 的“跨 run 计算分化”中心不成立，停止。
- **主张变化：** C05 / v2 中“task circuit 只部分对应”须改写：只在**按头编号**比较时部分对应；按功能类与因果读数映射时，IOI 计算在同初始化与异初始化模型间都对应（0.78–1.04）。共享初始化提供的只是“不用重新找就对得上的编号”，在 410M 连这一点也会在两个候选头之间翻转。这与 Tigges et al. 2024（算法稳定、成分轮换）一致，不构成新认识。
- **算力实际：** 约 0.5 GPU·时。
