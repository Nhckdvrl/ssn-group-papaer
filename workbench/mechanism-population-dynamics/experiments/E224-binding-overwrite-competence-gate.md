## 为什么要做这一次（给外人看的版本）

候选 1 想问：Transformer 做“变量绑定”有一套已被拆清楚的算法（Gur-Arieh ICLR 2026 的位置 / 词汇 / 反射三种机制；Oh & Demberg 2026 的提问时局部重绑定）。没有注意力、必须在被提问之前就把一切写进固定大小状态的循环模型（Mamba、Gated DeltaNet、RWKV-7），是走到同一套算法，还是换了一种？这是导师“独立训练的模型会不会形成同样的机制”在算法层的问法，判定靠已有文献给的反事实签名，不靠我们自定的阈值。

但这一切的前提是：这些循环模型**真的会做**绑定和覆写。文献里纯 GDN-340M 连散文检索都没到 80%（2609.33093），Feng & Steinhardt 的 binding ID 只在足够大的模型里出现。如果循环模型根本不会做，就没有机制可比，候选 1 不成立。本卡只回答这一个可行性问题，不回答机制问题。

## 设置

- **模型（6 个）：**
  - 同数据同预算（SlimPajama 100B token，fla-hub）：`fla-hub/transformer-1.3B-100B`、`fla-hub/mamba-1.3B-100B`（加法衰减）、`fla-hub/gated_deltanet-1.3B-100B`（delta 规则；若无法加载则换 `fla-hub/delta_net-1.3B-100B`，并在结果中注明）。
  - 大尺寸纯循环：`tiiuae/falcon-mamba-7b`（Mamba-1）、`RWKV/RWKV7-Goose-World3-2.9B-HF`（RWKV-7，广义 delta 规则）。
  - 大尺寸 Transformer（阳性对照）：`Qwen/Qwen3-8B-Base`。
  - 不用需要授权的模型（Llama 等），不用用户凭证。
- **两种格式（各自独立出题）：**
  - 代码式：`a = 4` 一行一个赋值，变量为不重复的单字母，值为不重复的一位数字；查询行 `print(a)` 后读下一个 token。前面放 2 个只含静态赋值的完整示例固定格式（示例里没有覆写，不示范覆写的答法）。
  - 叙述式：`Alice is in the kitchen.`，人名与地点各自不重复；覆写句 `Then Alice went to the garage.`；查询 `Question: Where is Alice? Answer: the`。同样 2 个静态示例。
- **五种条件（每种格式每种条件 150 题，种子 224）：**
  - S2：2 个变量，问其中随机一个。
  - S4：4 个变量，问其中随机一个。
  - O1：3 个变量，其中目标变量被覆写一次（新值不同于所有已出现的值），覆写之后再加一条无关的赋值（防止“最后一行的值就是答案”的捷径），问目标变量。正确 = 新值。
  - O1-other：与 O1 相同的上下文，问一个**没被覆写**的变量。检查覆写是否连带破坏其它绑定（全局衰减 vs 按键擦除）。
  - O3：同 O1，但目标变量的旧值在覆写前共陈述 3 次（中间穿插其它变量），之后只覆写一次。
- **命令：** `scripts/e224_gate.py`（本卡提交后写；结果在 `results/e224/`）。

## 读数

- 每题对上下文里出现过的所有候选值计算完整续写的对数似然之和（多 token 候选求和），取最大者为模型答案。准确率 = 答对比例；O 条件另报“旧值率”（答成被覆写的旧值的比例）。
- 95% 区间：按题 bootstrap 2,000 次。
- 机会水平：S2 0.5，S4 0.25；O1、O3 的候选含 4–5 个值。

## 阳性对照与噪声地板

- 阳性对照：Qwen3-8B-Base 在 S2、O1 两种格式上应 ≥ 0.95；达不到即判为脚本或格式有问题，先修脚本，不解读其它模型。
- 噪声地板：n = 150 时，p ≈ 0.9 的二项标准差约 0.025，95% 区间半宽约 0.05。

## 混杂审计（EXECUTION.md §4，只列相关项）

- 分词：候选按完整续写求和打分，不依赖首 token；代码式的值全是一位数字。已控制。
- 位置与近因捷径：查询变量随机；O 条件在覆写后加无关赋值。已控制。
- 格式依赖：两种格式独立出题，结论要求两种格式一致。已控制。
- 规模与训练数据：同数据 1.3B 一组可比；大模型一组跨家族，只用于“能不能做”，不比较高低。未控制（设计如此，写明）。
- 能力 vs 算法：本卡只测能力，不对任何架构的算法下结论。

## 决策表（跑之前写）

“过门槛”定义：S2 与 O1 两个条件、两种格式上准确率都 ≥ 0.9。这是可行性标准，不是科学主张。

| 结果 | 决定 |
|---|---|
| 阳性对照 Qwen3-8B 不过门槛 | 脚本或格式有误，修好再跑；不解读 |
| 同数据 1.3B 的 Transformer **和**至少一个 1.3B 循环模型过门槛 | 候选 1 可用同数据对照做机制研究；带结果回到集中讨论 |
| 1.3B 循环模型都不过，但 Falcon-Mamba-7B 或 RWKV-7 过 | 只能走跨家族的定性路线（同数据对照不可用）；带结果回到讨论，由人决定 |
| 所有纯循环模型都不过门槛 | 候选 1 按现在的提法不成立（没有行为可供分析机制）；如实报告，回到讨论，不追加补救实验 |
| 介于之间（例如只在一种格式过） | 如实报告为不确定，回到讨论；不换格式、不加提示去救结果 |

O1-other 与 O3 只作描述，不作主张、不触发后续实验；它们只用来回答讨论时会问的一个问题：覆写行为在这几类模型之间是否已经肉眼可见地分开。

**11-25 09:40 更正（脚本 bug，事后发现）：** E224–E227 的脚本无条件在输入开头加分词器的 BOS token。对默认**不加** BOS 的分词器，这会改变输入。逐模型影响：
- Qwen 系列没有 BOS，Falcon-Mamba 的 BOS 为空：不受影响，数字不变。
- fla-hub 1.3B 的分词器默认本来就加 BOS：不受影响。
- RWKV-7 的 BOS 是文本结束符，默认不加：**受影响**。在 E226 / E227 的同一批题上按分词器默认处理重测：
  - E226 无变化时问“一开始”（W1 / W4）：0.83 / 0.88 → 0.82 / 0.86，仍低于 0.9，排除不变；
  - E227 门槛 A（问物）：0.88 → **0.97**（这一方向改为过门槛）；
  - E227 门槛 B（问人）：0.36 → 0.43（仍不过）。
- E224、E225 里 RWKV-7 的数字（包括 E225 事后观察里“74% 答成新位置”）是在强制 BOS 下得到的，未重测，引用时须注明。

结论层面：Falcon-Mamba 不受影响，RWKV-7 只在 E227 方向 A 一处改为过门槛，架构轴“现有纯循环模型能力不足以比较算法”的判断不变。E228 起脚本改为按分词器默认处理。检查脚本：`bos_check2.py`（节点本地，未入库）。
