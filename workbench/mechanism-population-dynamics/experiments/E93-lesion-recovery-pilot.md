# E93：预训练中途受损后，能恢复什么？——受控损伤 + 匹配对照继续训练的校准 pilot（2026-10-16）

- **状态：** RUNNING（2026-10-16 02:12 起，8 个分组 × 1 卡：C_lo、C_hi、H_lo、H_hi、H2_lo（同时重置 3.2 与备份头 3.0）、R_lo（3.8）、N_lo、N_hi；warm-up 200 步）
- **类型：** PILOT（为方向 B 做校准；方向见 [knowledge/research/DIRECTION_2026-10-16.md](../knowledge/research/DIRECTION_2026-10-16.md)）
- **来源：** E90：两个自然 spike 后，损失大体恢复，晚出现的示例格式 ICL 不恢复，重学按原发育顺序（n = 2，无法区分原因）。DataDecide 1100 个 run 只有 4 次小幅困惑度回升，自然事件太少，必须受控。
- **最强已有认识：** Kim et al. ICLR 2025（后期知识获取变难、知识熵衰减）；Chang et al. NeurIPS 2024（后期学习效率下降不归因于学习率衰减）；ZClip / K2-V2（以损失能否恢复区分良性 / 恶性 spike）；BLOOM 头重初始化修复（arXiv 2603.09616，只看困惑度）；Hapax（重初始化 induction 头后长出更多 induction 头，重置这些头的优化器状态则卡住）。**未见逐项能力的损伤—恢复追踪。**

## Pilot 要回答的校准问题
1. 匹配对照（同一检查点、同一数据顺序、同一优化器设置、不损伤）在继续训练窗口内是否保持能力不漂移？（不保持则设置本身有问题，先修设置）
2. 局部损伤（重置 induction 的单点瓶颈 previous-token 头）与全局损伤（类 spike 的权重噪声）是否造成可测的能力损失？窗口内是否能看到恢复开始、恢复的先后？
3. 重建是否回到同一个头？
4. 学习率是否是晚出现能力恢复的主要限制（同一损伤在两种学习率下对比）？

## 设置
- 基座：Pythia-160M（原版，seed0），step 100000（训练后段，Pythia 余弦学习率在此约为峰值的 29%：1.74e-4）。枢纽头 3.2（previous-token 0.84，消融后 induction −12.2，也是反义词 ICL 第一承担头，E89）。
- 继续训练数据：NeelNanda/pile-small-tokenized-2b（GPT-NeoX 分词，1024 token / 段）前 4 个分片，所有分组同一顺序；batch 128 × 1024 = 131k token / 步，2000 步（2.6 亿 token）。AdamW（β 0.9 / 0.95，wd 0.01，eps 1e-8），梯度裁剪 1.0，优化器状态从零开始（Pythia 检查点不含优化器状态）——所有分组相同，前 50 步线性 warm-up。bf16 autocast，fp32 权重。
- 分组：
  - **C**：对照，学习率 1.74e-4（Pythia 在 100k 的值）；
  - **H**：重置枢纽头 3.2（该头的 Q/K/V 行与偏置、输出投影对应列，按 Pythia 初始化分布 small_init / wang_init 重抽）；
  - **R**：重置同层一个不重要的头（对照“任意重置”），按 E89 的 induction 效应最小、previous-token 分数低选取；
  - **N**：全局噪声，所有二维权重加 N(0, α·std(W))，α 在训练前标定到使验证损失上升约 1.5 nats（与 E90 两次 spike 的幅度相当）；
  - **C-hi / N-hi**：同 C / N，学习率取峰值 6e-4（再升温）。
- 读数（第 0、25、50、100、200、400、700、1000、1500、2000 步）：固定 48 篇文档验证损失；E92 的 42 任务能力组（Todd FV 35 + 初级 7）；每个头的 previous-token 与 induction 注意力分数（看枢纽是否在原头或别处重建）。
- 脚本：`scripts/e93_lesion.py`；结果 `results/e93/<arm>.json`。

## 决策表（看结果前写）
- **校准不过：** C 在窗口内 42 任务平均准确率变化 > 0.05 或任何任务系统性漂移 > 0.15 → 先调 batch / 学习率 / warm-up，不铺开。
- **窗口太短：** H / N 中没有任何能力在窗口内恢复到损伤前的 50% → 加长窗口或增大 batch 后再判断。
- **出现 E90 模式：** N（或 H）在窗口末损失恢复 ≥ 90%，而晚出现的 FV 任务（E92 中 160M 在 ≥ 8k 步才出现的任务）恢复 < 50% → 主实验铺开“损伤时间（8k / 43k / 100k）× 学习率 × 损伤类型”，区分学习率 / 可塑性 / 依赖。
- **学习率是主因：** N-hi 能恢复而 N 不能 → 主实验重点转向“学习率与恢复”（可能平凡，需判断）。
- **重建位置：** H 中枢纽在 3.2 重建 vs 换到别的头，作为描述登记；R 应几乎无损伤（否则重置操作本身有问题）。

## 冒烟（2026-10-16 02:08，H，30 步，warm-up 50）
- 损伤前：损失 2.686，FV 35 任务平均 0.346，induction 0.98，3.2 的 previous-token 分数 0.85。
- 重置 3.2 后（第 0 步）：损失 2.791，FV 0.248，induction 0.74，3.2 分数 0.03；最强 previous-token 头变成同层的 3.0（0.54）。
- 第 25 步：3.0 升到 0.72，induction 0.86，FV 0.317 → **恢复首先来自已有备份头接管**，而不是原位重长。损失反升到 2.872（优化器从零状态起步的短暂扰动，对照组也会有）→ warm-up 改为 200 步；新增 H2 分组（同时重置 3.2 与 3.0）检验没有现成备份时的恢复。
- 用时：30 步 + 2 次评估约 85 秒；2000 步预计约 1 小时。
