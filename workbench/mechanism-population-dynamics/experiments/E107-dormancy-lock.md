# E107：联合训练中进入休眠的头会被锁死吗？——更高学习率、更长窗口下冻结 vs 联合（2026-10-17）

- **状态：** RUNNING（02:50 启动；5000 步）
- **类型：** CLAIM（E106 留下的开放问题）
- **来源：**
  - E106：lr 2e-5、3000 步时，冻结其余部分的完整重置头学不回原角色，但也不休眠（第 0 个 token 注意力 0.00），3.2 在缓慢上升（0.03 → 0.09）。
  - 联合训练中同样的头休眠（0.45–0.63）。
  - Schallon 用 5e-5、多轮训练，冻结后的头被唤醒（是否恢复原功能未检验）。
- **问题：** 在学习率更高、窗口更长时：
  - 冻结的头最终能否长回**原角色**？
  - 联合训练中的头是否仍然休眠、不回来——即休眠会把它锁死？

## 登记的预测（02:50）
- **“休眠锁死”：** 冻结组的受损头效应 ≥ 损伤前的 30%（或 3.2 的 previous-token ≥ 0.4），且不休眠；联合组的受损头效应 < 10%，并且休眠（第 0 个 token 注意力 ≥ 0.4）。
- **“只是慢”：** 两组都回来（≥ 30%）。
- **“新鲜头学不会”：** 两组都不回来（< 10%）。
- **对照：** 若 C_lr5 损失比 step100k 上升 > 0.02，联合组的任务比较需要扣除漂移后再看；受损头自身的效应仍可直接比较。

- **补一组（事后加、单独标注）：** F32_joint5——3.2 完整重置、联合训练、lr 5e-5、5000 步。这是判断“休眠锁死”所必需、而原设计遗漏的对照。E93 / E96 中，lr 2e-5 联合训练时 3.2 不回来（由 3.0 接管）。

  - 3.2、9.3 符合“休眠锁死”：冻结时 ≥ 30% 且不休眠；联合时 < 10% 且休眠（9.3：0.42 ≥ 0.4）。
