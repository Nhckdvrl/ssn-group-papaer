# E53：为什么是 “Question:” 而不是 “Q:”？——Flan 中各模板与“依据上下文作答”的共现（2026-10-03，不用 GPU）

- **状态：** PARKED（v1、v2 阳性对照均失败：测量定义无效；见下）
- **类型：** PILOT（C04 的数据层机制解释；为 E48 的结果提供可检验的预期）
- **对应：** C04（E32：“Question:” 触发、语义等价的 “Q:/A:” 不触发）；E48 的数据准备统计：Flan 中 “Q:” 23.7 万次、“A:” 26.0 万次，多于 “Question:” 14.6 万次、“Answer:” 15.7 万次——所以 “Q:” 不触发不是因为见得少；对标 Chan NeurIPS 2022（数据分布性质 → 机制）、Kim ACL 2026（文档内重复 / 不一致 → 仲裁）、Xie ICLR 2022（ICL 作为对潜在文档类型的推断）
- **问题（一句话）：** 在 Dolma 1.7 的 Flan 中，“Question: … Answer:” 模板后面的答案出现在前文段落里（即“依据上下文作答”）的比例，是否远高于 “Q: … A:” 模板？
- **设置：**
  - 数据：E48 准备的 flan_orig（tulu_flan part-48 的前 8000 万 token，23.5 万篇文档），按 EOS 切文档后解码；均匀抽 5 万篇（种子 0）。
  - 模板出现：T_Question = “Question:” 后 600 字符内出现 “Answer:”；T_Q = 行首或空白后的 “Q:”（前一个字符不是字母），其后 600 字符内出现 “A:”（同样的边界规则）。
  - 每次出现：答案 = “Answer:” / “A:” 之后到换行为止的文本（去空白，取前 80 字符）；前文 = 同一文档中模板之前最多 2000 字符。
  - **依据上下文（grounded）：** 答案长度 ≥ 3 个字符、不是选项字母或 yes / no / true / false / 数字以外的短标签，且（忽略大小写）作为子串出现在前文中。
  - 另报：有长前文（≥ 300 字符）的比例；答案为选项 / 是否类的比例。
- **读数：** P(grounded | T_Question) 与 P(grounded | T_Q)，以文档为单位做 bootstrap 95% CI；同样报告小写 “question:” 与 “QUESTION:”。
- **阳性对照：** 人工抽查每种模板各 20 个随机样例，核对 grounded 判定（记录误判数）；判定规则若在抽查中误判 > 20%，本实验不可判定。
- **噪声地板 + MIE：** bootstrap CI；MIE：两个比例之差 ≥ 0.15 且 CI 不重叠。
- **混杂审计：** 只用一个源文件的前缀（Flan 各子任务在文件中混排，写进范围）；grounded 的字符串规则会漏掉改写过的答案（两种模板一视同仁）；不看模型。
- **决策表（跑之前写）：**
  - P(grounded | Question) − P(grounded | Q) ≥ 0.15 → 写成“开关学到的是模板与‘依据上下文作答’在指令数据中的共现，而不是问答语义”，并预测：E48 的线索替换会把开关整体搬到 “Query:” 上（因为改写保留了这种共现）；可设计后续的“共现互换”干预（另开卡）。
  - 差 < 0.15 → 这个解释不成立，“Question:” 的特异性另有原因，如实记录。
- **算力预算：** CPU，约 30 分钟　**实际：**

## 结果（跑完后填写）
- **v1 结果（2026-10-03 12:20）：不可判定（阳性对照失败）。** 人工抽查显示：(1) 解析错误——大量答案在 “Answer:” 的下一行，被当作空答案（“Question:” 的“短标签”比例 96.8% 即由此而来）；(2) 所用分片 part-48 以数学解题与翻译为主，任务分布不具代表性；翻译 / 摘要依赖上下文但答案不是原文子串，“子串 = 依据上下文”的定义不适用。grounded 比例两种模板都 ≈ 0.1%，不作任何解读。

## v2（2026-10-03 12:25 登记，跑之前写；v1 的阳性对照失败后重新设计，不是看结果改读数）
- **数据：** 从 tulu_flan 的 66 个分片中按固定种子抽 10 个，各取前 20 MB（共约 1 亿 token），按 EOS 切文档、按 “\n\n\n” 切样例（Dolma Flan 的样例分隔符，抽查确认）。
- **读数：** 对每个含模板的样例，“模板前的段落” = 样例开头到模板之间的文本。**主读数：依赖上下文 = 段落 ≥ 200 字符**（阅读理解、翻译、摘要、NLI 等都给出段落）；次读数：答案（模板后第一行非空文本，≤ 80 字符）是段落的子串。
- **模板：** “Question: … Answer:”、“Q: … A:”（前一字符不是字母）、小写 “question: … answer:”。
- **判定：** P(依赖上下文 | Question:) − P(依赖上下文 | Q:) ≥ 0.15 且 bootstrap（按文档）CI 不重叠 → 支持“共现”解释；< 0.15 → 不支持。阳性对照：每种模板人工抽查 20 个样例，核对“段落”切分是否正确（误判 > 20% → 不可判定）。
- **v2 结果（2026-10-03 12:40）：不可判定（阳性对照再次失败）。** 数字：依赖上下文的比例 Question: 0.200 [0.195, 0.205]、Q: 0.121 [0.118, 0.124]、question: 0.207（差 0.08 < 0.15）。但人工抽查（每种模板 10 个）显示：Flan 的段落多数出现在模板**之后**（“Question:\n<段落>\n\nDoes it follow that …? Answer:”；“Q: … Article: …”），“模板前 ≥ 200 字符”把大多数依赖上下文的样例判成了不依赖（Question: 10 个中至少 8 个误判）→ 误判 > 20%，按预注册不解读上述数字。
- **止损（memory：stop-loss rule）：** 同一实验两轮修复都在加条件，不做 v3。**状态：PARKED。** 重开条件：E48 显示开关随模板迁移，且论文需要回答“为什么是 Question: 而不是 Q:”时，先人工标注每种模板 100 个样例（是否需要段落作答），用标注集验证自动判定（一致率 ≥ 90%）后再跑全量。
