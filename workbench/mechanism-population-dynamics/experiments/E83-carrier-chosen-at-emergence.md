# E83：主力承担者是不是在任务行为出现时选定一次、之后保持？兄弟是否共享由那一刻决定？（2026-10-10）

- **状态：** RUNNING
- **类型：** CLAIM（在未接触过的数据上检验 E82 的事后观察）
- **对应：** E82（POST-HOC：Pythia-410M / 160M 的主力承担者在 IOI 行为出现前后选定后一直保持；兄弟是否共享，在那一刻就分出来了）；E81（继续训练保留承担者；同初始化兄弟不共享）
- **问题（一句话）：** 在 DataDecide-1B（同初始化、不同语料的兄弟，独立训练栈），IOI 主力承担者是否在任务行为出现时选定后保持到终点？同初始化兄弟在终点是否共享主力，能否由行为出现时是否共享来预测？
- **设置：** DataDecide-1B c4、dolma1_7、dolma1_7-no-flan、dclm-baseline × 3 seed（default、large-aux-2、large-aux-3；均为已核实的初始化）× step ∈ {2500, 5000, 7500, 10000, 17500, 35000, 69369}。测量同 E81（`scripts/e81_carriers.py`，输出 `results/e83/`）。未缓存的检查点测完即删。
- **定义：** 选定点 = 第一个 IOI logit 差 > 1 的检查点；主力 = 该检查点 DLA 最大的头。
- **预测（看 DataDecide 任何中间检查点结果之前写）：**
  - P1（选定后保持）：12 个 run 中 ≥ 9 个，选定点的主力仍是终点 DLA 最大的头，且选定点 top-3 与终点 top-3 至少重合 2 个。
  - P2（兄弟共享由选定时决定）：同 seed 不同语料的 18 对中，“终点是否共享主力”与“选定点是否共享主力”一致的比例 ≥ 80%。
  - 描述（不判定）：兄弟之间注意力角色对应随训练的变化。
- **决策表：**
  - P1、P2 都成立 → A10 第 6 步写“主力承担者在任务行为出现时选定一次并保持；同初始化兄弟是否共享，在那一刻决定”，并以 Pythia（E82）+ DataDecide（E83）两个训练栈为证据。
  - P1 成立、P2 不成立 → 只写“选定后保持”。
  - P1 不成立 → DataDecide 中主力在选定后仍会更换，“选定一次”不写；E82 的观察只作 Pythia 的描述。
  - 若 2500 步时 logit 差已 > 1（选定点早于第一个检查点），P1 / P2 以 2500 步为选定点照常判定，并如实注明分辨率不足。
