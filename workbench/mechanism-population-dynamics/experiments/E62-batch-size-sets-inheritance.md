# E62：batch 大小决定继承强度？——为 DataDecide 的规模趋势找机制（2026-10-03）

- **状态：** RUNNING
- **对应：** C05 第 5 条发现（“继承随规模增强”的原因）
- **动机：**
  - E46b2：在超参数固定的受控训练中，L 尺寸（约大 30 倍）的同 seed c4–papers 继承（0.14 / 0.14）并不高于 S 尺寸（0.19 / 0.24）→ 参数量本身不是原因；
  - E46c：学习率、初始化尺度也不是原因；
  - DataDecide 的 batch 随规模从 32 条序列增到 704 条，继承在 batch 32 时为 0.02–0.11，192–320 时 0.17–0.30，448–704 时 0.27–0.47；Pythia 所有尺寸 batch 1024，70M 时继承已有 0.59；
  - E46 B：S 尺寸（batch 64）只换数据顺序就部分改变分工（0.53–0.86，重跑 0.91–1.00）；
  - Forgetting-Time（2026）：batch 越小，训练越“忘记”初始化。
- **假说：** 关键期内的梯度噪声决定对称性由谁打破——batch 大，噪声小，对称性按 seed 与数据的低阶统计（跨语料相似）破缺；batch 小，具体的早期批次决定胜者。
- **设置（`scripts/e46_train.py --bs`，S 尺寸，学习率与调度不变）：**
  - batch 512（8 倍）与 batch 16（1/4），各 3 个 seed × {c4, papers}，外加只换顺序的对照（seed 1 × c4 × order 101）；
  - 只训练到第 2000 步（同一学习率调度的前 2000 步；E46 显示分工在第 250 步锁定，第 2000 步与终点相似 0.85–0.94），与已有 batch 64 run 的第 2000 步测量比较。
- **读数：** 第 2000 步的层内相似度：同 seed c4–papers（继承）、同 seed 同语料只换顺序（顺序敏感度）、不同 seed（基线），按 batch 16 / 64 / 512 排列。
- **怎么读：** 继承随 batch 单调上升、顺序敏感度随 batch 下降 → 写进第 5 条发现：“规模趋势来自随规模增大的 batch：关键期内梯度噪声越小，seed 越能决定槽位”；无关 → 规模趋势的原因留作开放问题，写成 DataDecide 缩放配方的整体性质。
- **算力：** 14 个 run，batch 512 的每个约为一个标准 S run 的 1.6 倍，batch 16 的很小；共卡运行。
