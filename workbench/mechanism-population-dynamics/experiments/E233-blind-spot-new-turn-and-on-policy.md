# E233：“新一轮”不靠不自然格式还成立吗？模型自己真的犯的错（on-policy）是不是更看不见？（2026-11-25）

- **状态：** PLANNED
- **类型：** PILOT（[提案](../TOPIC_PROPOSAL.md) 第 8 节检验 2；不推进主张）
- **对应：** Q1。前置 E229–E231。用户 11-25：“跑，多卡并行”。

## 问题

1. **S 的格式：** E229–E231 的 S（同一说话人新一轮）在 chat 里是两条连续的 assistant 消息，中间没有用户话，这对指令模型是不常见的格式。本卡加一个变体 **U**：错误那条消息结束后，另一方说一句中性的 “OK.”，再由模型开始新一轮。若 U 与 S 一样“看得见”，Q1 的结论（盲点主要是接着写）不依赖不自然格式。
2. **on-policy：** 注入的错误不是模型自己会写出的文字。Khullar 2603.04582 发现，监视器的“上一轮放水”只在评自己生成的内容（on-policy）时出现。本卡用模型自己在干净问法下真实答错 / 答对的回答作为“给出的答案”，在 C / S / O 下检验：on-policy 时 S 是否变得像 C 一样看不见。

## 设置

- **U 变体：** 模型 OLMo-3-7B base（F1）、Instruct-SFT / Instruct-DPO / Instruct（F2，SFT 与 Instruct 另跑 F1）；数据 SCLI5 + GSM8K-SC 300，错答案版与正确答案版；检查语 N 与 V；只跑 U 这一种放法（C / S / O 复用 E229–E231；DPO 是新模型，C / S / O 一并跑）。
  - F1：`Alice: {问题}\n\nBob: {给出的答案}\n\nAlice: OK.\n\nBob: {检查语}`
  - F2：user 问题 → assistant 给出的答案 → user “OK.” → assistant（以检查语开头）
- **on-policy：** 模型 base（F1）与最终 Instruct（F2）。
  1. 在 GSM8K 测试集 1313 题上跑干净问法（greedy，最多 512 token）；用 E229 的评判判断答对 / 答错。
  2. 答错的题：模型自己的完整回答作为“错答案版”；答对的题：模型自己的完整回答作为“正确答案版”。
  3. 每题跑 C / S / O × 检查语 N 与 V，三选一结论评判 + 认可规则（同 E230）。
- **对照：** 同一模型在注入错误（off-policy）上的结果（E230 / E231）。
- **命令：** `scripts/e229_blind_spot.py`（加 `--conds clean` 与通用题目文件）、`scripts/e230_check_frame.py`（加 `--conds`、U 放法）。

## 读数与判定

- 命中率 H、误报率 F、H − F（同 E231）；U 与 S、C、O 比较；on-policy 与 off-policy 的 (H − F)_S − (H − F)_C、(H − F)_O − (H − F)_C 比较。
- on-policy 的错答案题与正确答案题不是同一批题（不配对），H − F 的区间用分组 bootstrap。

## 阳性对照与噪声

- U 变体：O 的 H − F 应与 E231 一致（同模型同数据，直接复用）。
- on-policy：O 条件下对自己错答案的否定率应明显高于 0（否则模型对这些题根本不会，比较无意义）；低于 0.2 时，该模型的 on-policy 比较不解释。
- 噪声同前；Instruct 的 on-policy 错题预计只有 100–200 题，区间会更宽。

## 混杂审计

- on-policy 错题是模型不会的题：知识不足同样压低三种放法，主比较是放法之间的差。
- on-policy 的正确答案版与错答案版题目不同：H 与 F 来自不同题目，只作参考；主比较是同一批错题内三种放法的差。
- “OK.” 可能被理解为“确认答案对”：同时出现在错答案版与正确答案版，用 H − F 抵消。

**按决策表执行：**
- **纯文本格式（F1）：** U 与 S 接近（差 ≤ 0.06），都远高于 C → 在纯文本对话里，Q1 的结论（新一轮就能看见，盲点主要是接着写）不依赖“连续两条同一说话人的消息”这种格式。
- **chat 格式（F2）：** 多数格子里 U 远低于 S，SCLI5 上甚至低于 C → 按决策表，chat 里先前 S 的“看得见”**依赖不自然的格式**，Q1 在 chat 里需改写。
- **原因（看原文）：** 用户说 “OK.” 后，Instruct 不加检查语时几乎都回 “Great! If you have any more questions…”，把对话当作已被用户接受、收尾；加检查语后常写 “I will use a calculator / do a web search to verify”，然后不下结论。所以 chat 里 U 的低值主要来自“对话已收尾”和“不下结论”，而不是看了以后认可错答案（U 的误报率也接近 0）。GSM8K + V 例外（U ≈ S）。
- **含义：** 在正常的 chat 多轮对话里，只要用户对答案表示了接受，模型就不会回头检查自己的上一轮。“换一轮就能纠正”只在模型被重新给予发言、且没有接受信号时成立。

**on-policy（模型自己在 GSM8K 上真实写出的回答作为“给出的答案”）：H − F**
- base（F1，答错 300 / 答对 300）：V 下 C 0.04 / S 0.16 / O 0.29；S − C +0.13 [.09,.19]，O − C +0.25 [.20,.31]。无检查语时三种放法都几乎不否定（H ≤ 0.06）。
- Instruct（F2，答错 126 / 答对 300）：O 对自己真实错答案的否定率只有 0.10（V），低于 0.2 → 按决策表，知识不足，不解释。
- **按决策表：** base 的 on-policy S − C = 0.13，正好落在“S 变得接近 C（< 0.15）”的边界上，而 off-policy 时为 0.21–0.22。这只能算 on-policy 时新一轮的帮助变小的弱迹象，不能下结论。
