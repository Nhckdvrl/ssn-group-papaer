# E08 — 现成数据动作在完整开发集上是否仍有增益（2026-10-02）

- **状态：** DONE（完整开发集评估和独立 base 复跑已完成；不新增学生训练）
- **类型：** EXPLORE/REPRO measurement；对应 P02/P03、I02，不能单凭本卡升级 C03。
- **对应：** P02/P03/P05、I02、C03（仍 L0）。
- **问题：** E04 错误追随检索与 E05 分布匹配在 280 道小留出上只有几题差，扩大到未作为反馈的 1668 道完整开发题后，动作排序是否仍可区分？
- **设置：** 复用已冻结的 Gemma2-2B-IT parent、E00 静态 seed17/29/43、E04 retrieval 相同 seeds、E05 matched seed17 的 LoRA adapter；不重训、不改配方。所有模型在完全相同的 dev1740 文件上统一 zero-shot＋显式格式、greedy/max350、官方 scorer；报告 dev 减去 72 条 E04 反馈 smoke 的 heldout1668 为主，原 heldout280 只看和旧读数是否一致。每个评估保存逐题预测/哈希/摘要与运行成本。
- **读数：** 同训练 seed 的 retrieval－static 逐题配对准确率、matched17－retrieval17、各动作相对 base 的留出收益；每对报告题级 CI 和训练 seed 范围，CI 不当作跨学生证据。数据行动间 120 样本/3 epoch/optimizer reset 相同，E04 检索每 epoch 监督 token 比静态多 16.3%，E05 matched 比检索多 7.7%，不能归因于“错误信息”本身。
- **阳性对照：** 1668 全部题的 ID/题面哈希与冻结 dev 一致，已有静态 seed 在 full dev 上比 base 有真实学习信号；评分器复算与摘要一致。
- **噪声地板 + MIE：** 352 子集与完整批次在共有题上已出现少数正确性翻转；E00 同完整输入复跑评估中。动作差异需要三 seed 同向且至少约 2pp（约 33/1668 题），并明显超过推理复跑变化，才值得投入新训练分支。若不足，优先探索更不同的动作/learner state 或更高质量 teacher，而不是继续精修 TF-IDF。
- **混杂审计：** 题/评分器/提示/父模型/optimizer/训练 seed 已控制；teacher/API 皆无。动作数据的题型/长度/token/难度仍不同，matched 只有 seed17 且字符非 token 匹配，故此卡是优先级筛选，不是机制证明。完整 dev 来自 MATH train 而非独立测试，不用于最终论文 claim。
- **决策表（跑之前写）：** retrieval 三 seed 稳定超过 static ≥2pp 且 matched 追不上 → 优先测试哪种反馈信息/难度结构决定收益，并在新 learner state 中复验；retrieval 与 matched 接近或行动排序受 seed/评测批次支配 → 不继续围绕词面检索设计方法，转向更丰富动作或 learner state；静态强于其余或差异低于噪声 → 将强简单配方成功作为事实，研究为何复杂动作不值成本；任何 eval 不完整/不一致 → 修测量，不解释科学差异。
- **算力预算：** 追加 4 次完整开发集单卡评测；warm cache 推理约 1–2 分钟/次，但 vLLM 初始化可能再加数分钟，总计预计 ≤0.5 GPU·时；新增学生训练/CPU 选择/API = 0。**实际：** 协议修订后 9 次完整评测累计 **2147.3 GPU·秒 = 0.596 Blackwell GPU·时**；学生训练 0，API 0，CPU 离线分析另计。完整复跑和统一 eager 重评使实际次数超过本段原预算，但低于修订后的 1.2 GPU·时上限。

## 2026-10-02 推理协议修订（E08 尚未启动）

E00 同一完整 dev1740 的 base 独立复跑发生 50 题正确性翻转，达到 2.87%；因此本卡原先“复用 E06 base/静态结果、只加 4 次评测”的读数不够精确。先按 E00 补充做关闭 vLLM V1 multiprocessing 的同输入双跑 gate。若逐题预测完全一致，所有八个动作（base、静态三 seed、检索三 seed、匹配 seed17）都在这一冻结配置下重评完整 dev，**不混用旧模式结果**；额外约 4 次完整评测，预计总 ≤1.2 GPU·时，实际单列。若双跑仍不一致，则将 E08 保持 PLANNED，先校准推理噪声，不做行动排序。这个修订由真实测量失稳触发，不改变输入题、输出格式、数据动作或决策阈值。

**冻结执行协议（首个 gate 失败、第二个 gate 成功之后，E08 评测前）：** 单关 V1 multiprocessing 的 dev352 双跑仍翻转 8 题；再加 `enforce_eager=True` 后两次独立预测文件哈希完全相同、69/352 对 69/352。故 E08 全八组均按 `VLLM_ENABLE_V1_MULTIPROCESSING=0`＋`--enforce-eager`、同一台 fvcrc20 的 RTX PRO 6000 Blackwell、同一 dev1740 输入评测。为了避免 352 成功但 1740 批次不稳，base 在完整批次独立复跑一次；若该复跑有 ≥1% 题对错翻转，依旧只报告大效应并将小差异降级。保留首次/复跑成本和原始文件；评测只改变后端数值执行模式，学生/数据/严格 scorer 不变。

**反馈状态一致性读数（评测前补记）：** E04 检索动作由旧默认 vLLM 的 `base_format_smoke.jsonl` 中 60 道错误生成；该文件 SHA256 与 E04 manifest 的 `feedback_sha256` 一致。E08 的 base 完整 dev eager 输出会覆盖同一 72 道 smoke，因此离线报告旧错误集与 eager 错误集的交并及 Jaccard。若有明显差异，E04 冻结检索只能算“用旧测量挑出的一个真实标注动作”，不能把它的劣势外推为反馈信息本身无效；无需为这个诊断重训或加额外 GPU 运行。

**近重复替代解释的低成本审计（E08 结果前登记）：** 对静态/检索/匹配各 120 条训练题和主评估 heldout1668，用同一字符 3–5 gram TF-IDF 拟合联合题面，记录每条训练题对 heldout 的最大 cosine 相似度的中位数、90 分位、≥0.8 比例及对应最高相似例。若检索显著胜出且 near-duplicate 比例也大，则先将“目标模板接近”列为替代解释；若没有，不把低字符相似度解释为语义去重完成。此项不改训练/评估输入，只用 CPU 与已冻结数据。

**上述 CPU 审计结果（GPU 评测尚在运行）：** 静态/检索/匹配的每训练题最大 heldout 词面相似度中位数为 **0.356/0.398/0.320**，90 分位 **0.646/0.676/0.577**，≥0.8 的训练题分别 **7/5/3**。检索组整体更接近留出题，但最高相似度尾部并不比静态组更多；这些读数既不能排除语义模板重合，也不能预判哪种行动训练收益高。完整 ID/哈希见 [`results/E08_near_duplicate_audit.json`](../results/E08_near_duplicate_audit.json)。

## 结果（评测后追加）

- **主读数：** 排除 72 道反馈 smoke 后，base **327/1668**；静态 seed17/29/43 为 **397/388/394**，比 base 高 **+70/+61/+67** 题，即 **+4.20/+3.66/+4.02pp**。逐题 paired bootstrap 95% 区间分别为 **[+1.98,+6.29]、[+1.38,+5.76]、[+1.74,+6.00]pp**；这是同一批题的区间，不是跨学生/任务外推。
- **动作排名：** 错误检索 seed17/29/43 为 **410/407/416**，各比同 seed 静态多 **+13/+19/+22** 题（**+0.78/+1.14/+1.32pp**）；逐题区间分别 **[−0.90,+2.46]、[−0.48,+2.82]、[−0.36,+3.00]pp**。三 seed 同向，但全部低于预写的约 2pp 追进门槛，且 E04 检索每 epoch 监督 token 比静态多 16.3%。E05 匹配 seed17 为 **396/1668**，相对检索 seed17 **−14** 题、相对静态 **−1** 题；它只匹配级别/题型/字符长度且只跑一个训练 seed，故不把这一差异单独解释成“反馈信息因果有效”。原小 heldout280 的静态相对 base 为 **+2/+5/−1** 题，检索相对静态 **+8/+1/+9** 题，说明该小片对总体静态收益缺乏代表性。
- **训练配方复核：** 原运行 `run.json` 均记录 120 条、三 epoch/24 optimizer step、同父 revision 和 optimizer reset。静态/检索/匹配每 epoch 实际监督 token 为 **24,166/28,105/30,274**，各有 **3 条被 1024-token cutoff 截断**；这些差异没有在 E08 重训控制，所以只能比较已存在的行动整体，不能解释成单位 token、反馈或单一样本性质的因果优势。
- **评估复现与执行失败：** 完整 base 在同一 fvcrc20 GPU0、同一 eager 配置独立复跑，两个预测 JSONL 的 SHA256 **完全相同**，1740 题文本改变 **0**、正确性翻转 **0**，见 [`results/E08_eager_full_repeat_audit.json`](../results/E08_eager_full_repeat_audit.json)。`retrieval_seed43` 与 `matched_seed17` 两个远端 bash 在 Python 已写完完整 1740 题及摘要之后以 **126** 退出，报脚本对自身日志 `Permission denied`；这发生在我修改仍被 bash 读取的 `e08_eval.sh` 期间。保留日志、失败码与原始结果；逐题 ID/题面哈希、完整计数、摘要分数和独立分析全部通过，故使用已完成的 Python 评测读数，但不把这两次运行伪称端到端成功。此后不再改正在运行的脚本。
- **结果文件：** [`results/E08_full_dev_action_analysis.json`](../results/E08_full_dev_action_analysis.json)、[`results/E08_eager_full_repeat_audit.json`](../results/E08_eager_full_repeat_audit.json)；原始预测、摘要和日志在外部 `runs/e08/`，全部保留。词面近重复审计和旧/新反馈重合度见本卡上文。
- **按预写决策表：** E04 词面错误检索未达到投入新训练分支的门槛，停止围绕 TF-IDF 细化。可信的新事实是小预算真实金标静态配方在完整开发集有稳定收益，动态/错误检索在这套单轮设置中的边际效用小且成本混杂。它不能否定生成式反馈、其他学习状态或真正强的 gradient/online selector；下一建设动作优先补强生成 teacher 的资格或选择另一类**更不同**且文献认可的数据动作。C01–C04 保持 L0，不把 E08 单独写成论文现象。

**POST-HOC 诊断（未预注册，不升级主张）：** 完整 heldout1668 按原 MATH 类型等量分层后，Geometry 231 题上的 base 为 42，静态三 seed **33/26/31**，检索 **41/40/42**；Number Theory 237 题的静态 **46/47/41**，检索 **51/52/59**。其余类型有正有负，均值的 +13/+19/+22 主要由 Geometry/Number Theory 的差异抵消其他类损失。检索训练集 Geometry 仅 9/120、静态 15/120，故“几何题训练占比更多”无法直接解释这一项；但题目难度、答案风格、监督 token、题型内模板与批次抽样都未控制。静态输出的 `\\boxed` 数量在 Geometry 反而多于 base，故这项下降不只是没有遵守显式格式。该分层是**找下一高信息量实验的线索**，不能据此宣称新的几何课程 failure 或立刻为它造 router。
