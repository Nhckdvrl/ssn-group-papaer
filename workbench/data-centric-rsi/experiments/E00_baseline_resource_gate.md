# E00 — 本地强基线与资源审计

- 状态：RUNNING（本地单卡适配；workbench 仍为 PROPOSED）
- 对应：D1/D2/D4 建设；LP02/LP03；不预设支持 C01–C04。
- 目的：建立一套真实数据→学生训练→外部评估闭环，确认独立训练分支是否经济；不是先验证一个自造现象。
- 阳性对照：官方/可信训练材料相对不更新学生产生可测改善；同输入固定 seed 可重现预测与得分；已知错误/无效材料被 verifier 正确识别。
- 噪声地板 + MIE：同一固定数据与学生至少 2–3 次独立训练；记录任务级评估不确定性。MIE 按改善任务表现/选择数据动作是否值得其成本定义，在看 I# 效果前冻结，不机械套 2×noise。
- 决策表（跑之前写）：基线与测量都工作→进入 E01 的小矩阵；数据/环境故障→修复并记录适配差异；可信数据也无改善→检查学习预算/优化器/评估，不解释成 RSI 无效；原框架确实不可修复→换同领域成熟 substrate，保留失败资产。

## 入口与范围

优先 DataEnvGym math 的官方 Gemma2-2B 设定。先确认数据替代映射、模型许可证、版本和运行路径；不同时下载全部 VQA/code 资产。若节点不适配，先记录原因，再选择已支持的同类学生，结果明确标 modified reproduction。

本卡不授权跨节点梯度训练、不启动 SOAR 全配置，也不替用户购买云服务。GPU 执行需服从全库 ACTIVE 调度及单位资源许可。

## 必须测量

下载与缓存量、训练/生成/评估 wall-clock、GPU/CPU 占用、显存、每条候选真实成本、不可解析样本、执行超时、有效监督比例。锁定输入/数据/父状态 hash 与 train/dev/private 边界。

分别跑不更新、强固定数据、一个官方反馈策略。先把 baseline 调到可信水平，不给我们的方法更多 token/teacher 预算，也不禁止修复 baseline 的真实工程问题。

## 2026-10-02 扩大开发测量的跑前补充（29/43 仍在训练，尚未看到其读数）

72 题每格仅 2 题，只够 smoke；主测量预先固定 train 开发集中每个非空 `(level,type)` 格的前 10 题。实际有些格不足 10 题，因此生成后为 **352 题**（跑前原估计 360，选择规则未改）。用已经冻结的**显式格式指令**、同一官方 scorer 和贪心解码，评估 base 与 17/29/43 三个静态种子。按题配对报告每个 seed 的收益及 seed 范围；保留 72 题 smoke 全部原始/格式读数。若三种子的收益与格式修复后的 72 题方向不一致，暂停围绕静态收益讲故事，检查训练/评测分布和答案格式。若方向一致，才将其作为后续反馈策略比较的成本/噪声地板，仍不升级 I02/C03。

这批题是 dev 内子集，和 120 条静态训练题按规范化题面 hash 隔离；test 不用于选配方。其结果只能检验单一小学生、单一数据集、单一训练预算的测量闭环。评估成本预估约 5 分钟/模型，记录实测；不依据后验结果改题目或生成长度。

## 2026-10-02 阶段结果（E00 尚未完成官方反馈策略）

数据 manifest：MATH train/test 为 7500/5000；冻结 dev 1740、其中分层前 10 题共 352、smoke 72，静态训练 120，静态题面对 dev/test 的规范化 hash 均零重合。替代数据与原版 MATH 的逐题对应尚未核对，原论文数值不可直接比较。

72 题原版严格 scorer：base 6/72，静态 seed17 21/72；但 base 仅 17/72 输出 `\\boxed`。一句最终答案格式指令把 base 提到 12/72、静态 seed17 为 19/72，因此原口径 +20.8pp 至少部分混入输出协议差异。这个指令是看到首次读数之后的诊断，不作为预注册方法证据；后续开发测量统一固定它。

352 题、显式格式指令、同一贪心解码：base **45/352 = 12.78%**；静态 seed17/29/43 分别 **66/352 = 18.75%**、**74/352 = 21.02%**、**75/352 = 21.31%**。相对 base 为 +5.97/+8.24/+8.52pp；逐题配对 bootstrap 95% 区间分别约 [1.70,10.23]、[3.98,12.78]、[4.26,13.07]pp。均是同一 352 题上的 item 区间，不能当跨任务/跨 seed CI。训练 seed 17/29/43 的实际 wall 分别 234.4/112.8/249.0s，峰值 allocated 显存约 9.39GB；每个训练 24 optimizer step、3 epoch、同 120 条、每 epoch 约 24.2k 监督 token。GPU 型号/远程负载不同，wall 差异不能解释为方法加速。

主结果文件 [`results/E00_dev_analysis.json`](../results/E00_dev_analysis.json)；原始训练/评估输出及失败日志在 `ASSETS.md` 指定外部缓存。**判断：** 强静态自然 MATH 训练确实可学，E00 通过最低资源/学习信号 gate；答案格式是严肃测量混杂。仍未运行官方 GPT-4o 生成/反馈闭环，不能宣布 DataEnvGym 原版复现或任何 I## 成立。

## 2026-10-02 源码提示协议校对（看到 E04/E05 读数之后；POST-HOC）

复核固定源码 `examples/math/open_ended.py` 与 `trainable_predictors/math/local_llm.py` 后发现：官方示例给 base 使用 `prepare_few_shot_prompt`，LoRA 加载后因 `prompt_formatter` 未设置而改用题目本身；`always_apply_chat_template=True` 两者均应用。我们此前的 352 题比较让 base 与 LoRA 都使用 few-shot，且额外加一句格式提示，是一致评测条件下的数据动作比较，但**不是官方源码提示协议**。另外论文 App B.1.2 写 LoRA rank16/alpha32/dropout0.05，而仓库示例 LLaMA-Factory 配置未覆写这些项，vendor 默认 rank8/alpha16/dropout0；示例还设 `val_size=0.1`，本地 Trainer 用全部 120 题且按论文 LoRA 参数。两个来源不能悄悄合并为“精确复现”。

为审计而追加、不得倒过来挑对自己有利口径：在固定的 352 题、同一 scorer、temperature0/max350 下，对 base、静态三 seed、检索三 seed、匹配一 seed 都评估**零样例＋显式格式**，观察数据动作排序对 few-shot 是否敏感；另评估 base 的**few-shot＋无额外格式**和静态三 seed 的**零样例＋无额外格式**，作为官方源码评测提示的近似读数。逐字核对发现源码的 `apply_chat_template(..., tokenize=False)` 没有 `add_generation_prompt=True`，而我们此前加了模型开头；源码近似读数因此也省略该开头，不能把两者混列。前者对数据策略公平，但仍是我们改造的 SFT；后者更贴源码提示，但训练 recipe/数据源/teacher/轮数仍非官方。若排序反转，就将 E04/E05 结论降为提示依赖的局部现象；若排序同向，也不宣称论文结果复现。预计最多 12 次单卡评估，合计 ≤0.4 GPU·时；全部原始预测与配置保留。

**追加审计结果。** 统一 zero-shot＋显式格式时，base 为 **67/352**，静态 seed17/29/43 为 **73/80/71**，只多 6/13/4 题；held-out280 为 base **54**、静态 **55/60/53**。这与先前统一 few-shot＋格式下的 base45、静态66/74/75 差异很大，说明“120 条静态数据稳定给出 6–9pp 能力收益”的原说法依赖提示协议，须降级为局部读数。参见 [`results/E00_E04_E05_zero_format_analysis.json`](../results/E00_E04_E05_zero_format_analysis.json)。

接近固定源码提示的诊断口径（base few-shot、LoRA zero-shot，均无附加格式且省略 generation prefix）给出 base **24/352**、静态 **58/53/52**。由于训练前后评测 prompt 不一致，表面 +28–34 题**不是训练效用的因果估计**，不能作为强基线胜出的证据；原始预测及配对表见 [`results/E00_source_prompt_analysis.json`](../results/E00_source_prompt_analysis.json)。因此 E00 已证实可运行的单卡训练/评估闭环和成本，但“强静态训练有稳定实际收益”仍需更合适的统一协议/更高分辨率设置，官方生成反馈分支仍未完成。此次审计是看到 E04/E05 后的 POST-HOC 校对，不能拿其中最优数字做预注册结果。
