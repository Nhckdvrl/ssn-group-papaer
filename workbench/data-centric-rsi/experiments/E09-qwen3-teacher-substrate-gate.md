# E09 — 换一套真正能产出可训练数学题的本地教师（2026-10-02）

- **状态：** DONE（质量 gate 未过；原始输出与事后诊断均保留）
- **类型：** REPRO/EXPLORE substrate gate；不升级 C##，也不把教师质量当论文 idea。
- **对应：** P04、E06/E07；I02 的生成数据动作可行性。
- **问题：** E06/E07 的 Qwen2.5-32B 生成题存在可证实的错解；仓库已缓存的、官方声明数学能力更强且支持 thinking 的 Qwen3-32B，能否使 DataEnvGym 风格的**新题＋题解**达到值得训练学生的最低质量？如果不能，继续堆同一生成路线没有信息增益。
- **区分的解释：** 旧 gate 失败主要来自教师能力/推理不足，或来自这个开放式数学出题任务与答案验证本身的困难。此实验只判断替代 substrate 是否可用，不声称隔离教师能力、thinking、解码的单独因果效应。
- **设置：** 固定 Qwen3-32B 本地 revision `9216db5781bf21249d130ec9da846c4624c16137`，DataEnvGym pinned MATH 模板和 E07 明示自洽/勿复制补句，E07 的前 10 个采样索引、no-state/with-state 相同 6 个输入例和旧 72 smoke 反馈，共 20 次调用；每次要求 1 个 MathDataSpec。按[官方模型卡](https://huggingface.co/Qwen/Qwen3-32B)使用 `enable_thinking=True`、temperature 0.6/top-p 0.95/top-k 20，最多 3072 输出 token；允许 `<think>...</think>` 后的最终 JSON，预先只接受裸 JSON array 或完整一个 `json` 代码围栏，不做事后修补。思考模式与 JSON guided decoding 不同时启用，避免约束器抹掉推理。单张 fvcrc10 A100 80GB，已有 venv；所有 prompts/raw/失败/版本/哈希与 GPU 时间存外部 `runs/e09/`，不覆盖 E06/E07。
- **读数：** 每臂结构解析、必填字段、精确 dev/test 重合、臂内重复和输入例精确复制；对全部 20 道可解析题逐题核查问题自洽、答案与推理（可证明错解、题设矛盾、缺图均判不可用），用 SymPy/穷举能核的给出独立核对，不能核的明确列为未确认。旧 E07 相同索引：20 道中至少 4 道可证明错解、另 1 道矛盾。总 prompt/output token、GPU/CPU/wall/API 单列。
- **阳性对照：** 官方 schema parser、已知 E07 错例和 prompt hash/输入索引核对；人工算术检查须能再次找出旧 gate 的 4 个确定错误。若模型根本未生成完整 final JSON，则记为 substrate 失败，不用少数漂亮题代替全体。
- **噪声地板 + MIE：** 10/arm 只是工程资格筛选，不给质量率置信区间或跨任务主张。至少两臂各 9/10 结构＋非复制＋零 dev/test 重合，且 20 道中≥18 道经核算可训练、零系统性题型错误，才考虑更大生成池和真实学生训练；否则不扩同一 teacher prompt。这个门槛比 E07 的明显错解率大幅改善，仍不足以宣称高保真教师。
- **混杂审计：** 输入例、DataEnvGym 模板、索引、去污染和质量流程与 E07 对齐；模型、思考模式、采样、JSON 解码和输出长度一起变化，所以这里只能做资格判断。开放式题目难度、题型、语义近重复与旧反馈状态仍未控制；即使过 gate，后续学生训练需冻结有效样本选择规则并与真实标注强静态配方同 token/训练预算比较。
- **决策表（跑之前写）：** 两臂都过门槛 → 冻结 Qwen3 配方，按新 eager base 反馈重新生成足量样本，再做真实训练效用对照；任一臂没过或证明错误≥3/20 → 停止本次本地出题路线，不迭代 prompt，优先转向强数据选择或有外部验证的任务；边缘（例如 2 道错） → 不训练，先判断能否用预先存在的外部 verifier 挡住错误，且成本是否优于直接真实金标，否则转向。
- **算力预算：** 20 次单卡 32B thinking 生成，预计≤0.6 A100·时（冷载和长思考均计入）；学生训练 0，API 0。**实际：** 1757.8 秒 = **0.488 A100·时**（fvcrc10 GPU0；其中权重读取/装载 644.4 秒），输入 16,127、输出 39,398 token；API 0，学生训练 0。CPU 离线审计独立完成，未单独计量 CPU·时。

## 结果（运行后追加）

- **预写严格 gate：** 原始脚本要求 `<think>` 后为一个 JSON 数组，故 no-state **1/10**、with-state **0/10** 结构通过。19 个失败中，大多数是模型输出单个 JSON 对象而非数组，另有 **3/20** 在 3072 token 处截断思考。不能把 1/20 误写为“只有一题有数学内容”；也不能在看到结果后把对象解析的数值冒充预注册通过率。原始 prompt/raw/manifest 不可变，SHA 在外部 `runs/e09/manifest.json`，原始 raw SHA 为 `9a232e1e7c61d6d7c26fd757339b23e538f0eaeba26eed222e52e4355a7df06d`，生成脚本 SHA `bd3e1e87e3d74ee5729ab0f1dde7f5fe6876c63a541cc86e3f377710f70f6507`。
- **POST-HOC 对象解析诊断：** 若仅把**完整单对象**也当作规范数据（不修文本、不取半段），两臂各 **8/10** 可由官方 `MathDataSpec` 解析；剩余 4 次为 3 个未闭合思考和 1 个 LaTeX `\circ` 非法 JSON 转义。16 个可解析题对输入例、train 池、dev、private-test 题面 hash、同臂和跨臂重复均为 **0**。这仍低于两臂各 9/10 的门槛。
- **独立数学核查：** 对 16 个诊断可解析题逐条审阅题目、答案和题解，并用 SymPy/穷举核对适用的数值题，**13/16** 可训练；no-state #5 把正确解集 `{0} ∪ [1,7]` 写成 `[0,7]`（`x=1/2` 反例），#6 把满足整除条件的最小数 **51** 写成 **99**，#8 虽然最小值 `−45/11` 正确，却把 Hessian 行列式 **44** 写成 **11**。另一道 #3 的几何答案可核为 `4√2`，但原始 JSON 含非法 `\circ`，不计可训练；其余三次截断无最终题解。因此按全部 20 次调用计，严格正确且可解析仅 **13/20**（若宽容 #8 的错误推理也仅 14/20），低于预写 **18/20**。逐条 verdict、独立计算、污染审计见 [`results/E09_teacher_gate_audit.json`](../results/E09_teacher_gate_audit.json)，复核脚本见 [`scripts/e09_audit.py`](../scripts/e09_audit.py)。
- **按跑前决策表：** 原格式门槛未过，宽容单对象的诊断也未达到两臂各 9/10 或整体 18/20。因此不扩本地 Qwen3 生成池、不用这批题训练学生、不对 no-state/with-state 的训练价值下判断。E09 只说明当前本地教师＋模板＋thinking/采样/输出上限的组合尚不具备可信训练数据资格；与 DataEnvGym 原论文 GPT-4o 结果无关。C01–C04 仍 L0。下一投入转向有可靠监督/外部验证的动作空间，在同一强静态基线上测真实状态×动作效用；先明确动作、训练 token、父 checkpoint 和 optimizer 继承，再开卡运行。
