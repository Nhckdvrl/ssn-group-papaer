- **状态：** E17-0 RUNNING（人 11-29 批准离线矩阵）；E17-1、E17-2 PLANNED，不批预算。
- **类型：** PILOT（E17-0 只推理和执行，不训练）

- **问题：** 学习者用自己产生的测试训练自己时，“测试出自自己”这一点，在测试总体质量之外，是帮助还是妨碍学习？学习之后，学习者为自己产生的测试，是更能还是更不能纠正它新的错误？

## E17-0 设置（跑之前写定）

- **题目：** LeetCodeDataset 测试划分（`newfacade/LeetCodeDataset`，228 题，2024-07 至 2025-03，Easy 48、Medium 101、Hard 79），每题约 100 个关键字参数形式的隐藏测试和一个参考解。
  - 先在我们的执行环境里，用参考解跑一遍全部隐藏测试，不通过的题剔除。
  - 选它是因为：函数级，题在多数模型发布之后，7B 级解题率预计在中段，每个模型都有足够多的自身错误。
  - 剩下的污染：TCS 用 TACO 训练、CURE 用 CodeContests 等训练，与 LeetCode 2024 下半年以后的题重叠应很少。
- **模型（6 个）：**
  - 同底座、不同经历的两对：`deepseek-ai/DeepSeek-R1-Distill-Qwen-7B` 与 `XiaoBanni/TCS-7B`；`Qwen/Qwen2.5-7B-Instruct` 与 `Gen-Verse/ReasonFlux-Coder-7B`（CURE）。
  - 同家族的代码模型：`Qwen/Qwen2.5-Coder-7B-Instruct`。
  - 跨家族：`ByteDance-Seed/Seed-Coder-8B-Instruct`。
- **生成**（vLLM，只设引擎级种子；先在 20 题上数“不同输出数”）：
  - 解题：每题 8 个样本，T = 0.8、top-p 0.95。统一提示：先推理，最后用一个 ```python 代码块给出完整的 `class Solution`。
  - 测试，只给题意：每题 4 个样本，每个样本要求 8 个测试，格式与题面例子相同（`n = 5, queries = [[2,4]]`），连同期望输出放在 ```json 列表里；T = 0.8。
  - 测试，看了自己的一个错误程序（阳性对照，见下）：每个模型在有自身错误的题里取至多 60 题，每题 1 个样本。
  - 上限 16,384 token，截断记为未作答并报告比例。
- **判据：**
  - 程序对错：通过全部隐藏测试为对，否则为错；运行失败、超时也算错。
  - 多实现面板：参考解，加上至多 8 个去重后的“全部通过”模型程序。
  - 测试输入合法：参考解在时限内正常返回，且面板全部一致。不一致的输入视为规格没定义，丢弃并报告比例（arXiv 2608.19626 的教训）。
  - 两种制度：
    - 可信输出：期望输出用参考解的输出；
    - 模型输出：用模型自己写的期望输出，格式解析失败则丢弃该条。
  - 比较规则与数据集一致：结构相等，浮点按 1e-6 容差。
- **执行矩阵：** 每题“全部程序 × 全部测试”的输出，保存为紧凑文件，大文件不进 git。

- **运行记录（2026-11-29）：**
  - 题目准备（`scripts/e17_prepare.py`）：228 题中保留 223 题（Easy 48、Medium 98、Hard 77），每题中位 103 个隐藏测试。剔除 1 题（树结构输入）、4 题（可复现的隐藏测试少于 20 个）。

- **短跑（Qwen2.5-7B-Instruct，前 20 题，2026-11-29）与据此在看正式数据之前做的修改：**
  - 解题：20 题平均 0.14（1 题 8/8 全对，13 题 0/8）。失败程序多数确实错了；但个别题的隐藏测试含违反题目约束的输入（snake-in-matrix：题面保证不出界，部分测试出界）。所以加一个稳健性检查：去掉约束里写“输入保证……”（generated such that / guaranteed）的题再算一遍。
  - 测试解析：模型常把输入写成 JSON 对象而不是字符串，或在 JSON 里写 Python 表达式。解析改为两种都接受，并逐行抢救单条；空解析从 17/80 降到 4/80（3 条是截断）。只看格式，不看分数。
  - **单位改成单次生成。** 4 次生成合并后，可信输出制度下 Qwen 漏掉自己的错误程序约 1%，读数到顶。改为单次生成（约 8 条测试，相当于 RL 的一次奖励抽样）；另报逐条测试的读数。
  - **主读数限定在“看起来对”的错误程序**（通过 ≥ 70% 隐藏测试）。单次生成对全部错误程序的漏检只有 2.5%，错得离谱的程序谁的测试都能查出；限定后可信输出制度下漏检为 0.29，有量程。
  - **模型输出制度：** 单次生成里几乎总有一条期望输出写错，正确程序被拒的比例约 99%，按生成计的漏检读数失效。这个制度的主读数改为逐条测试的漏检（看起来对的错误程序上为 0.42）。这本身也是一个事实：7B 指令模型的无参考自产测试几乎不能直接当奖励。
  - 为了增加“看起来对”的错误程序，解题样本由每题 8 个改为 16 个。
  - **事前确定的主读数：**
    - 可信输出制度：单次生成的漏检；
    - 模型输出制度：逐条测试的漏检；
    - 两者都只看通过 ≥ 70% 隐藏测试的错误程序；
    - D 按上文定义，决策表不变。
  - 其余组合（全部错误程序；可信输出制度的逐条读数；模型输出制度的单次生成读数）作次要读数报告。

## 读数

- **漏检率 M_ij：** 生产者 j 的测试（每题合并 4 个样本、去重后的合法测试）在两种制度下，放过学习者 i 的错误程序的比例。按“题 × 错误程序”计；先在题内平均，再在题间平均。
- **模型输出制度下的误拒率：** 正确程序被 j 的测试判错的比例。期望输出写错的测试会冤枉正确程序。
- **同源交互（主读数）：** 每对模型 (i, k)，D_ik = [(M_ii + M_kk) − (M_ik + M_ki)] / 2。
  - 只在两人都有错误程序的题上计算；按题聚类 bootstrap 95% 区间。
  - D > 0 表示自己的测试更放过自己的错误，D < 0 表示更对口。
  - 生产者与学习者的主效应在加性模型下抵消；水平差距大的配对单独标注。
- **两类错误：**
  - 选择错误：可信输出制度下的漏检，只来自“没测到那个输入”。
  - 内容错误：模型输出制度下，额外放过的部分，即错误程序的输出恰好等于生产者写错的期望输出。
  - 内容错误再看“写错的期望输出与哪个模型的错误程序输出一致”：自己的对别人的，各自除以机会基数。
- **逐条错误的跨模型重合：** 两个生产者是否漏掉同一批错误程序，与独立基线（两者漏检率的乘积）比，报告超出的比例。
- **GRPO 组内优势：** 学习者每题 8 个样本作一组，奖励为“通过 j 的全部测试”。报告：
  - 有非零优势的组的比例；
  - 错误程序得分高于同组正确程序的比例（符号翻转）。

  自产与他产对比。只描述训练初始的一步，不当作训练结果。

## 对照

- **阳性对照（读数对“同源相关”是否敏感）：** 看了自己错误程序再写的测试，对该程序的漏检率，应高于只看题意写的测试（2607.05139：同模型、同会话，查错率 25% → 14%）。测不出这个差别，说明读数或流程不敏感，E17-0 的阴性不作结论。
- **噪声地板：** 每个模型的 4 个测试样本分成两半（1–2、3–4），两半各算一遍 D。两半之差给出“测试生成本身的随机性”。D 小于这个差，不作解释。
- **规模参照：** 不另加模型；Qwen2.5-Coder-7B 与 Seed-Coder-8B 的测试质量预计较高，作为生产者主效应的参照。

## 决策表（事前写定；最小有意义差 5 个百分点）

| 结果 | 动作 |
|---|---|
| 阳性对照不成立 | 先修流程；不解读 D |
| 至少一对的 D 在某一制度下 ≥ 5 个百分点，区间不含 0，且大于噪声地板（两类错误分开看） | H1 得到支持。起草 E17-1（对称交叉训练）的卡：选该对、该制度，算力另批 |
| 至少一对的 D ≤ −5 个百分点，区间不含 0 | 同源有利（自我适配）。同样起草 E17-1，方向反过来写 |
| 所有配对、两种制度的 D 区间都落在 ±5 个百分点以内 | H1 不成立。默认不训练（离线不对称太小，训练检测不到），把 H2、H3 是否还值得做交给人决定 |
| 其余（区间宽、跨 ±5） | 报告为不确定；不加模型、不加题去找显著。由人决定是否在功效分析后扩样本 |
