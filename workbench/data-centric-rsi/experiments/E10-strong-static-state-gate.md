# E10 — 更充分的强静态学生状态是否值得用于数据决策（2026-10-02）

- **状态：** DONE；这是 D1/D2 基线资格测量，不升级 C01–C04。
- **对应：** P03（简单静态配方意外强）、I01/C01 的必要前提。E08 的 120 条金标、3 epoch 学生已在 heldout1668 上比 base 高 3.66–4.20pp，但 base 与该学生的错误检索动作有 98/120 条相同。直接铺跨状态训练矩阵信息量低。
- **问题与两个解释：** 当前状态×数据动作很像，可能因为 120 条/24 步训练后学生状态仍过近；也可能是词面检索动作对显著学习状态变化仍不敏感。本卡先建设更充分的**真实金标静态 baseline**，检查学习收益和动作区分度；不把训练量与数据量的效果分开，也不把差异当 I01 证明。
- **设置（运行前冻结）：** 沿用 E00 固定 `google/gemma-2-2b-it@299a8560bedf22ed1c72a8a11e7dce4a7f9f51f8`、同一 LoRA/Trainer recipe（rank16/alpha32/dropout0.05、3 epoch、effective batch16、LR 1e-4 cosine/warmup0.1、cutoff1024）、seed17、从原始父模型开始、optimizer reset。新数据为冻结 `static_120.jsonl` **原顺序作为前 120 条**，再从 `train_pool.jsonl` 排除其 ID/题面 hash，在 `(level,type)` 格内按 record ID 排序、固定 RNG `20261002` 逐格 shuffle，按格名排序 round-robin 补 840 条，得到嵌套的 960 条；重复题面 hash 只留第一条。官方 `render_solution_for_scoring` 转监督，输入/输出哈希和选中 ID 全存；不得观察评测后换样本。当前输入 SHA：pool `73d48edf...e5c`、static120 `17e5d5e...e08`、dev `33999c27...8dc`、smoke `6f7e6d3...4fb`，运行时校验完整 SHA。test 只做既有封存 hash 排除，不评测。
- **评测：** 在同一 fvcrc10 **同一张 A100**、同一 vLLM 0.11 eager＋`VLLM_ENABLE_V1_MULTIPROCESSING=0`、zero-shot＋固定显式格式、temperature0/max350、官方 scorer、完全相同的 dev1740 输入上，顺序重新评 base、旧 static120 seed17、新 static960 seed17；不得用 E08 的 Blackwell 分数与 A100 的新分数直接相减。主指标为不含 72 条反馈题的 heldout1668 accuracy，逐题配对差及 bootstrap item CI；这是基线资格，不作为多 seed/cross-task 统计证据。报告三个状态的绝对分数、格式遵守率、按原类型分层、训练监督 token/截断/optimizer step/吞吐/显存/壁钟。唯一探索前定义的动作区分度：在同 72 道 smoke 的 A100 预测上，各状态对其错题做同一 char 3–5 gram TF-IDF 从冻结 pool 轮流取最近未用题直到各得 120 条；记录两动作的交集数、Jaccard、错误题交并。只生成候选列表，不训练这两个动作。
- **阳性对照：** 重新评的 static120 seed17 应相对 base 方向为正且量级接近 E08 的 +4.20pp；所有评估文件均完整 1740 ID 且相同题面哈希；960 条与 dev/test hash 零重合，旧 120 条完整保留。若 A100 不再测到既知静态信号，先停在 evaluator 核查，不能解释为学生状态无效。
- **噪声地板 + MIE：** E08 eager 同卡完整 base 双跑文本 SHA 相同、题级翻转 0；跨卡稳定性未知，故这里三组同卡重评。单 seed 的训练随机性仍未估计。若 static960 比重新测的 static120 至少多 **2pp（约 34/1668 题）**，且对应 120 条检索动作交集 **≤84/120**，才将其作为有足够信号/差异的 E01 状态候选；两条阈值是是否值得下一轮训练投入的 gate，非科学显著性标准。若增益或动作差异接近阈值，只保留诊断，不为跨状态结论补 seed。
- **混杂审计：** 同模型、prompt、evaluator、GPU、父 checkpoint、seed、recipe、分割已控制；960 vs120 同时改变例数、监督 token、优化步和 LR 曲线长度，**未控制**，本卡只评组合 baseline。原 train 池个别题解可能有质量问题，不能解释类型差异；问题词面相似度不代表语义策略。按类型读数只作事先描述，单类型不建方法。测试集只用于 hash 排除，所有选择在 dev 完成。
- **决策表（跑之前写）：** 960 比 120 ≥2pp 且动作交集≤84 → 将新状态用于下一张**真实训练效用** pilot，仍与强静态/等 token 控制比较；960 明显更强但动作仍高度重合 → 不铺 E01 的 TF-IDF 矩阵，寻找文献认可且实质不同的可验证动作；960 无明显收益或变差，而旧 120 阳性对照正常 → 这个数据/训练包不是合适的第二状态，审计训练损失和格式一次后，转向其他成熟 substrate/动作；旧阳性对照失效、评估未完成或文件不一致 → 停止解释，先修测量，不扩训练。
- **资源上限：** 一个 960 条单卡 LoRA 分支与同卡三次完整 dev 评估，预计 ≤1.5 A100 GPU·时；CPU 数据选择/分析与 API 分开记；不并行占用其他项目 GPU。若单次训练 >1 GPU·时或显存/输出异常，停止并保留失败 run。所有大文件放外部 `runs/e10/`，不进 git。

## 2026-10-02 选择器实现细则（base 评测已启动，但所有 E10 分数尚未产生）

词面特征只拟合一次：将冻结 train pool 的候选题面与完整 72 道 smoke 题面合并拟合 E04 参数的 char 3–5 gram TF-IDF，各状态共享同一向量空间。候选池对所有状态都排除嵌套 static960 已训练题目的 ID/题面 hash，避免将强学生已经见过的题当后续新动作；另排除 dev/test 题面（冻结 pool 已如此）。每轮按 smoke 题的冻结顺序，对其错题取当前相似度最高且未选过的候选，循环直至 120 条；平局按原 pool 顺序。这个细则在所有 E10 反馈/结果出现前固定，与 E04 的“只用各自错误拟合 IDF、每错题两条”不同，故 98/120 旧预检值只作背景，新的动作交集阈值按本卡独立判断。

## 结果（2026-10-02，运行后追加，不回改上文）

- **资格门结果：** 同一 fvcrc10 A100 GPU0、同一完整 dev1740 文件/zero-shot＋格式/eager/V1 multiprocessing=0：base **331/1740**、static120 **409/1740**、static960 **391/1740**。排除事先用于反馈的 72 题，heldout1668 为 **320、391、375**；static120−base **+71/1668 = +4.26pp**（逐题配对 bootstrap 95% [+2.10,+6.35]pp），static960−static120 **−16/1668 = −0.96pp**（[−2.94,+0.96]pp），static960−base **+55/1668 = +3.30pp**（[+1.08,+5.52]pp）。旧静态阳性对照与 E08 跨设备的 +70/1668 同量级；不把 bootstrap 当训练种子区间。完整逐题预测/摘要及分析哈希见 [`results/E10_state_gate_analysis.json`](../results/E10_state_gate_analysis.json)。
- **动作区分度：** 固定 72 道 smoke 中 base/static120/static960 错 **61/54/56**；共享 TF-IDF 空间、统一排除所有 960 已训题目后，base↔static120 的 120 条动作交集 **99**，base↔static960 **102**，static120↔static960 **110**（Jaccard 0.846）；错误题交集相应 **50/52/51**。既没达到预写的 ≥2pp 更强学生，也没达到 ≤84/120 动作交集；原 E01 式 TF-IDF 跨状态训练矩阵不启动。这只限制当前词面行动规则，不证明有效数据动作不会随状态改变。
- **一次训练/格式审计：** `static_960_e10.jsonl` 完整包含旧 120 条（前 120 行字节一致），其余 840 条按预写格子选择；960 ID/题面 hash 唯一，与 dev/test 精确题面 hash 交集 0。960 分支从原父模型重启 optimizer、seed17、3 epoch、180 optimizer step，每 epoch **215,214** 监督 token，20/960 条超过 cutoff1024；旧 120 是 24 step、24,166 token/epoch、3/120 截断。因此本卡**不能分离数据量、token、优化时长和课程**。960 train loss **0.610**、旧 120 train loss **0.749**（不同训练集，不能直接当泛化差）；960 的 180 个 step 均有有限 loss，首个 0.9977、末个 0.5857，未见 NaN/未完成。含固定 `Final Answer` 字符串的 1740 道输出从旧 120 的 **1259** 增至 960 的 **1504**，含 `\\boxed` 从 **1440** 增至 **1523**；所以总分下降不是显然的格式遵守率退化。没有为解释 −16 题追加调 LR、选 checkpoint 或筛 seed。
- **预算/资产：** 960 训练 wall **761.2s**，评估 base/static120/static960 为 **163.1/133.2/154.2s**，共占单卡约 **0.337 A100 GPU·时**；训练峰值 PyTorch allocated **9,387,350,016 bytes**，无 teacher/API。CPU 数据构造/TF-IDF/配对分析时间未单独测量，不伪报 CPU 小时。冻结源数据、选中 ID 与 SHA 在 [`results/E10_data_manifest.json`](../results/E10_data_manifest.json)；模型、训练日志、三份逐题评估在 `/home/xiang/.cache/research/data-centric-rsi/runs/e10/`，不进 git。新数据 SHA256 `36f0338d996d2b66fee86ce6b50e4e663726a346197f1cbbbeb777908090d208`。
- **按跑前决策：** 960 分支未提供更强第二状态，且错误检索动作与旧学生几乎相同。暂停这个 action family 的 E01 扩张；把金标静态120保留为**在当前预算/口径下**的强简单基线。下一项 GPU 投入须先找到与它在训练内容上有实质区别、仍可验证的动作，并明确其训练后收益如何产生高于“增大同一静态集”的信息量；或改用更适合可验证数据生成的成熟 substrate。一个 seed 的 −0.96pp 不构成“更多数据有害”的一般结论，也不建立新 I##。
