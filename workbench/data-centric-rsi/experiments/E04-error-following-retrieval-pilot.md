# E04 — 简单错误追随能否胜过强静态数据（2026-10-02）

- **状态：** DONE（运行前设计已冻结；三训练种子全数保留）
- **类型：** EXPLORE，E00 的强基线对照；不预设 I02/C03 为真。
- **对应：** I02、P01（baseline feedback 输入故障）、E00。
- **问题：** 在相同 120 题 SFT 预算下，依据学生真实错误检索已有正确标注题，是否比均衡静态配方更有训练收益？这检验“错误反馈直接指向有用数据”这个最便宜解释。
- **解释区分：** 若收益超过强静态，错误位置含可用决策信息；若没有，可能是粗糙检索无效、覆盖比相似度更重要、或 120 题 SFT 已足够，不能直接推断反馈没价值。
- **设置：** 与 E00 相同 `google/gemma-2-2b-it` revision、官方 DataEnvGym prompt/scorer、`EleutherAI/hendrycks_math` revision、LoRA recipe。反馈来自 base 在已冻结 72 题 smoke 上用显式格式 prompt 的贪心预测；只取错误题面，不给候选的答案。候选从 MATH train 排除全部 1740 dev 与 5000 test 的规范化题面 hash 后取得。字符 3–5 gram TF-IDF；每个错误轮流取相似度最高的尚未使用的 2 条，共 120，固定序与哈希。无 teacher/API。E00 静态 120 是现成对照。
- **训练/评价：** 先同训练 seed 17 对比 E00 static17，parent、optimizer reset、batch/LR/epoch/截断/解码与 E00 一致。主读数为 352 题开发子集扣除 72 题 feedback smoke 的 **280 题 held-out accuracy**，按题配对。若相对静态有值得追的增益/损失，再以预定 seed 29、43 重复；失败和无效数据均保留。报告全 352 题只作辅助，不用 feedback 题的得分做主结论。
- **阳性对照：** E00 静态训练应胜过 base；hash 排除应保持 train 对 eval 零精确题面重复；检索应覆盖 60 个错误而非偶然只取少数题。
- **噪声地板 + MIE：** E00 的 3 个静态 seed 在相同 280 题上的范围和配对任务 bootstrap。pilot 中相对 static17 的绝对收益至少约 5pp（14/280），且重复种子同向，才优先进一步测试；这是算力决策尺度，不是自动科学判决。
- **已知混杂：** 检索可能改变 level/type/题长/解答 token 分布，逐项记账；同例数/epoch/更新步不保证同训练 token。没有 teacher 正确性混杂。smoke/held-out 分离控制了直接反馈泄漏，仍是同源 MATH 的单模型局部结论。
- **最强替代解释：** 检索找到重复模板或改变题长/难度；若有效，先检查这些简单变量，不能把结果直接解释成“改进器学会研究”。
- **决策表（跑之前写）：** 检索显著优于强静态且复种子同向 → 研究它到底利用什么状态信息，并与更强检索/覆盖基线比较；检索相近或更差 → 保留强静态成功，避免把错误列表默认当行动方案，考虑真实动作收益测量；读数因格式/分布/训练失败不可信 → 修基线，不推进主张。
- **算力预算：** 1 个训练 seed + 352 题 eval 约 0.2 GPU·时；触发重复时总量约 0.6 GPU·时。CPU TF-IDF 单次，API 0。**实际：** 待填。

## 结果（2026-10-02）

- 检索 60 个 base 错误，每错 2 条不同训练题，合计 120；候选池 5759，所选与 feedback 题面精确 hash 重合 0。训练每 epoch 28,105 监督 token（静态为 24,166），3 条被 1024 截断。见 [`results/E04_retrieval_manifest.json`](../results/E04_retrieval_manifest.json)。
- **主读数 held-out280：** base 35/280；静态 seed17/29/43 为 48/53/58；错误检索相同 seed 为 **64/57/56**。检索－静态依次 **+16、+4、−2 题**，即 +5.71/+1.43/−0.71pp，三种子平均 +2.14pp。逐题 bootstrap 区间分别 [+2.50,+9.29]、[−1.79,+4.64]、[−3.93,+2.50]pp；这是题目抽样不确定性，不覆盖训练 seed 方差。全 352 题检索为 81/73/72，静态 66/74/75。
- 单次训练 wall 107.1/105.1/103.8s，单次 352 题评估约 74–80s，训练+评估合计约 **0.15 GPU·时**；本地重新准备数据并检索合计约 27s CPU wall（含 Python/import），API 0。原始预测与失败日志在外部缓存 `runs/e04/`，配对分析在 [`results/E04_dev_analysis.json`](../results/E04_dev_analysis.json)。
- **按决策表：** 首 seed 越过 5pp 复种子门槛，所以补 29/43；复种子没有同向大效应，不能将第一个 seed 包装成错误反馈优势。静态均衡策略仍是很强门槛；E05 的分布匹配对照已注册，用来检查首 seed 的替代解释。C03 **保持 L0**，I02 不升级。
- **已知局限：** 检索集更偏高难度且长于静态集，监督 token 多 16.3%；反馈来自 72 题低分 base，而非完整 DataEnvGym teacher 的开放式生成。这否定的是当前简单检索 pilot 的稳定优势，不否定反馈或 RSI 领域。
- **POST-HOC 提示协议审计：** 源码复核后统一换成 zero-shot＋同一句格式指令，held-out280 的静态 seed17/29/43 是 55/60/53，检索为 60/64/65；配对差 +5/+4/+12 题，即 +1.79/+1.43/+4.29pp，仍没有种子都超过预设 5pp 的强优势。原来 few-shot 下 seed17 特别高而 seed43 反向的排序对提示敏感，不能在两种口径里挑较漂亮的一组。分析见 [`results/E00_E04_E05_zero_format_analysis.json`](../results/E00_E04_E05_zero_format_analysis.json)。这项追加评测另用约 0.06 GPU·时。
