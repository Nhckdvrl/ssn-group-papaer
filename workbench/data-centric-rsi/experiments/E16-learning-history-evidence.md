# E16：学习经历与学习证据的生产（2026-11-28，草案）

- **状态：** PLANNED（草案，待组里看；不跑。阶段 0 只用公开模型做推理，可先于训练讨论完成）
- **类型：** PILOT
- **对应：** 讨论稿 10.8（v8，第八轮意见校对后）。没有现行主张（CLAIMS 为空）。
- **问题（一句话）：** 解题水平相近、但学习经历不同（学解题 / 学产生区分性证据）的模型，为后续学习产生证据的能力是否不同？这种不同能否改变之后的实际学习——包括共同的接收者，以及模型自己的继续学习？

**已知的部分（主笔读原文核对，均为单个设置、看起来单次运行）。**
- Learning to Self-Verify（arXiv 2602.07594）：Qwen2.5-1.5B/3B/7B-Instruct，各 1,000 步 GRPO。只训练解题，判断他人解答对错的准确率变化 +0.4 / −4.6 / +4.4；只训练判断，判断能力升 5–17 分，解题也达到与只训练解题相当的水平。
- TCS（arXiv 2609.03955）：R1-Distill-Qwen-1.5B，只做代码 RL 时解题 5.6 → 11.2（TACO），但用自己生成的测试挑选答案只再加 0.8；只做测试 RL 时，自生成测试的挑选收益 +7.5。
- CURE（arXiv 2506.03136）：只优化写代码，不提高写出正确单元测试的能力（14B，100 步）；它训练出的测试生成器作为另一个模型 RL 的奖励，效果接近人工标注的测试。
- 所以“学会解题不会自动带来判断与造测试的能力”在同一任务上已有直接证据；本卡不以重测这一点为目标。
- **还不知道的：**
  - (i) 不同学习经历产出的证据，对之后的实际学习价值是否不同；
  - (ii) 这种差别能否继续传下去；
  - (iii) 证伪“自己的错误”与证伪“外部的错误”是否同步；
  - (iv) 生成—验证差距理论（Mind the Gap）预言“验证能力更强的模型自我改进更多”，这一点在不同学习经历之间、而不只是不同预训练规模之间，是否成立。

- **设置：**
  **阶段 0：公开模型的自然实验与量程检查（不训练）。**
  - 模型：Qwen2.5-7B-Instruct 与以它为起点的 ReasonFlux-Coder-7B（CURE，解题与写测试共同训练）；DeepSeek-R1-Distill-Qwen-7B 与以它为起点的 TCS-7B（测试生成两阶段 RL）。两对各有同一起点，对内比较；对间不比（起点、数据都不同）。
  - 题目：带隐藏测试的代码题，取各模型训练截止之后的 LiveCodeBench 窗口，加 TACO 留出切片。
  - 读数矩阵（行为 × 信息条件 × 错误来源，只做必要的格子）：
    - 行为：解题；判断候选程序对错；构造能区分对错的输入。出题放到阶段 2。
    - 信息条件：给参考解与候选；只给候选（不保证它错）；给模型自己过去的真实解题输出与执行反馈。
    - 错误来源：参考解的 AST 变异体（固定面板）；其他模型的真实错误解；该模型自己的真实错误解。
  - 目的：确认这些读数有量程（初始模型不在 0 或满分附近），并确认已知“学过造测试”的模型分数更高（阳性对照）。不作因果结论。
  - **阶段 0 的具体设置（2026-11-28 定，跑之前）：**
    - 模型（HF，阶段 0 只推理）：`Qwen/Qwen2.5-7B-Instruct` 与 `Gen-Verse/ReasonFlux-Coder-7B`；`deepseek-ai/DeepSeek-R1-Distill-Qwen-7B` 与 `XiaoBanni/TCS-7B`（README 指明是 TCS 论文的模型；另外三个匿名副本的分片哈希与它相同）。
    - 题目：CodeContests 的 test 与 valid 划分（全部是 Codeforces 题，约 200 个生成测试 / 题）。
      - 入选条件：至少 2 个 Python3 正确解在我们的执行环境里通过全部测试；至少 1 个人类 Python3 错误提交属于“答案错”（在时限内跑完、输出错），排除超时和运行错误。
      - 按 Codeforces 评分分层抽 100 题；先用其中 10 题试点。
      - 污染：CURE 只用难度 ≤ 2 的非 Codeforces 题训练，重叠应很少；TCS 用 TACO 训练划分，评分前按题面文本查重叠，有重叠的题单独报告。
    - 错误来源（每题每种最多 2 个）：
      - 外部：人类错误提交。
      - 固定面板：正确解的 AST 变异体（比较符、边界常数 ±1、算术符），要求通过公开样例、但在隐藏测试上答案错。
      - 自身：该模型在解题任务里自己写出的、通过公开样例但隐藏测试答案错的程序。
    - 任务：
      - 解题：每题 4 个样本。
      - 判断：给题面和候选程序（人类正确解与错误提交各半），回答对或错；每个 2 个样本。
      - 构造区分性输入，给参考解：给题面、正确参考解和错误程序，输出一个输入。
      - 构造区分性输入，不给参考解：给题面和候选程序（错误与正确各半），若认为有错就给一个让它出错的输入，否则回答正确。
      - 两种构造任务每个实例各 2 个样本。
    - 判定：
      - 输入有效：至少 2 个正确解都在时限内跑完且输出一致（近似“满足题目约束”，写为局限）。
      - 区分成功：输入有效，且错误程序的输出与正确解不同，或它超时、报错。
    - 提示：主读数对四个模型使用同一套中性提示，并各用自己的聊天模板。另外，对 ReasonFlux-Coder-7B 和 TCS-7B 用各自论文的造测试提示格式再跑一遍“给参考解”的构造任务，作为对提示格式的敏感性检查。
    - 采样：温度 0.6、top-p 0.95，最多 16,384 个 token（R1 系模型推理较长）。
    - 执行：子进程，CPU 时限按题目时限的 2 倍，内存 1GB，空临时目录，`-I`。

      - 外部：1.5B 的错误解，要求通过 base 输入、在 plus 输入上答案错，即“看起来对”。
      - 固定面板：参考解的 AST 变异体，同样要求过 base、错在 plus。
      - 自身：各模型自己写出的同类错误解。每题每种最多 2 个。
    - 两轮：
      - 第一轮：所有模型只做解题（每题 4 个样本），由此得到外部错误与各自的错误。

    - 判定：
      - 合法：带约定断言的参考解在该输入上不报错。
      - 区分成功：错误程序的结果与参考解不同（浮点按 1e-6 容差），或错误程序报错、超时。
    - 读数分两层：给出合法输入的比例（格式与协议），以及给出合法输入条件下的区分成功率（能力）。

  **阶段 1：同一起点、两种学习经历（训练，先做试点）。**
  - 起点：Qwen2.5-1.5B 或 3B-Instruct（与 Self-Verify 同尺度，便于对照），由阶段 0 的量程决定。
  - H_solve：在题集上做代码生成 RL，奖励为隐藏测试通过。
  - H_evidence：在同一题集上，对候选程序（混合正确与错误的）构造区分性输入，执行参考解给出真值，奖励为“输入合法且能区分”（TCS 第二阶段的形式）。
  - 两者用同一题集、同一算法、同一训练算力；记录实际 rollout token、零优势组比例。两种监督的信息量不可能相等，本阶段识别的是两种学习经历的整体因果效应。
  - 对角线检查（Gemini 第八轮）：题集分两个互不重叠的算法族 A、B，只在 A 上训练，在 A、B 上都测。只在 A 上提高才算“学到的东西带来了相应的证据能力”，A、B 同步提高则多半是通用的格式或协议迁移。
  - 定期存 checkpoint；全部候选、执行结果、奖励逐样本保存。
  **阶段 2：证据的学习价值（小规模，从一开始就保留，不以阶段 1 的代理指标为门槛）。**
  - 共同接收者：H_solve、H_evidence（以及阶段 0 的公开模型对）各自为留出题选择输入；可信执行器给出输出，构成“题目—输入—输出”监督；用同样数量训练同一个接收者（起点模型）；用隐藏测试评估接收者的写代码与输出预测能力。这样把“会不会提出值得问的输入”和“会不会自己给出正确答案”分开。
  - 自身继续学习：每个经历的模型用自己产出的测试作奖励，再做一轮代码 RL（CURE 式），比较各自的增益。和共同接收者对照：只在自身继续学习上占优，说明优势在模型自己的验证锚点；在共同接收者上也占优，说明优势经由产出的数据传递。
  - 是否进入“第二次生产”（接收者再生产证据），等阶段 2 有结果后另写卡。
- **读数（按 GPT 第八轮的四个层次）：**
  - 证据正确性：输入合法、期望输出正确。
  - 区分性：对固定变异体、外部错误、自身错误的击杀率，三者分开报告。
  - 可学习性：接收者训练后的变化（相对接收者起点的增益）。
  - 迁移价值：在留出算法族与留出题上的变化。
  - 区分性只是机制读数，不替代学习价值。
- **事先预测（主笔，写于 2026-11-28；只作信息量参考）：**
  - H_solve 解题提高，区分性输入能力变化小（与 TCS、CURE 一致）；对自身错误的击杀率可能下降。把握中等。
  - H_evidence 区分性提高，解题小幅提高（与 Self-Verify 方向一致）。把握中等。
  - 共同接收者上，H_evidence 的数据更有学习价值，大小不确定——这是本卡最不确定、也最关键的一项。
  - 自身继续学习上，H_evidence 更好（生成—验证差距理论的预言）。把握中等。
- **阳性对照：**
  - 阶段 0：ReasonFlux-Coder-7B、TCS-7B 相对各自起点在区分性读数上应更高；不更高，先查读数。
  - 阶段 2：由参考解覆盖构造的输入（例如能杀死全部变异体的输入集）训练接收者，必须带来可测的增益；随机输入作阴性对照。正对照测不出增益时，本卡不具备检验能力，不解释为“没有效应”。
- **噪声地板 + MIE：**
  - 阶段 0：按题 bootstrap；同一模型重复采样两次的差作采样噪声。
  - 阶段 1：试点 2 个训练种子，正式 3 个。
  - 阶段 2：接收者 3 个种子，并且每个经历独立生产 2 份数据（测数据生产本身的随机性，不只是训练随机性）。
  - 报告效应量、配对差与置信区间；不显著不等于没有效应，功效不足时写“无法判断”。具体 MIE 在阶段 0 测完噪声后写入本卡（注明日期）。
- **混杂审计：**
  - 两种经历的监督信息量不同：未控制（本卡识别的是整体效应；更严格的信息匹配留作后续机制实验）。
  - 训练算力：控制步数与 rollout 预算，报告实际 token 与零优势组比例。
  - 格式或提示迁移：对角线设计控制。
  - 熟悉知识的锐化与新知识的获得（Gemini 第八轮）：本卡未控制；如果阶段 1 的增益主要在熟悉题上，另加“陌生语义的小程序族”一档（只在必要时）。
  - 题目污染：只用训练截止之后的 LiveCodeBench 窗口，并报告 TACO 切片。
  - 变异体算子的偏差：同时报告真实错误来源。
  - 阶段 0 的模型对之间：起点与数据都不同，只作量程和阳性对照，不作因果。
- **决策表（跑之前写）：**
  - 阶段 0 读数没有量程，或阳性对照不成立 → 先修读数，不进入训练。
  - 阶段 1 的结果与已知一致（H_solve 证据能力变化小、H_evidence 提高）→ 进入阶段 2（本卡的主问题）。若与已知相反，先复核实现。
  - 阶段 2：
    - 两种经历的证据，在共同接收者上的学习价值有差别（超出数据生产与训练两层噪声）→ 学习经历经由产出的证据影响他人的学习；下一张卡测能否继续传播（接收者的第二次生产），以及差别来自“自身错误”还是“外部错误”。
    - 共同接收者上没有差别，但自身继续学习有差别 → 差别在模型自己的验证锚点，不在产出的数据；对照生成—验证差距理论。
    - 两者都没有差别 → 在这个规模上，解题相近的不同学习经历，在经由证据生产的后续学习上没有可测差别。如实报告，回到 10.8 重新评估方向，不扩大规模去找效应。
