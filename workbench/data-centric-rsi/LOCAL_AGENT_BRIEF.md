# 本地 agent 接手说明

这是研究 workbench，不是要求从零写一个 RSI 框架的工程任务。当前 PROPOSED；未获得替换现有 ACTIVE 调度的授权。用户已授权调研和注册，本文件不会扩大算力/服务/数据授权。

## 先同步，保留遗产

读全库 README、AGENTS、RESOURCES、本 workbench README、FIELD_MAP、POSITIONING、ASSETS、CLAIMS、PAIN_LOG。同步最新 main，确认没有其他 agent 已经开始 E00；不得重复下载或重跑已有资产。

首先在完整本地仓库运行 `python3 tools/process/check.py`。本轮远程写入环境未能 clone 全库，因此没有声称已通过全库检查；发现问题按本仓库规则处理，不改其他线的科研状态。

## 真正的建设目标

在被批准的单卡/单节点资源槽位上，把一个强数据→训练→评估 baseline 做可信。默认考察 DataEnvGym 本地 math；修好数据入口/依赖，保留原论文和本地适配差异。运行前完成 E00 中尚待节点实测的字段。

不要根据论文摘要直接执行一套从零实现的 SOAR/SGS/ASP；不要把 3B 当完整内循环便宜的证明。不要为了“新方法”先建多 agent、知识图谱和复杂调度。

## 允许自主推进的事

在已有授权内修 baseline、冻结 manifest、执行跑前卡、记录成功/失败、提出对应真实痛点的小方法、补具体近邻全文/代码。科学问题允许在同一领域内成长；不要求硬证明 I01/I02。

## 不允许的漂移

- 不用某个局部 probe、几条奇怪题或一张相关性图宣称解决 RSI。
- 不把纯算术 toy 的改善当最终外部能力证据。
- 不使用 private test 调生成器、选择最佳 checkpoint 或搜索配方。
- 不只报告 best-of-n，隐去全部失败和选择开销。
- 不混淆从 M0 重训候选与持续更新同一学生。
- 不把已有论文的“difficulty≠utility”“anchoring”“cross-play”“targeted pilot”写成我们的创新。
- 不因近邻存在就 kill；先精确写增量，也不忽略近邻硬做重复工作。

## 决策点

E00 后先汇报 baseline 是否真正工作、单候选成本、测量噪声和有哪些实际痛点。E01/E02 不是无限遍历指令；在可行动效应、混杂解释或方法分支出现时做一次人审。两轮解释被简单对照吸收后，停止局部堆叠，回到领域地图和痛点，而不是自动开新项目。

每次汇报：推进了什么 → 真实数字/不确定性 → 哪条 C#/I#/P# 改变 → 目前最强替代解释 → 下一项能改变判断的实验。没有结果就写没有结果。
