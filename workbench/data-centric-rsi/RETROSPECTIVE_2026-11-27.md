# Data-centric RSI 回顾：做了什么，为什么没做出有用的东西

整理日期：2026-11-27。依据：本目录 README、CLAIMS、PAIN_LOG、三张 idea 卡、E00–E14 实验卡与 results、三天日志、2026-10-04 外部审计报告。除第 3.3 节一项补算外，没有新跑实验。

## 0. 结论

- **做的时间**：2026-10-02 到 10-04，三天，基本由 GPT agent 执行。之后一直停着，状态是 PROPOSED，所有主张 C01–C04 都还是 L0（没有证据）。
- **跑了什么**：两个底座。前半段是 Gemma2-2B 在 MATH 上的小 LoRA（E00–E10），后半段是 LLaVA-1.5-7B 在 Curation-Bench 上的 10K 全参 SFT（E12–E14）。后半段算力约 21.6 A100·h，另外还有十几个 Blackwell·h 的 judge。
- **可靠的结果只有一类**：拿真实标注数据训练，比不训练高（MATH 上 +3.7–4.2pp；LLaVA 上大约 +3.3–4.4 分）。数据选择方法之间的差别，几乎全在噪声范围内。
- **为什么没出东西**，按影响从大到小排：
  1. 我们最初想研究的“改进器自己变强”，**一次都没测过**。实验对象一步一步换成了别的东西。
  2. 能比较的数据动作彼此太像，差别本来就小。
  3. 每条只跑一个种子，而两个种子之间的差，就比各方法之间的差还大（第 3.3 节）。
  4. 本地没有能出合格数学题的教师模型，所以“生成数据”这条路从没接上训练。
  5. 问题本身不够尖锐：问的大多是“X 能否复用、有没有用”这类程度问题，结果事先就能猜到；近邻文献又已经占了大部分宽泛的说法。
  6. 工程和记账耗掉了大部分精力，文档写得太密，掩盖了“科学上没进展”这个事实。
- **节点上的大资产已经没了**（fvcrc10/12/13/20 的 `/var/tmp/xiang-data-rsi/` 都不存在了）。脚本还在 git 里，`~/.cache/research/data-centric-rsi/`（1.6G 的代码仓）和 `~/.venvs/data-centric-rsi` 也还在。

## 1. 当时想研究什么

**RSI**（recursive self-improvement）指递归自我改进。data-centric 版本是这样一个闭环：一个“改进器”（出题模型、选数据的程序，或者数据研究 agent）为学生模型制造或挑选训练数据，学生训练后变强，改进器再根据学生的反馈变得更会造数据。

当时写了三个候选 idea，都是很宽的“种子”：

| ID | 白话 | 想测的东西 |
|---|---|---|
| I01 | 一套选数据/造数据的策略，能不能拿给新学生直接用，只做少量调整 | 学生状态 × 数据策略的交互 |
| I02 | 看到学生做错题以后，除了“多给同类题”，系统能不能学会选出真正有效的训练干预 | 反馈 → 数据决策 → 训练收益，以及在新学生上是否还管用 |
| I03 | 短期看起来“学得动”的数据，是否也有长期价值 | 不同训练长度下的动作排序 |

工作台自己的文档写得很清楚：要说明这是 RSI，需要分别测三件事：**学生变强**、**改进器变强**、**改进器在新学生/新任务上仍然更会改进**。

## 2. 做了什么（按阶段）

| 阶段 | 实验 | 做了什么 | 关键数字 | 说明了什么 |
|---|---|---|---|---|
| A. MATH 底座 | E00、E08 | DataEnvGym 代码，Gemma2-2B-IT，从 MATH 训练集取 120 道真实标注题做 LoRA，评测 1668 道题 | 三个种子都比 base 高 **+3.66 / +4.02 / +4.20pp**；改成 vLLM eager 后两次评测逐题一致 | 训练闭环能跑，静态数据有真实收益。早期看到的大增益有一部分来自提示格式，后来纠正了 |
| A. 错题检索 | E04、E05、E08 | 按学生的错题，用 TF-IDF（词面相似度）找相似训练题，和静态 120 题比较 | 只多 **+0.78–1.32pp**，置信区间跨零；但监督 token 多 16.3% | 词面检索几乎没有额外价值，而且这点差还可能来自数据量 |
| A. 本地教师出题 | E06、E07、E09 | 用 Qwen2.5-32B、Qwen3-32B 代替原论文的 GPT-4o 出数学题 | 格式能过，但答案错、抄输入；Qwen3 严格格式只有 1/20 通过 | **0 条生成数据进入训练**，生成这条路没接上 |
| A. 第二个学生状态 | E10 | 用 960 题训练出一个“更强”的学生，看两个学生按错题检索选出的数据是否不同 | 960 题版本反而比 120 题低 0.96pp（单种子）；两个学生选出的 120 题里 **110 题相同** | 在这个动作空间里，学生状态几乎不改变动作，跨状态实验没有意义 |
| A. 静态换素材 | E11 | 草案 | 没跑 | 发现它还是在比静态数据，运行前搁置 |
| B. LLaVA 底座 | E12 | Curation-Bench：LLaVA-1.5-7B 全参 SFT 10K 样本，8 个多模态 benchmark（judge 用本地 Qwen3.5-27B）。比较 4 种静态选法 | base **28.96**（论文 28.8，量级对上）；random **32.30**、五源均衡 **33.44**、ICONS 公开池 **32.81**、ARDS **32.95**；同一 checkpoint 重评只差 −0.05 | 底座可信。只有“五源均衡比 random 高 1.14”明显超过种子噪声，其余差别都在噪声附近 |

| B. 最简单对手 | E14 | 只保留来源比例、全部换新数据 | init **32.78**，used **33.50** | 没有比别的方法好 |

**10-04 停步时自己写的判断**：“尚未形成可以推荐作为主线重押的、增量清晰的成形 idea。”同一天外部审计（`RSI_AUDIT_AND_EXPERIMENTS_2026-10-04.md`）也给出了同样的结论，并提出了一个转向建议（见第 5 节）。之后没有人做决定。

## 3. 为什么没做出有用的

### 3.1 核心对象被一步步替换，“改进器”一次都没测到

实际推进的链条是：

> 改进器能否学会造更好的数据 → 错题词面检索 → 修本地教师 → 换第二个学生状态 → 静态策展方法比较 → 冻结策展池补货

每一步单看都有理由（“先把基线做可信”“这个环节坏了先修”），合在一起却离原问题越来越远。到最后：

- “反馈 → 数据决策 → 训练收益”这条链，只在 E04 的词面检索里出现过一次，而且信号很弱；
- “改进器在新学生/新任务上更会改进”，**测了 0 次**；
- E12–E14 本质上是在比较“几种固定的选数据方法”，这和 RSI 已经没有关系了。

agent 自己在 PAIN_LOG 的 P06 里两次承认了这一点（“把资格门当成科学进展”），但承认之后的下一步（E12–E14）仍然在重复同一种模式。

### 3.2 动作空间太窄，差别本来就小

一个实验能分辨出东西，前提是被比较的动作彼此真的不同：

- E10：两个学生状态选出的数据 110/120 相同，学生状态再怎么不同也传不到动作上；
- E13：三个动作共用同一来源、同一监督 token 数，还保留 46 条共同样本，等于在“几乎一样的 10K 数据”里做微调；
- 在 LLaVA 这个设定下，任何合理的 10K 都能带来 +3–4 分，不同选法只在这之上差 1 分左右。用这么窄的差去分辨“哪层资产有价值”，信号很难出来。

### 3.3 只跑一个种子，而种子之间的差比方法之间的差还大（本次补算）

E12 的“ICONS seed17”和 E13 的“init/replay seed29”用的是**同一份 10K 数据、同一个父模型、同一套训练配方**，差别只有训练种子（另外评测节点也不同）。逐项对比如下：

| 任务 | seed17 | seed29 | 差 |
|---|---:|---:|---:|
| 8 项均值 | 32.81 | 33.34 | **+0.52** |
| LLaVABench | 34.8 | 38.5 | **+3.7** |
| MMBench | 52.75 | 51.37 | −1.37 |
| MMVet | 28.53 | 27.34 | −1.19 |
| MathVista | 22.5 | 23.7 | +1.2 |

对照一下：

- E13 同一父模型下各动作的均值差，最大 0.55，正好落在这个 0.52 的范围里；
- E13 审阅里当作“值得讨论的线索”的任务取舍（池内补货在 MathVista +1.8/+2.0、MMVet −2），和单纯换种子造成的逐项波动是同一个量级；
- E12 里只有“均衡比 random +1.14”明显超过这个范围。

当时的“噪声地板”只测了**同一个 checkpoint 重评一次**（−0.05）。这只是评测噪声，不是训练噪声，而训练种子才是真正的大噪声源。E13 的卡里其实写了“训练方差未估”，但仍然按单种子跑完了全部 8 支。所以 E13/E14 从设计上就**分辨不出它想分辨的效应**。

注意：这只是一对种子，而且混了评测部署的差异，还不是严格的方差估计。但它足以说明单种子读数不能用。

### 3.4 生成能力缺失，“造数据”从未接上训练

DataEnvGym 的原论文靠 GPT-4o 出题、解题。本地换成 Qwen2.5/Qwen3-32B 以后，题目答案错、抄输入、格式坏，预先写好的质量门槛三次都没过。所以 RSI 最核心的那一环（改进器**生成**新数据）从头到尾是空的。这一点不能外推成“DataEnvGym 或生成数据没用”，只说明我们的本地替代品不可用。

### 3.5 问题不够尖锐，近邻已经占了宽泛说法

三个 idea 都是“能否复用 / 有没有用 / 何时需要校准”这类**程度问题**。这类问题的结果大多能事先猜到（“有点用，看情况”），而且无论结果如何，都很难说明“所以呢”。这正是导师 11 月提出的标准里明确反对的问法（不要问程度，结果要真有信息量，不能事先猜到，要有参照和对比）。

同时，阅读中逐步发现，大部分宽泛说法已被近邻占据：

| 我们想说的 | 已经做过的近邻 |
|---|---|
| 学会可迁移的数据改进策略 | Data Mixing Agent（ACL 2026），冻结策略跨任务迁移 |
| 用真实训练反馈优化配比 | DUET（ICLR 2026）、MFMS-BO（NeurIPS 2025） |
| agent 写数据筛选程序 / 根据失败改数据代码 | Curation-Bench、CurateEvo |
| 经验库 + 先跑小实验 | EEM、AutoLLMResearch、Gödel Forest |
| 学生状态相关的选样、多步代理、跨尺度静态数据 | Group-MATES、BLISS、PDS、LESS |

拥挤本身不是放弃的理由，但这意味着需要一个比“X 能否复用”尖锐得多的问题，而当时没有找到。

### 3.6 工程和记账压过科学

大量时间花在：judge 冷启动失败（显存、FlashInfer 不兼容 sm120）、NFS 导入慢、vLLM 子进程没被清理、浮点等号误判、ICONS/ARDS 公开代码的索引 bug 等等。这些都被认真记了账，记录也确实可靠，但日志和状态页因此写得极密（一句话里塞五六个数字和 SHA），反而让人看不出“三天下来科学上没有进展”。

## 4. 留下来的有用东西

- **事实**（可以直接引用，不是新主张）：
  - 统一评测提示后，静态真实数据在 MATH/Gemma2-2B 上有稳定收益；
  - vLLM V1 离线贪心解码不确定，加 eager 后可逐题复现；
  - Curation-Bench 的 LLaVA 底座在本地能复现到论文量级（base 28.96 对 28.8）；
  - ICONS/ARDS 公开代码的索引映射有 bug（ICONS 58,201 条错指，ARDS 的 `global_id−1` 全错）；论文作者实际是否用错未知；
  - 单种子下，不同 10K 选法的差别大多在噪声内。
- **代码**：`scripts/` 里有 E00–E14 全部脚本（Curation-Bench 本地训练/评测、judge、进程守护、映射审计）。注意：节点上的 Arrow 数据（93GB）、父模型、checkpoint 都已删除，重启要重新下载。
- **文献**：60 篇分级阅读账本（`READING_LIST.md`）、论文卡（`library/themes/training-post-training/RSI_PAPER_CARDS.md`）、定位表（`POSITIONING.md`）。重拾方向时这部分最值得复用。

## 5. 10-04 审计提出的转向（没有人做过决定）

审计建议把对象从“学生的训练数据”换成“**研究 agent 的实验经验**”：用 AutoLLMResearch 公开的 460 次真实训练结果表，让一个冻结的 LLM agent 读历史实验，然后选下一个数据配比，看经验的不同写法（原始记录 / 总结 / 带适用条件的 lesson）会不会改变决策质量。完全不用新训练学生（R1–R3），有结果后再用真实训练验证（R4）。

我对这个建议的看法：

- **优点**：便宜，能直接测“经验 → 决策”这一环，正好补上 3.1 缺失的部分。
- **风险**：
  1. 这又是一次对象替换（从训练数据换成 agent 记忆），和原来的 data-centric RSI 已经是两回事；
  2. 近邻（EEM、Gödel Forest、AutoLLMResearch 本身）非常近；
  3. 一张有限的配比表，动作空间同样窄，很可能重蹈 3.2 的覆辙；
  4. 它提出的问题（“经验何时足以指导新条件”）仍然是程度问题。
- **判断**：可以作为候选之一，但不应该默认就是重启方向。

## 6. 重拾时值得先定的几件事

这些是从上面原因直接推出的做法，不是计划：

1. **先定一个尖锐的问题，再选底座。** 上次是先有底座（DataEnvGym、Curation-Bench），再在上面找能跑的东西。问题要有参照和对比，结果不能事先猜到，不是“有没有用 / 有多大用”。
2. **先测训练种子噪声。** 任何方法比较之前，同一配方至少跑 2–3 个种子；如果效应小于种子差，就换动作空间，而不是加 matching 控制。
3. **选差别大的动作。** 动作之间的差别要能大到盖过噪声：比如质量差异明显的生成数据和真实数据、数据量差一个量级，而不是同来源、同 token 数的微调。
4. **想测“改进器变强”，就必须有真实的生成或修订能力。** 本地教师不可用的问题要先解决（更强的本地模型、可执行验证的任务，或者干脆不做生成）。
5. **先读文献，再写卡。** 这次大部分“已被占据”的发现，都是跑到一半才读到的。
